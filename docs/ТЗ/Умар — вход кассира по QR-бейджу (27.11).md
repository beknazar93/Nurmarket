# Вход кассира по QR-бейджу — что нужно от сервера (27.11.2026)

**Не отправлено.** Черновик ТЗ для Умара. Касса 1.17.95+ уже умеет входить по QR-бейджу без сервера (см. «Как сейчас»), но у этой схемы есть ограничения, которые снимает только сервер.

## Зачем
Владелец: «открытие кассы с помощью QR — кассир подносит бейдж к сканеру и сразу входит от своего имени». Сканер — обычный USB (печатает как клавиатура). Пароль кассир не вводит.

## Как сейчас (без сервера, в кассе)
- Программа владельца выпускает бейдж: случайный код `NMBADGE:v1:<id 12 hex>:<секрет 32 hex>` (128 бит). Пароля и токена в нём нет.
- Реестр бейджей (только **SHA-256** секрета, id сотрудника, срок, отзыв, PIN-хэш PBKDF2) лежит в общем документе настроек компании: `api/main/app-settings/nurmarket-kassa/`, ключ `CashierBadgesJson`. Пишет владелец/админ, читают все кассы.
- Токен кассира касса получает **только паролем**. Поэтому касса хранит зашифрованный вход (refresh-токен) кассира с бейджем — только на той кассе, где он хотя бы раз вошёл паролем. Скан бейджа открывает этот сохранённый вход, сервер подтверждает его обычным обновлением токена. Перед входом касса перечитывает реестр с сервера: если бейдж отозван, касса сразу выходит.

**Ограничения:**
1. На каждой новой кассе кассир один раз вводит пароль. Если refresh-токен истёк или его отозвали, пароль нужен снова.
2. Refresh-токены кассиров хранятся на ПК кассы (зашифрованно, DPAPI).
3. Реестр с хэшами могут прочитать все сотрудники компании. Перебрать 128-битный секрет нельзя, а вот 4-значный PIN по хэшу перебрать можно.
4. Журнал входов по бейджу ведётся только локально на кассе. Владелец его не видит.
5. Отзыв доходит до кассы, только когда касса на связи.

## Что нужно на сервере

### 1. Бейджи сотрудников
- `POST api/users/employees/{id}/badges/` — выпустить бейдж (владелец, админ или сотрудник с `can_edit_employees`). Тело: `{"expires_at": "<ISO>|null", "require_pin": false}`. Ответ: `{"id": "...", "code": "NMBADGE:v1:<id>:<secret>", "created_at", "expires_at"}`. **Код возвращается один раз**, на сервере хранится только хэш (SHA-256 или лучше HMAC с серверным ключом). Прежние действующие бейджи этого сотрудника отзываются.
- `GET api/users/employees/{id}/badges/` — список без кода: `id, created_at, expires_at, revoked_at, last_used_at, last_used_device`.
- `DELETE api/users/employees/{id}/badges/{badge_id}/` — отозвать. Отзыв мгновенный для всех касс.
- Удалили или отключили сотрудника → все его бейджи недействительны.

### 2. Вход по бейджу — `POST api/users/auth/badge/`
Тело: `{"code": "NMBADGE:v1:...", "pin": "1234"|null, "device_id": "...", "device_name": "...", "replace_device": false}`.
- Успех — тот же ответ, что у `api/users/auth/login/`: `access`, `refresh`, профиль, права. Слоты устройств работают как при входе паролем (`409 device_slot_taken`).
- `401 {"code": "badge_invalid"}` — неизвестный код или неверный секрет. Неизвестный и неверный не различать.
- `403 {"code": "badge_revoked"}`, `403 {"code": "badge_expired"}`.
- `403 {"code": "badge_pin_required"}` — PIN нужен, но не прислан. `401 {"code": "badge_pin_invalid"}` — PIN неверный.
- `429 {"code": "badge_throttled", "retry_after": 30}` — защита от перебора: по IP и устройству, плюс по бейджу для PIN (например, 5 ошибок → пауза 30 с, дальше пауза растёт).
- Компания без доступа к кассе (тариф, `can_use_pos`) — как у входа паролем.

### 3. PIN («QR + PIN»)
PIN хранится только на сервере (PBKDF2/Argon2) и проверяется в `auth/badge/`. Нужна настройка компании `badge_requires_pin` (по умолчанию false) и/или флаг `require_pin` у конкретного бейджа.

### 4. Журнал входов
`GET api/users/auth/badge-log/?employee=&date_from=&date_to=` (владелец, админ): `time, employee_id, employee_name, device_name, result (ok|invalid|revoked|expired|pin_invalid|throttled), ip`. Код бейджа в журнал не писать.

### 5. Совместимость
Пока `auth/badge/` нет (404), касса работает по нынешней локальной схеме. Когда метод появится, касса перейдёт на него: refresh-токены кассиров на ПК хранить больше не нужно, и пароль на новой кассе тоже не понадобится. Ключ `CashierBadgesJson` в app-settings можно будет удалить, когда все кассы обновятся.
