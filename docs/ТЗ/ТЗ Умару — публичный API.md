# ТЗ Умару — публичный API для интеграторов (26.11.2026)

От: Бекназар (касса NurCRM). Пункт №12 отчёта о конкурентах (МойСклад — API и 100+ интеграций, Webkassa — Postman-коллекция, Checkbox — 200+ интеграций). Интеграторы и разработчики сайтов — сеть продаж. Общие правила — «ТЗ Умару — общие правила денег и расчёта (26.11).md».

## 0. Что есть сегодня

- Внутренний API `api/main/…` для кассы, сайта и мобилки: вход по паролю/PIN → JWT (срок входа 7 суток от пароля), права сотрудника, `capabilities`. Публичные `public/…` — витрина, тарифы, модули.
- Нет: ключей для внешних программ, документации, стабильной версии, лимитов на ключ, вебхуков для интеграторов. Отдавать интегратору JWT сотрудника — небезопасно (полные права, истекает, привязан к человеку).

## 1. Что видит пользователь

**Владелец → «Для разработчиков»** (программа владельца и сайт):

```
┌ Для разработчиков ─────────────────────────────────────┐
│ Ключи API                                  [+ Новый ключ]│
│ ┌──────────────┬────────────────┬────────┬───────────┐ │
│ │ Название     │ Права          │ Создан │ Последний │ │
│ │ Сайт магазина│ товары:чтение, │ 26.11  │ 5 мин     │ │
│ │              │ остатки:чтение,│        │ назад     │ │
│ │              │ заказы:запись  │        │ [Отозвать]│ │
│ └──────────────┴────────────────┴────────┴───────────┘ │
│ Вебхуки: [+ адрес]  события: sale.created, stock.changed │
│ Документация: docs.nurcrm.kg/api   Postman-коллекция ⤓  │
│ Журнал запросов (7 дней)                                │
└─────────────────────────────────────────────────────────┘
```

Новый ключ: название, права (галочки), филиалы, срок (бессрочно / до даты), IP-ограничение (необязательно). Ключ показывается **один раз** («скопируйте сейчас»).

## 2. Модель данных

```
api_key
  id, company, name, prefix (первые 8 символов, видимые), secret_hash (argon2/bcrypt), scopes[], branches[],
  ip_allowlist[], expires_at, created_by, last_used_at, revoked_at, rate_plan (default|extended)
api_request_log (key, method, path, status, ms, at, ip) — 7 дней, без тел запросов
webhook_endpoint (id, company, url (https), secret, events[], status, fail_count, disabled_at)
webhook_delivery (endpoint, event_id, payload, attempt, status, next_retry_at)
```

Формат ключа: `ncrm_live_<8 prefix>_<32 secret>`; тестовый — `ncrm_test_…` (работает на тестовом аккаунте/песочнице).

## 3. Права (scopes)

| Scope | Что даёт |
|---|---|
| `products:read` / `products:write` | товары, категории, цены, штрихкоды |
| `stock:read` | остатки по складам/филиалам |
| `sales:read` | чеки, возвраты (без персональных данных клиента, если нет `clients:read`) |
| `orders:write` | создать заказ покупателя / резерв (как заказ витрины) |
| `clients:read` / `clients:write` | клиенты, бонусный баланс (только чтение баланса) |
| `webhooks:manage` | управлять вебхуками |

**Запрещено ключам всегда** (И-4, И-10): проводить продажи и возвраты, двигать деньги смены, начислять/списывать бонусы, погашать подарочные карты, менять права и сотрудников, видеть закупочные цены без отдельного `products:cost`. Деньги — только через кассу.

## 4. Эндпоинты (v1, стабильные, отдельный префикс)

```
Authorization: Bearer ncrm_live_…        X-Api-Version: 1 (по умолчанию)
GET   api/v1/products/?updated_since=&cursor=&limit=100
GET   api/v1/products/{id}/
PATCH api/v1/products/{id}/              {price, name, barcode, is_active}   (Idempotency-Key)
GET   api/v1/categories/
GET   api/v1/stock/?product=&branch=&updated_since=
GET   api/v1/sales/?date_from=&date_to=&cursor=
GET   api/v1/sales/{id}/
POST  api/v1/orders/                     {items[{product, qty}], client{name, phone}, delivery?, comment}  (Idempotency-Key)
GET   api/v1/orders/{id}/
GET   api/v1/clients/?phone=&cursor=
POST  api/v1/webhooks/  | DELETE api/v1/webhooks/{id}/
GET   api/v1/me/                          → компания, scopes, лимиты
```

Правила: пагинация **курсором** (не page — стабильно при изменениях); деньги строками; даты ISO-8601 с поясом; `updated_since` везде, где есть изменения; удалённые товары — `is_deleted: true` в выдаче `updated_since` (а не исчезают); ответы только нужных полей (не внутренние объекты кассы).

Пример:

```json
// GET api/v1/stock/?updated_since=2026-11-26T10:00:00Z
{ "items": [ { "product": "p1…", "sku": "A-102", "branch": "br1…", "quantity": "14.000",
               "reserved": "2.000", "available": "12.000", "updated_at": "2026-11-26T10:03:11Z" } ],
  "next_cursor": "eyJ…" }
```

Вебхук (подпись `X-NurCRM-Signature: sha256=HMAC(secret, body)`, `X-NurCRM-Event-Id`):

```json
{ "id": "evt_…", "type": "stock.changed", "created_at": "…", "company": "…",
  "data": { "product": "p1…", "branch": "br1…", "available": "12.000" } }
```

События Ф1: `sale.created`, `sale.returned`, `stock.changed`, `product.updated`, `order.status_changed`. Доставка — не менее одного раза, повторы 1 мин → 5 мин → 30 мин → 2 ч → 12 ч, после 20 неудач подряд — отключить и написать владельцу.

## 5. Лимиты

- По умолчанию: 60 запросов/мин и 10 000/сутки на ключ; 5 ключей на компанию; ответ 429 + `Retry-After` + заголовки `X-RateLimit-Remaining/Reset`.
- Тариф: API — только на «Стандарт» и выше (или модуль), на «Старт-Free»/«Мини» — нет (`403 plan_limit {limit: "api"}`).
- Тяжёлые выгрузки (все продажи за год) — не через листание, а `POST api/v1/exports/ {type: "sales", date_from, date_to}` → ссылка на файл (Ф2).

## 6. Ошибки

`{ "code": "...", "detail": "...", "request_id": "..." }` — `invalid_api_key` (401), `api_key_revoked` (401), `insufficient_scope {required}` (403), `ip_not_allowed` (403), `rate_limited` (429), `validation_error {fields}` (400), `not_found` (404), `idempotency_conflict` (409 — тот же ключ с другим телом). Ошибки на английском + `detail` на языке `Accept-Language`.

## 7. Безопасность

- Секрет хранится только хэшем; в журнале — prefix. Отзыв действует мгновенно (кэш ≤ 30 с).
- Ключ не входит в программы клиентов (касса/мобилка) — только для серверов интеграторов; CORS для `api/v1` закрыт (браузерным сайтам — через свой бэкенд).
- Журнал: создание/отзыв ключа — в аудит; уведомление владельцу о новом ключе (Telegram-бот).
- Персональные данные клиентов — только с `clients:read`, телефон частично (маска) без `clients:read_full` (Ф2).

## 8. Документация

- OpenAPI 3.1 (генерировать из кода), страница `docs.nurcrm.kg/api` (ru, en; ky — Ф2), Postman-коллекция, примеры на curl/PHP/Python/JS, песочница = тестовый аккаунт с ключом `ncrm_test_`.
- Политика версий: `v1` не ломаем; новые поля — можно; удаление — только в `v2`, `v1` живёт ≥ 12 мес. после выхода `v2`; список изменений.

## 9. Признаки, права, модуль

- Признак `public_api` (касса/программа владельца показывают раздел «Для разработчиков»).
- Право `can_manage_api_keys` (только владелец).
- Модуль «API для интеграций» — цена решает владелец (предложение: входит в «Стандарт»; отдельно 300 сом/мес).

## 10. Тесты приёмки

1. Ключ с `products:read` → `GET products` 200; `PATCH products/{id}` 403 `insufficient_scope`.
2. Отозванный ключ → 401 в течение 30 с.
3. 61-й запрос за минуту → 429 с `Retry-After`.
4. `POST orders` дважды тем же ключом → один заказ; тот же ключ с другим телом → 409 `idempotency_conflict`.
5. Ключ филиала А не видит остатки филиала Б.
6. Вебхук `sale.created` приходит с верной подписью; адрес отвечает 500 → повтор через 1 мин.
7. Любой ключ: попытка провести продажу/возврат через `api/main/pos/...` → 401 (ключи не действуют на внутренний API).
8. Курсорная пагинация: добавление товаров во время листания не даёт пропусков и дублей.

## 11. Этапы

- **Ф1**: ключи, scopes, лимиты, `products/stock/sales/orders/me`, журнал, OpenAPI + Postman, раздел в программе владельца.
- **Ф2**: вебхуки, выгрузки, `clients`, IP-списки, песочница, каталог интеграций на сайте.

## 12. Что подхватит касса / программа владельца

- раздел «Для разработчиков» в программе владельца: ключи (создать/показать один раз/отозвать), права, вебхуки, журнал, ссылки на документацию — 5 языков;
- касса сама API-ключи не использует; заказы, созданные через API, приходят в «Заказы» как заказы витрины/покупателя (уже есть экран `customer-orders`).
