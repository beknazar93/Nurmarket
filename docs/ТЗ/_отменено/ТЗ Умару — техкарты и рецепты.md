# ТЗ Умару — техкарты и рецепты (состав со списанием) (26.11.2026)

От: Бекназар (касса NurCRM). Пункт №14 отчёта о конкурентах (Paloma365 «Полный», МойСклад «Производство», Poster «Рецепты»). Нужен для пекарен, кафе-лайт (см. «ТЗ Умару — кафе-лайт»), пошива, мяса (совместить с «Выходом мяса»). Общие правила — «ТЗ Умару — общие правила денег и расчёта (26.11).md».

## 0. Что есть сегодня

- **Комплект** (`is_bundle`, `bundle_items[] {product, quantity}`): у товаров с сервера **сервер сам списывает остатки компонентов** при продаже комплекта; касса список хранит только для показа (для офлайн-комплектов — источник состава). Это частный случай техкарты: целые штуки, без потерь, без полуфабрикатов, без себестоимости по составу.
- Партии и себестоимость FIFO на сервере (`stock_batches`, `costing_fifo`), дробное количество (`hardware_2026_11`), весовые товары (`is_weight`).
- Нет: граммовок ингредиентов, выхода, потерь при обработке, полуфабрикатов, производства «впрок», отчёта «себестоимость по составу».

## 1. Что видит пользователь

**Владелец/технолог → карточка товара → вкладка «Состав (техкарта)»:**

```
┌ Лепёшка тандырная — состав ─────────── выход: 1 шт ┐
│ Режим списания: (•) при продаже  ( ) при производстве│
│ ┌───────────────┬────────┬──────┬────────┬────────┐ │
│ │ Ингредиент    │ Брутто │ Ед.  │ Потери │ Нетто  │ │
│ │ Мука в/с      │ 0,250  │ кг   │ 0 %    │ 0,250  │ │
│ │ Вода          │ 0,150  │ л    │ 0 %    │ 0,150  │ │
│ │ Дрожжи        │ 0,005  │ кг   │ 0 %    │ 0,005  │ │
│ │ Кунжут        │ 0,010  │ кг   │ 10 %   │ 0,009  │ │
│ └───────────────┴────────┴──────┴────────┴────────┘ │
│ Себестоимость по составу: 14,30 сом · цена 30 · наценка 110 % │
│ [+ ингредиент] [+ полуфабрикат]    [История версий] │
└─────────────────────────────────────────────────────┘
```

**Производство** (режим «при производстве»): документ «Выпуск продукции» — «Лепёшка × 200» → списаны ингредиенты, оприходовано 200 шт по себестоимости состава. Программа владельца и касса (кнопка «Выпуск» для пекаря, с правом).

**Кассир:** ничего нового — продаёт блюдо/изделие как товар. При нехватке ингредиента — как при нехватке товара (политика «продавать без остатка»).

**Отчёты:** «Себестоимость по составу» (по блюдам: цена, себестоимость, маржа), «Расход ингредиентов за период» (норма vs факт после ревизии), «Что заканчивается» по ингредиентам.

## 2. Модель данных

```
recipe
  id, company, product (готовое изделие), version, is_active,
  yield_qty "1.000", yield_unit,
  writeoff_mode: on_sale | on_production,
  valid_from (для версий; продажа берёт версию, действовавшую на sold_at)
recipe_item
  recipe, ingredient (product — сырьё или полуфабрикат с своим recipe), qty_gross "0.250", unit,
  loss_percent "10.00", qty_net (вычисляется), optional bool (модификатор «без кунжута» — для кафе)
production_doc (id, company, branch, number, status: draft|posted|cancelled, posted_at, user,
                lines[{product, qty, recipe_version}], idempotency_key)
stock_movement  + reason: recipe_sale | production_in | production_out, source (sale_line | production_doc)
```

Ограничения: глубина вложенности полуфабрикатов ≤ 3; запрет циклов (A входит в B, B в A → 400 `recipe_cycle`); единицы ингредиента = единицы его складского учёта (конвертация г→кг на стороне ввода).

## 3. Расчёт на сервере

1. **Списание при продаже** (`on_sale`): на строку продажи `qty` сервер разворачивает техкарту версии на `sold_at`: расход ингредиента = `qty / yield_qty × qty_gross` (брутто — со склада уходит брутто). Полуфабрикат без своего остатка разворачивается рекурсивно; с остатком (произведён заранее) — списывается он сам.
2. **Списание при производстве** (`on_production`): продажа уменьшает остаток готового изделия (как обычный товар); ингредиенты списаны документом выпуска.
3. **Себестоимость** изделия = Σ (расход брутто × себестоимость ингредиента по FIFO/средней) — пишется в строку продажи (`cost`) — отчёт маржи и **И-1 (не ниже закупки)**: для товара с техкартой «закупка» = себестоимость по составу на момент продажи.
4. **Возврат** изделия: по умолчанию ингредиенты **не возвращаются** на склад (еда не возвращается), строка возврата уменьшает выручку; флаг товара `return_restocks_ingredients` (для пошива/комплектов — да). Для `on_production` — готовое изделие возвращается на остаток по флагу `return_restocks` (как у товара).
5. **Нехватка ингредиента**: как нехватка товара — 409 `insufficient_stock {product: ingredient, need, available}` без `allow_negative_stock`; с ним — проводится, ингредиент в минус, `warnings[].negative_stock` (касса уже понимает).
6. **Офлайн-касса**: продаёт изделие как товар; разворот техкарты делает сервер при досылке по версии на `sold_at`.
7. **Изменение техкарты** = новая версия; старые продажи не пересчитываются (И-8).
8. **Комплект** остаётся как есть; миграция в техкарту — по желанию (комплект = техкарта с `loss 0`, `yield 1`, целые штуки).

## 4. Эндпоинты

```
GET    api/main/products/{id}/recipe/                → активная версия (+ себестоимость сейчас)
PUT    api/main/products/{id}/recipe/                → новая версия (Idempotency-Key); ответ: version, cost_now
GET    api/main/products/{id}/recipe/versions/
POST   api/main/recipes/calculate/                   {items: [{product, qty}]} → расход ингредиентов и себестоимость (для кафе-заказа, отчётов)
POST   api/main/production/                          {branch, lines[{product, qty}]} (Idempotency-Key) → draft
POST   api/main/production/{id}/post/ | cancel/
GET    api/main/production/?date_from=&date_to=
GET    api/main/reports/recipe-cost/?category=
GET    api/main/reports/ingredient-usage/?date_from=&date_to=&branch=
```

Пример `PUT recipe`:

```json
{ "yield_qty": "1", "yield_unit": "шт", "writeoff_mode": "on_sale",
  "items": [ { "ingredient": "p_flour", "qty_gross": "0.250", "unit": "кг", "loss_percent": "0" },
             { "ingredient": "p_sesame", "qty_gross": "0.010", "unit": "кг", "loss_percent": "10" } ] }
// 200 { "version": 3, "cost_now": "14.30", "valid_from": "2026-11-26T14:00:00+06:00" }
```

В строке продажи (`pos/sales/{id}/`): `recipe_version`, `cost`, `ingredients_written_off[]` (по запросу `?expand=ingredients`).

## 5. Ошибки

400 `recipe_cycle`, 400 `recipe_depth_exceeded`, 400 `recipe_unit_mismatch {ingredient, expected_unit}`, 409 `insufficient_stock {product, need, available}`, 409 `production_already_posted`, 403 `recipe_edit_forbidden`.

## 6. Признаки, права, модуль

- Признаки: `recipes` (техкарты со списанием при продаже), `production` (выпуск продукции), `recipe_cost_reports`.
- Права: `can_edit_recipes`, `can_post_production`.
- Модуль «Техкарты и производство» — цена решает владелец (предложение 300 сом/мес; в профиле «Кафе», «Пекарня»).

## 7. Тесты приёмки

1. Лепёшка (мука 0,250 кг) × 4 → мука −1,000 кг; продажа 0,5 шт (дробь) → −0,125.
2. Кунжут 0,010 брутто, потери 10 % → списывается 0,010 (брутто), нетто 0,009 — только для показа.
3. Полуфабрикат «Тесто» (без остатка) внутри «Самсы» → списаны ингредиенты теста; с остатком теста 5 кг → списывается тесто.
4. Себестоимость: мука 50 сом/кг × 0,25 = 12,50 + … = 14,30; цена 13 со скидкой без права → 400 `price_below_cost` (закупка = себестоимость состава).
5. Изменили техкарту в 14:00; офлайн-чек 13:30, досланный в 15:00, — списание по старой версии.
6. Возврат лепёшки → ингредиенты не вернулись, выручка уменьшилась.
7. Цикл A→B→A → 400 `recipe_cycle`.
8. Выпуск 200 лепёшек дважды тем же ключом → один документ, одно списание.

## 8. Этапы

- **Ф1**: техкарта (ингредиенты, брутто/потери, выход), списание при продаже, себестоимость в строке, версии, отчёт «себестоимость по составу».
- **Ф2**: полуфабрикаты, производство «впрок», расход «норма/факт» после ревизии, необязательные ингредиенты (модификаторы «без …» для кафе).

## 9. Что подхватит касса / программа владельца

- вкладка «Состав» в карточке товара (программа владельца и «Склад → Товары» кассы, по праву), калькулятор себестоимости, история версий — 5 языков, чек-лист полей;
- документ «Выпуск продукции» в кассе (для пекаря) и программе владельца;
- значок «по техкарте» на плитке; нехватка ингредиента — существующее окно «нет остатка»;
- отчёты в программе владельца.
