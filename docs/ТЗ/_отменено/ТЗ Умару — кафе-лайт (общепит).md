# ТЗ Умару — «Кафе-лайт»: столы и счета, кухня, экран повара, официант с телефона (26.11.2026)

От: Бекназар (касса NurCRM). В отчёте о конкурентах — «за пределами ТОП-15, L, только если идём в общепит» (Poster, iiko, Paloma365 сильны здесь). **Отдельный большой этап** Ф1–Ф3. Зависит от «ТЗ Умару — техкарты и рецепты». Общие правила — «ТЗ Умару — общие правила денег и расчёта (26.11).md».

Цель — не «второй iiko», а **кафе на 5–30 столов, кофейня, шаурма, столовая, чайхана**: открыть счёт на стол, отправить на кухню, повар видит, официант добавляет с телефона, расчёт с разделением, списание по техкарте.

## 0. Что есть сегодня

- Касса продаёт товары/услуги, отложенные чеки (локально), комплекты (сервер списывает состав), консультант в продаже (официант — как консультант с процентом), принтеры чеков (ESC/POS, несколько принтеров), мобилка NurCRM (каталог, продажа), офлайн-очередь, скидки/бонусы.
- Нет: столов и залов, открытых счетов на сервере, гостей, модификаторов, кухонных принтеров/экранов, курсов подачи, разделения счёта, обслуживания (% за обслуживание).

**Повар → экран кухни (Android/Windows, браузер):** карточки заказов по времени, позиции с модификаторами и комментарием, таймер, «Готовлю» → «Готово» (официанту приходит уведомление), фильтр по цеху (кухня/бар/гриль). Без экрана — **кухонный принтер** печатает «бегунок» по цеху.

**Официант с телефона (мобилка NurCRM, роль «Официант»):** свои столы, открыть счёт, добавить позиции с модификаторами, отправить на кухню, пречек, «Готово» с кухни; оплату принимает касса (Ф1) или сам официант по QR (Ф3).

**Владелец:** залы и столы (схема), цеха и принтеры, модификаторы, % обслуживания, отчёты: выручка по столам/официантам/часам, время приготовления, отмены после отправки на кухню (контроль воровства).

## 2. Модель данных

```
hall (id, company, branch, title)       table (id, hall, number, seats, x, y, shape)
station (id, company, branch, title: Кухня|Бар|Гриль, printer_id?, display_enabled)
product + station_id, modifiers_group_ids[]
modifier_group (id, title, min, max, required)   modifier (id, group, title, price_delta "30.00", recipe_delta (Ф2: −лук / +сыр в техкарте))
open_check   — серверный открытый счёт (главная новая сущность)
  id, company, branch, number, table (null = на вынос), guests, waiter, status: open | precheck | paid | cancelled,
  lines[{id (uuid), product, qty, price, modifiers[{id, price_delta}], comment, course (1..3),
         seat (номер гостя), sent_at, station, kitchen_status: new|sent|cooking|ready|served|voided,
         void_reason, voided_by, added_by}],
  service_percent, discounts (как в чеке), version, opened_at, sale_id (после оплаты), split_from
kitchen_ticket (id, open_check, station, lines[], printed_at, displayed, created_at)
```

## 3. Правила сервера

1. **Открытый счёт — на сервере**, общий для всех касс и телефонов (два официанта не потеряют позиции). Каждое изменение — `PATCH` с `version` (конфликт → 409 с актуальным счётом, клиент сливает и повторяет); добавление строк — операция «append» с `line.id` от клиента (повтор не дублирует строку, И-4).
2. **Отправка на кухню**: неотправленные строки → `kitchen_ticket` по цехам (печать на принтер цеха / экран). Повтор отправки тем же ключом — без второго бегунка.
3. **Отмена после отправки** (`void`) — только с правом `can_void_sent_lines` и причиной; бегунок «ОТМЕНА» на кухню; в отчёт отмен. До отправки — свободно.
4. **Цена строки** = цена товара + Σ `price_delta` модификаторов; акции/уровень/промокод — общий расчёт (`quote` по открытому счёту); И-1 — не ниже себестоимости по техкарте (с модификаторами).
5. **Обслуживание** `service_percent` — отдельная строка-услуга от суммы после скидок, без бонусов (как доставка); отключаемо на счёте (с правом).
6. **Пречек** — печать без фискализации, статус `precheck` (счёт можно дополнить — снова `open`).
7. **Разделение счёта**: по позициям (выбранные строки → новый `open_check`, `split_from`), по гостям (`seat`), поровну на N (сумма делится, копейки — на первого). Каждая часть оплачивается отдельной продажей; сумма продаж = сумма счёта (И-6).
8. **Оплата**: `POST open-checks/{id}/pay/` = обычная продажа (`pos/checkout/` из строк счёта, `Idempotency-Key`), счёт `paid`, стол свободен; повтор — та же продажа; второй платёж того же счёта → 409 `check_already_paid`.
9. **Списание**: по техкарте при продаже (ТЗ техкарт); модификаторы с `recipe_delta` — Ф2. Отменённые до оплаты, но приготовленные (`void` после `cooking`) — списание ингредиентов как «порча» (флаг цеха).
10. **Офлайн**: касса держит копию открытых счетов; без сети — работает с локальной копией (одна касса — источник, телефоны без сети не работают), при связи сливает по `line.id`. Кухонный принтер в локальной сети печатает напрямую с кассы (без сервера) — это обязательное требование для Ф1.
11. **Смена**: открытые счета при закрытии смены — предупреждение; переносятся на следующую смену (не закрываются автоматически).

## 4. Эндпоинты

```

POST   api/main/cafe/open-checks/                     {table, guests, waiter} (Idempotency-Key)
POST   api/main/cafe/open-checks/{id}/lines/          {lines[{id, product, qty, modifiers, comment, course, seat}], version}

POST   api/main/cafe/open-checks/{id}/precheck/
```

## 5. Ошибки

409 `check_version_conflict {check}`, 409 `table_busy`, 409 `check_already_paid`, 403 `void_forbidden`, 400 `modifier_required {group}`, 400 `modifier_limit {group, max}`, 409 `line_already_sent` (правка отправленной строки).

## 6. Признаки, права, модуль

- Признаки: `cafe_tables` (Ф1), `cafe_kitchen_display` (Ф2), `cafe_waiter_app` (Ф2), `cafe_stream` (Ф2).
- Права/роли: `waiter` (свои столы), `cook` (только экран кухни), `can_void_sent_lines`, `can_remove_service_charge`, `can_manage_cafe_layout`.
- Модуль «Кафе-лайт» — цена решает владелец (предложение 300–500 сом/мес вместе с техкартами; профиль «Кафе»).

## 7. Тесты приёмки

1. Два официанта одновременно добавляют позиции в стол 2 → обе позиции в счёте (слияние по `line.id`), версия +2.
2. Повтор «Отправить на кухню» → один бегунок.
3. Отмена отправленной позиции без права → 403; с правом → бегунок «ОТМЕНА», запись в отчёт отмен.
4. Самса 90 + «двойной сыр» +30 → 120; акция −10 % → 108; обслуживание 10 % от суммы после скидок.
5. Разделить поровну 1 000 на 3 → 333,34 + 333,33 + 333,33; три продажи на 1 000,00.
6. Оплата счёта дважды тем же ключом → одна продажа; другим ключом → 409 `check_already_paid`.
7. Сеть пропала: касса добавила 2 позиции, бегунок напечатан на локальном принтере; связь вернулась → позиции на сервере, без дублей.
8. Лагман по техкарте: продажа ×2 списала ингредиенты ×2; void после «Готовлю» — списание как порча.

## 8. Этапы

- **Ф1 — Счета и кухонный принтер (касса Windows/Android):** залы/столы, серверные открытые счета, модификаторы (цена), цеха и печать бегунков **с кассы по локальной сети**, пречек, оплата, перенос/объединение, отмены с правом, отчёт по столам/официантам. Зависимость: техкарты Ф1.
- **Ф2 — Экран повара и официант с телефона:** экран кухни (статусы, таймеры), роль официанта в мобилке, поток событий (SSE/WebSocket), курсы подачи, разделение по гостям, модификаторы с `recipe_delta`.
- **Ф3 — Самообслуживание и оплата у стола:** QR-меню на столе с заказом гостя (подтверждает официант), оплата официантом по QR (ТЗ автоподтверждения QR), чаевые, бронь столов (ТЗ записи).

## 9. Что подхватит касса

- экран «Зал» (схема столов, статусы, таймеры), счёт стола, модификаторы при добавлении, «Отправить на кухню», пречек, разделение, оплата из счёта — 5 языков, чек-лист полей на 1024×600;
- печать бегунков на принтеры цехов (несколько принтеров уже поддерживаем), в том числе без сети;
- локальная копия открытых счетов и слияние по `line.id`;
- мобилка: роль «Официант» (Ф2); экран кухни — отдельное приложение/страница (Ф2).
