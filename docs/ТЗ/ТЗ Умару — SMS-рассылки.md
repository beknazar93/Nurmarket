## 2. Провайдер, имя отправителя (Кыргызстан)

- Агрегатор SMS с доступом к трём операторам КР (Beeline, MegaCom, O!). Кандидаты — проверить условия и API: Nikita (smspro.nikita.kg), прямые договоры с операторами (bulk SMS), международные (Infobip и аналоги) — по цене за SMS, наличию API статусов доставки и регистрации имени. **Договор с провайдером — у NurCRM** (мы перепродаём SMS пакетами), ключ — только на сервере.
- **Имя отправителя** (альфа-имя, до 11 латинских символов) регистрируется у операторов через провайдера на юрлицо/ИП магазина (документы магазина) — срок дни/недели. До одобрения — общее имя `NurCRM` (только сервисные сообщения, не реклама).
- Длина: кириллица 70 символов на SMS (67 при склейке), латиница 160 (153); кыргызские ң, ө, ү — кириллица.

## 3. Модель данных

```
sms_account   (company 1:1: balance_sms int, reserved_sms int, price_per_sms "1.50" (наша цена, решает владелец NurCRM),
               sender_name, sender_status: none|pending|approved|rejected, operators_approved[], night_quiet {from: "21:00", to: "09:00"})
sms_topup     (id, company, sms, amount, invoice (ELQR billing), status, created_at)
sms_template  (id, company, kind: order_ready|repair_ready|booking_reminder|debt_due|birthday|custom, text{ru,ky,uz}, is_active)
sms_campaign  (id, company, segment {kind, params}, text, send_at, status: draft|scheduled|sending|done|cancelled,
               recipients_count, sms_parts, reserved_sms, sent, delivered, failed, refunded_sms, promo_code?)
sms_message   (id, company, campaign?, kind, client?, phone_hash, phone_enc, text, parts, status: queued|sent|delivered|failed|expired,
               provider_id, cost_sms, idempotency_key, created_at, status_at)
consent       (существующая: client, category service|marketing, channel sms|telegram|whatsapp, granted_at, revoked_at, source)
```

## 4. Правила сервера

1. **Баланс (деньги)**: SMS покупаются пакетами (счёт ELQR — ваш `users/billing`). Перед отправкой — **резерв** `parts × получатели` в транзакции (`balance − reserved ≥ нужно`, иначе 409 `sms_balance_insufficient`); по статусу провайдера: доставлено/отправлено — списание из резерва; ошибка оператора (номер не существует, недоставлено по вине сети, отказ до отправки) — **возврат на баланс** (`refunded_sms`). Баланс никогда < 0 (И-3).
2. **Идемпотентность**: одно сообщение — один `idempotency_key` (`(kind, объект, событие)`, например `repair_ready:<order>`; рассылка — `(campaign, client)`); повтор не отправляет и не списывает второй раз (И-4). Кампания при повторном «Отправить» тем же ключом — тот же запуск.
3. **Согласие**: сервисные (`order_ready`, `repair_ready`, `booking_reminder`, `debt_due`) — по согласию `service` (или по закону о договоре — уточнить у юриста); **рекламные — только с `marketing` согласием** по каналу `sms`. Без согласия — получатель исключается до резерва (не тратим SMS).
4. **Отписка**: в каждой рекламной — короткая ссылка `nurcrm.kg/u/{token}` (страница «Отписаться от SMS магазина X») и/или «STOP» на входящие; отписка снимает `marketing` по `sms` мгновенно; повторная подписка — только явным действием клиента.
5. **Тихие часы**: рекламные не уходят с 21:00 до 09:00 (время компании) — переносятся на 09:00; сервисные — по настройке.
6. **Частота**: не больше 4 рекламных SMS одному клиенту в месяц от магазина (настройка, защита от спама и жалоб операторам).
7. **Сегменты** считает сервер (те же, что в кассе: «не были N дней», «должники», «день рождения на неделе», «много покупали», «уровень лояльности», «купили товар/категорию»), список фиксируется на момент запуска.
8. **Персональные данные**: телефон в `sms_message` — шифрованно + хэш для поиска; в логах — маска; текст рекламы без персональных данных кроме имени.
9. **Офлайн-касса**: касса SMS не шлёт сама — событие (ремонт «Готов», заказ «Собран») уходит на сервер обычным путём, SMS отправляет сервер.
10. Канал выбора: если клиент привязан к Telegram-боту — сначала Telegram (бесплатно), SMS — только если Telegram нет (настройка `prefer_telegram`, по умолчанию да).

## 6. Ошибки

409 `sms_balance_insufficient {need, available}`, 409 `sender_name_not_approved` (реклама под общим именем), 400 `sms_text_too_long {parts, max_parts: 3}`, 400 `sms_text_forbidden` (стоп-слова/ссылки без домена магазина — по правилам операторов), 403 `consent_missing`, 429 `sms_frequency_limit`, 502 `sms_provider_unavailable` (повтор позже, резерв держится до 24 ч, потом возвращается).

## 7. Признаки, права, модуль

- Признаки: `sms_notifications` (сервисные), `sms_campaigns` (рассылки), `sms_inbound_stop` (если провайдер даёт входящие).
- Права: `can_send_campaigns` (владелец, маркетолог), `can_topup_sms`.
- Модуль «SMS» — абонплата не нужна, доход — с пакетов (цена за SMS решает владелец: себестоимость провайдера + наценка; показать варианты 1,2 / 1,5 / 2,0 сом).

## 8. Тесты приёмки

1. Баланс 100, рассылка на 120 → 409 `sms_balance_insufficient {need: 120, available: 100}`.
2. Рассылка 50 SMS: 47 доставлены, 3 «номер не существует» → списано 47, возвращено 3.
3. Повтор события «Ремонт готов» по тому же заказу → одно SMS, одно списание.
4. Клиент без `marketing` согласия исключён до резерва; отписка по ссылке → следующая рассылка его не включает.
5. Рассылка на 22:30 → перенесена на 09:00, видно в ответе `quiet_hours_shift: true`.
6. Текст 140 кириллических символов → 3 части (67×3), стоимость ×3.
7. Клиент с Telegram и `prefer_telegram` → ушло в Telegram, SMS не списано.
8. Провайдер недоступен 24 ч → резерв возвращён на баланс, кампания `failed` с причиной.

## 9. Этапы

- **Ф1**: договор с провайдером, баланс и пакеты (ELQR), сервисные SMS (заказ, ремонт, запись, долг) по шаблонам, согласие, статусы доставки и возвраты, общее имя `NurCRM`.
- **Ф2**: рассылки по сегментам, имя отправителя магазина, отписка, тихие часы и частота, связь с промокодами, отчёт.

## 10. Что подхватит касса / программа владельца

- в «Клиентах» кассы — кнопка «SMS по сегменту» (при `sms_campaigns`) рядом с уже планируемой «Написать по очереди» (WhatsApp/Telegram, без Умара);
- галочка согласия на SMS в карточке клиента (категории `service`/`marketing` уже есть, канал `sms`);
- программа владельца: раздел «Рассылки» (баланс, пополнение, имя отправителя, шаблоны на ru/ky/uz, кампании, отчёт) — 5 языков интерфейса;
- карточка Маркетплейса `sms` из «скоро» → «доступно» при признаке, цена — с сервера.
