# ТЗ Умару — промокоды и подарочные карты (26.11.2026)

От: Бекназар (касса NurCRM). Пункт №9 отчёта о конкурентах (у Poster промокоды только через стороннее приложение, у Loyverse карты — через интеграции). Общие правила — «ТЗ Умару — общие правила денег и расчёта (26.11).md». Главное: **баланс карты — только на сервере**, одна на все кассы, иначе кассиры «потратят дважды».

Ничего (поиск по коду кассы пуст). Есть на что опереться: скидка на чек `order_discount_percent|order_discount_total`, ключи повтора, журнал ключей, офлайн-очередь, возврат `pos/sales/{id}/return/` с `items`, «Некорректные чеки» для владельца.

## 1. Что видит пользователь

**Кассир, окно оплаты:** поле «Промокод / подарочная карта» (ввод или скан штрихкода/QR карты).

```
┌ Оплата ─────────────────────────────── Итого 1 180,00 ┐
│ Промокод / карта: [ NC-7H2K-9QPL     ] [Применить]    │
│  ✓ Промокод OSEN10: −10 % (−120,00)        [убрать]   │
│  ✓ Подарочная карта …9QPL: доступно 500,00            │
│      списать [ 500,00 ] (остаток 0,00)     [убрать]   │
│ Осталось оплатить: 680,00                             │
│ (•) Наличные ( ) Безнал ( ) Смешанная                 │
└───────────────────────────────────────────────────────┘
```

Без связи: «Подарочные карты и одноразовые промокоды принимаются только при связи с сервером». Отказы — понятным текстом: «Промокод истёк 30.11», «Карта уже использована», «На карте 120,00».

**Кассир, продажа карты:** товар-услуга «Подарочная карта» (номинал 500/1000/свободный) → после оплаты сервер **активирует** карту, касса печатает чек и карту (код + штрихкод/QR). Пластиковые карты с заранее напечатанным кодом — скан при продаже.

**Владелец:** «Промокоды» — создать (код вручную или «сгенерировать 100 одноразовых»), тип, условия, срок, лимиты, отчёт использований; «Подарочные карты» — выпущенные, баланс, история, срок, заблокировать, «выпустить на сумму» (подарок/компенсация без продажи — отдельное право, в отчёт как расход).

## 2. Модель данных

```
promo_code
  id, company, code (уникален в компании, без учёта регистра), batch_id,
  kind: percent | amount | free_product,  value, free_product_id,
  scope {products[], categories[]} | null (на чек), min_receipt "500.00",
  starts_at, ends_at, max_uses_total, max_uses_per_client, single_use bool,
  stackable_with_promotions bool, offline_allowed bool (только многоразовые), allow_below_cost bool,
  status: active|paused|expired, used_total
promo_redemption (promo, sale, client, amount, status: applied|released, created_at)

gift_card
  id, company, code (16 символов, без похожих 0/O/1/I, с контрольной цифрой), pin (опц., 4 цифры, хэш),
  initial "1000.00", balance "1000.00", currency,
  status: inactive | active | blocked | expired | exhausted,
  issued_sale, issued_by, issued_reason (sale|gift|compensation),
  activated_at, expires_at (по умолчанию +12 мес., владелец задаёт), branches[] (пусто = все),
  version (оптимистическая блокировка)
gift_card_tx (card, kind: activate|redeem|refund|adjust|expire|hold|release, amount, sale, return, key, balance_after, at, user)
```

## 3. Расчёт и правила сервера

**Промокод** — скидка, шаг 6 порядка (после акций и уровня). Проверки: статус, срок (время компании, `sold_at`), `min_receipt` (от суммы после акций), scope, лимиты. `free_product` — товар из чека бесплатно (одна единица, самая дешёвая из подходящих). И-1 — обрезка до закупки без `allow_below_cost`. Один промокод на чек (Ф1).

**Подарочная карта** — **средство оплаты**, не скидка (шаг 10): в `payment.payments[]` строка `{method: "gift_card", code, amount}`. Несколько карт в чеке — можно (до 3). Сдачи с карты нет; остаток остаётся на карте.

**Атомарность (И-3, И-4):**
1. Погашение — в транзакции продажи: `SELECT … FOR UPDATE` строки карты, проверка `balance ≥ amount`, запись `redeem` с `balance_after`, уменьшение баланса; всё или ничего.
2. Повтор продажи тем же `Idempotency-Key` → прежний ответ, второго списания нет.
3. Две кассы одновременно на одну карту: вторая получает 409 `gift_card_insufficient {available}` → продажа не создана; касса предлагает списать доступное.
4. **Удержание (hold)** для долгого окна оплаты (Ф2): `POST gift-cards/{code}/hold/ {amount, ttl_sec: 300}` → `hold_id`; продажа с `hold_id` превращает удержание в списание; истёк срок — удержание снимается само. На Ф1 без hold — проверка в момент продажи.
5. Одноразовый промокод: счётчик в транзакции продажи; гонка → второй чек 409 `promo_used`.

**Возврат (И-5):**
- Деньги, уплаченные картой, возвращаются **на ту же карту** (`refund`), даже если срок истёк (срок продлевается на 30 дней, `adjust` в журнал). Наличными за карту — только с правом `can_refund_gift_card_cash` и PIN руководителя.
- Порядок при частичном возврате: сначала деньги — до суммы, уплаченной деньгами, затем карта (решение владельца, альтернатива — пропорционально; см. вопрос 2).
- Промокод: скидка возвращаемых единиц пересчитывается пропорционально (реально уплаченное); при **полном** возврате одноразовый/лимитированный промокод возвращается в счётчик (`released`), если не истёк. При частичном — остаётся использованным.
- Возврат **проданной** подарочной карты: только если не было погашений (`balance == initial`) — карта блокируется, деньги возвращаются; с погашениями — 409 `gift_card_used`.

**Офлайн-касса:** карты не принимаются без связи (И-4). Многоразовый промокод с `offline_allowed=true` — по кэшу (`GET pos/promo-codes/offline/`), при досылке нарушенные лимиты не отменяют чек, а дают `warnings[].promo_limit_exceeded`. Продажа карты офлайн — разрешена, карта активируется при досылке (печатать «Карта будет активна после связи с сервером»).

**Защита от подбора:** `GET gift-cards/{code}/` — не больше 10 неудачных кодов в минуту на кассу/пользователя, далее 429 и запись в журнал безопасности; PIN — при сумме > порога (настройка владельца). Код карты и PIN не пишутся в логи целиком (только последние 4).

## 4. Эндпоинты

```
# Промокоды (владелец)
GET/POST          api/main/promo-codes/
POST              api/main/promo-codes/generate/   {count: 100, prefix: "NY", kind, value, ...} → batch_id
PATCH             api/main/promo-codes/{id}/
GET               api/main/promo-codes/report/?date_from=&date_to=
# Касса
POST              api/main/pos/promo-codes/check/  {code, client, items[]} → {ok, discount, reason}
GET               api/main/pos/promo-codes/offline/   (только offline_allowed, ETag)

# Подарочные карты
GET               api/main/gift-cards/?status=&q=
POST              api/main/gift-cards/issue/       {amount, reason: gift|compensation, expires_at, count} (Idempotency-Key, право can_issue_gift_cards)
GET               api/main/gift-cards/{code}/      → {status, balance, expires_at, branches} (маска кода в ответе)
GET               api/main/gift-cards/{code}/history/
POST              api/main/gift-cards/{code}/block/ | unblock/
POST              api/main/gift-cards/{code}/hold/ | release/      (Ф2)
```

Продажа карты: строка чека `{product: <товар-услуга с kind=gift_card>, qty: 1, price: "1000.00", gift_card: {code?: "…" (пластик), expires_at?}}` → в ответе `gift_cards_issued: [{code, balance, expires_at}]`.

Погашение — в `pos/checkout/`:

```json
"promo_code": "OSEN10",
"payment": { "method": "mixed", "received": "700.00",
  "payments": [ { "method": "gift_card", "code": "NC-7H2K-9QPL", "amount": "500.00" },
                { "method": "cash", "amount": "680.00" } ] },
"expected_total": "1180.00"
```

Ответ: `gift_cards: [{code_mask: "…9QPL", redeemed: "500.00", balance_after: "0.00"}]`, `order_discounts: [{kind: "promo_code", code: "OSEN10", amount: "120.00"}]`.

## 5. Ошибки

| Код | Текст для кассира |
|---|---|
| 404 `promo_not_found` | Промокод не найден |
| 409 `promo_expired {ends_at}` / `promo_not_started` | Промокод истёк / ещё не действует |
| 409 `promo_used` / `promo_limit_reached` | Промокод уже использован |
| 409 `promo_min_receipt {min}` | Сумма чека меньше {min} |
| 404 `gift_card_not_found` (одинаковый ответ на неверный код и чужую компанию) | Карта не найдена |
| 409 `gift_card_inactive` / `gift_card_blocked` / `gift_card_expired {expires_at}` | Карта не активна / заблокирована / истекла |
| 409 `gift_card_insufficient {available}` | На карте {available} |
| 403 `gift_card_pin_required` / `gift_card_pin_invalid` | Нужен PIN карты |
| 429 `gift_card_too_many_attempts` | Слишком много попыток, подождите |

## 6. Признаки, права, модуль

- Признаки: `promo_codes`, `gift_cards`, `gift_card_hold` (Ф2).
- Права: `can_manage_promo_codes`, `can_issue_gift_cards` (выпуск без продажи), `can_refund_gift_card_cash`.
- Модули: «Промокоды» и «Подарочные карты» (можно одним, предложение 200 сом/мес).
- Бухгалтерия: проданная карта — **не выручка**, а обязательство (аванс); выручка — при погашении. В Z-отчёте отдельные строки «Продано карт», «Погашено картами». Для eKassa (фискализация) — уточнить у вас, как фискализировать продажу карты (аванс) и погашение (зачёт аванса).

## 7. Тесты приёмки

1. Карта 1000, чек 1 180: карта 1000 + наличные 180 → баланс 0, статус `exhausted`.
2. Две кассы одновременно списывают 600 и 600 с карты 1000 → одна 200 OK, вторая 409 `gift_card_insufficient {available: 400}`.
3. Повтор той же продажи тем же ключом → 200 `replayed`, баланс не изменился.
4. Возврат чека (карта 500 + нал 680) целиком → 500 на карту, 680 наличными; частично на 300 → 300 наличными (сначала деньги).
5. Истёкшая карта при возврате → деньги на карту, срок +30 дней.
6. Одноразовый промокод в двух чеках одновременно → второй 409 `promo_used`; полный возврат первого → код снова действует.
7. Промокод −10 % при акции 2+1: скидка от суммы после акции (2+1 воды 300→200, промокод −20,00).
8. Промокод −50 % на товар с закупкой 90 и ценой 100 → цена 90 (обрезка И-1).
9. 11 неверных кодов карты за минуту → 429.
10. Продажа карты офлайн → после досылки карта `active`; погашение офлайн → касса не даёт.

## 8. Этапы

- **Ф1**: промокоды (`percent/amount`, срок, лимиты, один на чек), подарочные карты (продажа/активация, погашение в чеке, возврат на карту, блок, история), Z-отчёт, права.
- **Ф2**: `free_product`, генерация партий, hold, PIN, выпуск без продажи, многоразовые офлайн-промокоды, электронная карта по ссылке/в Telegram.

## 9. Что подхватит касса

- поле «Промокод / карта» в окне оплаты (скан штрихкода/QR), запрос `check`/`gift-cards/{code}`, строки разбора, остаток к оплате;
- `promo_code` и `payments[]` с `gift_card` в теле `pos/checkout/`; запрет без сети (сообщение на 5 языках);
- товар-услуга «Подарочная карта», печать карты с кодом и штрихкодом (графический режим принтера как у ценников);
- возврат: показ «вернётся на карту …9QPL: 500,00»;
- программа владельца: окна «Промокоды», «Подарочные карты», отчёт; Z-отчёт с новыми строками.
