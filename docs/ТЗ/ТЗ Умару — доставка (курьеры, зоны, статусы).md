## 1. Что видит пользователь

**Кассир/диспетчер → «Заказы → Доставка»:**

Статусы: Новый → Подтверждён → Собирается → Собран → Передан курьеру → В пути → Доставлен (→ Оплачен у курьера) / Отменён / Возврат. В кассе — кнопка «Продать» на этапе «Собран» (если оплата при получении — продажа проводится при «Доставлен»).

**Курьер (мобилка NurCRM, роль «Курьер»):** список своих заказов, адрес и звонок, «Забрал», «Доставил», «Принял наличные N», «Не дозвонился», фото/подпись (Ф2).

**Владелец:** зоны (на карте многоугольником или по радиусу), тарифы, курьеры, отчёт «по курьерам» (заказов, сумма, наличные к сдаче, среднее время), «наличные у курьеров» (не сданы в кассу).

## 2. Модель данных

```

delivery_tariff (zone, base "150.00", per_km "0.00", free_from "2000.00", min_order "500.00",
                 eta_min 40, eta_max 60, weekdays[], time_from, time_to (вечерний тариф и т. п.))
courier         (id, company, employee (опц.) | name+phone (внешний), kind: own | external, is_active, cash_limit "10000.00")
delivery
  id, company, order (showcase / customer-order) | sale, number,
  address {text, lat, lng, entrance, floor, flat, comment}, zone, tariff_snapshot,
  fee "150.00" (рассчитано сервером), fee_discount, eta_from, eta_to,
  payment_mode: prepaid | cash_to_courier | card_to_courier | qr_on_delivery,
  amount_to_collect "1990.00", collected "0.00", courier, status, status_history[{status, at, by, lat?, lng?}],
  version
courier_cash    (courier, delivery, amount, kind: collected | handed_over, shift, at, by) — наличные у курьера
```

## 3. Расчёт и правила сервера

1. **Зона**: точка адреса → первая подходящая зона по `priority`; нет зоны → 409 `address_out_of_zone`.
2. **Стоимость** = `base + per_km × расстояние (по прямой или маршруту — решите)`; 0, если сумма товаров **после скидок** ≥ `free_from`; заказ меньше `min_order` → 409 `delivery_min_order {min}`. Тариф по дню/часу — время компании.
3. **В чеке/заказе доставка — отдельная строка-услуга** «Доставка (зона Центр)», не участвует в базе процентных скидок и бонусов (общая часть, шаг 8); промокод «бесплатная доставка» (Ф2) — `kind=free_delivery` в промокодах. Доставка без НДС-особенностей — как услуга магазина (если доставляет внешний курьер-агрегатор — уточнить).
4. **Фиксация цены**: `quote` возвращает `fee` и `tariff_snapshot`; при создании заказа фиксируется; смена тарифа после — не меняет созданный заказ (И-8).
5. **Деньги у курьера**: `cash_to_courier` → при «Доставлен» продажа проводится сервером (или кассой по кнопке) со способом `cash`, но наличные **не в кассе смены**, а на счёте курьера (`courier_cash collected`); «Сдал в кассу» — внесение в кассу смены (`handed_over`) и уменьшение долга курьера. Отчёт «наличные у курьеров». `cash_limit` — предупреждение диспетчеру.
6. **Частичная доставка/отказ у двери**: курьер отмечает принятые позиции; продажа на принятое; остальное — возврат на склад (снятие резерва). Отказ целиком — заказ «Возврат», резерв снимается, доставка оплачивается по политике магазина (`refusal_fee`).
7. **Идемпотентность**: смена статуса — `PATCH {status, version}` (конфликт версий → 409), «Принял наличные» — `Idempotency-Key` (двойной тап курьера не удваивает сумму, И-4).
8. **Офлайн-курьер** (мобилка без сети): статусы и «принял наличные» копятся в очереди с ключами, уходят при связи с исходным временем.
9. **Агрегаторы** (Glovo, Yandex и т. п.) — Ф3, по спросу, через их API как отдельного «внешнего курьера».

## 5. Ошибки

409 `address_out_of_zone`, 409 `delivery_min_order {min}`, 409 `delivery_version_conflict`, 409 `delivery_already_collected`, 400 `collect_exceeds_due {due}`, 403 `courier_not_assigned`.

## 6. Признаки, права, модуль

- Признаки: `delivery` (зоны, тарифы, доставки, статусы), `delivery_courier_app` (роль курьера в мобилке), `delivery_aggregators` (Ф3).
- Права: `can_dispatch_deliveries`, роль `courier` (видит только свои), `can_manage_delivery_zones`.
- Модуль «Доставка» — цена решает владелец (предложение 200 сом/мес).

## 7. Тесты приёмки

1. Точка в «Центре», товары 1 650 → доставка 150, «ещё 350 до бесплатной»; товары 2 000 → 0.
2. Промокод −10 % на 2 100 → товары 1 890 < 2 000 → доставка 150 (порог — после скидок).
3. Скидка на чек 10 % не уменьшает строку доставки; бонусы не начисляются на доставку.
4. Тариф изменили после создания заказа → сумма заказа прежняя.
5. Курьер дважды жмёт «Принял 1 990» → `collected` 1 990 один раз.
6. Наличные курьера не попадают в кассу смены до «Сдал»; после «Сдал 5 000» — внесение в смену 5 000, долг курьера −5 000.
7. Отказ от 1 позиции из 3 у двери → продажа на 2, резерв третьей снят.
8. Адрес вне зон → 409, витрина показывает «вне зоны», заказ не создаётся.

## 8. Этапы

- **Ф1**: зоны (радиус + многоугольник), тарифы, `quote`, доставки со статусами, назначение курьера, накладная, оплата при получении с наличными у курьера и «Сдал в кассу», отчёт.
- **Ф2**: приложение курьера (мобилка), частичная доставка, фото/подпись, `free_delivery` промокод, расстояние по маршруту.
- **Ф3**: агрегаторы.

## 9. Что подхватит касса

- вкладка «Доставка» в «Заказах»: доска по статусам, курьер, накладная, «Продать»/«Доставлен», «Сдал в кассу» (внесение в смену) — 5 языков, чек-лист полей;
- строка «Доставка (зона)» в чеке и окне оплаты из `quote` (без сети — последний тариф зоны из кэша, сверка `expected_total`);
- Z-отчёт: «Наличные у курьеров» отдельной строкой;
- программа владельца: зоны на карте, тарифы, курьеры, отчёт; мобилка — роль курьера (отдельная задача).
