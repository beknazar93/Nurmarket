# ТЗ Умару — конструктор акций (26.11.2026)

От: Бекназар (касса NurCRM). Пункт №7 отчёта «Конкуренты — чего у нас нет и что слабо 26.11.2026» (самый частый запрос розницы; у Poster есть «купи 2 — третий бесплатно»). Общие правила денег, порядок скидок, инварианты И-1…И-10, `pos/quote/`, `expected_total` — в «ТЗ Умару — общие правила денег и расчёта (26.11).md»; здесь не повторяются.

## 0. Что есть сегодня

- У товара поле `promotion_rules[] {min_amount, discount_percent, promo_quantity, position}` (задаётся на сайте в карточке товара). Сервер применяет к строке: подходит правило, если `цена × кол-во ≥ min_amount`, из подходящих — с наибольшим `min_amount`; скидка = % от суммы, но не больше чем на `promo_quantity` штук. У товара с правилами сервер **игнорирует** ручную скидку кассира. Скидка на чек — от суммы после акции. (Проверено 28.09, продажи 1143–1144.)
- Касса повторяет этот расчёт у себя (`PromotionRules.LineDiscount`), правила кладёт в строку чека и кэширует на диск (`promotion_rules.json`) — расчёт без сети совпадает с сервером.
- Нет: «N+M», скидки на категорию, по дням/часам, периода действия, комбо, лимитов, приоритетов, отчёта по акциям. Модуль Маркетплейса «Акции видно сразу» только показывает.

## 1. Что видит пользователь

**Владелец (программа владельца → «Акции»):** список акций (активные / запланированные / завершённые), кнопка «Новая акция» → мастер из 4 шагов:

```
┌ Новая акция ───────────────────────────────────────────┐
│ 1. Тип:  (•) Купи N — получи M     ( ) Скидка %/сумма  │
│          ( ) Комбо (набор по цене) ( ) Цена от кол-ва  │
│ 2. На что: [Товары ▾] [Категории ▾] [Бренды ▾]         │
│            Исключить: [ ... ]                          │
│ 3. Когда: с [01.12.2026] по [31.12.2026]               │
│           Дни: [Пн][Вт][Ср][Чт][Пт][Сб][Вс]            │
│           Часы: с [10:00] до [14:00]  («счастливые»)   │
│ 4. Условия: только для клиентов [уровень ▾] / всем     │
│    Лимит: на чек [2] раз, всего [500] раз, на клиента 1│
│    [ ] Суммируется с ручной скидкой кассира            │
│    [ ] Суммируется с другими акциями                   │
│    [ ] Разрешить ниже закупки (только владелец, PIN)   │
│ Предпросмотр: «Вода 1 л ×3 = 300 → 200 (−100)»         │
│                       [Отмена]  [Сохранить черновик] [Запустить] │
└────────────────────────────────────────────────────────┘
```

Отчёт «Акции»: по каждой — чеков, единиц, сумма скидки, выручка, маржа (с себестоимостью), сравнение «до/во время».

**Кассир (касса):** в строке чека — метка акции «2+1» и зачёркнутая цена; в окне оплаты — строки «Скидка по акции “…”: −100,00»; подсказка «Добавьте ещё 1 — будет бесплатно» (из `quote.hints[]`). Ручная скидка на строке с акцией недоступна (как сегодня), если акция не разрешает.

**Покупатель:** чек с разбором; на витрине — бейдж акции (уже есть «Акции видно сразу»).

## 2. Модель данных

```
promotion
  id, company, title, description, status: draft|active|paused|finished,
  kind: buy_n_get_m | percent | amount | fixed_price | combo | qty_tiers,
  params (JSON по kind, см. ниже),
  scope: { products[], categories[], brands[], exclude_products[] },
  starts_at, ends_at (null = бессрочно), weekdays [1..7], time_from, time_to (часовой пояс компании),
  audience: all | clients | levels[] ,
  priority int (больше — раньше), stackable_with_manual bool, stackable_with_promos bool,
  allow_below_cost bool (только владелец), branches[] (пусто = все),
  limit_per_receipt, limit_total, limit_per_client, used_total (счётчик),
  version, created_by, updated_at
promotion_usage   (sale, line_index, promotion, version, qty, amount, client, sold_at) — для отчёта, возврата и лимитов
```

`params` по типам (на примерах):

| kind | params | Пример |
|---|---|---|
| `buy_n_get_m` | `{buy: 2, get: 1, get_discount_percent: 100, cheapest: true}` | вода 100 сом ×3 → третья бесплатно: −100; ×6 → −200; ×5 → −100 |
| `percent` | `{percent: 15}` | −15 % на категорию «Молочка» |
| `amount` | `{amount: "20.00", per: "unit" \| "line"}` | −20 сом за штуку |
| `fixed_price` | `{price: "79.00"}` | «Хлеб за 79» |
| `combo` | `{items: [{product\|category, qty}], price: "250.00"}` | бургер + кола + картофель = 250 вместо 310 |
| `qty_tiers` | `{tiers: [{min_qty: 5, percent: 5}, {min_qty: 10, percent: 10}]}` | от 10 шт −10 % |

Сегодняшние `promotion_rules` товара — это `kind=percent` с порогом суммы; **миграция**: каждое правило товара → акция `percent` со `scope.products=[товар]`, `params {min_amount, percent, max_qty}` (тот же расчёт). Поле `promotion_rules` в товаре оставить ещё 2 версии кассы (старые кассы).

## 3. Расчёт на сервере (правила)

1. Кандидаты строки: активные акции на `sold_at` (дата, день недели, часы — время компании), подходящие по scope, филиалу, аудитории (клиент/уровень), не исчерпавшие лимиты.
2. **Пересечения**: сортировка по `priority` ↓; при равенстве — та, что даёт **большую скидку покупателю**. Если `stackable_with_promos=false` у любой из двух — применяется одна. Комбо и N+M «занимают» единицы: одна единица товара участвует максимум в одной акции типа «на единицы» (`buy_n_get_m`, `combo`, `qty_tiers`).
3. N+M: бесплатными считаются самые **дешёвые** единицы группы (`cheapest: true`) — защита от «купил дорогое, бесплатно дорогое». Группа может включать разные товары категории.
4. Комбо собирается жадно, максимум комплектов; скидка комбо распределяется по строкам пропорционально цене (для возврата и чека).
5. Лимиты: `limit_per_receipt` — сколько раз сработать в чеке; `limit_total`/`limit_per_client` — счётчик увеличивается **в транзакции продажи** (гонка двух касс → вторая получает без акции и `warnings[].promotion_limit_reached`, не отказ).
6. И-1: если после акции цена единицы < закупки и нет `allow_below_cost` — акция для этой строки **ограничивается** до закупки (`warnings[].promotion_capped_by_cost`), а не отказ продажи. С флагом — продаётся ниже, в отчёте отметка.
7. Правила и результат совпадают в `quote`, `checkout`, корзине (`add-item`) и досылке офлайн (по `sold_at` и `version`).

## 4. Эндпоинты

```
GET    api/main/promotions/?status=&updated_since=        список (для кассы — только active+scheduled, с ETag)
POST   api/main/promotions/                                создать (Idempotency-Key)
GET    api/main/promotions/{id}/
PATCH  api/main/promotions/{id}/                           изменить → новая version; активную — только без смены kind
POST   api/main/promotions/{id}/pause/ | resume/ | finish/
POST   api/main/promotions/preview/                        {promotion: {...}, items: [...]} → расчёт без сохранения (для «Предпросмотра»)
GET    api/main/promotions/report/?date_from=&date_to=&promotion=
GET    api/main/pos/promotions/active/?branch=             компактный набор для кассы (кэш без сети)
```

Пример ответа для кассы:

```json
{ "version": "2026-11-26T10:00:00Z",
  "promotions": [{ "id": "pr_12", "title": "2+1 на воду", "kind": "buy_n_get_m",
     "params": { "buy": 2, "get": 1, "get_discount_percent": 100, "cheapest": true },
     "scope": { "categories": ["cat_water"] }, "starts_at": "2026-12-01T00:00:00+06:00",
     "ends_at": null, "weekdays": [1,2,3,4,5,6,7], "time_from": null, "time_to": null,
     "audience": "all", "priority": 10, "stackable_with_manual": false,
     "stackable_with_promos": false, "allow_below_cost": false, "limit_per_receipt": null }] }
```

В строке ответа `quote`/`checkout`: `applied: [{kind: "promotion", id, version, title, qty, amount}]`, подсказки `hints: [{promotion, text: "Добавьте ещё 1 — будет бесплатно"}]`.

## 5. Ошибки

| Код | Когда |
|---|---|
| 400 `promotion_invalid {field}` | неполные `params`, `ends_at < starts_at`, пустой scope |
| 409 `promotion_kind_locked` | смена типа у активной акции |
| 403 `promotion_below_cost_forbidden` | `allow_below_cost` ставит не владелец |
| 409 `total_mismatch` | итог кассы и сервера разошёлся (общая часть) |
| warnings: `promotion_limit_reached`, `promotion_capped_by_cost`, `promotion_version_changed` | продажа проходит |

## 6. Признаки, права, модуль

- `capabilities.features`: `promotions_v2` (конструктор), `pos_quote` (общий предпросмотр).
- Право сотрудника `can_manage_promotions` (по умолчанию — владелец, админ).
- Модуль `public/modules`: `promotions` — «Конструктор акций». Цена — решает владелец (предложение 200 сом/мес; входит в «Стандарт»).

## 7. Тесты приёмки (у вас и у нас одинаковые числа)

1. 2+1, вода 100: ×2 → 200; ×3 → 200; ×6 → 400; ×7 → 500.
2. 2+1 по категории, разные цены 120, 100, 80 → бесплатна 80; итог 220.
3. Пересечение: «−15 % молочка» (priority 5) и «2+1 кефир» (priority 10), кефир 60 ×3 → применяется 2+1 (=120), не 15 %.
4. Счастливые часы 10:00–14:00: чек в 13:59 со скидкой, 14:00 без; офлайн-чек 13:50, досланный в 15:00, — со скидкой (по `sold_at`).
5. Комбо 250 из 120+90+100: итог 250, скидка 60 разложена 23,23 / 17,42 / 19,35 (пропорционально, сумма 60,00).
6. Лимит на чек 1 при 2+1 и ×6 → скидка −100, не −200.
7. Лимит всего 1, две кассы одновременно → один чек со скидкой, второй без + `promotion_limit_reached`.
8. Закупка 90, цена 100, акция −20 % без флага → цена 90 (`promotion_capped_by_cost`); с флагом → 80.
9. Частичный возврат 1 шт из 2+1 (×3, оплачено 200) → возврат 66,67 (уплачено за единицу), не 100 (И-5).
10. Миграция: товар с `promotion_rules {min_amount 300, percent 10, promo_quantity 10}` даёт те же суммы, что сегодня (тест кассы `PromotionRules`: 30 × 11 при пределе 10 → 135,00 → 30,00 скидки).

## 8. Этапы

- **Ф1** (2–3 нед.): модель, `percent`/`amount`/`fixed_price`/`buy_n_get_m`, период/дни/часы, приоритет, `pos/promotions/active/`, расчёт в `checkout`/`quote`, `applied[]`, миграция `promotion_rules`, отчёт «по акциям» (простой).
- **Ф2** (2 нед.): `combo`, `qty_tiers`, лимиты с счётчиками, аудитория по уровням (после ТЗ уровней), `hints[]`, `preview`, отчёт с маржой.

## 9. Что подхватит касса

- загрузка `pos/promotions/active/` с ETag, кэш на диск (как `promotion_rules.json`); локальный расчёт тех же типов (обобщение `PromotionRules.LineDiscount` в движок по `kind`) — тесты по числам раздела 7;
- метки акций в строке чека и плитке, подсказки «ещё 1 — бесплатно», разбор скидок в окне оплаты и на печатном чеке;
- запрет ручной скидки на строке с акцией (как сейчас) с учётом `stackable_with_manual`;
- окно «Акции» в программе владельца (мастер, список, отчёт) — 5 языков, чек-лист полей без налезания.
