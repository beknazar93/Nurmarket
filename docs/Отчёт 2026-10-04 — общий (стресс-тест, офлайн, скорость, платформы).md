## 2. Что выпущено и что готово к выпуску

**Выпущено:**

- Windows 1.17.45 (клиентам): 10 пунктов магазина — опт, скидка в убыток, предоплата в чеке, прокат в Z-отчёте, склад, PLU, выход из аккаунта, остаток.
- Linux test1: https://github.com/beknazar93/Nurmarket-Linux/releases/tag/linux-1.17.44-test1
- Android test1: https://github.com/beknazar93/Nurmarket-Android/releases/tag/android-1.17.44-test1

**В main (3b19f6e), собирается для Windows, Linux и Android, ещё не выпущено:**

1. Офлайн и сбои сервера (раздел 3).
2. Возврат: сумма с сервера, строка «Выдать покупателю: N сом». Z-отчёт без двойной предоплаты.
3. QR клиента «NURCRM» + телефон → клиент в чеке, новый клиент с подставленным номером.
4. Два пальца на сенсоре — прокрутка, без двойных нажатий.
5. Окно бота: «ИИ на сервере» — клиент сам вставляет ключ Gemini.
6. Сжатие ответов сервера (gzip).
7. Android-проект (окна-слои, печать USB/Bluetooth/сеть, второй экран).

**Перед выпуском обязательно** — регресс на тестовом аккаунте через окно кассы:

- продажи, долг, возврат (полный, частичный, «в долг»);
- внесение/изъятие, открытие/закрытие смены;
- работа без интернета (правило брандмауэра);
- QR со сканером.

Сегодня это не сделано: в кассе на этом компьютере работал владелец.

## 3. Офлайн и сбои сервера

Стенд: поддельный сервер с режимами — обрыв, «чёрная дыра», 5xx, 429, медленный ответ, HTML вместо JSON. Против него — настоящие сервисы кассы.

| Действие | Было | Стало |
|---|---|---|
| Оплата при «чёрной дыре» | 2,9 с; повторная 1,8 с | 1,8 с в очередь; повторная **0 с** |
| Открытие смены, сервер молчит | 55 с | 2 с, смена офлайн |
| Закрытие смены, сервер молчит | 55 с | 3 с, на сервер — очередью |
| Автовход без связи, токен истёк | вход не прошёл, **сохранённый вход стирался** | 0–2 с, автономно, вход сохранён |
| Продажа прошла, сервер ответил 520 | **2 продажи на 1 чек** | 1 |
| Сервер ожил | 51,7 с до «Онлайн» | 9,2 с |

Не сделано:

- возврат и оплата долга в первые секунды после падения сервера (пока касса ещё «Онлайн») ждут до 55 с; в аварии — сразу «недоступно»;
- ручной вход по паролю при «чёрной дыре» — до 55 с.

Риск: двойная продажа, если сервер дважды подряд отвечает 500 и не сохраняет ключ. Нужна гарантия бэкенда (раздел 7).

- ИИ на сервере, 40 вопросов по 10 одновременно:
  - 35 ответов;
  - 5 ошибок «Все модели Gemini недоступны (503)»;
  - часть ответов пустые;
  - время ответа: медиана 4 с, худшее 12,7 с.
- Повтор (30 по 10): всё ответило, но худшее время 11 с.
- Подделать сообщения боту снаружи нельзя: сервер отвечает 403. Это хорошо.
- Ответы бота (журнал NBS):
  - цены «60.000 сом»;
  - видны `**звёздочки**`;
  - заказ 10×60 записан как 700;
  - заказ оформляется без подтверждения;
  - нет памяти разговора;
  - «Адрес: 1234»;
  - кнопок нет.
- Всё по боту — ТЗ ч.9. У клиентов без своего ключа ИИ не работает: общий ключ — ТЗ ч.8 §1. В программе есть поле для своего ключа.

## 8. Не проверено и риски

- Окна кассы с новыми правками (возврат, смена, QR, два пальца, офлайн) вживую не открывались — касса была занята. Нужен регресс (раздел 2).
- Android на аппарате не запускался. Главный риск — вложенный цикл диалогов (`AndroidNestedLoop`); выключатель — файл `android-no-nested-loop`.
- Linux: запущен разработчиком приложения NurCRM. Печать и звук на Linux не проверены.
- Попутно найдено: обновлённые токены входа не сохраняются в `auth.dat`. Если сервер отзывает старый токен, после перезапуска кассы придётся входить заново — проверить.
