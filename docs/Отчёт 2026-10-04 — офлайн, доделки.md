## 3. Обновлённые токены → auth.dat

**Какой файл главный.** Автовход берёт сессию из `auth.dat` (`SecureStorageService`, DPAPI). `offline_auth_session.dat` (`OfflineAuthSessionStore`) — старый формат: вход его очищает, а обновление токена писало только туда — то есть в никуда.

**NBS (только вход и обновление токена):**

- `POST auth/refresh/` отдаёт **только новый access** (живёт 15 мин); refresh-токен не меняется, старый **не отзывается** (повтор старым — 200); refresh живёт 7 дней от входа.
- Поэтому перезапуск кассы до сих пор не ломался. Но: (1) в auth.dat отметка «последняя связь с сервером» стояла на моменте входа/автовхода — 60 часов офлайн-работы считались от неё, а не от последнего ответа сервера; (2) включи NurCRM смену refresh-токена при обновлении (обычная настройка simplejwt) — касса после перезапуска просила бы пароль.

**Что сделано.** `NurMarketApiClient.SessionTokensRefreshed` — событие после каждого успешного обновления токена (оба пути: автовход и 401 посреди работы). `OnlineOfflineAuthenticationService` переписывает auth.dat (access, refresh, срок, отметку связи), **только если сохранённая сессия та самая**, чей refresh только что обменяли: после «Выхода», без «Запомнить меня» или при сохранённом входе другого кассира файл не трогается. Записи auth.dat из сервиса идут по одной (общий на процесс замок) — найдено обвязкой на NBS: при нескольких экземплярах сервиса одновременная запись давала IOException.

**Проверено:**

| Где | Сценарий | Было | Стало |
|---|---|---|---|
| стенд | как NBS (refresh не меняется), 401 посреди работы → обновление | auth.dat не обновлён; перезапуск входит | auth.dat обновлён; перезапуск входит |
| стенд | сервер меняет refresh и отзывает старый | перезапуск: **«Сессия отозвана. Войдите снова.»** | перезапуск входит Online |
| NBS, настоящие сервисы кассы | вход → обновление → «перезапуск» (новые экземпляры клиента, хранилища и сервиса) | — | auth.dat = новый access; автовход Online без пароля; с истёкшим access — автовход обновил его и записал |

Наблюдение для бэкенда: refresh-токен не продлевается, поэтому касса раз в 7 дней после последнего входа по паролю всё равно попросит пароль. Если включить смену refresh-токена при обновлении — касса к этому готова.

## 5. «Прокат за смену»: возврат залога

**NBS (`GET api/rentals/`, только чтение):** полей `deposit_refunded` / `deposit_withheld` в ответе **нет** ни в списке, ни в карточке — касса читала их как 0. Возврат залога сервер проводит движением денег «Возврат залога по прокату №N» (расход, `source_kind=rental`) на сумму **залог − штраф**: №8 500 − 0 = 500, №4 500 − 200 = 300, №3 1000 − 200 = 800.

**Что сделано** (`RentalsApi.Parse`): нет полей от сервера — для возвращённого проката с денежным залогом «возвращено = залог − удержано», «удержано = min(штраф, залог)»; под документ — 0. Отдаст сервер поля сам — берутся его числа. Попутно исправилось окно «Прокат» → «Принять возврат»: «Верните клиенту залог: 0,00» → настоящая сумма (то же поле).

**Стенд** (прокат в виде NBS): было «Возвращено: 3» без залога; стало «Возвращено: 3, залог −800.00 сом / Удержано из залога: 200.00 сом / Штрафы: 200.00 сом».

## Риски

- **5 с на первую порцию.** Если живой сервер когда-нибудь будет отвечать на первую страницу продаж/клиентов дольше 5 с без единого ответа — окно скажет «недоступен» и объявит аварию (касса ~10 с поработает офлайн до проверки связи). На NBS ответ 0,2–1 с. Константа — `ServerAnswerWait.FirstPortionBudget`.
- **8 с на шаг входа.** То же для входа по паролю (`ManualLoginServerBudget`).
- **Отложенная досылка старого пути.** Чек, чей checkout действительно не дошёл до сервера, уходит не сразу, а через 3 мин (+ до 45 с цикла). Двойная продажа при «500 дважды подряд» на быстром пути остаётся — это гарантия бэкенда (см. прошлый отчёт).
- **Событие обновления токенов статическое.** В кассе один сервис входа; при нескольких экземплярах (обвязки) записи идут по очереди и не мешают друг другу.
- **Прокат:** если сервер начнёт удерживать из залога не штраф, а другую сумму, касса покажет «залог − штраф», пока сервер не отдаст `deposit_refunded`/`deposit_withheld` (они будут взяты сразу).
