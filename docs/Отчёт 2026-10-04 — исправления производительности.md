## 2. Что не сделано и почему

| Что | Почему |
|---|---|
| Остатки чужих продаж (другая касса, сайт) видны с задержкой до 15/30 мин (раньше до 2 мин) | Продажа не меняет `updated_at` товара — «версия» каталога остатков не видит (проверено на NBS). Так задано в задаче; свои продажи вычитаются сразу, соседние кассы — по локальной сети. Нужен BE-10-5 (`updated_after` / лёгкий список остатков) |
| «Версия» каталога пропускает часть изменений | На NBS товар «Нан» имеет `updated_at` 08:33, а в сортировке `-updated_at` стоит седьмым (сервер сортирует по другому полю, чем отдаёт). Такие правки приходят полной загрузкой (15/30 мин). Правки цен и товаров с сайта (обычный `updated_at`) — за 2 мин |
| Память Vosk после выключения голоса на ходу | Нативная куча Vosk/Kaldi после освобождения модели возвращает системе только ~170 МБ из 0,7–1,2 ГБ. Попытка `HeapCompact` по кучам процесса уронила обвязку (AccessViolation) — в программу не вносилось. Совет кассиру: после выключения голоса перезапустить кассу |
| Долгий замер памяти программы владельца (утечка?) | Нужен многочасовой замер `dotnet-counters` на работающей программе — по правилам задания запущенные программы не трогались |
| №18 (чек на 200+ строк) | Не входил в задание (низкий приоритет) |
| Живая проверка окон (касса, владелец, «Платёж принят», окно смены) | Запрет задания: окна запущенных программ не трогать, `deploy_both.ps1` не запускать. Проверено обвязками и сборкой |

- **Обвязка `PerfHarness`** (вне репозитория, `scratchpad\perf05\harness`) вызывает настоящие классы из собранных DLL этой рабочей копии: `SyncService`, `AvaloniaCatalogCacheService`, `MainStatusViewModel`, `CatalogPanelViewModel`, `PosCheckoutService`, `ShiftStateService`, `CashShiftService`, `SalesHistoryBackfill`, `LocalProductRepository`, `ProductCatalogMapper`, `VoiceControlService`, `SpeakerVerificationService`, `ServerShiftReport`, `ShiftDetailsDialog.BuildPrintableReport`. Пути `%AppData%` / `%LocalAppData%` перенаправлены в песочницу (Harmony), данные установленной кассы не тронуты. Запросы считаются через EventSource `System.Net.Http`. Одна и та же обвязка собрана дважды: «до» (код 8edc9d9) и «после» (`-p:PerfAfter=1`).
- **Сервер** — только NBS, запросы последовательные (не больше 3 одновременно у массовых загрузок). Созданы 6 продаж по 17 сом («жумуртка», наличные, смена Nur Test cbc71293, касса «Основная касса компании») — 3 до и 3 после правок. Ничего не удалялось.
- **Стенд «офлайн и сбои сервера»** (`scratchpad\perf05\stand`, копия стенда из коммита 76a592c) — поддельный NurCRM на 127.0.0.1: обрыв, «чёрная дыра», 502/503/504/520, 429, ответ через 25 с, 200 с HTML, дубли, зависшие запросы. Итог на новом коде — в разделе 4.
