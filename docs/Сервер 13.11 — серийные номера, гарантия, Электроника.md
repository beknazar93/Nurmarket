# Сервер 13.11 — серийные номера, гарантия, «Электроника»

Сборка сервера: `…+apl1311+sn1311` (номер в `.server_version`). Всё добавлено **новыми полями**: старая касса работает как раньше.

## 1. Товар
`GET products/list/`, `products/changes/`, карточка товара — новые поля (можно и записывать):
- `track_serials` (bool) — товар продаётся с серийными номерами;
- `warranty_months` (число или null) — гарантия в месяцах.

## 2. Строка корзины / продажи — `serial_numbers`
Список строк, до 500 в строке, каждая до 64 символов. Пробелы и регистр при сравнении не учитываются.

Куда можно прислать:
- `POST pos/checkout/` (касса, в каждой строке `items[]`): `"serial_numbers": ["SN1", "SN2"]`;
- `POST pos/sales/<cart>/items/bulk/` (в каждой строке);
- **отдельно для уже добавленной строки** (кнопка «+» и любая правка): `POST pos/sales/<cart>/items/<item>/serials/` с телом `{"serial_numbers": [...]}` **заменяет** список строки целиком. Ответ: `{"id", "serial_numbers"}`.

Одинаковые строки товара в корзине склеиваются — серийники тоже склеиваются (без повторов).

В ответах: строка корзины — `serial_numbers`; строка проданного чека — `serial_numbers` и `warranty_until` (дата «гарантия до» = дата продажи + `warranty_months`).

## 3. Проверки (только с флагом компании `electronics_2026_11` и `X-NurMarket-Client` новой версии, только онлайн)
Ошибки в обычном формате строки (`code`, `index`):
- `serial_already_sold` — серийник продан и не возвращён (`serial`, `sale_id`);
- `serial_count_mismatch` — серийников больше, чем количество (`count`, `quantity`);
- `serial_duplicate_in_line` — один серийник дважды в строке;
- `serial_too_long`.

**Офлайн-чек не отклоняется никогда**: если серийник уже числится проданным, продажа проходит, а запись помечается `duplicate: true` (видно в поиске).
Серийников **меньше**, чем количество, сервер не запрещает: «Пропустить» и PIN старшего решает касса.

## 4. Поиск продажи по серийнику
`GET serials/?serial=SN1` → 
```json
{"serial": "SN1", "sold": true, "results": [
  {"serial": "SN1", "sale_id": "…", "sale_number": 1234, "sale_status": "paid",
   "sale_item_id": "…", "product_id": "…", "name": "…", "sold_at": "…",
   "warranty_until": "2027-11-13", "warranty_active": true,
   "returned": false, "returned_at": null, "sale_return_id": null, "duplicate": false}]}
```
Поиск идёт по связи с продажей, а не по номеру чека, поэтому **офлайн-чек, получивший новый номер, тоже находится** (п.4 твоего списка).

## 5. Возврат
`pos/sales/<id>/return/` и т.п. — как раньше, плюс в строке `items[]` можно прислать `serial_numbers` (что именно вернули — после сверки сканом):
`{"items": [{"sale_item_id": "…", "quantity": 1, "serial_numbers": ["SN1"]}], "reason": "Гарантия"}`
- полный возврат — все серийники чека становятся «возвращёнными»;
- частичный без `serial_numbers` — возвращёнными считаются первые N по количеству (лучше присылать);
- аннулирование или правка возврата снимает отметку.
Возвращённый серийник можно продать снова. Причина «Гарантия» — обычный текст в `reason`; срок проверяется по `warranty_active` из поиска.

## 6. Профиль «Электроника»
`GET public/sphere-profiles/` теперь отдаёт два профиля: `hardware` и `electronics` (`serials: true`, `features.warranty`, `features.serial_lookup`, `flag: "electronics_2026_11"`). Ремонт и trade-in — **позже** (`features.repair/trade_in: false`).

## Флаг
`electronics_2026_11` включается компании в подключённых функциях (`company/addons/`), как `hardware_2026_11`. Тестовая компания — скажу после выкладки.
