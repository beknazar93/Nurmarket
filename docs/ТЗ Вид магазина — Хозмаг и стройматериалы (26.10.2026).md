## 0. Коротко

1. **Сейчас хозмаг на кассе продать 2,5 м кабеля не может.** Количество штучного товара округляется до целого в кассе (5 мест) и в мобилке (2 места). Дробное количество бывает только у «весового» товара, а весовой показывается как «кг» и ждёт весов.
2. **Сервер к дробному готов по схеме:** `SaleItem.quantity` — строка-десятичное. Но правило «можно ли 2,5 у `is_weight=false`» сервер не подтвердил. Это Б-52, проверка записью на NBS.
3. **Упаковка и штука.** В кассе есть одна «поштучная продажа из упаковки» (`packages`, одна запись). Есть доп. штрихкоды с полем «кол-во в упаковке», но при продаже в кассе это количество **не умножается**. В мобилке и в ревизии кассы умножается. Хозмагу нужно: «коробка 200 саморезов» одним сканом = 200 шт; «мешок 25 кг» = 25 кг; «упаковка плитки 1,44 м²».
4. **Сфера.** На сервере `market_sphere` по схеме принимает только `grocery|clothing|services`. Значение `hardware` сервер не примет. Поэтому до Б-38 профиль хранится так, как решено в ТЗ сфер: `grocery` + `marketSphereDetail = "hardware"`.
5. **Первым делаем (без бэкенда):**
   - профиль `hardware` (подсказки единиц, категорий, онбординг);
   - дробное количество по единице (после проверки Б-52 на NBS);
   - скан упаковки = N штук;
   - ввод длины и площади на сенсоре;
   - калькулятор расхода;
   - ценник «за единицу и за упаковку»;
   - услуги «Доставка / Резка / Подъём».
6. **Ждёт бэкенда:**
   - несколько единиц с коэффициентом и своим штрихкодом (Б-53);
   - цены по категории клиента и от количества (Б-55);
   - прораб: лимит долга и объекты (Б-56);
   - характеристики-атрибуты и поиск по ним (Б-57);
   - «где лежит» (Б-58);
   - сопутствующие и аналоги (Б-59);
   - заказ под клиента с резервом и доставкой (Б-60);
   - партии с оттенком (Б-61).

## 1. Что нужно хозмагу и строительному маркету — главные потребности

Источник: опыт аналогов (1С:Розница и УТ — упаковки и коэффициенты единиц, ценник с ценой упаковки; МойСклад — упаковки со своими штрихкодами; Cleverence — зоны хранения и отрезной товар; калькуляторы расхода на сайтах стройматериалов), список из задания и код кассы и мобилки. Ссылки — в конце.

**Два типа магазина — один профиль.**
- **Хозмаг у дома** (20–80 м², 1–2 кассы, 2–5 тыс. товаров): крепёж поштучно и на вес, сантехника, электрика, краска, бытовая химия, садовое; прорабов мало.

### 3.1. Код, названия, база

- **Код:** `hardware` (как в Б-38 и таблице 5.2 ТЗ сфер).
- **Базовое поведение:** `grocery`. Все ветки `IsClothing`/`IsServices` для хозмага выключены, как у продуктов. Размеры и цвета (варианты) **выключены по умолчанию**, но доступны в карточке товара: перчатки, спецодежда и обувь бывают в хозмаге.
- **В `market_sphere` на сервер** — `grocery`. Точное значение — `marketSphereDetail = "hardware"` в `app-settings` (до Б-38), потом `market_profile = "hardware"`.

### 3.6. Шаги подсказок при первом запуске (онбординг, 5 шагов, можно «Пропустить»)

Показываются один раз после выбора `hardware`: первый запуск или смена сферы в Настройках. Хранение — локальная отметка `HardwareOnboardingDone`, в своём JSON пакета, не в `UserPreferences`.

1. **«Какой у вас магазин?»** — «Хозмаг у дома» / «Строительный маркет» (3.2).
2. **«Как вы продаёте?»** — галочки: «метры и м² (кабель, плитка)», «мешки и коробки, а также штуки из них», «на вес (гвозди)», «в долг прорабам». Включают пункты из 3.2.
3. **«Категории»** — список 3.4 с галочками, кнопка «Создать отмеченные». Создаются только категории, товары не трогаются.
4. **«Услуги»** — «Доставка», «Подъём на этаж», «Резка» с ценой (можно 0, тогда цена вводится в чеке). Создаются товары вида `service`.
5. **«Ценник»** — пробная печать ценника `hardware_58x40` на выбранном принтере или «Позже».

Кассиру (без прав владельца) онбординг не показывается: он видит только итог.

### 3.7. Как выбирается

- **При создании магазина** (окно первого запуска `MarketSphereChoiceWindow` — пакет СФ2) — плитка «🔨 Хозтовары и стройматериалы».
- **Позже** — Настройки → Операции → «Сфера магазина» (СФ2), блок «Что изменится»:
  - «Можно продавать 2,5 м и 1,44 м²»;
  - «Скан коробки добавит все штуки»;
  - «Окно длины и площади»;
  - «Калькулятор расхода»;
  - «Ценник с ценой за упаковку».
- **Сайт NurCRM** (регистрация компании) — после Б-38, поле `market_profile`.

### 3.8. Существующие магазины — ничего не ломать

1. Магазины с `grocery`, `clothing`, `services` **не замечают ничего**: все новые функции включаются только при `hardware`.
2. Магазин, который переходит на `hardware`:
   - товары, цены, остатки и единицы **не меняются**;
   - дробное количество включается только для товаров, у которых единица из списка дробных (3.3);
   - товары с `шт` остаются целыми.
3. **Скан упаковки = N** (меняет поведение скана) — только при `hardware` и после галочки «Скан коробки добавляет все штуки» на шаге 2. По умолчанию для перешедших магазинов — **выкл**, для новых — вкл (В-Х4).
4. **Старые кассы в том же магазине** (1.17.60 и ниже, мобилка 1.18.x) не знают `hardware` и округляют количество:
   - Если на новой кассе продали 2,5 м, а возврат делают на старой, то старая может предложить вернуть «3». Перед включением дробного новая касса показывает владельцу: «Обновите все кассы и телефоны магазина до 1.17.6x и мобилку до 1.18.y — иначе возвраты и чеки с метрами на них будут неточными» (с галочкой «Я обновил»).
   - Сервер узнаёт версии по `X-NurMarket-Client` (Б-01). Список устройств компании и их версии — по желанию в Б-52.
5. Переход обратно на «Продукты» выключает функции. Уже проданные дробные чеки остаются как есть: возврат идёт по их фактическому количеству.

## 4. Требования по платформам

### 4.1. Касса (Windows / Linux / Android-касса)

**Продажа (P0):**
1. Дробное количество для товаров с дробной единицей (3.3):
   - ввод с клавиатуры, «+/−» с шагом единицы, отправка на сервер до 3 знаков (как вес);
   - минимум продажи (1 м по умолчанию для `m`; настраивается в профиле; после Б-52 — по товару);
   - сумма строки = количество × цена, округление до копейки по О6;
   - **скидка и возврат по строке пересчитываются от дробного количества** (`ReturnSaleDialog` уже считает долю: `:920`).
2. Окно «Количество» (ХМ6) — по нажатию на количество в строке и при добавлении товара с дробной единицей:
   - поле с единицей («м»);
   - кнопки шагов: м — 0,5 / 1 / 2 / 3 / 5 / 10 / 25 / 50 / 100; м² — 1 / 2 / 5 / 10 / 20; л — 0,5 / 1 / 2 / 5 / 10;
   - «Д × Ш» для м² (два поля, результат с округлением вверх до шага);
   - «Целая упаковка» (если у товара есть упаковка: «бухта 100 м», «уп 1,44 м²»);
   - сумма строки сразу; «Готово» — Enter, «Отмена» — Esc.
   - Цифры — экранная цифровая клавиатура окна (как в оплате). Своя полная клавиатура запрещена, текст — только `osk.exe`.
3. Скан упаковки (ХМ3): доп. штрихкод с количеством N > 0 → строка товара +N базовых единиц, подпись «Коробка ×200». Повторный скан той же коробки прибавляет ещё N.
4. Выбор «штуками или упаковкой» (`PackageChoiceDialog`) — для товара с упаковкой при добавлении из каталога. Запоминать последний выбор на товар до конца смены.

**Карточка товара (P0–P1):**
5. Поле «Ед.» с подсказками единиц профиля (3.3) — СФ3.
6. Вкладка «Упаковка»: для `hardware` подпись «Продавать и упаковкой» вместо «Поштучная продажа». До Б-53 — одна упаковка (как сейчас), после Б-53 — список «единица, сколько базовых, штрихкод, цена».
7. Доп. штрихкод с количеством: подпись «Кол-во в упаковке (скан добавит столько)» — только при включённом «Скан упаковки = N».
8. Блок «Для калькулятора» (ХМ5) — **без бэкенда** берётся из упаковки (м² в упаковке, л в банке, кг в мешке) и из правил профиля:
   - норма расхода на м² — по категории, правится владельцем;
   - хранение — ключ `hardwareCalc` в общих настройках компании, ≤ 8 КБ.

**Калькулятор расхода (P1, ХМ5)** — кнопка «Сколько нужно?» в карточке товара в продаже и в «Подробнее»:
- Плитка и ламинат: площадь (м² или Д×Ш, минус проёмы) → + запас (10 % по умолчанию; 15 % для диагональной укладки) → м² → упаковки (вверх) → «В чек: 9 уп (12,96 м²)».
- Краска: площадь × слоёв × расход л/м² → л → банки (вверх).
- Обои: периметр × высота, ширина и длина рулона, раппорт → рулоны (вверх). Формула — в коде с комментарием.
- Клей и затирка (сопутствующие): площадь × расход кг/м² → мешки.
- Итог показывает: «нужно 11,9 м² · с запасом 13,1 м² · 10 упаковок · 7 490 сом». Кнопка «В чек» добавляет **упаковки** (если продаётся упаковками) или м².
- Формулы — в одном чистом классе без UI. Проверка — консольным стендом, без `dotnet test`.

**Ценник и этикетка (P1, ХМ7):** 3.5. Массовая печать ценников по категории — в существующем `BulkPriceTagPrintDialog`.

**Клиенты и документы (P1):**
9. «Опт для отмеченных клиентов» (ХМ8, до Б-55):
   - галочка у клиента «Покупает по оптовой цене (прораб)», хранение — ключ `clientPriceGroups` в общих настройках (только id клиента и уровень, ≤ 16 КБ);
   - выбрал такого клиента в чеке → все строки на опт (существующий переключатель). Кассир видит плашку «Цена прораба».
   - После Б-55 — серверный уровень цены, ключ удаляется.
10. КП / счёт / «Смета» (ХМ9): в `ClientDocEditorWindow` — поле «Объект» (название или адрес), строка доставки и подъёма; заголовок «Смета» как вид КП (тот же `Quote`, другой заголовок печати). Дробное количество в строках — уже есть (`ClientDocEditorWindow.cs:2047`).
11. Долг: для «Строительного маркета» срок по умолчанию 14 дней (настройка профиля). Лимит долга — после Б-56.

**Сопутствующие (P2, ХМ10):**
- правила «категория → категория» владельцем («Плитка → Клей, Затирка, Крестики»), хранение — ключ `upsellRules`, ≤ 8 КБ;
- `UpsellService` получает правило как дополнительный вес. Статистика остаётся.

**Нур Советник (P2, ХМ11):** в контекст ИИ — профиль `hardware`, единицы товаров (не «кг/шт»), сезон по месяцу. Подсказки:
- «что заказать к сезону»: март–май — сад, краска, грунт; сентябрь–ноябрь — утеплитель, герметик, обогреватели;
- «неликвид > 180 дней»;
- «прорабы с долгом > 30 дней»;
- «наценка ниже 15 % по категории».

**Отчёты (P2):** до Б-26 — локальный отчёт «Неликвид» по продажам на кассе (без продаж N дней, остаток × закупка) в программе владельца.

### 4.2. Программа владельца (`--owner`)

- Выбор сферы и онбординг (3.6–3.7); «Что изменится».
- Калькулятор: нормы расхода по категориям (таблица из 6–8 строк, правка, сброс к типовым).
- Ценники: шаблон `hardware_58x40` в списке; массовая печать по категории.
- Клиенты: отметка «Прораб / опт» (ХМ8), должники-прорабы — фильтр «с отметкой» в должниках.
- Сводка: плитка «Неликвид» (ХМ11/отчёт).
- После бэкенда: уровни цен (Б-55), ячейки (Б-58), сопутствующие (Б-59), заказы под клиента (Б-60).

### 4.3. Android-касса и Linux

То же, что Windows: Portable и Android берут все `*.cs` глобом. Отличия:

### 4.4. Мобилка (Flutter)

**Зависит от ТЗ «Мобилка — сферы»** (отдельное, по ТЗ сфер 5.5): читать `market_profile` / `marketSphereDetail` вместо `shop.clothing`. Если его ещё нет — пакет МХ1 делает минимум: чтение `marketSphereDetail` из `app-settings/nurmarket-kassa/` (ключ общий с кассой) только для `hardware`.

1. **Продажа (P0):**
   - дробное количество по единице (те же правила 3.3; убрать округление в `sale_screen.dart:678`, `sales_repository.dart:76, 109` — только для дробных единиц);

   - скан упаковки — уже прибавляет N (оставить), показывать «Коробка ×200».
2. **Карточка и приёмка (P0–P1):**
   - список единиц из профиля (вместо зашитых 4);
   - приёмка в упаковках («10 коробок × 200 = 2000 шт»);

- **В-Х4.** «Скан коробки = все штуки» — для новых хозмагов включено, для перешедших — выключено (владелец включает сам)? **По умолчанию — да.**
- **В-Х5.** Цена прораба до сервера — через оптовую цену для отмеченных клиентов (ХМ8)? Или ждать Б-55? **По умолчанию — ХМ8 сейчас.**
- **В-Х6.** Калькулятор расхода — какие виды нужны первыми: плитка, ламинат, краска, обои, смеси? **По умолчанию — все пять.**
- **В-Х7.** Тема кассы для хозмага — оставлять текущую или предложить «Сенсорную» / новую «Стройка»? **По умолчанию — не менять, тему «Стройка» сделать только для сайта (ХМ12).**
- **В-Х8.** Учёт обрезков (бухта, труба) и партий с оттенком — нужно в первой версии? **По умолчанию — нет (P3), отдельным ТЗ по заявке магазина.**
- **В-Х9.** Кто проверит переводы ky, tr, uz названий, категорий и единиц? **По умолчанию — владелец (ky, uz), tr — как есть.**
- **В-Х10.** Есть ли живой хозмаг или стройбаза для пилота? Нужен второй тестовый аккаунт (не NBS), чтобы не менять сферу NBS. **По умолчанию — завести тестовый аккаунт «Хозмаг тест».**
- **В-Х11.** Онбординг (3.6) создаёт категории и услуги на сервере по кнопке — согласны? **По умолчанию — да, только по кнопке.**
