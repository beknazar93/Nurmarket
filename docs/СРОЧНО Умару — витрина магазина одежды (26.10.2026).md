- Заказ с размером на сервер **уже создаёт бот нашей кассы**: `POST public/companies/{slug}/orders/` со строкой `variant`. На NBS 22.10 заказ №10 пришёл с вариантом «L, Белый».

**Что не работает у магазина одежды сегодня** (по сборке фронта, без запросов к API):
1. «Оформить» на сайте **не создаёт заказ в NurCRM**: в сборке нет запроса `orders/`, заказ уходит только текстом в WhatsApp. Магазин не видит заказ ни в NurCRM, ни в кассе, ни в Telegram; остаток не резервируется.

3. Нет фильтров (размер, цвет, цена, бренд), избранного, примерки.
4. Нет кнопки Telegram и чата.
5. Шрифтов — 7. Любой другой фронт молча заменяет на Roboto Condensed.

## 2. P0 — первая неделя

### 2.1. Заказ с сайта в NurCRM (Б-34 п. 1–3, Б-22, Б-90)

**Зачем.** Сейчас заказ сайта — только текст в WhatsApp. Магазин теряет заказы, остаток не резервируется, продавец не получает уведомление в Telegram (Б-22), касса не видит заказ в «Заказах с сайта».

**Что уже есть.**
- Адрес `POST api/main/public/companies/{slug}/orders/` работает, наша касса им пользуется.
- В схеме у `ShowcaseOrder`:
  - `customer_name`, `customer_phone` (обязательные);
  - `delivery_type pickup|delivery`, `delivery_address`, `comment`, `source`, `stock_reserved`;
  - статусы `new|accepted|ready|done|canceled`.
- У `ShowcaseOrderItem`: `product`, `variant`, `variant_size`, `variant_color`, `qty`, `price`, `total`.

**Контракт — фронт** (по кнопке «Оформить»):
```http
POST /api/main/public/companies/{slug}/orders/
Idempotency-Key: <32 hex, один на нажатие «Оформить»; повтор при обрыве — тот же>
Content-Type: application/json

{
  "customer": {"name": "Айгуль", "phone": "+996700123456"},
  "items": [
    {"product": "<uuid товара>", "variant": "<uuid варианта, обязательно у товара с вариантами>", "qty": "1"}
  ],
  "delivery": {"type": "pickup"},               // или {"type":"delivery","address":"…"}
  "comment": "Позвоните после 18:00",
  "source": "showcase",
  "source_detail": "site_cart"                  // необязательно, Б-90
}
```
- Ответ `201`: `{"id": "…", "number": 57, "total": "2450.00", "status": "new"}`.
- **Цену фронт не передаёт** — её считает сервер.
- После `201` — экран «Заказ №57 принят» (`cart.success_text`). Если в дизайне `cart.order_channel` = `server_and_whatsapp` — **потом** открыть WhatsApp с текстом «Заказ №57 …».
- При `cart.order_channel = whatsapp` — как сейчас, без запроса.

**Контракт — бэкенд** (проверки, Б-34 п. 2–3). Ошибки — JSON по правилу О1, `detail` первым ключом:

| Случай | Ответ |
|---|---|
| у товара есть варианты, а `variant` нет | `400 {"detail":"Выберите размер и цвет","code":"variant_required","errors":[{"index":0,"field":"variant","code":"variant_required"}]}` |
| вариант от другого товара | `400 … "code":"variant_mismatch"` |
| не хватает | `409 {"detail":"Осталось 1 шт","code":"variant_out_of_stock","errors":[{"index":0,"available":"1"}]}` |
| повтор с тем же ключом | `200`, тот же заказ, `"replayed": true` |
| тот же ключ, другое тело | `409 idempotency_conflict` |
| пустой телефон | `400 … "field":"customer.phone","code":"required"` |
| частые заказы | `429` с `Retry-After`; не больше 10 заказов в час с IP |

**Резерв варианта и товара** — при создании; `canceled` возвращает оба. Сразу после заказа — уведомление продавцу в Telegram (Б-22).

**Права.** Публично, без входа. **Совместимость.** Поля `source_detail` и `Idempotency-Key` необязательные; старые клиенты (бот кассы) работают как раньше.

**Как принять.**
1. На NBS (сфера `clothing`) положить в корзину товар с размером → «Оформить» → заказ виден в `showcase/orders/` и в кассе в «Заказах с сайта» с размером и цветом; остаток варианта −1.
2. Нажать «Оформить» ещё раз (имитация обрыва, тот же ключ) → тот же номер заказа.
3. Заказать больше, чем есть → понятная фраза «Осталось 1 шт» в корзине, заказа нет.

### 2.2. Карточка товара одежды: размер, цвет, остаток, галерея (Б-33, Б-34)

**Зачем.** Покупатель не может выбрать размер. Продавец потом звонит «какой размер?», заказ теряется.

**Что уже есть.**
- Варианты товара в NurCRM — касса и мобилка с ними работают.
- В публичном списке, по нашему ТЗ 21.10, есть `has_variants` и `price_range`.
- Схема 26.10 публичной карточки `GET public/companies/{slug}/showcase/{product_id}/` не описана. 26.10 в ней нет `colors` и `sizes` (наша проверка, Н-26).

**Контракт — бэкенд, публичная карточка** `GET /api/main/public/companies/{slug}/showcase/{product_id}/`:
```json
{
  "id": "…", "name": "Платье «Мира»", "price": "2450.00", "final_price": "2450.00", "old_price": null,
  "has_variants": true,
  "images": [{"image_url": "…", "is_primary": true, "color": "Чёрный"}],
  "colors": [{"name": "Чёрный", "hex": "#111111", "images": ["…"]}],
  "sizes": ["42", "44", "46", "48", "50"],
  "variants": [
    {"id": "…", "size": "44", "color": "Чёрный", "color_hex": "#111111", "sort_order": 2,
     "in_stock": true, "available": 3, "price": "2450.00", "final_price": "2450.00", "old_price": null}
  ],
  "size_chart": null
}
```
- `sizes` — по `sort_order`. Без него: XXS…5XL, затем числа, затем W26…W36, затем по алфавиту.
- `available` — число, **только если ≤ 5**, иначе `null` (точные остатки конкурентам не показываем); `in_stock` — всегда.
- Остаток — по филиалу витрины за вычетом резервов. Неактивные варианты не отдавать.
- В списке `GET …/showcase/` у товара: `colors[{name,hex}]` (до 8) и `sizes_in_stock[]`.

**Контракт — фронт** (макет `docs/Витрина одежды — макет карточки товара.html`):
- кружки цвета;
- кнопки размеров: нет в выбранном цвете — серая зачёркнутая;
- «В корзину» неактивна, пока не выбраны размер и цвет;
- ключ строки корзины — `product + variant`;
- `?variant=<uuid>` в адресе открывает карточку с выбранным вариантом;
- галерея: листание, фото выбранного цвета первыми, формат из `card.photo_ratio` (у тем одежды `3:4`, `photo_fit: cover`);
- в списке — кружки цветов и «от … сом» по `price_range`.

**Права.** Публично. **Совместимость.** Только новые поля.

**Как принять.**
1. «Nike» (18 вариантов на NBS) → кружки цвета с `hex`, размеры по порядку.
2. Выбрать цвет, в котором нет 46 → 46 серый, «В корзину» неактивна.
3. Обнулить «46 Белый» на кассе → через ≤ 60 с на сайте 46 Белый недоступен.

## 3. P1 — вторая неделя

### 3.1. Размерная сетка (Б-50)
- **Зачем.** Меньше возвратов и вопросов «какой мне размер».
- **Сейчас.** `showcase/size-charts/` → 404.
- **Контракт.**
  - `GET/POST/PATCH/DELETE api/main/showcase/size-charts/` — `{id, name, category?, columns[{key,title{ru,ky,en,tr,uz}}], rows[{size, values{key: "86–89"}}]}`;
  - в публичной карточке — `size_chart` (товара, иначе его категории, иначе `null`);
  - фронт: ссылка «Таблица размеров» → окно с таблицей.
- **Приёмка.** Сетка для категории «Платья» → видна у всех платьев; у товара своя — показывается своя.

### 3.2. Фильтры (Б-33, Б-93)
- **Зачем.** Каталог одежды без фильтров не листают.
- **Контракт.**
  - `GET public/…/showcase/?size=M,L&color=Чёрный&min_price=&max_price=&brand=&in_stock=1` — по вариантам **в наличии**;
  - `GET public/…/showcase/facets/?category=&search=` → `{sizes[{value,count}], colors[{name,hex,count}], price{min,max}, brands[{value,count}]}`;
  - кэш 30–60 с, сброс при продаже, приходе, возврате;
  - фронт: панель фильтров (на телефоне — шторка), выбранные фильтры чипами, «Сбросить».
- **Приёмка.** `?size=46&color=Белый` → «Nike» в списке; после обнуления — пропал; `facets` считает `count`.

### 3.3. Избранное и быстрый просмотр (только фронт)
- **Избранное.** Сердечко на карточке, страница «Избранное», хранение в `localStorage` по `slug`. Сервер не нужен.
- **Быстрый просмотр.** Окно товара из списка с выбором размера и «В корзину».
- **Приёмка.** Добавить 3 товара в избранное → после перезагрузки страницы они на месте.

### 3.4. Кнопка «Заказать в Telegram» и перенос корзины (Б-32, Б-91)
- **Зачем.** Покупатели одежды в КР пишут в мессенджеры. Бот магазина у нас уже принимает заказы с размером.
- **Контракт — бэкенд.**
  - Ключи дизайна `cart.telegram.enabled`, `button_text{5}`, `placement[] ⊂ cart|product|header|floating`.
  - Публичный `showcase/design/` отдаёт `telegram {enabled, bot_username, url, product_url_template, button_text, placement}`.
    - `enabled=false`, если бот не на сервере или `webhook_ok=false`;
    - **никогда** — `token`, `owner_chat_id`.
  - `POST public/…/cart-link/ {items[{product, variant?, qty}]}` → `{token, expires_at}`: 24 ч, ≥ 128 бит, ≤ 20 в час с IP.
  - `GET public/…/cart-link/{token}/` → строки с ценой на момент запроса.
  - Заказ с `cart_token` — один на токен. Просрочен — `410 cart_link_expired`.
- **Контракт — фронт.**
  - Кнопки по `placement`.
  - Корзина → `cart-link` → `tg://resolve?domain=<бот>&start=c_<token>`; не открылось — `https://t.me/<бот>?start=c_<token>`.
  - Карточка → `…?start=p_<product_id>`.
- **Приёмка.** Включить → токена бота в ответе нет (поиск по строке). Корзина из 2 вещей с размерами → бот показывает их и оформляет один заказ `source=telegram_bot`.

### 3.5. Шрифты с кириллицей (Б-92 п. 1)
- **Зачем.** 7 шрифтов мало для бутиков и вечерней одежды. Незнакомый шрифт сейчас молча становится Roboto Condensed.
- **Контракт.**
  - `editor/options.fonts` → `[{family, weights, cyrillic_ext}]`. Добавить Playfair Display, Cormorant Garamond, Oswald, Manrope, Unbounded, Comfortaa, Lora, Rubik — **только если есть ң, ө, ү**.
  - Новый ключ `theme.font.heading_family` (пусто = `family`).
  - Фронт грузит оба шрифта с `subset=cyrillic,cyrillic-ext`. Незнакомый шрифт → `Inter`, а не Roboto Condensed.
- **Приёмка.** Строка «Ңң Өө Үү Ёё / İı Şş Ğğ / Oʻoʻ» в заголовке Playfair Display — без «квадратиков».

### 3.6. Чат ИИ-помощника (Б-83, Б-79, Б-88, Б-89) — начать
- **Зачем.** Ответ ночью: «есть ли 44 в чёрном», «можно обменять», подбор размера. Покупатель не уходит с сайта.
- **Главное правило — ключ ИИ только на сервере.** Во фронте нет ни ключа, ни имени модели.
- **Контракт.**
  - Сеансы и сообщения чата — `public/…/chat/sessions/…` (Б-83). ИИ отвечает на сервере по каталогу через функции (Б-79) — тот же Gemini, что у серверного бота (`test-ai/` с `functions_called` у вас уже есть).
  - Добавки для открытого сайта (Б-88):
    - капча Turnstile при создании сеанса;
    - бюджет **вызовов модели**: сеанс — 6 в минуту и 40 в сутки, IP — 120 в сутки, компания — 300 в сутки на бесплатном ключе;
    - сверх бюджета — `{"ai":"busy"}`: фронт показывает «Помощник занят» и кнопки Telegram, WhatsApp, телефон;
    - ответ структурой `{text, cards[], actions[{type:"add_to_cart"}], needs_human}`, цены в `cards` — из каталога;
    - **сервер сверяет каждую цену и количество в тексте с данными**, иначе «уточню у продавца»;
    - знания магазина: обмен, примерка, доставка (Б-89).
  - Фронт: кнопка-чат, окно, карточки товаров с размерами, «В корзину», «Позвать продавца», согласие на номер, состояние «занят».
- **Приёмка.** Вопрос о наличии → карточка с ценой как на сайте. 41-й вызов модели сеанса → «занят». Ключа в ответах нет.
