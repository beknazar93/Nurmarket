## 0. Коротко

- **Идея.** Сфера перестаёт «зашивать» функции. Каждая функция — **модуль** с кодом (`id`). Сфера = только список модулей «из коробки». Владелец любого магазина через Маркетплейс ставит любой другой модуль (бесплатный сразу, платный — по ключу, на сайте или через поддержку). Весы с этикетками можно поставить хозмагу, «Сроки годности» — строймагу, «Серийные номера» — магазину одежды.
- **Что уже сделано.** 15 функций уже живут как «модули» Маркетплейса (карточки `Gated(...)`): лояльность, табель, ремонт, trade-in, смета, прокат, весы, аналитика склада, ценники, массовая печать, редактор этикетки, Word/Excel, Телеграм-бот, итоги смены, языковой пакет; плюс 7 пакетов «Стандарта» на «Старте» и темы/виды. [код] `Services/MarketplaceCatalog.cs`.
- **Что зашито в сферу** (топ-8, раздел 2.3): серийники и гарантия (Электроника), всё «автозапчастное» (каталожный номер, аналоги, заказ под клиента, импорт прайсов), упаковки и скан коробки (Хозмаг/Строймаг), дробные единицы и окно «длина/Д×Ш», цена «прораб/СТО», размеры и цвета (Одежда), консультант и правила обмена (Одежда/Электроника), школьные списки и накладная из чека (Канцтовары).
- **Главная проблема не в хранении флагов, а в коде:** около 90 мест вида `MarketSpheres.IsHardware / IsClothing / IsAutoParts / ElectronicsProfile.IsActive` (раздел 2.4). Пока они есть, «поставить из Маркетплейса» не сработает, даже если флаг включён.
- **Что рекомендую.** Один реестр `FeatureModules` (данные, 5 языков, цены, зависимости), одна функция `FeatureModules.IsEnabled(id)`, одно хранилище включённого (сначала общие настройки компании в `SettingsCloudSync`, потом документ `company-modules` на сервере), перенос по одному модулю без смены поведения. Первые четыре: Сроки годности, Весы с этикетками, Серийники/гарантия, Упаковки + уровни цен.
- **Тариф «Своё» (дополнение владельца 20.11):** клиент сам выбирает модули в Маркетплейсе; абонплата = цена основы («Старт» или «Стандарт») + сумма цен добавленных модулей, не входящих в основу и в сферу; цену и расчёт делает сервер (`tariff/quote/`), касса только показывает. Раздел 10.
- **Что не трогаем:** базовое поведение сферы для сервера (`market_sphere` = grocery/clothing/services), единицы и категории-подсказки (остаются «наборами при выборе сферы»), темы/виды кассы (остаются отдельным видом карточек).

## 1. Требования владельца (из слов и прежних решений)

1. [слова 20.11] Любую функцию любой сферы можно поставить из Маркетплейса в магазин другой сферы.
2. [слова 20.11] Сфера «из коробки» даёт свой набор модулей; остальное — по желанию.
3. [решение 20.11] «Аренда по умолчанию только в строймаге, у остальных — через Маркетплейс» (уже сделано как `RentalFeature`) — образец для всех модулей.
4. [решение 13.11] «Ремонт и trade-in — как доп. услуги в Маркетплейсе, чтобы желающие могли подключить» — уже сделано.
5. [решение 19.11] Смета — Строймаг из коробки, остальные включают в Маркетплейсе (`EstimateFeature`).
6. [решение 05.10] Платная функция на «Старте» — по ключу/через поддержку; на «Стандарте» часть входит в тариф.
7. Данные не теряются: выключение скрывает, а не удаляет (так уже работают `ServerAddons`, прокат, табель).

## 3. ЦЕЛЕВАЯ МОДЕЛЬ «Реестр модулей» (FeatureModule)

### 3.1 Запись модуля (данные, не код) [предложение]

Файл-источник: `NurMarketKassa.Infrastructure/Services/Modules/FeatureModuleCatalog.cs` (новый), текст — тип `L5` (уже есть). Тот же реестр кладётся в мобилку как `assets/feature_modules.json` (и позже отдаётся сервером, раздел 7).

```csharp
public sealed record FeatureModule
{
    public required string Id { get; init; }            // «expiry_dates»; для старых — прежний slug (loyalty, repair, scales…)
    public string? ServerCode { get; init; }            // «kassa-scales» — код на сервере; null — только локальный флаг
    public required L5 Title { get; init; }             // название
    public required L5 ShortDescription { get; init; }  // одна строка
    public required string Group { get; init; }         // scales / expiry / prices / variants / serials / autoparts / service / docs / money / quick / clients / print / analytics / look
    public required string IconKey { get; init; }       // значок (AppIcons) + эмодзи для плитки
    public decimal? PriceSom { get; init; }             // null — не задана; 0 — бесплатно; N — сом
    public PricePeriod Period { get; init; }            // OneTime / Monthly
    public TariffRule Start { get; init; }              // Included / Paid / NotAvailable
    public TariffRule Standard { get; init; }
    public TariffRule Custom { get; init; }             // «Своё»
    public TariffRule Mini { get; init; }               // «Мини» — только если у модуля есть мобильная версия
    public string[] DependsOn { get; init; } = [];      // жёсткие: без них не включить (price_levels → нет; waybill_a4 → нет)
    public string[] Enhances { get; init; } = [];       // мягкие: работает лучше с … (consumption_calc ← estimate)
    public string[] ConflictsWith { get; init; } = [];  // пока пусто
    public Platforms Platforms { get; init; }           // флаги: Kassa | Owner | Mobile | Site
    public string[] ServerNeeds { get; init; } = [];    // признаки сервера: «expiry_batches», «hardware_2026_11»…
    public string[] DefaultFor { get; init; } = [];     // id сфер, где «из коробки» (источник правды для SphereProfile.DefaultModules)
    public string[] TypicalFor { get; init; } = [];     // «обычно нужен» (подсказка в карточке), может шире DefaultFor
    public bool Hideable { get; init; } = true;         // можно ли выключить «из коробки»
    public ModuleDataPolicy OnDisable { get; init; }    // HideKeepData (по умолчанию) / BlockIfOpenDocs
}
```

Принципы:
1. **id = прежний slug**, где он есть (`loyalty`, `timesheet`, `repair`, `trade_in`, `estimate`, `rental`, `scales`, `analytics`, `pricetag`, `bulktag`, `labeleditor`, `export`, `telegram`, `shiftstats`, `language`): серверные коды `kassa-<id>` и облачные ключи не меняются, миграции не нужны. Новые — `snake_case`.
2. Тексты 5 языков для карточки — как сегодня (`MarketplaceContent*.cs`), реестр держит короткие (название + одна строка), длинные описания остаются в `MarketplaceContent`.
3. Цена — только число из решения владельца; `null` = «по решению владельца».

### 3.2 Профиль сферы = список модулей

```csharp
SphereProfile.DefaultModules : string[]   // вычисляется из FeatureModule.DefaultFor, не дублируется руками
```

В профиле остаётся только то, что **не** модуль: `Id`, `BaseBehavior` (для сервера), `Title/ShortTitle/Description`, `Icon/IconKey/AccentHex`, `Units`, `CategoryHints`, `ChoiceVisible`. Поля `ShowVariants`, `ShowProductDetails`, `FractionalUnits`, `PackScan`, `QuantityPad`, `ConsumptionCalc`, `ForemanPriceAvailable`, `HasEstimate`, `HasRentalsByDefault`, `HardwareFamily` — уходят (одно за другим, по этапам; на время миграции остаются как вычисляемые «только чтение»).

`Units` и `CategoryHints` — это **наборы-подсказки**, а не модули: при установке модуля, которому они нужны (`fractional_units`, `sale_units`), касса предлагает кнопку «Добавить единицы м, м², л, упаковка…» один раз (создаётся только по кнопке — как сейчас).

### 3.3 Единая проверка

```csharp
FeatureModules.IsEnabled(string id) => State(id).Enabled;
FeatureModules.State(string id)     => ModuleState { Enabled, Reason, Blocked, Hint }
```

Порядок правил (первое совпавшее решает):

1. **Явное решение владельца** (`overrides[id]` = on/off) — побеждает всё, кроме «заблокировано».
2. **Сервер выдал** `kassa-<id>` (куплено/пробный/поддержка) и срок не вышел → включено, причина «Подключено · по ключу / пробный период / поддержка» (как `ServerAddons`).
3. **Куплено ключом** (`*Unlocked` из ключа) → включено.
4. **Сфера по умолчанию** (`DefaultModules`) → включено бесплатно, причина «Входит в вашу сферу».
5. **Есть данные модуля** (миграция: прокат, серийники, сроки…) → включено, причина «Данные уже есть» (как `RentalFeature.EnableForExisting`). Только пока нет явного решения владельца.
6. Иначе выключено.

Отдельно (не «выключено», а **заблокировано**, чтобы причины не путались — так же, как в мобильном ТЗ):

| `Blocked` | Когда | Что видит владелец |
|---|---|---|
| `Price` | платный, не куплен | «Активировать — N сом» / «Подключить» / «Купить на сайте» |
| `Tariff` | тариф не включает (`Start/Standard/Mini = NotAvailable`) | «Доступно на тарифе Стандарт» — **без блокировки уже введённых данных** |
| `Server` | у сервера нет нужного признака (`ServerNeeds`) | «Сервер ещё не поддерживает — включит поддержка» (не путать с «не оплачено») |
| `Platform` | модуль не для этого устройства | «Только в кассе» / «Только на телефоне» |
| `Dependency` | не включён `DependsOn` | «Сначала включите: …» |

`State` — чистая функция от (`ModuleRegistry`, `SphereProfile`, `overrides`, `grants`, `tariff`, `serverFlags`, `hasData`) — легко проверяется таблицей тестов. Слой `SectionVisibility` («скрыть пункт меню») остаётся поверх: `пункт виден = IsEnabled(модуль) && !SectionVisibility.IsHidden(ключ)`.

Единая вкладка «Функции» (сейчас карточки собираются в `MarketplaceCatalog.GetItems()` вручную: после М3 функция-карточки генерируются из реестра, а `MarketplaceContent*` даёт длинный текст).

### 3.6 Что происходит с данными при выключении

Правило «скрыть, не удалять» (как у `ServerAddons`, проката, табеля):

| Модуль | Что скрывается | Что остаётся |
|---|---|---|
| Серийники и гарантия | блок в карточке, поле в чеке, журнал, печать гарантийного талона | серийники в проданных чеках и журнале, гарантия в истории — видны при просмотре |
| Сроки годности | метки, предупреждение при продаже, утренний отчёт | сроки партий на сервере |
| Упаковки, уровни цен | скан коробки, «прораб/СТО» в оплате | цены уровней, `sale_units`, отметки клиентов; в чеках — как были |
| Прокат, ремонт, заказы под клиента, резервы | меню и новые оформления | **открытые документы** (прокаты, ремонты, предоплаты) — через раздел «Незавершённое»; выключение предупреждает «открыто N» |
| Размеры/цвета | выбор размера в карточке | варианты и штрихкоды размеров |
| Весы | отправка PLU | настройки весов, PLU, правила штрихкода |

`ModuleDataPolicy.BlockIfOpenDocs`: прокат, ремонт, заказы под клиента — нельзя выключить, пока есть открытые документы (предложить закрыть); остальные — `HideKeepData`.

### 3.7 Касса, программа владельца, мобилка

- **Касса и программа владельца** — один и тот же `FeatureModules` (общий exe). Меню (`SideMenuViewModel`, `OwnerShellWindow.*`) строится по `IsEnabled`, а не по `IsXxx`.
- **Мобилка** читает тот же список: `ModeProfile.feats` (мобильный ТЗ 3.2) = модули реестра; ключи `Feat` = `id` модулей (один словарь на касса/мобилка/сайт). `defaultFeats` сферы = `DefaultFor`. Состояние (`overrides`/`grants`) — из документа `company-modules` (М4); до М4 — из `app-settings` компании, если мобилка их читает [не проверено]. «Мини» (мобилка, один сотрудник) видит только модули с `Platforms.Mobile`.
- **Сайт (витрина)**: модули с `Platforms.Site` (темы сайта, размеры и цвета на карточке товара, Telegram-бот на витрине) получают состояние от того же документа. Сейчас сайту нужно только знать «размеры включены».

### 3.8 Тарифы

- `Start/Standard/Custom/Mini` на каждом модуле: `Included` (в тарифе), `Paid` (покупается отдельно, как сегодня пакет 1500 + 400/мес или по ключу), `NotAvailable` (нельзя: «Доступно на тарифе…»).
- Тариф определяется **не по имени плана**, а по коду `plan.code` (`mini/start/standard/custom`, ТЗ Тарифы Б-39, ТЗ Мини Б-М1) — до появления кода касса считает «неизвестный тариф как сегодня» (всё работает по ключам и кэшу).
- При понижении тарифа: модуль уходит в «Доступно на тарифе…»; **новое создавать нельзя, прежние данные видны** (ТЗ Тарифы 4.3).
- «Своё» — основа (Старт или Стандарт) + набор модулей; абонплата и корзина — раздел 10.
- Платные новые модули группируются в комплекты («Автозапчасти Про», «Опт Про» — ТЗ Тарифы 3.4): комплект — просто запись в реестре со списком `Includes` (модули внутри); отдельные модули тоже продаются, если владелец решит (вопрос 5).

### 3.9 Безопасность

1. Право на платный модуль подтверждает **сервер** (`kassa-<id>`, `until`, ключ). Локальный флаг — только видимость на экране.
2. Деньги, остатки, цены уровней, серийники в чеке, предоплаты — проверяет сервер (права роли, `capabilities`) независимо от того, включён ли модуль на кассе. Кассир с руками в `user-settings.json` ничего не получит.
3. Включать/выключать модули — только владелец и администратор (как общие настройки компании). Кассир видит результат, но не меняет.
4. Кэш принадлежит компании (`LastDataAccountKey`): при смене аккаунта стирается (как `ServerAddons`).
5. Журнал: каждое «Установить/Выключить/Активировать» пишется в журнал кассы и, после М4, в журнал компании (кто и когда).

3. «Сроки годности» → «Установить» → в карточке прихода поле «Срок годности», метки на складе, предупреждение при продаже просроченного (`ProductExpiryIndex`, `ExpiredSaleGuard`).
4. Проверка независимости: что надо убрать/проверить — (а) карточку `scales` показывать и на «Стандарте» (`if (start)` в `MarketplaceCatalog.cs:331`); (б) убедиться, что `ProductExpiryIndex` не зависит от продуктовой аналитики [не проверено вживую]; (в) хозмаговый ценник (`HardwarePriceTag`, `PriceTagPrintDialog.axaml.cs:49`) не заменяет весовую этикетку; (г) `WeightGoods` у Хозмага уже `true` [код].

**Сценарий Б. Продуктовый + «Упаковки и уровни цен» (из строймага).**

2. ## 7. БЛОК ДЛЯ УМАРА (М4) — для отправки в WhatsApp

### 10.2 Как «Своё» выглядит в реестре модулей

Поля модуля (дополняют 3.1; значения **только с сервера**, в реестре кассы цены — лишь запасной показ без связи):

| Поле | Смысл |
|---|---|
| `monthly_fee` | абонплата модуля в месяц, сом; **0 = входит бесплатно** |
| `activation_fee` | разовое подключение (сегодня у пакетов 1500; остаётся ли — вопрос 10.7 п. 1) |
| `trial_days` | пробный период (0 — нет; у пакетов такое поле уже есть) |
| `included_in` | коды планов, где модуль **входит в тариф**: `start`, `standard`, `mini` (для базовых функций) |
| `default_for` | сферы, где модуль бесплатный «из коробки» (то же, что `DefaultFor`) |
| `bundle_of` | для комплектов («Автозапчасти Про», «Опт Про») — модули внутри; цена комплекта обычно ниже суммы (решает владелец) |

**Правило «Своё» (считает сервер):**

`абонплата = цена_основы(план компании: Старт или Стандарт) + Σ monthly_fee(модуль)`
по модулям, которые клиент добавил в тариф и которые **не** входят в основу (`included_in` содержит код основы) и **не** входят в сферу (`default_for`).

- **Что вычитается:** модуль, входящий в основу (`included_in`), стоит 0 и помечается «Входит в ваш тариф»; модуль, входящий в сферу, — «Входит в вашу сферу» (0); модуль, уже купленный/подключённый, — «Уже подключено» (`already_active`); модуль внутри купленного комплекта — не доплачивается.
- Платным остаётся только **недостающее**: на «Старте» — всё, что в «Старте» не входит (сегодня пакеты); на «Стандарте» — только то, чего нет в «Стандарте» (сегодня все 11 пакетов в «Стандарт» входят — значит, поверх «Стандарта» реально продаются новые «профессиональные» модули: комплекты «Автозапчасти Про», «Опт Про», заказы под клиента, валюта и т. п., когда владелец решит их цену).
- Подсказка «Стандарт дешевле» (`standard_cheaper`) имеет смысл только на основе «Старт»; на основе «Стандарт» её нет (нечего «удешевлять»).
- Касса и мобилка **ничего не считают**: показывают `base`, `monthly`, `modules[].monthly` из `quote`. Нет ответа — «Не удалось рассчитать, повторите», без цифры (как сейчас в окне).
- Цены базы и модулей решает владелец; цифр я не называю.

### 10.3 Корзина модулей в Маркетплейсе

**Карточка платного модуля** у компании, которая собирает или имеет «Своё»: кнопка **«Добавить в тариф»** вместо «Активировать — N сом»; под ней «N сом в месяц» (из прайса сервера). Если модуль входит в тариф/сферу — «Входит в ваш тариф» / «Входит в вашу сферу» и кнопки «Добавить» нет. Для компаний на «Старте»/«Стандарте», не собирающих «Своё», карточки как раньше (ключ, «Подключить», «Купить на сайте»); добавляется ссылка «Собрать тариф «Своё»».

**Плашка корзины** внизу Маркетплейса: «Ваш набор поверх тарифа «Стандарт»: +3 модуля · Абонплата в месяц: N сом». Список: добавляемые («+ Упаковки — N сом»), убираемые («− Прокат»), входящие («Входит в ваш тариф — 0»). Число N — **ответ сервера** (`quote`), пересчёт через 350 мс после последнего изменения; пока ответа нет — «Считаем…».

**Подтверждение** (диалог): основа («Основа: Стандарт — B сом»); состав набора; «Абонплата в месяц: N сом» (основа + модули); «Разово: K сом» (если есть подключение); **«Новая абонплата действует с ДД.ММ.ГГГГ»** — дату даёт сервер (`next_billing_date`), касса её не вычисляет; пробный период («Первые 7 дней бесплатно, потом N сом» — если `trial_days > 0`). Подтверждает только владелец (админу сервер отдаёт 403).

**Результат.** Пока сервер обрабатывает заявку вручную — «Заявка №… принята, менеджер свяжется» (как сегодня); когда сервер включает сам после оплаты ELQR — модуль «Включено · Подключено по тарифу «Своё»», событие `features_changed` обновляет кассы и мобилку.

**Удаление модуля из набора:** работает до конца оплаченного периода (`until`), потом скрывается, данные остаются (3.6); абонплата уменьшается **со следующего периода** (в диалоге: «Со следующего периода — N сом вместо M»); повторное добавление до конца периода — без двойной оплаты; модули с открытыми документами — сначала закрыть документы (`BlockIfOpenDocs`).

**Пробный период модуля.** `trial_days`: на время пробы в итоге «0 сом до ДД.ММ», потом обычная цена; один раз на модуль и компанию; предупреждение за несколько дней до конца (число дней решает владелец); источник `trial` показывается в карточке. Продление после пробы — только после явного «Подтвердить» (вопрос 10.7 п. 4).

**Мобилка и сайт** — только чтение (состав и абонплата); оформление — в программе владельца или на сайте.

### 10.4 Старт, Стандарт, Мини, Своё: чьё базовое, что вычитается, как считает сервер

| | Старт | Стандарт | Мини | Своё |
|---|---|---|---|---|
| Что за набор модулей | задан планом (`includes`) + «из коробки» сферы | задан планом (в сути «всё», `includes:"all"`) + «из коробки» сферы | только мобильные модули (`Platforms.Mobile`), 1 сотрудник | **основа (Старт или Стандарт) + модули, добавленные клиентом** |
| Чьё базовое (что платится по умолчанию) | цена плана «Старт» | цена плана «Стандарт» (3500 по живой проверке 20.10) | ~500 сом (слова владельца, в коде нет) | цена **той основы, что выбрана**: «Старт» или «Стандарт» |
| Что вычитается | модули `included_in: start`, модули сферы | модули `included_in: standard`, модули сферы | модули `included_in: mini`, мобильные модули сферы | у основы — как у её плана; плюс модули сферы; уже подключённое не считается дважды |
| Как докупают | пакет вне плана: подключение 1500 + 400/мес (временно; цены с сервера) | почти нечего докупать (только то, что в «Стандарт» не входит) | не определено (вопрос ТЗ Мини) | **«Добавить в тариф»** — цена модуля в абонплате |
| Расчёт `quote` | `base = Старт`, `monthly = Σ пакетов вне «Старта»` | `base = Стандарт`, `monthly = Σ модулей вне «Стандарта»` (0 для всех пакетов, что в него входят) | пока нет | `base` = цена основы **компании**, `monthly` — Σ недостающих; `standard_cheaper` только при основе «Старт» |
| Лимиты (сотрудники, устройства) | по плану | по плану | по плану | как у основы; расширение лимитов — вопрос |
| Как касса узнаёт | `plan.code = start` | `standard` | `mini` | `custom` + `base_plan = start/standard` + `features` с `source:"tariff"` |

Принцип: **в фиксированных тарифах набор задан планом** (пакеты — надбавка); **в «Своём» тариф = основа + выбранный набор**. Один реестр и один `IsEnabled` для всех четырёх; различие — чья основа и как считается сумма.

Изменения в кассе при основе «Стандарт»: (1) окно «Своё» берёт имя основы из ответа сервера, а не жёстко «Старт»; (2) пакеты, входящие в основу, показываются «Входит в ваш тариф» (галочка отмечена и недоступна, цена не плюсуется); (3) сообщение «для вашего тарифа недоступно» остаётся только как ответ сервера для планов, где «Своё» действительно нельзя (например, «Мини» — решает владелец); (4) в Маркетплейсе кнопка «Добавить в тариф» работает на «Стандарте» так же, как на «Старте».

### 10.5 Как сфера влияет на «Своё»

1. **Профиль сферы = модули по умолчанию.** Они входят в базу «Своё» и **бесплатны**; остальное клиент добавляет, и оно отражается в абонплате. Следствие: два «Своё» с одним набором функций могут стоить по-разному (у Хозмага «Упаковки» бесплатны, у Продуктового — платные); карточка прямо пишет «Входит в вашу сферу — 0 сом» / «N сом в месяц».
2. **Цена модуля не зависит от сферы** (один прайс); сфера лишь делает «свои» модули бесплатными. Так проще объяснить и считать (вопрос 10.7 п. 6).
3. **Смена сферы не должна менять цену молча.** Касса просит у сервера расчёт «после смены» (`quote` с параметром `sphere`) и показывает: «Сейчас N сом в месяц → после смены M сом в месяц. Модули прежней сферы, по которым у вас есть данные: A, B — останутся включёнными и будут стоить +K сом». Владелец выбирает «Оставить (платно)» или «Убрать». Без подтверждения сфера не меняется. Модуль, бывший бесплатным по прежней сфере и ставший платным, **сам не выключается** (правило «по данным», 3.3 п. 5): работает до конца текущего периода, данные не теряются. Новая абонплата — со следующего периода (вопрос 10.7 п. 5).
4. **Первая настройка:** при выборе сферы в мастере — «В вашей сфере уже включено: …». «Для вашей сферы необычно, но доступно» — информация, не запрет (3.5).
5. Фиксированные тарифы сфера тоже меняет («из коробки»), но цена плана не меняется — предупреждение «что включено / что пропадёт», без суммы.

### 10.6 Что нужно от Умара (сервер)

1. **Каталог модулей с ценами**: `GET api/public/modules/` (или `modules` в `GET public/tariffs/`): `{code, name{ru,ky,en,tr,uz}, group, monthly_fee, activation_fee, trial_days, included_in[plans], default_for[spheres], platforms[], requires[], bundle_of[]}`; ETag, кэш 10 мин; **единственный источник цен** для кассы, мобилки и сайта; коды = `id` реестра (`kassa-<id>`); `packs` остаётся для совместимости.
2. **«Своё» поверх «Стандарта»:** убрать `409 plan_not_allowed` для компании на `standard`; в `plans` у `custom` — список допустимых основ (`bases: ["start","standard"]`), а не одно `base`; `quote` считает по **текущему плану компании**.
3. **Расчёт по набору**: `POST users/company/tariff/quote/` принимает `modules[]` (и `packs[]`) и необязательный `sphere`; ответ: `base_plan` (код основы), `base` (её цена), `monthly`, `once`, `modules[{code, monthly, once, included_in_base, in_sphere, already_active, trial_until}]`, `next_billing_date`, `standard_cheaper`/`standard_price` (только при основе «Старт»), `diff_from_current` (для смены сферы). Модуль с `included_in_base: true` — 0 и не в сумме.
4. **Счёт и включение**: `POST users/company/tariff/custom/` после оплаты сам ставит `plan.code=custom`, `base_plan`, включает модули (`features`, `source:"tariff"`), шлёт `features_changed`; `DELETE users/company/tariff/modules/{code}/` — убрать со следующего периода (ответ `effective_from`); пробный период (`trial_days`, один раз на модуль); журнал «кто и когда».
5. **События**: `features_changed` (Б-46) и `modules_version` в `capabilities`.
6. **Согласование с ELQR** (ТЗ 19.11): сумма счёта = **абонплата набора на момент выставления** (`base + Σ monthly`) − ручная скидка + 30 сом «Комиссия банка» отдельной строкой один раз на счёт; **продление — по цене тарифа без комиссии**. Корзина в кассе показывает «Абонплата в месяц: N сом» **без** 30 сом и подпись «+30 сом комиссии банка при оплате через ELQR». Что выставлять при смене набора в середине периода (довыставление за остаток или со следующего периода) — решает владелец (вопрос 10.7 п. 5), сервер реализует одним правилом.
7. **Права:** набор меняет только владелец; цену клиент не присылает — только коды модулей.
8. **Не выдавать `custom`**, пока в кассе нет пакета Ф1 (`custom = основа + features`) — иначе касса откроет всё; это касается и основы «Стандарт».

### 10.7 Вопросы владельцу (цены не выдумываю)

1. **Цены модулей «Своё»:** сколько стоит в месяц каждый платный модуль? Единый ориентир («Конструктор»: 200–500 сом/мес — упомянут в Б-39) или своя цена? Какие входят бесплатно? Остаётся ли разовая плата за подключение (сегодня 1500, временно) или только месячная?
2. **Скидки:** автоскидок за 3/6/12 месяцев нет (решение 19.11) — оставляем? Нужна ли скидка за большой набор или за комплект («Автозапчасти Про», «Опт Про»)?
3. **Минимальный набор и основа:** обязательна ли основа («Старт» или «Стандарт»)? Может ли «Своё» строиться поверх «Мини»? Может ли «Своё» стоить дешевле «Мини»?
4. **Пробный период:** нужен ли для модулей, сколько дней, один раз на модуль, продлевается ли сам или только после «Подтвердить»?
5. **Середина периода:** добавленный модуль включается сразу — с доплатой за остаток периода или бесплатно до конца периода? Удалённый работает до конца оплаченного периода, возврата денег нет (подтвердить)? Новая сфера и новая цена — со следующего периода?
6. **Сфера и цена:** подтвердить, что цена модуля одна для всех сфер, а сфера лишь делает «свои» модули бесплатными; при смене сферы платные модули прежней сферы с данными — оставлять платно или предлагать отключить?
