## 1. Склад «10 из 10»: К-4, К-5, К-8 в бою
Включение — для каждой компании отдельно, `PUT settings/stock/`:
- `costing_method: "fifo"` — партии + себестоимость по партиям (FIFO/FEFO);
- `batches: true` — партии и сроки без смены себестоимости;
- `expired_sale_policy: allow | warn | block` — продажа из просроченной партии;
- `reserved_sale_policy: warn | block` — продажа сверх свободного остатка.
Признаки в `capabilities`: `stock_batches`, `costing_fifo`, `expiry_batches`, `expired_sale_policy`, `reservations`.

**К-4 партии**
- `GET products/{id}/batches/` — партии товара: `qty_in`, `qty_left`, `unit_cost`, `expires_at`, `lot_no`, `supplier`. Этикеточные партии (tz26) — тот же адрес с `?kind=label`; у компаний без партий всё как раньше.
- Продажа списывает сначала партию с ближайшим сроком, потом самую старую. Себестоимость строки чека (`cost_price`) = цена этих партий. В `GET pos/sales/{id}/` у строки есть `allocations [{batch_id, qty, unit_cost, expires_at, lot_no}]`.
- Возврат по чеку возвращается в ту же партию. Удаление прихода снимает именно его партию.
- Остаток до включения раскладывается по последним приходам; что не уместилось — партия `opening` по прежней закупке.

**К-5 сроки:** в строке прихода можно передать `expires_at` (или `produced_at` + `shelf_life_days`) и `lot_no`. `stock/expiring/` считает по партиям.

**К-8 резервы**
- `POST reservations/ {product, qty, comment, expires_at?}` с Idempotency-Key. Свободного не хватает — 409 `insufficient_available`, разрешить сверх — `allow_over: true`.
- `GET reservations/`, `DELETE reservations/{id}/` — снять.
- У товара появились поля `reserved` и `available`.
- Касса при продаже сверх `available` получает предупреждение или отказ (по `reserved_sale_policy`). Чтобы продать сам резерв — передать `reservation_ids` в чеке.
