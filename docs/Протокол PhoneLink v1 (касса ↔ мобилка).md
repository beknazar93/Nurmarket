# Протокол PhoneLink v1 (касса ↔ мобилка)

Документ для исполнителя мобилки (NurMarketMobile, `lib/core/link/kassa_link.dart`). Описывает то, что касса (NurMarketKassa 1.17.62+) делает на самом деле. Источники: `NurMarketKassa.Infrastructure/Services/PhoneLink/PhoneLinkProtocol.cs`, `PhoneLinkServer.cs`, `PhoneLinkPairing.cs`, `NurMarketKassa.Avalonia/Services/PhoneLink/PhoneScanHandler.cs`. Дата: 27.10.2026 (ревью денежных правок, поток Р-4).

Статус полей, добавленных 27.10.2026: **необязательные** (мобилка 1.18.7 без них работает как раньше). Что мобилке нужно сделать, — в разделе «Что сделать на стороне мобилки».

## 1. Транспорт

- TCP, порт 47830 (если занят — 47831…47839). Касса слушает все интерфейсы, только пока приём включён (Настройки → Печать → «Телефон как сканер»).
- Одно соединение = один запрос. Телефон шлёт ОДНУ строку JSON в UTF-8, заканчивающуюся `\n` (допустимо закрыть отправку без `\n`). Касса отвечает ОДНОЙ строкой JSON с `\n` и закрывает соединение.
- Лимиты кассы: запрос ≤ 64 КБ; на чтение запроса 5 с; не больше 20 запросов в секунду с одного адреса; не больше 16 соединений одновременно и не больше 4 одновременных с одного адреса (сверх лимита — ответ `busy`).
- Таймаут телефона на соединение 2 с, на ответ 4 с (как сейчас в `kassa_link.dart`). Поиск товара на кассе для `scan` ограничен 2,5 с, поэтому в обычных условиях ответ приходит быстрее 4 с.

## 2. Запрос

```json
{"v":1,"op":"scan","phone":"<id телефона>","ts":1730000000,"nonce":"<base64url, 16 байт>","body":"{\"code\":\"4870000000001\",\"seq\":1730000007}","sig":"<base64url>"}
```

| Поле | Тип | Правило |
|---|---|---|
| `v` | число | Только `1`. |
| `op` | строка | 1–32 символа. Известны: `hello`, `scan`. Другая операция — `bad_request`. |
| `phone` | строка | id телефона: 8–64 символа, без управляющих символов и без `|`. Мобилка делает 22 символа base64url (16 случайных байт), создаёт один раз и хранит. |
| `ts` | целое | Секунды UTC (`millisecondsSinceEpoch ~/ 1000`). |
| `nonce` | строка | 16–64 символа base64url; мобилка шлёт 16 случайных байт (22 символа). На каждую попытку — НОВЫЙ nonce (повтор с тем же nonce — `replay`). |
| `body` | **строка** | JSON-объект, сериализованный в строку (JSON внутри строки). Именно строка, а не объект: подпись считается по её UTF-8 байтам как есть. Пустая строка = пустой объект. |
| `sig` | строка | base64url без `=`, подпись запроса (см. 3). |

## 3. Подпись запроса

```
sigString = "1|" + op + "|" + phone + "|" + ts + "|" + nonce + "|" + sha256hex(UTF8(body))
sig       = base64url( HMAC-SHA256( key, UTF8(sigString) ) )
```

- `key` — 32 байта (из QR при сопряжении), `ts` — десятичное целое, `sha256hex` — строчные hex.
- Проверка у кассы — за постоянное время. Порядок проверок кассы: разбор → подпись → время → повтор nonce → тело → сопряжение → операция.
- Время: `|now − ts| ≤ 10 минут`, иначе `bad_time`.
- Повтор: касса помнит пары (phone, nonce) 25 минут (ёмкость 5000; раньше было 15 минут / 1000). Повтор — `replay`. Запоминается только после верной подписи.

## 4. Сопряжение (hello)

- Касса: Настройки → «Подключить телефон» создаёт новый одноразовый ключ на 5 минут и показывает QR `nurmarket-link:v1?d=<id устройства>&h=<ipv4>&p=<порт>&k=<ключ base64url 32 байта>&n=<имя кассы>&c=<8 hex компании>`.
- Телефон шлёт `hello` с телом `{"name":"<имя телефона>"}`, подписанный ключом из QR. Касса привязывает ключ к `phone` (одноразово). Дальше ключ постоянный; на `hello` обычного сопряжённого телефона имя обновляется.
- Ответ `hello`: `{"ok":true,"code":"ok","kassa":"<имя>","company":"<8 hex>","shift_open":true|false}`.
- «Отключить телефон» на кассе стирает ключ: дальше `revoked` (ответ без подписи, см. 6) до нового сопряжения.

## 5. Операция scan

Тело: `{"code":"<штрихкод до 128 символов>","seq":<целое>[, "at":<секунды UTC>]}`.

- `seq` — целое, растёт всегда (мобилка: `max(prev+1, секунды часов)`). Пара (phone, seq) — идентификатор скана: повтор того же seq → `duplicate` (успех, `ok:true`), товар второй раз НЕ добавляется. С 27.10.2026 касса запоминает последние 200 seq каждого телефона **на диске**: повтор после перезапуска кассы тоже даёт `duplicate`.
- `at` (**необязательно, новое**) — время скана на телефоне в секундах UTC. Если оно старше 30 секунд к моменту обработки, касса отвечает `stale` и в чек ничего не кладёт (скан не должен попасть в чек следующего покупателя). Мобилка 1.18.7 `at` не шлёт — тогда проверки возраста нет; подробности в разделе «Что сделать на стороне мобилки».
- Скан не принимается (в чек не попадает), если окно кассы не активно или идёт оплата.

### Ответ scan

`{"ok":true,"code":"added","seq":1730000007,"name":"Товар 1"}` — `name` есть, если товар найден по названию. «added» означает «поставлено в очередь сканов чека кассы»; редкие отказы позже (вариант товара, весовой товар, остаток) касса показывает кассиру на своём экране.

## 6. Ответ и коды

Ответ — JSON-объект: `ok` (bool), `code` (строка), необязательно `msg` (русский текст для человека) и дополнительные поля операции. Неизвестные поля мобилка обязана игнорировать.

| `code` | `ok` | Что значит | Что делает телефон |
|---|---|---|---|
| `ok` | true | Ответ на `hello`. | Связь есть. |
| `added` | true | Скан принят в очередь чека. | Убрать из очереди, показать название. |
| `duplicate` | true | Этот (phone, seq) уже принят. | Как `added`. |
| `not_found` | false | Товара нет в каталоге кассы (в т. ч. «нет связи с сервером», если поиск не уложился в 2,5 с). | Убрать из очереди, показать «не найден». |
| `till_inactive` | false | Окно кассы не открыто/не активно/свернуто. | Убрать из очереди (состояние кассы, не ошибка связи). |
| `busy` | false | Касса занята: слишком много запросов/соединений, **идёт оплата** (с 27.10.2026), запрос уже обрабатывается или операция не уложилась в 15 с. | Повторить позже тем же seq (новый nonce). |
| `replay` | false | Такой nonce уже был. | Повторить с новым nonce. |
| `stale` | false | Скан старше 30 с (только если телефон прислал `at`). | Убрать из очереди, показать «устарел, отсканируйте ещё раз». |
| `bad_request` | false | Неверный формат, тело не JSON-объект, нет `code`/`seq`, операция не поддерживается. | Убрать, показать ошибку. |
| `bad_sig` | false | Подпись неверна (или чужой ключ). | Состояние связи: переподключить телефон. |
| `bad_time` | false | Часы телефона расходятся с кассой больше чем на 10 минут. | Показать «проверьте время на телефоне». |
| `unknown_phone` | false | Касса не знает этот телефон. | Переподключить. |
| `revoked` | false | Телефон отключён на кассе. | Переподключить. |
| `too_big` | false | Запрос больше 64 КБ. | Ошибка. |
| `disabled` | false | Резерв (касса сейчас не отдаёт: при выключенном приёме порт закрыт). | — |

Коды `stale` и поле `at` — новые; на запросы мобилки 1.18.7 касса их не использует.

## 7. Подпись ответа (новое, необязательное поле `sig` + `sv`)

С 27.10.2026 касса подписывает ответ тем же ключом телефона, если запрос прошёл проверку подписи. К ответу добавляются поля `"sv":1` (версия формулы подписи) и `"sig":"<base64url>"`.

```
replySigString = "1r|" + op + "|" + phone + "|" + nonce + "|" + (ok ? "1" : "0") + "|" + code + "|" + extraDigest
extraDigest    = sha256hex( UTF8( join("\n", [ key + "=" + value  для каждого поля ответа, кроме ok, code, msg, sig, sv, по возрастанию ключа (побайтово, ordinal) ]) ) )
sig            = base64url( HMAC-SHA256( key, UTF8(replySigString) ) )
```

- `op`, `phone`, `nonce` — из ЗАПРОСА, на который пришёл ответ (то есть ответ привязан к конкретной попытке; чужой ответ или запись старого ответа не подойдёт).
- `value`: строка — как есть; `true`/`false` — слова `true`/`false`; целое — десятичной записью без пробелов и плюса. Других типов (числа с точкой, объекты, массивы) в подписанных ответах нет. `\n` — один символ перевода строки (0x0A). Если дополнительных полей нет — `sha256hex("")` = `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`.
- `msg` в подпись НЕ входит (текст для человека).

Что подписывается / что нет:

- Подписаны ответы, где запрос уже прошёл проверку подписи: `ok`, `added`, `duplicate`, `not_found`, `till_inactive`, `busy` (от обработчика), `bad_time`, `replay`, `bad_request` (по телу), `stale`.
- НЕ подписаны ответы, где ключа ещё нет или он неверен: разбор строки (`bad_request`), `unknown_phone`, `revoked`, `bad_sig`, `too_big`, а также `busy` от ограничителя частоты/соединений (запрос ещё не читался). Подписи у них нет и быть не может: телефон должен считать такой ответ неподтверждённым — он годится только как подсказка «переподключить», но не как «успех».

Тестовые векторы (ключ — байты 0…31, `AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8`; phone `AAAAAAAAAAAAAAAAAAAAAA`; nonce запроса `AQIDBAUGBwgJCgsMDQ4PEA`; op `scan`):

| Ответ | `replySigString` (хвост — digest) | `sig` |
|---|---|---|
| `ok:true, code:added, seq:1730000000, name:"Товар 1"` | `…|1|added|5fcdb8e62dd2c568e12b78ece116bf24ab9333644f82bd802acaa2ab1efb6a5d` | `QqWfeYfZUTG3lkbblS5JFKDlM1eGGO32e6IxR6q6NNw` |
| `ok:true, code:ok, kassa:"Касса 1", company:"a1b2c3d4", shift_open:true` (op `scan` для примера) | `…|1|ok|0fd2a194039bf9d58c49e4da5173cbe6a25334481db5699416589165097270c2` | `i18YJKB0neTp1zveeMZ2kUtTQrXZWeuv2NYQ7s8Za9Y` |
| `ok:false, code:till_inactive, seq:1730000001` | `…|0|till_inactive|405be447d434222c8f41210df900bdb9a95f812962d180b9be55eac506fbd6af` | `oDhQZyLa0a5Mp6Mp5MEUkaZ79RGhdJty7BM9RPcLTA8` |
| `ok:false, code:bad_time` (без доп. полей) | `…|0|bad_time|e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` | `_bK5taXFXDEvzzU8xnLfon1Np-J12lcJY4lFy0x-_oY` |

Полная строка первого примера: `1r|scan|AAAAAAAAAAAAAAAAAAAAAA|AQIDBAUGBwgJCgsMDQ4PEA|1|added|5fcdb8e62dd2c568e12b78ece116bf24ab9333644f82bd802acaa2ab1efb6a5d`. Векторы сверены независимо: Python (`hmac`) и C# (стенд `phonelink-scan`) дали одинаковые подписи.

## 8. Что сделать на стороне мобилки (отдельная задача, мобильный исполнитель)

1. **Проверка подписи ответа (Ф-4).** Если в ответе есть `sig`: пересчитать по разделу 7 и сравнить за постоянное время; не совпало — считать ответ чужим (`KassaNetException`/«касса не подтверждена»), успех не засчитывать. Если `sig` нет — для `ok:true` (`ok/added/duplicate`) считать ответ неподтверждённым после того, как касса 1.17.63+ будет у всех (до этого момента — принимать без подписи, чтобы не ломать связь со старыми кассами; версию можно узнать по наличию `sv` в ответе на `hello`). Поиск кассы в сети (`_discover`/`_isOurs`): принимать касса-кандидата только с верной подписью ответа на `hello`.
2. **Время скана (С-1).** Класть в тело `scan` поле `"at":<секунды UTC>` (время нажатия/сканирования). Касса отказывает `stale`, если скан старше 30 с; мобилка уже убирает из очереди старше 3 минут — сократить TTL повтора до 30 с и обработать `stale` как «устарел, отсканируйте ещё раз» (не повторять).
3. **Код `busy` во время оплаты.** Теперь он приходит, когда у кассира идёт оплата: повторять тем же seq, но не дольше TTL (30 с).
4. **Таймаут ответа (С-2).** Поиск товара на кассе ограничен 2,5 с (дольше — `not_found` «нет связи с сервера»), так что в обычных условиях ответ приходит быстрее таймаута телефона 4 с; ложных «потерь связи» из-за долгого поиска (раньше до 15 с) быть не должно. Только если окно кассы «зависло» (UI-поток не отвечает), ответ может прийти позже 4 с — это штатный повтор тем же seq.
5. Состояние `disabled` в мобилке недостижимо (касса его не отдаёт) — можно убрать или оставить.
6. Не рассчитывать на `msg` (русский текст): показывать собственный перевод по `code`.

## 9. Что изменилось на кассе 27.10.2026 (для справки)

- Приём сканов с телефонов теперь переживает выход из кассы, смену кассира и смену компании: порт открывается заново у нового окна; при смене компании список телефонов и ключи прежней компании сбрасываются.
- Скан принимается в очередь чека только в момент, когда окно кассы активно и оплата не идёт (проверка повторяется непосредственно перед постановкой в очередь).
- Принятые `seq` сохраняются на диск.
- Окно запоминания `nonce` увеличено до 25 минут / 5000 записей (раньше 15 / 1000: при сдвиге часов +10 минут повтор был возможен 5 минут).
- Добавлены: подпись ответа (`sv`, `sig`), код `stale`, ограничение 4 соединений с одного адреса.
