## 0. Коротко

- Автозапчасти — это **не «товар с названием», а товар с номером**. Покупатель говорит не «колодки», а «колодки на Камри 2012» или приносит старую деталь с номером «04465-33471». Продавец ищет по номеру (с пробелами, тире, латиницей и кириллицей вперемешку), а если нет в наличии — ищет **аналог** и называет цену оригинала, аналога и Б/У.
- Постоянные клиенты — **СТО и мастера**: берут много, каждый день, по другой цене, часто в долг. Это «прораб» из хозмага с другим названием.
- Много **Б/У и «с разборки»**: каждая деталь уникальна (одна штука, своя цена, своя история — с какого авто).
- **Заказ под клиента:** «нужной детали нет — привезут завтра/через неделю, внесите предоплату».
- **В кассе уже есть (по коду):** артикул у товара и поиск по нему (но простой «содержит», без чистки номера); доп. штрихкоды с названием; бренд и страна; вес и габариты; `warranty_months` у товара и гарантия строкой в чеке (но только у «Электроники»); долг, предоплата, отложенные чеки; PIN старшего; возврат поставщику; импорт накладных по артикулу; профили сфер; модули «Ремонт», «Trade-in/скупка», «Смета».
- **Нет совсем:** нормализации номера, кросс-номеров и OEM, панели «Аналоги», «подходит к авто», «ячейка/полка», «Оригинал/Аналог/Б/У», заказа под клиента как отдельной вещи, донора для «с разборки», прайсов поставщиков.
- **Ловушка в коде [код]:** `CatalogPanelViewModel.cs:1321` — `IsGrocerySphere = !IsClothing && !IsServices`. У новой сферы база `grocery`, значит поиск по доп. штрихкодам (`:1335`, строка включена только «не в продуктах») **для автозапчастей будет выключен**. Заменять надо признаком профиля, а не проверкой базы.
- **Главный вывод:** 80 % пользы — поиск по номерам, аналоги, состояние, ячейка, цена СТО и заказ под клиента — делается в кассе без сервера. Серверу нужны несколько полей (раздел 7), чтобы данные были общими на всех кассах и на сайте.

## 1. Бизнес-логика магазина автозапчастей

### 1.1. Типовые сценарии у прилавка

| Сценарий | Что делает продавец | Что нужно от программы |
|---|---|---|
| «Фильтр масляный на Камри 2012» | Вводит «камри 2012 фильтр» или берёт номер из каталога | Поиск по словам и по «Подходит к авто» |
| Клиент принёс старую деталь | Читает номер: «0 986 452 041», «W 712/75», «04465-0K090» | Поиск по номеру в любом написании |
| Оригинала нет | Предлагает аналоги: «Bosch, Mahle, китайский — разные цены» | Панель «Аналоги» с наличием, ценой, производителем |
| Мастер СТО берёт 6 позиций | Продаёт по цене СТО, часть в долг | Цена «СТО / мастер», долг, PIN на скидку |
| «Нужна Б/У фара, есть?» | Смотрит Б/У-карточки, показывает фото | Метка «Б/У», фото, донор |
| «Привезите к пятнице» | Оформляет заказ, берёт предоплату | Заказ под клиента: срок, предоплата, поставщик, уведомление |
| Деталь не подошла | Возврат или обмен | Срок возврата, «не подлежит» для установленных и электрики, причина |
| Брак от поставщика | Возвращает партию | Возврат поставщику с причиной (в кассе уже есть) |

### 1.2. Данные товара: что нужно хранить

| Что | Зачем | Где сейчас [код] |
|---|---|---|
| **Каталожный номер** (основной) | Главный ключ поиска | `article` — есть, поиск «содержит» без нормализации |
| **OEM-номера** (оригинальные номера автопроизводителя) | Клиент называет номер оригинала | Нет |
| **Кросс-номера / аналоги** (номера других производителей, взаимозаменяемые) | Найти аналог | Нет. Ближе всего — `alternate_barcodes[{barcode,name,quantity}]` |
| **Производитель** (Bosch, Toyota, Mahle) | Выбор, отчёты | `brand_name` — есть |
| **Страна** | Для выбора и таможни | `country` — есть |
| **Состояние:** оригинал / оригинальный поставщик (OES) / аналог / Б/У / восстановленный | Значок, цена, гарантия, возврат | Нет |
| **Подходит к авто:** марка, модель, поколение/годы, двигатель | Подбор по авто | Нет |
| **Ячейка / полка** | Найти деталь на складе | Нет |
| **Гарантия** | Печать в чеке, возврат по гарантии | `warranty_months` — есть на сервере, но в днях не бывает (на запчасти — 7/14/30 дн.) |
| **Вес, габариты** | Доставка, транспортная | `characteristics` (высота, ширина, глубина, вес) — есть |
| **Единица** | шт / комплект / пара / литр | Единицы профиля (`UnitDef`), дробные — по флагу `hardware_2026_11` |
| **Ёмкость и вязкость масла** (4 л, 5W-40) | Название и поиск | Название/описание (отдельного поля не нужно: пишем в название «5W-40 4 л») |
| **Срок годности** (автохимия, антифриз, тормозная жидкость) | Списание | Сервер К-5 `expires_at` (в «Единое ТЗ», П1-6) |
| **Фото** | Б/У и сложные детали | Фото товара есть |
| **Донор** (для «с разборки»: марка, модель, год, VIN, пробег) | Происхождение детали, доверие | Нет |
| **Сертификат / паспорт** | Редко, для оптовиков | `attachments` — сервер 404 [С Умар] |

### 1.3. Цены

- **Розница** — обычная цена товара.
- **СТО / мастер** — оптовая цена для отмеченных клиентов. Механика уже есть для хозмага: `SphereProfile.ForemanPriceAvailable`, блок `APP\Views.axaml\Main\ClientForemanBlock.cs` (сейчас видимость завязана на `MarketSpheres.IsHardware`, текст «Покупает по оптовой цене (прораб)»), серверные уровни `price_level` (`INF\Spheres\PriceLevels.cs`). Для автозапчастей — **та же механика, другая подпись** «СТО / мастер» и видимость по признаку профиля.
- **Опт** — у товара есть `wholesale_price` (поле есть).
- **Предел скидки и PIN старшего** — готово (`INF\AntiFraudSettings.cs`, `INF\MaxDiscountGate.cs`); в мастере только **предлагать** включить (как у электроники).
- **Цена Б/У** — отдельная карточка со своей ценой (каждая деталь — своя), закупка = цена скупки.
- **Комиссия / маржа:** маржа по состоянию (оригинал / аналог / Б/У) — отчёт владельца (раздел 4). «Комиссионная» продажа (чужая деталь под реализацию, магазин берёт долю) — в «потом».

### 1.4. Заказ под клиента

Деталь не в наличии, поставщик привезёт. Нужно: клиент и телефон, что заказано (товар или свободная строка с номером), **срок** (дата), **предоплата** (сумма и способ), **у какого поставщика**, статус (Принят → Заказан → Приехал → Выдан → Отменён), «позвонить клиенту, когда приехало», печатная квитанция заказа. Если клиент отказался — **возврат предоплаты** (деньги, `/code-review`).

### 1.5. Возврат, брак, обмен

- Срок возврата/обмена — настройка (умолчание 14 дней, как у электроники, `ExchangeDays`); **установленные детали, электрика, датчики, блоки — обычно не принимаются** (список «не подлежит возврату» редактирует владелец; в коде есть образец `APP\Services\NonExchangeableRules.cs`, где сейчас список только у одежды). Вопрос по закону КР — юристу (раздел 6).
- Причины возврата: «Не подошло по номеру», «Пересорт», «Брак», «Гарантия» (причина «Гарантия» уже есть у электроники).
- Брак → **возврат поставщику** (окно есть: `SupplierReturnEditDialog`). Связь «клиентский возврат → возврат поставщику» — версия 2.

## 2. Что делается локально, а что требует сервера

«Локально» здесь значит: касса и программа владельца сами, без новых полей сервера, на уже существующих полях или файле на ПК (как «Смета» и серийный журнал). **Предупреждение:** всё, что хранится файлом на ПК, видно только на этой кассе — для магазина из двух касс это неудобно, поэтому там, где можно, используем существующие поля сервера (столбец «Носитель сейчас»).

## 3. Функции по версиям

### MVP (первый выпуск, 8 пунктов; всё в кассе, малый риск для денег)

1. **Сфера `autoparts`:** профиль (иконка, 5 языков, единицы, категории, услуги), плитка в окне первого запуска и в Настройках, короткий мастер (раздел 6).
2. **Умный поиск по номеру:** нормализация (убрать пробелы, тире, точки, слэши, регистр; кириллица↔латиница у похожих букв: А/A, В/B, Е/E, К/K, М/M, Н/H, О/O/0, Р/P, С/C, Т/T, Х/X). Работает в кассе, на складе, в приёмке. Порядок: точный номер → кросс/OEM → начало номера → название. Подпись поля: «Каталожный номер».
3. **Кросс-номера, OEM и «Подходит к авто»:** три поля в карточке товара (с подсказками марок и моделей); кнопка **«Аналоги (N)»** у плитки и в поиске: список карточек с тем же номером или кроссом — производитель, состояние, цена, остаток, ячейка.
4. **Состояние детали:** Оригинал / Оригинальный поставщик / Аналог / Б/У / Восстановленный; значок на плитке и строкой в чеке; производитель и страна выводятся рядом.
5. **Ячейка / полка:** поле у товара, показывается кассиру в плитке («Ячейка А-3-2»), колонка и сортировка на складе, в ценнике.
6. **Гарантия и возврат запчастей:** срок гарантии на карточке в днях, строка «Гарантия до ДД.ММ.ГГГГ» и «Б/У» в чеке (используем готовый блок гарантийного талона электроники); срок возврата профиля и список «не подлежит возврату».
7. **Цена «СТО / мастер»:** отметка клиента (или серверный `price_level`), подпись по сфере; долг и PIN — как есть.
8. **Заказ под клиента:** отложенный чек типа «Заказ» с клиентом, сроком, поставщиком, предоплатой, квитанцией и кнопкой «Написать в WhatsApp, что приехало».

## 4. Экраны

Общие правила: шкала размеров Д-8 (`App.axaml`: `NurFontBody` 14…, кнопки `nur-primary` / `nur-secondary`, высоты 36 / 44 / 52, поля `modal-field`), без вертикальных полос (AllowAutoHide), одно окно — один экземпляр (`WindowSingleton`), текст не обрезается на ru / ky / en / tr / uz при 1024×600 и на сенсоре. Все тексты — `Tr.T(ru, ky, en, tr, uz)`. Макет — словами.

### 4.1. Карточка товара (`APP\Views.axaml\Dialogs\ProductEditDialog.axaml.cs`, `.Save.cs`)

Только при профиле `autoparts` — блок «Запчасть» сворачиваемый, сверху, перед ценами:
