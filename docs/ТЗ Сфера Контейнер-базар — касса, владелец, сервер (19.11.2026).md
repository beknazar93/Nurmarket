# ТЗ: Сфера «Контейнер / базар» — две сферы: «Контейнер — розница» (`bazaar_retail`) и «Контейнер — опт» (`bazaar_wholesale`) — касса, программа владельца, сервер (19.11.2026, ред. 2)

**Запрос владельца (19.11.2026):** «обдумай сферу: магазин-контейнер, типа базар».
**РЕШЕНИЕ ВЛАДЕЛЬЦА (19.11.2026):** «Сфера контейнер есть оптом и розница — раздели их». Вместо одной сферы `bazaar` — **две сферы на общей основе**. Редакция 2 переписывает ТЗ под это решение. Одна сфера `bazaar` в коде не появлялась (этап 1 — только документ), переносить нечего.
**Этап 1 — только документ.** Код — после «можно кодить». Всё, что помечено «гипотеза — спросить владельца», — мои предположения о рынках, а не проверенные факты.
**Основа (по коду, 19.11):** профили сфер `INF\Spheres\*Profile.cs` (`SphereCatalog.cs`, признаки СФ4), `ElectronicsProfile` / `StationeryProfile` (образец оформления), `PriceLevels.cs` и `ProductSaleUnits.cs` (хозмаг), срок долга `CheckoutViewModel.DebtDue.cs`, консультант `ConsultantDirectory.cs`, группы F1–F12 (`hotkey_group` у товара), офлайн-очередь `OfflineOperationsWindow`, окно возвратов, `TransferDocument*` (перемещение), ТЗ «Сервер — единое (13.11)», ТЗ «Сфера Электроника» и «Канцтовары» (12.11).
**Пути:** `INF` = `NurMarketKassa.Infrastructure\Services`, `APP` = `NurMarketKassa.Avalonia`, `VM` = `NurMarketKassa.ViewModels`.
**Параллельно:** ТЗ «Сфера Автозапчасти». Общее вынесено в раздел 5 («Общие функции»), чтобы не делать дважды.
**Обозначения пакетов:** `БЗ-ОФ*` — общие для обоих профилей (и частично для «Автозапчастей»), `БЗ-Р*` — только розница, `БЗ-О*` — только опт. Префикс «БЗ-» оставлен, чтобы не путать с планом владельца «О1–О8» (`docs/owner-redesign-plan.md`).

## 0. Коротко

- **Розница** — человек у прилавка, пара / вещь, торг и круглая цена, наличные и QR, скорость. **Опт** — клиент с карточкой (регион, цены, долг), ряды / мешки / тюки, заказ и предоплата, накладная, отгрузка, долги со сроком, закупка партиями в валюте.
- Они на **общей основе**: профиль на базе `grocery`, быстрые плитки, товар без штрихкода по фото, упаковки `sale_units`, `volume_prices`, долги со сроком, WhatsApp-выписка, мини-курсы валют, офлайн, права / PIN.
- **Чего в кассе нет совсем:** валюты и быстрый курс; округление торга «до 10 / 50 / 100»; цена по количеству без клиента; регион в отчёте долгов; накладная с нумерацией и печатью A4; отгрузка / карго; договорные цены клиента; лимит долга на экране; акт сверки; закупка в юанях / долларах с пересчётом в сомы.
- **Что уже есть и берём как есть:** срок долга и рассрочка, долг с WhatsApp-напоминанием (`DebtWhatsAppButton`), отложенные чеки, скидка вручную с PIN и пределом, быстрый ввод «3*код», группы F1–F12, `sale_units` (хозмаг), `price_level` клиента, `volume_prices` (сервер, qf1311), `credit_limit` и 409 `credit_limit_exceeded`, офлайн-очередь, этикетки (`BarcodePrintWindow`), комплекты, консультант с процентом, возвраты, мобилка-сканер.
- **База обеих сфер — `grocery`** (как у электроники и канцтоваров): размеры одежды завязаны на `IsClothing` (около 25 мест) — не трогаем. «Ряд размеров» — через упаковку / комплект (раздел 3.9).
- **Рекомендованная форма (вариант A, раздел 8, вопрос 2):** две плитки в мастере, но внутри — **один набор флажков**, профиль только расставляет их по умолчанию. Тогда контейнер, который торгует и так, и так, не заперт в сфере.
- Принципы MVP: **розница — не больше 2 нажатий на продажу**; **опт — не больше 1 экрана на накладную**; всё работает на планшете и телефоне, без интернета.

### 1.3 Как профили включаются
- **Мастер первого запуска** (`MarketSphereChoiceWindow`): две плитки «Контейнер — розница» и «Контейнер — опт» (названия — вопрос 1). Под плитками одна строка: «Торгуете и так, и так? Выберите розницу, оптовые функции включите в Настройках». Плитки появляются после готовности MVP и признака сервера `market_profile`.
- **Настройки → Операции → Сфера** (`OperationsSettingsView.Sphere`): смена профиля и флажков.
- **Маркетплейс:** карточка «Контейнер — опт» / «Контейнер — розница» как пакет настроек (флажки + категории + курсы). Ничего не создаётся молча: «Применить профиль» показывает список, что будет добавлено.
- **Точное значение** хранится в `MarketSphereDetail` (`bazaar_retail` / `bazaar_wholesale`), на сервер как база уходит `grocery`, плюс `market_profile`.

### 1.4 Можно ли переключать, что при смене
- **Между двумя контейнерными профилями — можно самому** (владелец / старший с PIN): «Настройки → Операции → Сфера → сменить профиль». Они на одной основе, поэтому смена безопасна. Раньше выбор сферы «закреплялся» (`MarketSphereLock`, смена только через поддержку) — для пары `bazaar_retail` ↔ `bazaar_wholesale` делаем исключение; на другие сферы (электроника и т. д.) — по-прежнему через поддержку.
- **Что меняется:** только значения флажков по умолчанию, видимость экранов и подсказки категорий. Перед сменой — окно «Что изменится» (список флажков «включится / выключится»), кнопки «Сменить» / «Отмена».
- **Что НЕ меняется и не теряется никогда:** товары, цены, ступени `volume_prices`, `sale_units`, группы F1–F8, клиенты (регион, `price_level`, договорные цены, лимит), долги и сроки, курсы валют, заказы, накладные, открытые смены, офлайн-очередь. Выключенный флажок только **прячет** экран; данные остаются и возвращаются при включении.
- **Флажки владельца сохраняются:** если вручную включили «Накладная» в рознице, при смене на опт этот флажок остаётся «включён вручную» (отмечаем в `SphereSettingsJson` как `user_set`); профиль перезаписывает только флажки, которые владелец не трогал.
- **Откат:** перед сменой копия раздела `bazaar` сохраняется как `bazaar.prev`; кнопка «Вернуть прежний профиль» доступна 30 дней.
- **Сервер:** смена профиля — одна запись `market_profile`, база `grocery` не меняется, схему и сервер не ломает.

## 2. Контейнер — РОЗНИЦА (`bazaar_retail`)

### 2.1 Бизнес-логика
**Кто.** Хозяин + 1–2 продавца у прилавка. Покупатель стоит в проходе, продавец одной рукой держит товар, другой считает деньги. Касса — планшет или телефон, иногда старый ПК. Интернет на рынке часто плохой (гипотеза — спросить владельца).

**Как продают (гипотеза).**
1. **Поштучно:** одна пара, одна вещь. Цена «для своих» и «для чужих», **торг**; финал — круглая сумма (до 10 / 50 / 100 сом).
2. **Скорость:** покупатель не ждёт; цель — 2 нажатия: плитка → «Оплатить».
3. **Розница и «мелкий опт от N»:** одна пара — 1 200; от 3 пар — 1 100; от 10 — 1 000. Это не оптовик с карточкой, а ступень цены по количеству (`volume_prices`).
4. **Оплата:** наличные, QR (МБанк / Optima и другие), смешанная; иногда доллары или рубли — сдача в сомах.
5. **Возврат и обмен:** «не подошёл размер» — обмен на другой, разница доплачивается.
6. **Ценник на полке:** цена на бумажке / ярлыке; обновляется при смене цены.

**Боль.**
- Касса «для супермаркета» медленна: искать товар, считать, давать сдачу.
- Торг и курс считают в голове → ошибки и недостача.
- Нет штрихкодов — путаница товара.
- Нет дневной прибыли: аренда и расходы идут из кассы без учёта.

### 2.2 Принципы экрана
- **Минимум ввода:** количество по умолчанию 1; повторное касание плитки = +1; «3*код» работает (есть).
- **Одной рукой:** крупные кнопки ≥ 52 px, главные действия в нижней трети экрана (на телефоне и планшете), горизонтальная прокрутка плиток запрещена — только вертикальная.
- **Без клавиатуры:** цена и количество — крупные цифровые кнопки; экранная клавиатура только `osk.exe`.

### 2.3 Торг и округление (главное отличие розницы)
- В окне оплаты: кнопки «До 10», «До 50», «До 100» и поле «Договорились за …».
- Касса считает **скидку суммой на чек** (механизм скидки и PIN уже есть); **не** строка «Округление» (она только для весовых). Строки чека не меняются; скидка — отдельной строкой.
- **Предел:** по умолчанию скидка выше **5 %** — нужен PIN старшего; выше **10 %** — запрещена без права «Скидка выше предела». Предел правит владелец (вопрос 9).
- Округление идёт **вниз** (в пользу покупателя) — округлить вверх кнопкой нельзя.
- Отчёт «Скидки по продавцам» (в программе владельца) — против кражи «договорились за 1 000, а в кассу 900».

### 2.4 Розница против «мелкого опта от N»
- Строка чека показывает подпись «Опт от 10 — 450»; при наборе количества цена пересчитывается по порогам `volume_prices`.
- **Ручная цена кассира главнее** (с PIN, если включён).
- Клиента не требует: «мелкий опт» — только по количеству. Если нужен клиент с договорными ценами — это уже опт (3.2).

### 2.5 Быстрые кнопки категорий и ценник на полке
- Сверху — ряд категорий (F1–F8), под ним сетка плиток с фото и ценой; продажа — 1–2 касания.
- **Ценник на полке:** кнопка в карточке товара и массовая «Распечатать ценники» (по категории или по изменившимся ценам) — этикетка с названием и ценой, крупно (`BarcodePrintWindow`, формат этикетки уже настраивается). Без штрихкода — печатается свой код по полке.

### 2.6 Оплата
Вкладки: **наличные / QR / смешанная** (+ «В долг» — только если включён флажок). Наличные: кнопка «Курс» и выбор валюты (сом / $ / ₽ / ¥); «Принял $20 по 87,5 = 1 750 сом, сдача 50» — в чек уходит сом-эквивалент, валюта и курс — в заметку платежа (гипотеза Б-БЗ2).

### 2.7 Возвраты и обмен
- Одно окно «Обмен»: найти чек (по сумме / дате / телефону) → отметить вернувшийся товар и причину → выбрать новый товар → «Доплатить / вернуть разницу». Сумма не меньше нуля без PIN.
- Использует существующее окно возвратов («куда товар», причины); новое — только связка «возврат + продажа» в одном чеке.

### 2.8 MVP розницы (7 функций)
1. **Профиль `bazaar_retail`** + плитки категорий и фото-сетка (БЗ-Р1, поверх БЗ-ОФ1/2).
2. **Торг «до 10 / 50 / 100»** + «Договорились за …», предел и PIN (БЗ-Р2).
3. **Цена розница / мелкий опт от N** с подписью в строке (БЗ-ОФ3).
4. **Ценник на полке** (печать по категории и по изменившимся ценам) (БЗ-Р3).
5. **Оплата: наличные / QR / смешанная** + приём валюты со сдачей в сомах (БЗ-Р4, поверх БЗ-ОФ5).
6. **Режим «одной рукой»** для планшета и телефона: нижняя панель, крупные кнопки, 2 нажатия (БЗ-Р5).
7. **Возврат / обмен** одним окном (БЗ-Р6).

### 2.9 Экраны розницы
- **Касса:** ряд категорий + сетка плиток; строка чека — количество +/- крупно, единица, подпись «Опт от 10 — 450», кнопка «Цена»; итог — крупная «Оплатить», рядом «До 10 / До 50 / До 100».
- **Окно оплаты:** вкладки способов, «Принял» в валюте → «К оплате в сомах» / «Сдача в сомах», курс виден всем, правит старший.
- **Карточка товара:** группа F, фото, ступени цены «от 3, от 10», единицы «ряд / мешок / пара», кнопка «Печать ценника».
- **Окно «Обмен»:** две колонки «Вернули» / «Взяли», внизу «Разница».
- **Чек:** «Кроссовки, пара — 1 200»; скидка торга строкой; «Принято $20 (курс 87,5)»; WhatsApp и ссылка на электронный чек.
- **Настройки:** «Округление торга» (шаги 10 / 50 / 100, по умолч. 10), предел скидки, «Курсы валют», «Опт: пороги по умолчанию (3 / 10)».
- **Отчёты:** «Продажи за день по категориям и продавцам»; «Наличные: ожидалось / принято / изъято»; «Скидки по продавцам».

## 3. Контейнер — ОПТ (`bazaar_wholesale`)

### 3.1 Бизнес-логика
**Кто.** Хозяин-оптовик + менеджер / кладовщик. Склад — контейнер, павильон, склад рядом. **Клиенты — оптовики и перекупщики из регионов** (Ош, Жалал-Абад, Нарын, Каракол, Баткен, Талас, Казахстан, Россия). Покупка большая, цена обсуждается, часть — **в долг до следующего приезда**, товар — **отправка карго**.

**Как торгуют (гипотеза — спросить владельца).**
1. **Продают рядами, мешками, тюками, коробками;** сумма называется целиком («забирай тюк за 18 000»).
2. **Цены по уровням:** «розница / мелкий опт / крупный опт / свои» + **договорные цены** для постоянных клиентов по конкретным товарам.
3. **Минимальная партия:** меньше ряда / коробки не отдают (или с наценкой).
4. **Заказ и предоплата:** клиент из региона заказывает по телефону, вносит предоплату, товар резервируется до приезда / отправки.
5. **Накладная:** на каждую отгрузку расходная накладная (печать A4, номер, подпись), копия клиенту в WhatsApp.
6. **Отгрузка и карго:** мест, перевозчик (маршрутка, фура, «Грузовик-экспресс»), город / адрес получателя, трек-номер.
7. **Долги со сроком:** «вернёт до 15 числа», лимит долга по клиенту, акт сверки раз в месяц.
8. **Закупка партиями:** Китай / Турция / Узбекистан, в юанях / долларах + логистика + растаможка → себестоимость в сомах и маржа по партии.

**Боль.**
- Долги в тетради: нет «кто из Оша должен и до какого числа».
- Клиентские цены держатся в голове у хозяина.
- Накладные пишут от руки; номера повторяются; нет акта сверки.
- Предоплата без резерва: товар продали другому.
- Партии: себестоимость в сомах считается «потом» → прибыль неизвестна.

### 3.2 Цены: уровни, количество, договорные
**Порядок выбора цены в строке (предложение — сверить с Умаром, как считает `price-levels/quote/`):**
1. Ручная цена кассира / менеджера (с PIN, если включён);
2. **Договорная цена клиента** по этому товару (если есть);
3. **Уровень цен клиента** (`price_level`: розница / мелкий опт / крупный опт / свой);
4. **Цена по количеству** (`volume_prices`, `min_qty`);
5. Розничная цена.
Под строкой подпись источника: «Договорная», «Уровень: крупный опт», «Опт от 10». Если выбран пункт 2 или 3, а `volume_prices` даёт цену ниже, берём **ниже** (в пользу клиента) — правило уточнить у владельца (вопрос в 8).
**Минимальная партия:** у товара / категории `min_qty` продажи; продажа меньше — предупреждение, продолжить с PIN.

### 3.3 Продажа рядами / мешками / тюками / коробками
- Единица продажи `sale_unit` с `factor`: «Ряд (6 пар)», «Мешок (50 шт)», «Тюк (100 шт)», «Коробка (24 шт)». Остаток списывается `qty × factor`, показывается «2 ряда = 12 пар».
- Цена упаковки может быть задана отдельно (`price`) или считаться от штуки.
- Ряд размеров — раздел 3.9.

### 3.4 Заказ с предоплатой и резервом
- Окно «Заказ с предоплатой»: клиент, строки (товар / ряд / мешок), срок «забрать до», предоплата (сумма и способ, деньги идут в смену), комментарий.
- **Резерв:** остаток уменьшается на «в резерве», товар остаётся физически на полке; срок резерва по умолчанию 3 дня (гипотеза), по истечении — напоминание, снять резерв вручную.
- Статусы: `новый → резерв → собран → отгружен | отменён`; отмена возвращает предоплату (по решению старшего).
- Заказ превращается в накладную одной кнопкой «Отгрузить» (предоплата засчитывается).
- Общий «заказ покупателя» с Автозапчастями (раздел 5; Б-60 / `customer-orders/`).

### 3.5 Карточка клиента-оптовика (экран)
- Шапка: имя / название, телефон (WhatsApp одним касанием), **регион**, группа.
- Блок «Цены»: `price_level`, список договорных цен (товар → цена), кнопка «Добавить договорную цену» (владелец / старший).
- Блок «Долг»: текущий долг, **лимит**, остаток лимита, ближайший срок «вернёт до», просрочка красным.
- Блок «История»: накладные, заказы, оплаты, акт сверки за период.
- Кнопки: «Новый заказ», «Накладная», «Принять оплату», «Написать в WhatsApp».

### 3.6 Накладная / отгрузка (экран)
- Окно «Накладная / Отгрузка»: клиент (подставляется из заказа), строки с единицей и ценой с подписью источника, итог, скидка, **оплачено / в долг (с датой «вернёт до»)**.
- Блок «Отгрузка»: мест, перевозчик, город / адрес получателя, трек-номер, статус «собрано / отправлено / получено».
- Печать **A4**: заголовок, реквизиты продавца и клиента, номер и дата, таблица строк (единица, количество, цена, сумма), итог прописью (гипотеза), подпись, мест и перевозчик. Шаблон — на основе `TransferDocument*`.
- **Нумерация:** сквозная по компании (сервер выдаёт номер). Офлайн — временный номер с префиксом точки, при отправке заменяется серверным; два одинаковых номера недопустимы (Б-БЗ13).
- Электронная накладная: PDF / ссылка → «Отправить в WhatsApp».

### 3.7 Долги, лимит и акт сверки
- **Лимит долга** у клиента (`credit_limit`, есть на сервере). В окне накладной / оплаты: «Долг 80 000 / лимит 100 000, остаток 20 000». При превышении — сервер отвечает 409 `credit_limit_exceeded`; касса показывает понятное сообщение и (только старший) просьбу о подтверждении, если сервер даст такой путь (вопрос Умару Б-БЗ11).
- **Срок «вернёт до»** у долга; телефон и регион обязательны.
- **Акт сверки:** по клиенту за период — вход. остаток, отгрузки (накладные), оплаты, исход. остаток; печать A4 и PDF в WhatsApp; кнопка «Клиент подтвердил».
- **Взаиморасчёты:** возврат товара клиентом уменьшает долг; предоплата засчитывается; сторно корректировок — только старший.

### 3.8 Закупка партиями в валюте
- Документ «Партия»: поставщик, валюта (CNY / USD), курс на дату, строки (товар, количество, цена в валюте), **расходы:** логистика, растаможка, прочее (в сомах или валюте).
- **Себестоимость строки в сомах** = `цена × курс` + доля расходов. Распределение расходов: по стоимости (по умолчанию) / по количеству (опция).
- Изменение курса пересчитывает себестоимость партии (с логом: кто, когда).
- **Маржа по партии:** «Партия № 12: закуплено на 840 000 сом, продано на 62 %, прибыль 215 000». Отчёт «Себестоимость партии в сомах».
- MVP-lite (до сервера): ручное поле «Себестоимость в сомах» на приходе + «Доп. расходы» с распределением на кассе; полная версия — Б-БЗ4.

### 3.9 Ряд размеров (гипотеза — спросить владельца)
- **Пока:** карточка «Кроссовки Nike — ряд 36–41», единица «Ряд» с `factor = 6`, цена ряда; остаток рядами. Поштучная продажа — вторая единица «Пара» в той же карточке.
- **Проблема:** сервер спишет шесть единиц базовой единицы, а не по размерам. Для точного учёта нужен `bundle` / комплект из вариантов (v2, Б-БЗ5).

### 3.10 Отчёты опта
- **Долги по регионам и срокам:** регион, сумма, просрочка (в красном), строка клиента → позвонить / написать.
- **Топ клиентов:** по обороту, по прибыли, по долгу; за период.
- **Продажи по рядам / мешкам:** сколько ряд / мешков продано по товару и категории.
- «Отгрузки за день» (кому, сколько мест, перевозчик, статус).
- «Маржа по партиям» (v2).

### 3.11 MVP опта (8 функций)
1. **Профиль `bazaar_wholesale`** + карточка клиента-оптовика: регион, `price_level`, лимит, договорные цены (БЗ-О1).
2. **Цены:** уровни по количеству и по клиенту + договорная цена + минимальная партия, подпись источника цены (БЗ-О2, поверх БЗ-ОФ3).
3. **Заказ с предоплатой и резервом** (БЗ-О3, общий с «Автозапчастями»).
4. **Расходная накладная A4** с нумерацией и WhatsApp (БЗ-О4).
5. **Отгрузка / карго:** мест, перевозчик, адрес / регион, трек, статус (БЗ-О5).
6. **Долг «вернёт до» + лимит по клиенту + акт сверки** (БЗ-О6, поверх БЗ-ОФ6).
7. **Отчёты:** долги по регионам и срокам, топ клиентов, продажи по рядам (БЗ-О7).
8. **Закупка партиями в валюте + логистика + растаможка → себестоимость в сомах, маржа по партии** — MVP-lite, полная версия после Б-БЗ4 (БЗ-О8).

### 3.12 Версия 2 и потом
- **P1:** ревизия по контейнеру; доли продавцов (`consultant`); импорт накладной поставщика (Excel / фото); `bundle` для ряда размеров; единые курсы компании на сервере; статусы отгрузки «получено» с подтверждением клиента.
- **P2:** цена товара в валюте (прайс в $); налоговый режим и фискальный чек (если потребуется); витрина Маркетплейс «Мой контейнер» (фото-каталог, WhatsApp-заказ); печать этикеток карго; интеграция с перевозчиками (трек онлайн).

## 5. Общие функции (делаем один раз — для обоих профилей и для «Автозапчастей»)

ТЗ «Автозапчасти» делается параллельно. Чтобы **не делать дважды**, общее — отдельный пакет «ОФ». В сферах — только профиль и экраны.

| Общая функция | Розница | Опт | Автозапчасти | Что делаем один раз |
|---|---|---|---|---|
| **Оптовые цены: уровни по количеству и клиенту, договорные цены** | мелкий опт от N | уровни + договорные | СТО / оптовик, розница | один механизм: `price-levels` + `volume_prices` + договорная цена + подпись «Опт от N» (БЗ-ОФ3) |
| **Заказ под клиента / с предоплатой и резервом** | — | заказ с предоплатой | «под заказ из-за границы» | один «заказ покупателя» (ХМ16, `customer-orders/`, Б-БЗ12) |
| **Долги со сроком, лимит, регион / контакт, акт сверки** | редко | основа | долг СТО | один «долг со сроком» (есть) + `region` + лимит + акт сверки |
| **Закупка в валюте + расходы → себестоимость** | — | партии | Европа / ОАЭ | один приход с `currency`, `rate`, `extra_costs` (Б-БЗ4) |
| **Единицы продажи / упаковки** | пара, ряд | ряд, мешок, тюк | комплект, набор | один `sale_units` (есть) |
| **Нет штрихкодов / поиск по фото** | да | да | поиск по OEM и кросс-номерам | общая сетка плиток с фото + поиск по коду |
| **Накладная / отгрузка / перемещение с получателем** | — | да | по складам | один документ «Перемещение / накладная с получателем» (`TransferDocument*`, Б-БЗ7) |
| **WhatsApp-выписка клиенту** | да | да | да | один блок «Отправить» (есть в долге) |
| **Мини-курсы валют** | да | да | иногда | одно окно «Курсы» (`SphereSettingsJson` / Б-БЗ8) |

**Что только у розницы:** торг «до 10 / 50 / 100», ценник на полке, режим «одной рукой», «Обмен».
**Что только у опта:** карточка клиента с договорными ценами и лимитом, накладная A4 с нумерацией, отгрузка / карго, акт сверки, отчёты по регионам и партиям.
**Что только у автозапчастей (не делать здесь):** кросс-номера и OEM, подбор по VIN / авто, применимость.
**Порядок:** общие функции (ОФ) → профили розницы и опта (данные) → экраны розницы → экраны опта; профиль автозапчастей — параллельно на тех же ОФ. Конфликты файлов: `MainWindow.Dialogs.cs`, `CheckoutViewModel*` (денежный файл — только по согласованию владельца), `SphereCatalog.cs` (по одной строке регистрации на профиль).

## 7. Риски

- **Деньги в валюте:** ошибка курса даёт недостачу. Курс правит только старший; в чеке всегда сумма в сомах; курс сохраняется в истории (дата, кто изменил).
- **Скидка «до круглого» (розница):** возможна кража. Предел и PIN по умолчанию, округление только вниз, отчёт «Скидки по продавцам».
- **Договорные цены и «свои» уровни (опт):** менеджер может поставить клиенту цену ниже закупки. Правка договорных цен — только старший (право «Изменение цены»); продажа ниже закупки — право `can_sell_below_cost`.
- **Лимит долга и 409:** если сервер не даёт пути подтверждения, менеджер не сможет отгрузить «своему» клиенту — решение владельца (Б-БЗ11).
- **Нумерация накладных офлайн:** дубли или дыры. Серверный номер при отправке; временный номер в печатной форме помечен «черновик».
- **Резерв без срока:** товар «зависает». Срок резерва и напоминание.
- **Нет штрихкодов:** путаница товара. Фото-плитки и своя этикетка уменьшают риск.
- **Остаток рядами** расходится с остатком по размерам (3.9).
- **Слабый интернет и планшет:** офлайн-очередь, лёгкие плитки (Б-БЗ9), не грузить полный каталог при каждой продаже.
- **Данные между кассами:** курс, регионы и флажки идут через общий ключ ≤ 16 КБ, не через схему базы.
- **Смена профиля:** данные не удаляются (1.4), но видимость экранов меняется — предупреждаем окном «Что изменится».

## 8. Вопросы владельцу (10, с рекомендацией)

**Вариант A — две сферы** (решение владельца 19.11): две плитки в мастере, у каждой свой профиль и главный экран. *Плюсы:* понятно новому клиенту, разные экраны «из коробки», тексты и подсказки точные. *Минусы:* контейнер «и так, и так» вынужден выбирать; два профиля и две статьи в базе знаний.
**Вариант B — одна сфера + режим:** одна плитка «Контейнер», режим «Розница» / «Опт» / «Оба» и флажки «Опт» в Настройках. *Плюсы:* один профиль, не надо выбирать, смешанная торговля естественна. *Минусы:* новому клиенту труднее понять, что включить; главный экран один на всех (плитки или карточка клиента).
**Рекомендую A, реализованный через общие флажки (раздел 1.2):** две плитки (как решил владелец), но профиль только расставляет флажки по умолчанию. Смешанный контейнер выбирает «Розница» и включает флажки «Опт» (карточка клиента, накладная, заказ, отгрузка) в «Настройках → Операции → Контейнер» — отдельной сферы не нужно; профили переключаются самим владельцем без потери данных (1.4). Решение остаётся за владельцем: если выберет B, вся реализация (флажки, данные, отчёты) остаётся той же, меняется только мастер выбора (одна плитка вместо двух).

1. **Как назвать две сферы в мастере?** «Контейнер — розница» / «Контейнер — опт», либо «Базар: розница» / «Базар: опт». **Рекомендую «Контейнер — розница» и «Контейнер — опт»** (так говорят продавцы).
2. **Вариант A (две сферы) или B (одна сфера + режим)? Нужен ли профиль «опт+розница» вместе?** **Рекомендую A через флажки** (текст выше): розница по умолчанию, оптовые функции — флажками «Опт»; отдельной третьей сферы «опт+розница» не делаем.
3. **Валюты:** какие принимаете (USD, RUB, CNY)? Нужна ли оплата в валюте или только закупка? **Рекомендую USD + RUB для оплаты, CNY + USD для закупки**; курс вводит старший; в чек идёт сом-эквивалент.
4. **Налог:** патент / ЕНП, нужна ли фискализация (чек eKassa)? **Рекомендую** не включать по умолчанию; спросить 3–5 контейнеров обоих типов.
5. **Лимит долга:** один лимит на клиента, на группу или по умолчанию для всех? Кто может превысить? **Рекомендую** лимит у клиента, по умолчанию «без лимита» до первого долга, превышение — только старшему по PIN (если сервер позволит).
6. **Накладная нужна? Печать A4?** Форма (ваш образец), нумерация («Н-0001» сквозная?). **Рекомендую** да: A4 с сквозной нумерацией и PDF в WhatsApp; покажите вашу текущую накладную, сделаем похожую.
7. **Карго нужен?** Что записывать: мест, перевозчик, адрес, трек? Нужны ли статусы «отправлено / получено»? **Рекомендую** в первой версии только поля в накладной (мест, перевозчик, город, трек) и статус «отправлено», без интеграций.
8. **Ряды по размерам:** остаток ведёте по размерам или рядами? **Рекомендую** MVP — ряд как упаковка, v2 — комплект из размеров.
