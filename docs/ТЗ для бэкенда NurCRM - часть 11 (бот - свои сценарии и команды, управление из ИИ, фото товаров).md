# ТЗ для бэкенд-программиста NurCRM, часть 11: свои сценарии и команды бота, управление ботом из ИИ-советника, фото товаров в ответах

Дата: 05.10.2026. Заказчик — владелец NurMarket.

**Коротко.** Бот магазина работает на сервере (режим `server`, ТЗ части 5, 7, 9, 10). Сейчас владелец может только включать и выключать готовые функции (`PATCH /api/main/telegram-bot/settings/`: команды, ИИ-консультант, голос, сводка смены, напоминания о прокате). Нужно три вещи:

1. **Свои сценарии и команды** — владелец сам добавляет боту ответы: «на слова "доставка", "привезёте" — ответить таким-то текстом», «команда /adres — адрес и график работы».
2. **Управление ботом из программы владельца через ИИ-советник** — владелец пишет советнику «добавь боту команду /akcii со списком акций», советник готовит сценарий, владелец подтверждает кнопкой, программа сохраняет его на сервере через API из п. 1.
3. **Фото товара в ответах** — когда бот (и ИИ-консультант, и обычный поиск) называет товар, у которого есть фото, он присылает фото.

Программа владельца (Windows и Android) со своей стороны будет готова к API из этого ТЗ: экран сценариев и действия ИИ-советника делаются в программе. Без API сервера они не работают.

## 1. Свои сценарии и команды

### 1.1. Что такое сценарий

Сценарий — правило «если покупатель написал X — ответить Y». Два вида:

| Вид | Срабатывает | Пример |
|---|---|---|
| `command` | Сообщение — ровно команда `/имя` (с параметром или без) | `/adres` → адрес и график |
| `keywords` | В сообщении есть хотя бы одно из ключевых слов или фраз (без учёта регистра, ё = е, кыргызские буквы ң ө ү — как есть) | «доставка», «привезёте», «жеткирүү» → условия доставки |

### 1.2. Модель данных (таблица `telegram_bot_scenarios`, на компанию)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | uuid | — | |
| `company` | FK | — | Компания (из токена, как во всех API) |
| `kind` | `command` \| `keywords` | да | |
| `command` | строка 1–32, `[a-z0-9_]` | для `command` | Без «/». Не совпадает со встроенными командами (`start`, `help`, `segodnya`, `nedelya`, `top`, `abc`, `zakaz`, `ostatki`, `dolgi`, `dolg`, …) → 400 |
| `keywords` | массив строк, 1–30 шт., каждая 2–60 символов | для `keywords` | |
| `title` | строка до 80 | да | Название для владельца («Доставка») |
| `reply_text` | строка 1–3500 | да | Ответ. Разметка Telegram HTML (`<b>`, `<i>`, `<a href>`); сервер проверяет, что HTML валиден для Telegram |
| `buttons` | массив до 6 `{text, url}` или `{text, command}` | нет | Inline-кнопки под ответом |
| `photo_product` | uuid товара | нет | Прислать фото этого товара вместе с ответом (см. раздел 3) |
| `audience` | `customers` \| `owner` \| `all` | да, по умолчанию `customers` | Кому отвечать: покупателям, владельцу (чат `owner_chat_id`) или всем |
| `languages` | массив `ru`, `ky`, `en`, `tr`, `uz` или пусто (все) | нет | Если язык покупателя известен |
| `priority` | число 0–100, по умолчанию 50 | нет | Сработало несколько — берётся с большим приоритетом |
| `is_active` | bool | да, по умолчанию true | |
| `show_in_menu` | bool | нет | Только для `command`: добавить в меню команд бота (`setMyCommands`) с описанием `title` |
| `created_by`, `updated_by`, `created_at`, `updated_at` | | — | Кто и когда (для журнала, п. 2.4) |
| `source` | `owner` \| `ai_advisor` | — | Создано вручную или через ИИ-советник (п. 2) |
| `hits` | число | — | Сколько раз сработал (для статистики) |

Ограничение: не больше 100 сценариев на компанию.

### 1.3. API

Все адреса — под `api/main/telegram-bot/`, доступ — владелец и пользователи с правом «Настройки» (как у `settings/`).

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `scenarios/` | Список: `[{…все поля…}]`, сортировка по `priority` убыв., потом `title` |
| POST | `scenarios/` | Создать. Ответ 201 + объект. Ошибки 400 с полями, как в DRF (`{"command": ["Такая команда уже есть"]}`) |
| PATCH | `scenarios/{id}/` | Изменить любые поля |
| DELETE | `scenarios/{id}/` | Удалить. 204 |
| POST | `scenarios/test/` | `{"text": "а доставка есть?", "audience": "customers"}` → `{"matched": {id, title, kind} \| null, "reply_text": "…", "buttons": […]}`. Ничего не отправляет в Telegram — проверка «что ответит бот» |
| POST | `scenarios/sync-menu/` | Пересобрать меню команд Telegram (`setMyCommands`) из встроенных команд и сценариев с `show_in_menu`. Вызывать и автоматически после каждого изменения команд |

### 1.4. Как бот применяет сценарии

1. Порядок обработки входящего сообщения:
   1. Служебное (кнопки, оформление заказа по ТЗ части 9) — как сейчас.
   2. **Сценарий `command`**, если сообщение — команда и она есть среди активных сценариев компании.
   3. Встроенные команды — как сейчас.
   4. **Сценарий `keywords`** — если нашлось совпадение.
   5. ИИ-консультант / поиск товара — как сейчас.
2. Сценарий отвечает **без ИИ** (быстро и бесплатно): `reply_text` + кнопки + фото (если указано).
3. Учитывается `audience`: сценарий `owner` в чате покупателя не срабатывает, и наоборот.
4. После ответа — `hits += 1`, запись в журнал обращений (`inquiries/`) с отметкой `scenario_id` и `scenario_title` (новые поля в ответе `inquiries/`).
5. Ключевые слова совпадают по границам слов: «доставка» срабатывает на «доставка есть?», но «ока» не срабатывает на «кока-кола».
6. Защита от петель и спама — как для обычных ответов (лимиты части 7).

### 1.5. Сценарии в подсказке ИИ-консультанта

Если покупатель спросил своими словами, а ключевые слова не совпали («а вы домой привозите?»), ИИ должен ответить по сценарию. Для этого в системную подсказку ИИ-консультанта добавлять блок:

```
ОТВЕТЫ МАГАЗИНА (используй их, если вопрос о том же):
• Доставка: <reply_text без HTML>
• Адрес и график: <reply_text без HTML>
```

Только активные сценарии с `audience` = `customers`/`all`, не больше 30, общий размер блока до 4000 символов.

## 2. Управление ботом из программы владельца через ИИ-советник

В программе владельца есть раздел «ИИ-советник» (с версии 1.17.49): владелец пишет вопросы о магазине, ИИ отвечает по его данным. Следующий шаг — советник по просьбе владельца **меняет настройки бота и добавляет сценарии**. Всё, что советник предлагает изменить, программа показывает владельцу карточкой «Применить / Отмена»; на сервер уходит только после «Применить».

### 2.1. Что делает программа (сделаем мы)

- Нейросеть советника получает список действий, которые ей можно предложить: включить/выключить функцию бота (поля `settings/`), создать/изменить/выключить сценарий (п. 1.3).
- Ответ нейросети с действием программа превращает в карточку: «Создать команду /adres: "Адрес: …"», «Выключить голосовые ответы».
- После «Применить» программа вызывает `PATCH settings/` или `POST/PATCH/DELETE scenarios/` с токеном владельца и показывает результат («Готово» или текст ошибки сервера).
- Перед сохранением сценария программа вызывает `scenarios/test/` и показывает владельцу, что ответит бот.

### 2.2. Что нужно от сервера

1. API из п. 1.3.
2. Поле `source` при создании: программа передаёт `"source": "ai_advisor"`. Сервер сохраняет как есть.
3. **Ничего не применять без запроса программы** — сервер сам ИИ-советника не вызывает.
4. Ошибки — понятным текстом на русском (программа показывает их владельцу как есть).

### 2.3. Безопасность

- Менять сценарии и настройки — только владелец и пользователи с правом «Настройки». Кассир без права → 403.
- `reply_text` и `buttons.url`: запрещены `javascript:`, `data:` и ссылки на другие Telegram-боты (`t.me/...bot`); разрешены `https://`, `tel:`, `t.me/<канал или пользователь>`. Иначе 400.
- Токен бота и ключ ИИ через эти API не возвращаются и не меняются.

### 2.4. Журнал изменений

`GET api/main/telegram-bot/audit/?limit=50` → `[{at, user_name, action: "scenario.create"|"scenario.update"|"scenario.delete"|"settings.update", object_title, source: "owner"|"ai_advisor", changes: {поле: [было, стало]}}]`. Программа покажет его в разделе «Телеграм-бот».

## 3. Фото товара в ответах бота и ИИ

### 3.1. Где присылать фото

1. **Ответ ИИ-консультанта**, если в ответе названы товары из каталога, который ему передали (поиск по вопросу): после текста ответа — фото этих товаров.
2. **Ответ на поиск товара без ИИ** (ИИ выключен или нет ключа) — как в ТЗ части 9, п. 2.2: карточка товара — фото с подписью.
3. **Сценарий** с `photo_product` — фото этого товара вместе с ответом.
4. **Чат владельца**: на «покажи фото кока-колы» / «фото <товар>» — фото товара (поиск по названию, как у покупателя).

### 3.2. Как определить, какие товары назвал ИИ

Вариант, который работает в программе: в каталоге для ИИ у каждого товара есть название; после ответа ИИ сервер ищет в тексте ответа названия товаров из переданного каталога (без учёта регистра, по целому названию или по названию без объёма/веса: «Coca-Cola 1,5 л» и «Coca-Cola»). Совпавшие товары, у которых есть фото, — в ответ. Порядок — как в тексте ответа.

### 3.3. Как присылать

- Один товар — `sendPhoto` с подписью `<b>Название</b>\n💰 95 сом · ✅ в наличии` (как карточка в части 9) **после** текстового ответа ИИ.
- 2–5 товаров — одно сообщение `sendMediaGroup` (альбом) с подписью у каждого фото. Больше 5 — только первые 5.
- Фото только у товаров **в наличии** (покупателю нет смысла смотреть на то, чего нет), владельцу — всегда.
- Фото берётся из `image_url` товара. Telegram должен суметь его скачать: адрес публичный, `https://`, ответ `200` с `Content-Type: image/*`, до 5 МБ. Если адрес внутренний или фото больше — сервер сам скачивает и отправляет файлом (multipart), уменьшив до 1280 px по большей стороне.
- **Кэш `file_id`**: после первой отправки Telegram возвращает `photo[-1].file_id` — сохранить его у товара (`telegram_photo_file_id`, сбрасывать при смене фото) и дальше отправлять по `file_id` — быстрее и без повторной загрузки.
- Ошибка отправки фото **не должна** ломать ответ: текст уже ушёл; ошибку — в журнал сервера.

### 3.4. Настройка

Новое поле в `settings/`: `"send_product_photos": true` (по умолчанию `true`). Программа добавит переключатель «Присылать фото товаров» в раздел «Телеграм-бот».

## 4. Приёмка

Проверять на тестовой компании NBS, бот @kssirBot, режим `server`.

| № | Действие | Ожидается |
|---|---|---|
| 1 | `POST scenarios/` `{"kind":"command","command":"adres","title":"Адрес","reply_text":"<b>Адрес:</b> …","show_in_menu":true}` | 201; в меню команд Telegram появилась /adres |
| 2 | Покупатель пишет `/adres` | Ответ `reply_text` за ≤ 2 с, без ИИ; в `inquiries/` — `scenario_title: "Адрес"` |
| 3 | `POST scenarios/` с `command: "start"` | 400 «Это встроенная команда» |
| 4 | Сценарий `keywords: ["доставка","привезёте"]`; покупатель «а доставка есть?» | Ответ сценария, `hits` = 1 |
| 5 | Покупатель «вы домой привозите?» (слов нет) | ИИ отвечает по тексту сценария «Доставка» (п. 1.5) |
| 6 | `POST scenarios/test/` `{"text":"доставка"}` | `matched.title = "Доставка"`, в Telegram ничего не ушло |
| 7 | Кассир без права «Настройки» вызывает `POST scenarios/` | 403 |
| 8 | `reply_text` с `<a href="javascript:…">` | 400 |
| 9 | Покупатель «есть кока-кола и фанта?», у обоих есть фото | Текст ИИ, затем альбом из 2 фото с подписями |
| 10 | Второй раз тот же вопрос | Фото уходят по `file_id` (в журнале сервера нет повторной загрузки) |
| 11 | Товар без фото / не в наличии | Фото нет, текст как обычно |
| 12 | `image_url` ведёт на 404 | Текст ушёл, в журнале сервера — ошибка фото, бот работает дальше |
| 13 | `settings/` `send_product_photos: false` | Фото не присылаются |
| 14 | `GET audit/` после п. 1, 4, 13 | Три записи с `user_name`, `source`, изменениями |
