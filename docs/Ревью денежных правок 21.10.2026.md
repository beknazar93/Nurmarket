## Подтверждённые находки — оплата долга, поставщики, документы клиента

### Важно

✅ **A1. Сохранение «Оплата долга» в настройках может выключить «Нужен код сотрудника» на всех кассах.** (перепроверено)
`Views/Settings/DebtPaymentSettingsCard.cs:147-154` + `Infrastructure/Services/DebtPaymentSettings.cs:209-217`.
Набор `wanted` собирается из переключателей на экране. Если значения с сервера при открытии не пришли (связь мигнула, первый
запуск) — на экране значения по умолчанию («код не нужен»). Владелец включает «Безнал в кассе» → `SaveAsync` сам делает
`RefreshAsync` и получает «код нужен», но в PATCH уходит старый экранный набор → код выключен для всех касс, экран этого не
покажет. То же, если другой админ менял настройку < 2 мин назад. Исправить: после свежего чтения менять только нажатый
переключатель, или при расхождении не отправлять, а показать значения сервера; переключатели не включать, пока значения не получены.

✅ **A2. Окно «Принять оплату» не видит долги без продажи.** `PayDebtDialog.axaml.cs:530-531` (`pos/sales/?status=debt`),
`AcceptDebtPaymentWindow.cs:386, 405-409`. Долг, записанный в «Клиентах» как «Долг без продажи» (500 сом), — окно пишет «Долгов
нет», принять нельзя. Если есть и чеки, «одной суммой» сервер может погасить сначала ручной долг, а план в подтверждении
(«закроет чек №…», «Останется долг») будет неверным. Суммы в смене верные (по `paid` ответа). Исправить: подгружать и сделки
без `sale` или хотя бы долг из `clients/debtors/` с предупреждением; порядок погашения проверить на NBS.

✅ **A3. Документы клиента: правка, которая старее серверной версии, отправляется бесконечно.** (перепроверено)
`ClientDocsStore.cs:120` (в списке побеждает серверная, если `mine.UpdatedAt < d.UpdatedAt`), `:435-437`, `:474-476` (из очереди
снимается только при совпадении `UpdatedRaw`). Документ поправили на другом ПК позже (или часы этого ПК отстают) → правка этого ПК
не видна и навсегда остаётся в очереди → `SchedulePush(800)` каждые ~0,8 с: GET + PATCH всего списка, пока открыта программа.
Исправить: снимать из очереди правку, если серверная версия новее (и сказать владельцу, что документ изменён на другом ПК).

✅ **A4. Документы клиента: одновременная запись двух ПК теряет документ.** `ClientDocsStore.cs:395, 428, 433-441`.
GET → слияние → PATCH всего ключа `quotes` без проверки версии: второй PATCH затирает новый документ первого ПК, а первый ПК уже
снял его из очереди → документ пропадает и у него при следующем обновлении; так же «воскресает» удалённый. Исправить: после
PATCH перечитать сервер и снимать из очереди/«удалённых» только подтверждённое, остальное отправить снова.

✅ **A5. Документы клиента: старые реквизиты продавца (банк, расчётный счёт) затирают новые.** `ClientDocsStore.cs:140-141,
209-216, 490-495`; редактор `ClientDocEditorWindow.cs:126, 743-747, 805-812`. Новый номер документа помечает изменённым весь
профиль → при записи с сервера берутся только счётчики, остальной профиль уходит с этого ПК. ПК Б сменил расчётный счёт, ПК А
(не обновлялся) создаёт счёт → на сервере снова старый счёт, клиент заплатит не туда. Исправить: счётчики — отдельно от профиля
(слияние по максимуму), в профиль писать только изменённые поля.

✅ **A6. Скидка документа в % не пересчитывается при добавлении строк.** `ClientDocEditorWindow.cs:832-845`, пересчёт строки
`:1086-1091` не вызывает `DiscountChanged`. «10%» при подытоге 1000, потом добавили товара до 2000 → в поле «10%», на бланке
скидка 100 вместо 200. Аналогично «500» при подытоге 300 сохраняется как 300 и не растёт. Исправить: разбирать поле скидки при
каждом пересчёте итогов.

✅ **A7. Долг поставщику на 60/90 дней разбивается на 2–3 взноса.** (перепроверено) `SupplierDebtRecorder.cs:330`:
`debt_months = Round(DueDays / 30)`, а по комментарию там же сервер понимает `debt_months` как число ежемесячных взносов
(45 дней → тоже 2). Задуман один взнос на дату. Исправить: всегда `debt_months: 1`, срок — `first_due_date`.

## Подтверждённые находки — возвраты, касса, смена (проверял сам)

### Важно

✅ **1. Возврат продажи «в долг» с предоплатой картой/переводом велит выдать НАЛИЧНЫЕ.**
`NurMarketKassa.Avalonia/Views.axaml/MainKassir/MainWindow.axaml.cs:1475-1477` (RememberSaleForReturns) + `ReturnSaleDialog.axaml.cs` ComputeRefundSplit (~стр. 1221-1245).
- Сценарий: включена «выбор способа предоплаты долга», чек 1000, в долг, внесено 300 **безналом**. В журнал SaleReturnLedger
  пишется `PaidCash = 300, PaidNonCash = 0` (для `debt` берётся весь `cash_received`, а флаг безнала `IsDebtPrepaymentNonCash`
  сюда не доходит). Полный возврат → `money = 300`, `cash = 300` → «Выдать покупателю: наличными 300,00»; в событие смены —
  `cash=300`, в Z-окне «Возвраты: наличными 300». Кассир отдаёт 300 из ящика за деньги, пришедшие на счёт → недостача в ящике.
- Исправить: передать в LastSaleInfo признак/сумму безналичной предоплаты (`checkoutVm.NonCashReceivedForApi`) и в
  RememberSaleForReturns для `debt` класть её в `paidNonCash`, а в `paidCash` — только остаток.

✅ **2. Возврат долгового чека после того, как клиент долг уже погасил: «Выдать 0,00 · долг уменьшен на …».**
`SaleReturnLedger.cs:79-80` (Debt / DebtLeft) и ComputeRefundSplit (ветка isDebtSale).
- `DebtLeft` знает только возвраты, но не оплаты долга. Сценарий: продажа 1000 в долг без предоплаты → через неделю клиент
  погасил 1000 → вернул товар. Если сервер не отдал движение денег по возврату (`ReturnCashOutAsync` = null: нет строки
  cashflow, сбой или общий таймаут 8 с вместе с ListReturns), касса считает `money = amount − min(amount, DebtLeft=1000) = 0`
  и уверенно пишет «Выдать покупателю: 0,00. Долг клиента уменьшен на 1 000,00 — эти деньги не выдаются», хотя долга уже нет.
  Без журнала (`ledger == null`, метод `debt`) — тоже 0.
- Исправить: перед расчётом брать текущий остаток долга по сделке/клиенту с сервера (remaining_debt) и уменьшать долг не
  больше него; если остаток неизвестен — не показывать «0», а предупреждение «проверьте долг клиента перед выдачей».

✅ **3. Журнал возвратов стирается целиком при одной ошибке чтения.**
`SaleReturnLedger.cs:189-206, 209-230`.
- `Update` сбрасывает кэш и вызывает `Load()`; если `File.ReadAllText`/`Deserialize` бросили исключение (файл занят антивирусом
  или второй программой, повреждён), `Load` возвращает **пустой** словарь, и сразу `Save(all)` перезаписывает файл одной записью.
  Все сохранённые продажи (доля скидки на чек, оплата, срок долга) пропадают → следующие возвраты чеков со скидкой снова по
  цифрам сервера (возврат больше оплаченного, К1), копии долговых чеков без срока.
- Плюс замок только внутри процесса, а файл общий у кассы и программы владельца (`%LOCALAPPDATA%\NurMarketKassa`): две
  одновременные записи теряют одну из них.
- Исправить: при ошибке чтения не записывать (прервать Update, записать WARNING), либо сохранять копию `.bak` и читать её;
  межпроцессный замок (именованный Mutex) вокруг чтения-записи.

### Мелочь

✅ **4. Пока касса сверяет «ответ не дошёл», можно открыть другой чек — разбивка возврата посчитается по его способу оплаты.**
`ReturnSaleDialog.axaml.cs` ReturnSelectedCoreAsync: внутренний `finally { IsBusy = false; }` срабатывает до
`ReportReturnIfAppliedAsync` (до 10 с ожидания `PosSaleGetAsync`). Кнопка «Выбрать» и двойной щелчок проверяют только `IsBusy`
(не `_operationInProgress`) → кассир открывает другой чек → `_currentSaleMethod` уже чужой; `ResolveRefundAsync` берёт
`_ledger` = null (id не совпал) и `ComputeRefundSplit(null, чужой метод, …)` → неверная строка «Выдать … наличными/на карту» и
заметка события смены. Исправить: проверять `_operationInProgress` в SelectSale/DoubleTapped или передавать метод оплаты в
ResolveRefundAsync параметром.

✅ **5. Сверка закрытия смены покажет «излишек» после возврата чека со скидкой (следствие ошибки сервера, не кассы).**
Касса выдаёт верные 75,00, а сервер списал из смены 80,00 (ТЗ 19.9) — ожидаемый остаток сервера на 5 меньше ящика. Запись в
«Некорректные чеки» есть, но в окне закрытия смены об этом не сказано — кассир может «подогнать» ящик. Предложение: в
CloseShiftDialog показать строку «Сервер записал возвраты больше выданного на N сом (см. Некорректные чеки)».

## Проверено — в порядке

- **Возвраты:** доля скидки на чек (decimal, округление AwayFromZero, потолок — остаток оплаченного, «весь чек» — ровно остаток);
  ключ идемпотентности привязан к чеку и составу, живёт 10 мин, забывается после успеха/4xx и после сверки «уже прошёл»;
  двойной клик закрыт `_operationInProgress`; событие смены пишется один раз (ключ с временем); остаток каталога — на UI-потоке,
  брак не возвращается; «сервер вернул больше» → кассиру сумма кассы + «Некорректные чеки»; смешанная оплата делится по остаткам.
- **Предоплата долга в checkout (PosCheckoutService):** один ключ на одинаковое тело, сверка «уже оплачено» по remaining_debt/paid_on
  перед повтором — двойной оплаты не вижу.
- **Оплата в кассе:** «0,00» и запятая разбираются (`NormalizeDecimal`), суммы для API — InvariantCulture «0.00», MoneyText только
  для показа; кнопка «В долг / Получить X · в долг Y» с ограничением; Enter сканера в окне оплаты не проводит оплату и
  возвращает поле «Получено»; Enter в смешанной — только при совпадении сумм; убыток считается до показа скидки.
- **Бонусы К13:** начисление (`CreditOrRedeemLoyaltyPoints`) берёт тот же `EarnedPointsPreview`, у долга — только внесённая часть.
- **Срок долга:** 7/14/30 = `DateTime.Today.Date.AddDays(n)`, в API — `yyyy-MM-dd`.
- **Чеки:** «Товарный чек»; долг — «Оплачено/В долг/Вернуть до/график», телефон маской (длина ≥ 6, индексы безопасны).
- **Смена:** закрытие — поле пустое, `CashAmountInput` (запятая не тысячи), сумма фиксируется при подтверждении, фоновое
  обновление не перетирает ввод; внесение — причина и подтверждение; запасной остаток пишется только при открытой смене.
- **MoneyText / CashAmountInput:** без «-0,00», NaN → «—»; минус и двусмысленные «1.500.000» отвергаются.
- `ClientDebtsApiService.IsEndpointMissing`: 404 с JSON больше не уводит оплату на старый путь — риск двойной оплаты меньше.
- **Оплата долга (агент):** двойное нажатие/Enter закрыты флагом до первого await; запись «в пути» на диск до запроса, повтор
  только тем же ключом, 24 ч; файловый замок касса ↔ владелец; событие смены уникально по ключу; суммы decimal через
  `CashAmountInput`, не больше точных остатков; события до окон — через `Dispatcher.UIThread.Post`; async void обёрнуты в try/catch;
  PATCH настроек — только ключ `DebtPaymentOptions`.
- **Документы клиента (агент):** PATCH `app-settings/nurmarket-mobile/` несёт только `quotes`, `waybills`, `docsProfile` — QR оплаты,
  DebtAccess и другие ключи мобилки не затираются (сервер сливает верхний уровень, пустой список уходит `[]`, не null); 403 — без
  бесконечного повтора; НДС «в т.ч.» = итог × ставка / (100 + ставка); итог не уходит в минус.
- **Сумма прописью (агент):** 0, 1, 2, 11, 21, 101, 1 001 («одна тысяча»), 2 000 («две тысячи»), 5 000, 21 000 («двадцать одна
  тысяча»), 1 000 000, 1 234 567,89, 0,5, 100,999 → «Сто один сом 00», 99,995 → «Сто сом 00»; кыргызский «миң», «жүз», «нөл» — верно.
- **Долги поставщикам (агент):** журнал до запроса, после сбоя — сначала поиск по метке, без слепого второго создания; двойное
  нажатие закрыто; `SupplierApiService` денег не пишет.
