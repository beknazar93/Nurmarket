# «Заказ под клиента» — перенос на сервер customer-orders/ (20.11.2026)

Основание: ответ Умара 20.11, раздел В.4 («Всё за 20.11 — сделано и что нужно от тебя»). Сервер уже держит заказ покупателя: резерв, предоплату отдельным движением в смене, выдачу чеком и отмену с возвратом предоплаты. Касса до сих пор вела заказы локально (`parts-orders.json`, предоплата «в конверте»).

## Что сделано (этап 1, за признаком `customer_orders` в capabilities)
- `CustomerOrdersApi` (Infrastructure/Services/Spheres/CustomerOrdersApi.cs): список открытых (`status=confirmed,reserved,waiting_supply,ready`, страницами), карточка, **выдача** `POST customer-orders/<id>/deliver/ {payment:{method, received}}`, **отмена** `POST customer-orders/<id>/cancel/ {}`; все POST — с `Idempotency-Key` (ключ на попытку, чтобы отказ 409 `shift_not_open` не залипал).
- Серверные заказы попадают в окно «Заказы под клиента» копией (`PartsOrder.ServerId`, `ServerStatus`, `ServerLeftToPay`, `ServerVersion`, `ServerSaleId`; в файле старых записей полей нет — читаются как местные). Номер — номер заказа сервера. Статусы: `confirmed`/`draft` → Новый, `reserved`/`waiting_supply` → Заказан, `ready` → Пришёл, `delivered`/`closed` → Выдан, `canceled` → Отменён.
- В карточке серверного заказа: «Выдать — наличные / карта» (к оплате = `left_to_pay` сервера; предоплата зачитывается строкой «Зачёт» самим сервером), «Отменить заказ» (с предоплатой — PIN руководителя до запроса; сервер возвращает предоплату из кассы **текущей** смены тем же способом, 403 — «нет права» понятным текстом). Кнопки «Отметить», «Оформить продажу» (обычный чек → 409 `reserved_stock`) и «Изменить» у серверного заказа скрыты.
- Ошибки: `shift_not_open`, `order_not_confirmed`, `order_waiting_supply`, `order_closed`, `order_already_delivered` (копия обновляется, второго чека нет), `order_reserved`, `prepayment_exceeds_total`, `version_conflict`, `reserved_stock`, 403 на отмене, 404 — 5 языков (`CustomerOrderErrors`).
- Местные заказы работают как раньше (без признака сервера окно не меняется ни на пиксель).

## Что остаётся (этап 2 и дальше)
1. **Создание на сервере.** `POST customer-orders/ {status:"confirmed", client?, customer_name, customer_phone, due_date, note, items:[{product, qty, price?}], prepayment?{amount, method}}` + `Idempotency-Key`. Для строк «под заказ» без товара каталога (`ProductId` пуст) сервер строки не примет — нужен ответ Умара: создавать временный товар или оставлять заказ местным. Окно `PartsOrderEditDialog`: при включённом признаке создавать на сервере, а локальную запись хранить копией.
2. **Предоплата отдельным действием** `POST prepay/ {amount, method, shift?}` (409 `prepayment_exceeds_total`, `data.max`). Заменяет «предоплата в конверте»: деньги идут в смену, строка «Предоплаты по заказам на руках» для серверных заказов исчезает (уже исключены из суммы).
3. **Резерв** `POST reserve/ {create_supplier_order?, supplier?}`: кнопка «Зарезервировать»; нехватка → `waiting_supply` (+ черновик заказа поставщику). Событие ленты `customer_order_ready` → обновлять список и показывать «Пришёл».
4. **Правка с версией** `PATCH customer-orders/<id>/` + `If-Match: <version>` (409 `version_conflict` → «обновите список»). Строки меняются только до резерва.
5. **Печать чека выдачи** по `sale_id` из ответа deliver (сейчас кассир видит сообщение и сдачу, чек пробит на сервере; печатное окно чека для такого sale_id — отдельная задача в духе «печать чека продажи с сервера»).
6. **Перенос старых местных заказов**: кнопка «Отправить на сервер» (владельцу) — создание + предоплата одним пакетом; предоплату «в конверте» вносят в смену как `prepay` тем способом, что принят. До переноса — по одному заказу с подтверждением.
7. **Android-касса и мобилка**: тот же `CustomerOrdersApi` (Infrastructure общий), окно — отдельно.
8. **Живая проверка** на тестовой компании «ТЕСТ Автозапчасти» (PIN владельца в документы не пишем): выдача наличными и картой, отмена с предоплатой из открытой и из закрытой смены (`shift_not_open`), выдача уже выданного заказа, потеря связи посреди выдачи.

## Вопросы Умару (минимум)
- Строки без товара каталога в `items[]`: можно ли `product: null` с названием, или обязателен товар?
- Признак в `capabilities.features`: имя — `customer_orders`? (касса ждёт именно его; без него серверные заказы не показываются.)
- `prepayment.amount` в ответе — сумма внесённого минус возвращённого или внесённого? (касса считает «возвращена», если среди `payments` есть `kind: refund`.)
