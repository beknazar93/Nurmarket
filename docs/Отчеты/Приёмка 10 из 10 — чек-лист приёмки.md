# Приёмка 10 из 10 — чек-лист приёмки

К документу `Приёмка 10 из 10 — ТЗ и план внедрения.md`. Номера пунктов совпадают с ТЗ.
Правило: оценка измерения = ⌊10 × отмечено / всего⌋; **10 только когда отмечены все пункты**. Итог — минимум по семи измерениям.
Тесты — только `tools/qa/test-safe.ps1`; снимки — Avalonia.Headless; живая проверка — NBS (окно согласовать с владельцем).
Проверяют оба входа: «Склад → Приёмка» и «Закупки → Приём товара».

## (а) Скорость

- [ ] С-1 Известный товар ×1 — 1 действие, фокус в скане
- [ ] С-2 Известный товар ×N — ≤ 2 действий (Enter в «Кол-во» при известных ценах → скан)
- [ ] С-3 Повторный скан — ≤ 2 (окно «Сколько?»), без окна — 1 в единицах колонки
- [ ] С-4 Новый товар типовой — ≤ 3 действий после скана, KLM ≤ 10 с, живой NBS медиана ≤ 10 с
- [ ] С-5 Новый нетиповой (кг / своя цена / упаковка / PLU) — +1 действие на отличие, без мыши
- [ ] С-6 Провести — ≤ 2 действий после последнего скана (F9 → Enter)
- [ ] С-7 Сценарий 30 строк — ≤ 46 действий, фокус не теряется
- [ ] С-8 Локальный скан ≤ 100 мс p95 (50 тыс. каталог, 500 строк)
- [ ] С-9 Серверный скан: «Ищу…» ≤ 100 мс, итог ≤ 1,5 с p95; без связи ≤ 100 мс; таймаут 3 с → «Неизвестно»
- [ ] С-10 Итог и прибыль обновляются на каждый символ, ≤ 16 мс при 500 строках

## (б) Деньги

- [ ] Д-4 Пределы сервера соблюдены; > 1 млн — жёлтая пометка; «Прибыль» без «трлн» (Б-2)
- [ ] Д-5 Штрихкод в ячейке цены, количества или наценки не записывается, уходит в скан
- [ ] Д-6 Пустой и нулевой ввод — как в правилах (прежнее значение, «не будет оприходована»)
