# Velopack — безопасный план обновления (05.11.2026)

**Решение на этот выпуск.** Velopack **не обновляем**: остаются пакет `Velopack` 1.0.1 в `NurMarketKassa.Infrastructure.csproj` и утилита `vpk` 1.0.1 (стоит на этом ПК: `dotnet tool list -g`). Причина: автообновление клиентов держится на связке «установленный `Update.exe` старой версии + лента `releases.win.json` и пакеты, которые собрал `vpk`». Если новый `vpk` соберёт ленту или пакет в формате, который старый `Update.exe` у клиентов не поймёт, касса перестанет обновляться сама, а чинить придётся ручной переустановкой на каждой точке. Целевая версия из отчёта — 1.2.161; пока не проверена цепочка на тестовом канале, в стабильный выпуск она не идёт.

## Что менять (когда дойдём)
1. Пакет `Velopack` в `NurMarketKassa.Infrastructure.csproj` — до точной версии (не `*`), например `1.2.161`.
2. Утилита: `dotnet tool update -g vpk --version <та же версия>`. **Пакет и `vpk` — всегда одной версией.** `Update.exe`, который попадает в клиентскую установку, берётся из `vpk` в момент `vpk pack`.
3. В коде вероятно менять нечего, но проверить компиляцию и поведение `Services/VelopackUpdateService.cs` (`UpdateManager`, `GithubSource`, `VelopackAsset`, `VelopackLocator`, `NullVelopackLogger`, список откатов `_rollbackTargets`) и `Program.cs` (`VelopackApp.Build()...Run()` и обработчики установки/удаления).
4. Команда сборки в `docs/AI_HANDOFF.md` 4.3 (`vpk pack --packId NurMarketKassa ... --channel win`) — сверить параметры по `vpk pack --help` новой версии.

## Что прочитать до начала (заметки к выпускам Velopack 1.0.1 → 1.2.x на GitHub `velopack/velopack`)
- Изменился ли формат ленты `releases.win.json` / имена файлов `*-full.nupkg`, `*-delta.nupkg`, `*-Setup.exe`, `*-Portable.zip` и умеет ли новый клиент читать ленту старого `vpk` (нужно для отката выпуска) и наоборот (старый клиент читает ленту нового `vpk` — это главный риск).
- Минимальная версия Windows у `Update.exe` и `Setup.exe` (у нас есть ТЗ «Касса — установка на Windows 7»: если новая версия требует более новую Windows, обновление нельзя).
- Дельта-пакеты: как строятся, нужен ли предыдущий полный пакет в папке `releases/`.
- Поведение ярлыков, автозапуска, ключей `--veloapp-*`, подпись/Smart App Screen.
- Изменения API `UpdateManager`, `GithubSource` (в т. ч. предварительные выпуски `prerelease`), `UpdateOptions` (`ExplicitChannel`, `AllowVersionDowngrade`), `VelopackAsset.NotesMarkdown`.

## Проверка на тестовом канале (по порядку)
Тестовые версии выходят на GitHub как **pre-release**; обычные кассы их не видят, касса тестировщика (Настройки → Обновления → код тестировщика) видит. Проверять на отдельной машине или в виртуальной машине, **не на рабочей кассе владельца**; данные кассы лежат в `%APPDATA%\NurMarketKassa`, не в папке установки.
1. Чистая установка **текущего стабильного** выпуска (собран `vpk` 1.0.1) через его `Setup.exe`. Запомнить версию `Update.exe` (размер/дату).
2. Собрать **тестовый** выпуск `X.Y.Z-test` новой связкой (пакет + `vpk` новой версии), канал `win`, выложить как pre-release через `tools/release/gh_release.py`.
3. На установке из п. 1 включить тестовый канал и обновиться на тестовый выпуск. Проверить: касса сама перезапустилась; версия в «О программе» и «Что нового» верная; данные на месте (база, настройки, лицензия, принтер); ярлыки и автозапуск работают; программа владельца (`--owner`) запускается; в журнале нет `Velopack update check failed`.
4. Второй шаг: выложить ещё один тестовый выпуск и обновиться **уже новым** `Update.exe` (проверка дельта-обновления и самообновления `Update.exe`).
5. Откат из окна «Обновления» (список версий, `_rollbackTargets`): откатиться на предыдущую и вернуться вперёд.
6. Сбои: нет интернета при проверке; обрыв скачивания; антивирус держит файл; запуск обновления при открытой смене (смена и несохранённые продажи не теряются).
7. Чистая установка **нового** `Setup.exe` на пустой машине (новая установка тоже должна работать).
8. Только после всех пунктов — выпустить стабильную версию и смотреть журналы первых обновившихся касс.

## Откат
- Пока тестовый выпуск — только pre-release: удалить его на GitHub (клиенты его не видят), вернуть в `csproj` `Velopack` 1.0.1, `dotnet tool update -g vpk --version 1.0.1`, пересобрать. Клиенты не затронуты.
- Если уже вышел стабильный выпуск на новой связке и у части касс сломалось: на GitHub пометить плохой выпуск как pre-release/удалить (касса берёт «последний стабильный»); выпустить следующий патч, собранный проверенной связкой; для кассы, которая не обновляется, — ручная переустановка `Setup.exe` поверх (данные в `%APPDATA%` сохраняются).
- Перед первым выпуском на новой связке сохранить локально ленту и пакеты предыдущего выпуска (`releases/`) и текущий `vpk` (`dotnet tool list -g`).

Если вернёмся: не в установку, а **докачкой по кнопке** «Скачать голос (49 МБ)» — модель `vosk-model-small-ky-0.42` (Apache-2.0, ~49 МБ) с проверкой SHA-256 в `%LOCALAPPDATA%\NurMarketKassa\models\`; для работы нужны ещё пакет Vosk и его родная библиотека `libvosk.dll` (в установку не возвращаем — тоже докачка или отдельный дополнительный пакет).
