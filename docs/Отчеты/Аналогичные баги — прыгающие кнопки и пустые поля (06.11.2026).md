# Аналогичные баги — прыгающие кнопки и пустые поля (06.11.2026)

Основание: два дефекта со снимков клиента (прыгает левая панель-иконки после нажатия; в Складе пустая колонка «Код / штрихкод»). Корни этих двух ищет другой исполнитель (a4c90c5dfcc2a5963) — здесь они не разбираются. Задача: найти **аналогичные** дефекты в остальной программе.

Как проверял: только чтение кода (рабочая копия на 06.11.2026, с незакоммиченными правками по колонке кодов: `ProductCodeBackfill`, `CodeDisplay/BarcodeDisplay`). Кассу не запускал, сборок и тестов не было. Все стили `*.axaml` (155 файлов) разобраны скриптом по селекторам `:pressed/:selected/:pointerover/:checked/:focus` и классам `.active/.selected/.on/...`, затем найденное прочитано вручную. Секреты не печатал.

Условные обозначения: **высокая** — часто используемое, тач, деньги, данные или поиск по штрихкоду; **средняя**; **низкая**. «Гипотеза» — по коду выглядит так, вживую не проверено.

Справка по причине класса А. В Avalonia смена `Margin / Padding / BorderThickness / FontWeight / Width / IsVisible` у выбранного пункта меняет размер самого пункта и сдвигает соседей. Смена цвета, фона, `Opacity` ничего не двигает. `RenderTransform` (scale/translate) раскладку не меняет, но рисует кнопку со сдвигом и наползанием на соседей. В коде уже есть правильные примеры: `RadioButton.PayTypeOption:focus-visible` (CheckoutDialog.axaml:87-91: рамка толще на столько, на сколько меньше отступ), `Button.mp-tile:focus-visible` (MarketplaceView.axaml:97-101), `SettingsTab` (рамка 1 px прозрачная всегда, акцент — отдельным элементом `tabline`).
