## (б) Корневые причины неудобства

**1. Поле названия в узком виде почти не оставляет места под текст (главная причина видео).** Предварительно высокая уверенность по расчёту разметки, подтвердить снимком/тестом.
- `WarehouseWindow.axaml:1500` — `TextBox` названия в шаблоне правки: `MinHeight="0"`, **без `Padding`, `Height`, `Watermark`**.
- `WarehouseWindow.axaml:156–165` — общий стиль `TextBox`: `Padding="10,8"`, рамка 1,5.
- `WarehouseWindow.axaml:1431` — высота строки `RowHeight="52"`; во втором ряду шаблона (`:1503–1506`) поле штрихкода 22 px + отступ 2 → на название остаётся ≈ 28 px; минус рамка 3 и поля 16 → **≈ 9 px на текст 14 px**. Текст обрезается, каретка короткая (как на видео).
- Соседние поля задают отступы сами: количество `Height=28 Padding="6,0"` (`:1551`), штрихкод `Height=22 Padding="6,0"` (`:1505`). У названия забыли. В широком виде (штрихкод-ряд скрыт, `:437`) поля хватает — поэтому в наших проверках не ловилось.
- Автоформа тоже не помогает: в режиме правки у поля нет `Watermark` (серая подсказка «название» `NewNameHintText`, `WarehouseWindow.ReceivingScan.cs:33`, видна только когда ячейка НЕ редактируется). Пустое поле в фокусе — просто чёрный прямоугольник.

**2. Касса не объясняет, что делать.** В «Склад → Приёмка» после скана неизвестного кода строка просто встаёт сверху и курсор прыгает в ячейку названия (`OnReceivingLineAdded`, `WarehouseWindow.ReceivingScan.cs:303–319`) — **без сообщения**. В «Закупки → Приём товара» сообщение есть («Новый товар: впишите название, цену закупки и цену продажи…», `PurchasesWindow.Receive.cs:649`). Подсказка про «впишите название» живёт только в справке/пустом состоянии (`ReceivingScan.cs:81`, `O9.cs:61`).

**3. Новый товар — это строка таблицы на ~14 колонок, а не карточка.** Нужные поля разбросаны, обязательность не видна:
- единица — текстовая колонка «Ед.» (`WarehouseWindow.axaml:1523`): надо кликнуть и вписать «кг» руками; чипов нет (чипы `ReceiveUnitChips` есть только в «Закупках», `PurchasesWindow.Receive.Render.cs:129`);
- категории в приёмке склада **нет вообще** (`ReceivingLineVm.CategoryName` заполняют только «Массовое добавление» `BulkScanSession.cs:199` и накладная) — товар создаётся без категории (`PurchaseReceivingService.cs:1025`);
- упаковка — ссылка «упак. ▾» под числом; штрихкод — второй ряд названия (узкий вид); «Сгенерировать штрихкод» и «Найти в интернете» — две иконки 16 px без текста (`:1469–1481`);
- закупка/продажа — отдельные колонки правее; цена продажи считается от «Наценка для всех, %», но это видно только по колонке «Как посчитана цена».
Обязательное «название» выясняется только при «Оприходовать» (`PurchaseReceivingService.Validate`, `:727–730`).

**4. Нет помощи с названием.** Подсказки: только кнопка «Найти в интернете» по штрихкоду (по нажатию, это правильно). Нет ответа на «Корона Изобилия» из видео: рядом лежат 2 похожих товара (№10, №11), а нового — того же бренда — приходится печатать с нуля; нет «похожих на складе»/«как у…» (копия категории, единицы, наценки).

**5. Путь по Enter короче, чем кажется, но обрывается.** `ReceivingGrid_PreviewKeyDown` (`WarehouseWindow.ReceivingScan.cs:345`): Название → Принимаем → Закупка → Продажа → поле скана. Единицы и категории в цепочке нет; если название не видно (п. 1), цепочка не стартует.

## (в) Предлагаемый сценарий «неизвестный штрихкод» в приёмке

**Принцип:** неизвестный код → не ячейка таблицы, а **компактная карточка нового товара над таблицей** (не модальная — скан не блокируется; штрихкод уже подставлен). Строка в таблице остаётся (с названием по мере ввода), итоги не прыгают.

Карточка (Tab/Enter-порядок, фокус сразу в 1):
1. **Название** — фокус, подпись «Название нового товара *», большое поле (высота 44), при вводе ≥ 3 букв — до 5 «Похожие на складе» (только локальный каталог, без сети); клик по строке = «как у …» (единица, категория, наценка; название не подменяется). Рядом кнопка «Найти в интернете» с текстом — только по нажатию.
2. **Единица** — чипы шт / кг / л / м / уп. (общий компонент с `ReceiveUnitChips`), по умолчанию «шт» или последняя использованная; клавиши 1–5 или стрелки. «кг» → весовой товар (как сейчас).
3. **Количество** — по умолчанию из поля «×N» над таблицей (обычно 1); для упаковки — ссылка «Принять упаковками» (существующее меню, логику упаковок карточка не дублирует).
4. **Закупка** — обязательное, фокус после Enter.
5. **Цена продажи** — подставлена по «Наценке для всех, %» (если наценка включена — показать «= закупка + 20 %»); можно изменить; Enter.
6. **Категория** — одна строка: «последняя использованная» + до 5 частых чипов, необязательно (не блокирует).
7. **Штрихкод** — показан, у нового без кода — кнопка «Сгенерировать» с текстом (то же действие, что `ReceivingBarcode`, не дублировать).
8. **Enter на последнем поле или кнопка «Готово»** — карточка сворачивается, строка в таблице обычная «новая», **фокус в поле скана**.

**Бюджет:** цель ≤ 3 действий и ≤ 10 секунд на новый товар в типичном случае (единица «шт», категория последняя, цена продажи по наценке):
- действие 1 — набрать название, Enter (≈ 4 с);
- действие 2 — набрать закупку, Enter (≈ 2 с; количество = 1 из поля «×N», единица «шт», продажа по наценке, категория последняя);
- действие 3 — Enter «Готово» → скан следующего (≈ 1 с).
Нетипичное (кг, свой процент, упаковка) — по 1 дополнительному действию (клавиша/чип), не обязательно мышь.

**Узкий вид / сенсорный экран:** карточка в одну колонку, поля ≥ 44 px, кнопка «Готово» ≥ 44 px; в таблице строка нового товара — высота ≥ 72 px (название в 2 строки).

**Немедленная правка до карточки (Ф0, закрывает Б-5):** в `WarehouseWindow.axaml:1500` задать полю названия `Padding="8,0"`, `Height="30"`, `Watermark` («Название нового товара»), в `ReceivingScan.cs` после скана неизвестного кода показывать сообщение из «Закупок» (`Receive.cs:649`, 5 языков), строкам `Unknown/Internet` в узком виде — минимальную высоту 72.

## (г) Чего НЕ делать автоматически

- Не искать в интернете (и в общей базе по названию) без нажатия — как решил владелец 09.11; результат только предлагать и помечать «Из интернета».
- Не создавать товар на сервере до «Оприходовать» (как сейчас: `CreateProductAsync` при проведении, `PurchaseReceivingService.cs:1019`).
- Не подставлять название/категорию молча из «похожих»: только по явному выбору; категорию — только показать выбранной, не скрытой.
- Не генерировать штрихкод сам; не менять штрихкод, по которому товар найден (существующие правила `ReceivingGrid_BeginningEdit`).
- Не принимать Enter сканера за конец названия: код из сканера в поле названия не попадает (`BarcodeInput`/`HandleScanInsideField`, `WarehouseWindow.BulkScan.cs:66`).
- Не терять данные при новом скане с открытой карточкой: карточка сворачивается в строку, оставляя введённое (пустое название — красная пометка «нужно название»), открывается карточка следующего товара; при проведении — существующая проверка названий (`Validate`).
- Не открывать модальные окна на каждый неизвестный скан (скан блокируется; в «Товары/Ревизия» уже так: «Товар не найден → Создать» + полная `ProductEditDialog` — два окна, `WarehouseWindow.ScanLookup.cs:116`).
- Не округлять и не менять цены при выходе (правила денег: штрихкод в ячейке цены, цена-великан — уже защищены, `ReceivingLineVm.BarcodeInCellText`).

6. Повторный скан того же неизвестного кода → «Сколько штук?» (существующее окно), а не вторая карточка.
