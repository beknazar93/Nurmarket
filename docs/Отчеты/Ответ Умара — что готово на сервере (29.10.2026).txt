1. Д-4 (Б-04). Возврат по строкам со скидкой на чек — ГОТОВО
   - Сумма строки возврата учитывает долю скидки на чек. Последний возврат по чеку — ровно остаток.
   - Сумма всех возвратов не больше оплаченного. Превышение → code "refund_exceeds_paid",
     409 для нового клиента, 400 для старого; data: {paid, refunded, requested, refundable}.
   - У продажи (pos/sales/, pos/sales/{id}/) новые поля refunded_total, refundable_total.
   → Можно убрать «поправку сервера» на кассе после проверки на NBS.

2. Б-13. Оплата долга вне смены и коды ошибок — ГОТОВО
   Адреса: clients/{id}/pay-debt/, pos/sales/{id}/pay-debt/, deals/pay-any/.
   - Деньги «вне смены» (shift:null, касса «Основная касса компании», source_kind debt_repayment):
       * если запрос из программы владельца, мобилки или сайта (X-NurMarket-Client: owner/… , mobile/… , site/…)
         и shift не передан;
       * или если у владельца нет своей открытой смены.
     ВНИМАНИЕ: программа владельца должна слать заголовок owner/<версия>, иначе при открытой смене
     владельца деньги пойдут в его смену, как раньше. Так сделано нарочно: владелец часто сам стоит
     за кассой, а старая касса shift не присылает.
   - Кассир без shift — как раньше, в свою открытую смену.
   - method и payment_method принимаются оба; разные значения → 400 "field_conflict".
   - В ответе новые поля: method, payment_method, received_by{id,name}, received_at, shift, cashbox,
     applied[].sale_number, applied[].sale_debt_left, replayed.
   - Коды: no_debt, amount_exceeds_debt (data.max), amount_invalid, shift_required (только новый клиент,
     кассир без смены), shift_closed, shift_not_found, shift_not_owned (403 для нового клиента),
     method_not_allowed (data.allowed, только новый клиент), cashbox_not_found.
   - pos/checkout/ с закрытой сменой → code "shift_closed"; с чужой → "shift_not_owned"
     (403 новый клиент, 400 старый).
   - Повтор с тем же ключом после закрытия смены → 200, replayed:true.

6. mass-incoming: поле unit (Б-42) — ГОТОВО
   - unit в строке применяется к существующему и создаваемому товару. Принимается код (kg, pcs, m, l…)
     или название (кг, шт, упак, литр…). Неизвестная единица → ошибка строки code "unit_unknown".
   - Ответ: items[{client_row_id, product_id, quantity, unit, purchase_price, price, price_changed}],
     errors[{index, client_row_id, code, detail}], replayed. Старые поля остались.
   - По умолчанию вся пачка атомарна (как раньше). Частичный успех — только с полем "partial": true в теле.
   - markup_percent, category, supplier в строке — пока НЕ сделаны (в ТЗ «желательно»).

7. Б-102. Поток событий — ГОТОВО (через WebSocket)
   - Основной канал: wss://app.nurcrm.kg/ws/main/events/?branch=<id>&since=<event_id>
     Авторизация как у ws/company/: первым сообщением {"token": "<access>"} (можно ?token= или Authorization).
     Без токена за 10 с — закрытие 4401; истёк токен — закрытие 4401. Повторный {"token": …} продлевает.
   - Сообщение: {"id","type","at","branch","ids","actor", …поля типа}; ids до 500, больше — null.
   - Типы: price_changed, product_changed, stock_changed, settings_changed (app, keys[] — только имена ключей),
     sale_created (sale_id, cashbox, shift), sale_changed (возврат), shift_changed (state: opened/closed/
     cash_in/cash_out), debt_changed, client_changed, bonus_changed, staff_changed, license_changed.
     Неизвестный тип — игнорируйте.
   - Переподключение: since=<id последнего события> → пришлём пропущенные. Если пропущено больше 500,
     или since старше 7 дней — придёт {"type":"resync"} (перечитать всё).
   - Heartbeat: {"type":"ping"} каждые 20 с.
   - Права: только своя компания; сотрудник филиала — только свой филиал; кассир не получает
     настройки owner и license_changed, staff_changed — только про себя.
   - GET /api/main/events/stream/ (SSE) долгого потока НЕ держит (на сервере это заняло бы все воркеры):
     отвечает одним событием event: use_websocket, data {"url":"wss://…/ws/main/events/"}. Используйте WebSocket.
   - Склейки событий одного товара за 1 с нет; продажа присылает один stock_changed на чек.
   - Если поток не подключён — опрос с ETag/304 из п. 5.
