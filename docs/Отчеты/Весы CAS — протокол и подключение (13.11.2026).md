# Весы CAS — протокол и подключение (13.11.2026)

Разбор перед добавлением марки «CAS» в кассу и программу владельца. Решение владельца 13.11: добавить весы с печатью этикеток CAS. Образец разбора — «Rongta-RLS1000-разбор.md».

## 1. Коротко

- У CAS **два семейства протоколов по сети**, и разные модели говорят на разных:
  1. **CL5000J и CL3000 — двоичный протокол «CL5000J Communication Protocol»** (официальный документ CAS, 05.10.2007, Rev 1.0, 19 страниц, с шестнадцатеричными примерами). Кадр `Opcode(2) + Address(4) + ',' + Длина(2) + ':' + Данные + ':' + Сумма(1) + CR`, карточка PLU — структура 147 байт. Есть открытый клиент (alexesDev/cas, Go, MIT) — работает с CL5000J и CL3000. **Это подтверждено документом и сверено с независимой реализацией.**
  2. **CL5000 (старый) / CL5500 — текстовый протокол «CL5000/CL5500 Protocol's Manual» (W02A…)** с полями вида `F=<ptype>.<stype>,<размер>:<данные>`. Видел только сетевое руководство 2005 г. (текст с искажениями при извлечении) — полного описания нет. **Не реализуем.**
- CL5200, CL7200 (на них же CL-Works Pro по TCP 20304) и LP-1.6: открытого описания протокола не нашёл. Для них — только файл для CL-Works (см. раздел 6), сеть не обещаем.
- Порт по умолчанию **20304** (CL-Works, руководства CAS, инструкция Рарус). Меняется на весах (меню 1913), поэтому порт — настройка.
- На живых весах **ничего не проверено**. Всё ниже — по документам.

## 3. Кадр (подтверждено документом)

```
Opcode0  Opcode1  Address(4, LE)  ','  Длина(2, LE)  ':'  Данные(до 512)  ':'  Сумма(1)  CR(0x0D)
```
- Все числа — little-endian. «Scale ID» по умолчанию 1; от ПК шлют Address = 0, ответ весов несёт их Scale ID.
- Opcode0: `W` запись, `R` чтение, `G` «хорошо» (ответ), `N` «плохо» (ответ).
- Opcode1: `L` PLU, `N` состояние, `B` штрихкод, `A` этикетка, `S` магазин, `M` сообщение, `Y` PCS…
- **Сумма = сумма байтов от Address до второго `:` включительно, по модулю 256.** Это следует из живых примеров документа (ответ весов `47 4C 01 00 00 00 2C 04 00 3A 41 42 0F 00 3A 37 0D` → 0x37; запрос записи PLU → 0xFF). Формула из таблицы документа («ABCD → 0x88») с примерами расходится: 0x88 — это сумма БЕЗ последнего `:`. Выбрана версия по примерам (и так же у alexesDev/cas). Юнит-тесты сверяют 7 кадров документа.
- Коды ошибок (в ответе `N?` последний байт данных): 99 конец данных, 98 нет такого, 97 неверная структура, 95 неизвестный тип, 89 память заполнена, 88 память сообщений, 84 ошибка кадра/суммы, 82 номер слишком большой.

## 4. Запись PLU — команда `WL` (подтверждено документом, структура по стр. 4)

Данные = структура PLU 147 байт (+ до 300 байт «прямого сообщения» — не используем). Ответ: `G L ScaleID , 4 : DeptPLU(4) :` где DeptPLU = отдел × 1 000 000 + номер PLU (пример: отдел 1, PLU 1 → 1 000 001 = `41 42 0F 00`); при отказе `N L … : DeptPLU(4) + Ошибка(1)`.

| Смещение | Тип | Поле | Что делает касса |
|---|---|---|---|
| 0 | u16 | отдел | префикс штрихкода 20…29 (см. раздел 5) — **догадка** |
| 2 | u32 | номер PLU | закреплённый номер товара, 1…999999 |
| 6 | u8 | тип PLU | 1 весовой, 3 по количеству — **значения в документе не расписаны; взяты по порядку меню весов «1 по весу, 2 не весовой, 3 по количеству»** |
| 7 | char[40] | название 1 | первые 39 байт, остальное — в название 2 |
| 47 | char[40] | название 2 | |
| 87 | char[5] | название 3 | не используем |
| 92, 94, 96, 98 | u16 | группа, этикетка, доп. этикетка, происхождение | этикетка — из настройки (0 = по умолчанию весов) |
| 100, 101 | u8, u32 | единица веса, фиксированный вес | 0 |
| 105 | u32 | **код товара (item code)** | код из колонки «Код в штрихкоде» — это «I» в формате штрихкода |
| 109, 111, 112 | u16, u8, u8 | штук, символ, тип фикс. цены | 0 |
| 113 | u32 | **цена** | в наименьших единицах весов (125,50 → 12550 при 2 знаках) |
| 117 | u32 | специальная цена | 0 |
| 121, 125 | u32, u8 | тара | 0 |
| 126, 128 | u16 | номер формата штрихкода | из настройки (0 = «как настроено на весах») |
| 130…139 | | даты производства/упаковки/«годен до» | 0 (срок годности в этом протоколе — отдельная семантика, не трогаем) |
| 146 | u8 | сообщение | 0 |

Названия: в документе кодировка не названа. alexesDev/cas в примере пишет «Привет мир cp1251». Берём **cp1251**; кыргызские/казахские/узбекские буквы (ү, ө, ң, ў, қ, ғ, ҳ…) заменяем ближайшими русскими (у, о, н…), остальное вне cp1251 → «?». Шрифт кириллицы зависит от прошивки (русские CL5000J — есть; **на весах владельца не проверено**).

Цена и вес: число знаков после запятой задаётся на весах; их можно **прочитать** командой `RN` (смещение 5 — знаков веса, 6 — знаков цены). Поэтому «Проверить связь» показывает их, а настройка «знаков в цене» по умолчанию 2 (как в CL-Works).

## 5. Штрихкод: как этикетка CAS совместима с кассой (СВЕРЕНО по руководству, НЕ проверено на весах)

- Формат штрихкода задаётся на весах (меню 1260 «Barcode», глобально 1520) строкой из символов: `D` отдел, `I` код товара, `N` номер PLU, `P` цена, `V` контрольная цифра цены, `W` вес, `U` цена за единицу, `Q` количество, `F` префикс PLU, `C` контрольная цифра всего кода, `%` — «напечатать следующий символ как есть». Длина поля = число повторов буквы. Пример по умолчанию: `DDIIIIIPPPPPC` (EAN-13: отдел 2 + код 5 + **цена** 5 + контрольная).
- Раскладки кассы (ScaleUi.CompanyFormatText): **«по PLU»** — префикс 2 + PLU 5 + значение 5 + контрольная; **«по коду»** — префикс 2 + код 6 + значение 4 + контрольная.
- Формат для весов CAS (в кассе — `CasBarcodeFormat`): **по весу**: раскладка «по PLU» → `DDIIIIIWWWWWC`, «по коду» → `DDIIIIIIWWWWC`; **по сумме**: `DDIIIIIPPPPPC` / `DDIIIIIIPPPPC`. Используется `I` (код товара = колонка «Код в ШК», в карточке PLU поле «Item Code»), а не `N` (номер PLU): так код в штрихкоде можно задавать отдельно от номера ячейки, как у Rongta и TM-30F.
- Префикс 20…29 весы возьмут из **номера отдела** (`DD`) — так же, как у Rongta («отдел = префикс»). Отдел на весах должен существовать; это **догадка по практике русских настроек (отдел 21 и т. п.)**, документ про это молчит.
- Что делаем: в карточку PLU пишем отдел = префикс из настроек марки (20…29), код = «Код в штрихкоде», номер формата штрихкода — из настройки. **Формат штрихкода и отдел на весы сами не пишем** (команды `WB`/запись отделов не реализуем — как у Rongta: не переписываем настройки владельца). Показываем строку формата, которую надо задать на весах, и пример этикетки со сверкой кассой (как у TM-30F/Rongta).
- Вес `W` печатается в наименьших единицах (граммы при трёх знаках) — на весах с шагом 5/10 г сверять живой этикеткой.

## 6. Что нельзя было подтвердить документом

1. Работа **CL5500, CL5200, CL7200, LP-1.6** по этому двоичному протоколу — документ называется CL5000J; для CL5500 это другой (текстовый) протокол.
2. Значения «тип PLU» (1/2/3) и «отдел как префикс» — взяты из руководства оператора (меню весов), документ протокола их не расписывает.
3. Кодировка названий (cp1251 — по примеру открытого клиента), шрифт кириллицы на конкретной прошивке.
4. Порт для CL3000: по CL-Works 20304; у alexesDev в примере порт 20000 — вероятно свой.
5. Поведение при повторной записи уже существующего PLU (по документу ответ тот же `GL`; перезапись ожидаема).
6. Разрешено ли записывать PLU в отдел, которого нет в таблице отделов (может вернуть ошибку).
7. Ответ `RN` на CL3000 — по README alexesDev, «возвращает нули»; связь это всё равно подтверждает.

## 8. Что сделано в кассе (13.11.2026)

- Модель выбирается в окне «Настройки весов CAS» (вкладка «Быстрая настройка»): **CL5000J и CL3000 — по сети** (порт 20304, кадры `WL`/`RN`, пометка «не проверено на весах» в окне, подзаголовке «Весы» и итоге отправки); **CL5500, CL5200, CL7200, LP-1.6 — только файл для CL-Works** (кнопка «Сохранить файл для CL-Works», кодировка Windows-1251 по умолчанию или UTF-8, разделитель цены «.» или «,»; инструкция «Файл → Импорт → CSV»).
- Файлы: `CasProtocol`, `CasScaleService` (журнал `cas-exchange.log`), `CasScaleSettings` (JSON в `UserPreferences.CasScaleConfig`, на сервер не уходит; ключ `cas` в `ScaleBarcodeRulesSync` НЕ добавлен), `CasBarcodeFormat`, `CasCsvWriter`; окно `CasScaleSettingsWindow`; плитка «CAS» в Настройки → Весы; отправка в окне «Весы» — `ScalesPluWindow.Cas.cs`.
- На весы уходят только карточки PLU (`WL`) по одной с ответом `GL`; проверка связи читает состояние (`RN`) и показывает число знаков цены и веса на весах. Стирание, отделы, форматы штрихкода и этикеток не пишутся. В сканер сети порт 20304 не добавлен (подтвердить «это CAS» можно только командой `RN`, а сканер ищет без неё).
- Название: первые 39 байт — «Название 1», остаток по словам — «Название 2»; ү, ө, ң и др. заменяются русскими буквами (у, о, н…). Цена: наименьшие единицы при «знаках в цене» (по умолчанию 2), предел 999999.
- Профиль весов («Настройки → Весы») хранит IP и порт; модель, префикс, знаки цены — общие для кассы (не в профиле). Автоотправка изменений для CAS выключена (`ScaleAutoSendPolicy`).

## 9. Что нужно для живой проверки

1. Весы CAS CL5000J или CL3000 в сети кассы (или рядом с ПК, кабель), IP (меню 1913), порт 20304.
2. На весах: создан отдел 21 (или какой выбран префиксом), формат штрихкода `DDIIIIIWWWWWC` / `DDIIIIIIWWWWC` и глобальный формат (1520) включён; формат этикетки.
3. Порядок: «Проверить связь» (только чтение `RN`) → один товар → смотреть журнал `cas-exchange.log` → печать пробной этикетки → скан на кассе.
4. Прислать журнал обмена (hex). При ответе `N…` — номер ошибки из раздела 3.
