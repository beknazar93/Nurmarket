## A. Z-отчёт после закрытия смены без ответа сервера (деньги)

**Причина.** `CashShiftService.CloseShiftAsync` ждал ответа сервера 3 с, потом закрывал смену у себя (и ставил закрытие в очередь). У `MainWindow.ShowShiftClosedReport` ответа закрытия не было, поэтому он брал цифры из журнала кассы (`LocalShiftTotals`) с более высоким приоритетом, чем итоги сервера. Окно открывалось с `LocalReport=true` и вообще не загружало данные с сервера. В журнале кассы было 6 продаж из 13, долг без учёта оплаты (65) и только местные возвраты (−75). Отсюда выручка 423 и «Корректировка +838,98».

**Что сделано.**
- Срок ответа сервера на закрытие: **10 с** вместо 3. Пока касса ждёт, в строке состояния «Закрываю смену, жду ответ сервера…» на 5 языках, и касса занята. Если сервер не ответил, всё как раньше: смена закрывается в кассе и ставится в очередь. Повтор идемпотентен: «уже закрыта» снимает запись из очереди.
- Окно «Закрыть смену» отдаёт отчёт смены сервера, который оно уже получило (`CloseShiftDialog.ServerReport`). Z без ответа на закрытие строится из него. Логика вынесена в `Services/ShiftClosedReportBuilder.cs`:
  1. Есть ответ закрытия — как раньше.
  2. Нет ответа, но есть отчёт сервера этой смены, полученный до закрытия. Цифры продаж, долга, возвратов и внесений берутся из него, то есть те же, что у владельца. «В ящике должно быть» остаётся из окна закрытия (`ServerShiftReport.ApplyTo(..., keepShiftExpected)`).
  3. С сервера нет ничего — данные кассы. Если долг гасили в этой же смене, «Остаток долга» показывается как «—», а не как «65» красным. Продажа в долг видна строкой «Продажи в долг».
- Отчёт сервера, полученный до досылки очереди, не используется, если досылать было что (чеки или внесения/изъятия). Отчёт чужой смены тоже не используется.
- Отчёт помечен «Предварительно: сервер ещё не подтвердил закрытие смены. Данные уточняются после синхронизации — отчёт обновится сам» на 5 языках. Окно каждые 15 с, в течение примерно 5 минут, заново запрашивает отчёт смены. Как только сервер отдаёт отчёт с явным статусом «закрыта», окно перерисовывается: цифры как у владельца, включая ящик, расхождение, товары, скидки и прокат. Пометка меняется на «Цифры обновлены по данным сервера». Если «Печать» нажали до обновления, на бумаге будет строка «! Предварительно…». После обновления печатаются цифры сервера.

**Тесты** (`UiTests/Screens/ShiftCloseTimeoutZReportTests.cs`, `LivePass2711FixesUiTests.cs`):

- Отчёт чужой смены отбрасывается. Без отчёта используются данные кассы. Если долг гасили в смене, остаток долга неизвестен. С ответом закрытия отчёт не предварительный. Срок ответа на закрытие от 8 до 10 с.

## B. «В ящике должно быть» в X-отчёте после возврата на кассе
`ShiftDetailsDialog.ReturnsForExpected`: раньше, если в журнале кассы была хоть одна запись, брался только журнал. Теперь берутся возвраты сервера целиком, минус то, что по журналу кассы ушло не наличными (карта, счёт долга, товарная часть обмена, server_over). Результат не меньше наличных возвратов журнала. Если есть возврат без связи (offline=1), используется только журнал кассы, как раньше. Тот же расчёт теперь и в окне «Закрыть смену». Тесты: 834,90 → после возврата 50+25 будет 809,90 (было −50). Обмен 500 при сдаче 20 → 20.

## E. Владелец: «Смены → Сегодня → Закрытые 0»
`FinanceWindow.ShiftInPeriod`: закрытая смена попадает в период по дню закрытия (`closed_at` есть в списке смен сервера). Если `closed_at` не пришёл — по дню открытия, как раньше. Тест: открыта вчера, закрыта сегодня — видна в «Сегодня».

## G. «Некорректные чеки», первое открытие ~7 с
Причина: чтение базы (журнал и вся очередь продаж вместе с выгруженными, JSON каждой строки, SQLite под общим замком) шло в потоке окна. Теперь из очереди читаются только невыгруженные (`LoadAllUnsynced`), а первое чтение идёт в фоне: окно рисуется сразу, результат тот же. Если чтение дольше 1 с, в журнал пишется строка PERF. **Замер до/после на настоящей базе не делался**: это тестовая касса владельца, базу не трогал. Проверить по строке PERF в журнале после установки.

## J. «Использовано: …» у Нур-советника
Проверено по коду: строка добавляется только если `tools.Used.Count > 0`, а `Used` заполняется только при настоящих вызовах инструментов. Вопрос «Кто должен больше всех?» решился сводкой без вызовов, поэтому строки нет, и это правильно. Тест: без вызовов `Used` пуст и строки нет, после `list_sections` — одна запись.

## H. Вкладки «Весов» без мыши
Вкладкам добавлены имена для диктора (`AutomationProperties.Name`). Раздел теперь переключается по `IsChecked`, то есть и через UI Automation, а не только по щелчку. Клавиатура: ←/→/Home/End. Тест: выбор через IsChecked и Home переключают раздел.
