# Ответ сервера на ТЗ 30.10.2026: что готово для кассы

Сделано в ветке `nurcrm-changes-2026-10-29` (репозиторий NurCRM-Microservices-Service, папка `backend-django/`). На боевом сервере **пока нет**: будет после выкатки, о ней сообщим отдельно. Старые кассы работают как раньше: все поля новые и необязательные.

## №9. Ссылка на электронный чек (QR)
- `POST /api/main/pos/sales/{id}/share-link/` → `200 {url, token, expires_at, pdf_url, created}`.
  - Повторный вызов для той же продажи возвращает ту же ссылку и `created: false`.
  - Срок жизни ссылки 90 дней. Токен случайный, 192 бита.
- `DELETE /api/main/pos/sales/{id}/share-link/` → `{revoked: true}`. После этого страница отвечает 404. Новый `POST` выдаст новую ссылку, старая не оживёт.
- `GET https://app.nurcrm.kg/r/<token>` — страница чека без входа. На ней: магазин, адрес, телефон, номер и дата, строки, скидки, бонусы, способ оплаты, итог, кассир (имя), статус (`paid` / `partially_returned` / `returned` / `debt`), кнопки «Скачать PDF» и «Печать».
  - Язык выбирается по `Accept-Language` (ru, ky, uz, tr, en) или по `?lang=`.
  - Про покупателя на странице только инициалы.
- `GET .../r/<token>.pdf` — тот же чек в PDF.
- `GET /api/public/receipts/<token>/` — тот же чек в JSON. Добавлены поля `company.address`, `company.phone`, `cashier`, `client` (инициалы), `status`, `bonus {earned, redeemed}`, `totals.returned_total`.
- В `pos/sales/` и `pos/sales/{id}/` появилось поле `share_url` (null, если ссылки нет или она отозвана).
- Права: любой пользователь своей компании. Чужая продажа → 404.
- Старый `pos/sales/{id}/public-link/` (Н-32) работает как раньше.

## №10. Возврат по строкам со скидкой
- В `pos/sales/{id}/` у каждой строки (`items[]`) появились три поля:
  - `refundable_quantity` — сколько ещё можно вернуть;
  - `refundable_amount` — сколько денег вернёт сервер за весь остаток строки;
  - `unit_refund_price` — за одну штуку с долей скидки на чек.

  Правило: цена после скидки на позицию × (итог чека / сумма строк), округление до копеек. Последний возврат — ровно остаток чека. Сумма `refundable_amount` по всем строкам равна итогу чека.
- В ответе возврата появилось `refund.lines: [{sale_item_id, quantity, amount}]`. Просим брать суммы отсюда, а не считать на кассе. Сумму, присланную кассой, сервер не принимает: он считает сам.
- Новая касса (заголовок новой версии): если просят вернуть больше остатка строки, ответ `409 {code: "refund_exceeds_paid", data: {line_id, requested_quantity, max_quantity, max_amount}}`. Старая касса получает прежний ответ 400.
- По чекам 001916 и 001909: возвраты прошли 27–28.10, ещё на старом коде сервера. Тогда скидка на чек при возврате не учитывалась: по 001916 при чеке на 3,60 вернули 2,00 + 2,00. С выкатки 29.10 сервер вернул бы 1,80 + 1,80.

## №11. Чек из очереди при нулевом остатке
- `POST /api/main/pos/checkout/` с `"allow_negative_stock": true`: продажа проходит, даже если остатка не хватает, и остаток уходит в минус.
  - В ответе `stock_negative: [{product_id, variant_id, balance}]` — какие товары ушли в минус. Решение по ним за владельцем.
- Без флага всё как раньше: `insufficient_stock`.
- Офлайн-досылка `offline: true` + `offline_created_at` и раньше принималась в минус (Н-15). Теперь она тоже возвращает `stock_negative`.
- Флаг ставить **только** для чеков из очереди, то есть для продаж, которые уже состоялись.

## Поступления и партии
1. `GET /api/main/suppliers/receipts/?product_id=<id>` (можно `product=`) возвращает только приходы с этим товаром, а в `items` — только его строки. Пагинация прежняя.
2. Новые поля прихода:
   - `number` — номер прихода внутри компании. Старым приходам номера проставятся по порядку создания.
   - `document_number`, `document_date` — номер и дата накладной поставщика. Передаются в `POST suppliers/{id}/receipt/`, дата в формате `YYYY-MM-DD`.

   Новые поля строки: `batch_id`, `batch_number`, `batch_remaining` — партия (метка Б-61) и её остаток сейчас. Если у строки нет партии, там `null`.
3. Файл накладной:
   - `POST /api/main/suppliers/receipts/{id}/file/` (multipart, поле `file`). Принимаются xlsx, xls, PDF, PNG, JPG, WebP до 5 МБ.
   - В ответе и в самом приходе появились `attachments: [{id, url, size, content_type, sha256, created_at}]` и `file` — ссылка на первый файл.
   - Удалить файл: `DELETE .../file/{attachment_id}/`.
4. `payment_type`, `paid_amount`, `debt_amount` в `suppliers/receipts/` уже были (Н-10).
5. `created_at` приходит с часовым поясом, например `2026-10-30T15:20:00+06:00`. `created_by` — id сотрудника, который принял приход, рядом прежний `created_by_name`.
