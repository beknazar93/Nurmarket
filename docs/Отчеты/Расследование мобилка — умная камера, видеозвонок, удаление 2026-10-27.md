## 1. Умная камера по фото не находит существующий товар

### 1.1. Путь «снимок → ИИ → каталог»

1. Снимок: `LiveShotPage.open` (`lib/features/scan/live_shot.dart:168`) → JPEG.
2. ИИ: `VisionService.recognize` (`lib/core/ai/vision.dart:898–935`), подсказка «Ты распознаёшь товары магазина в Кыргызстане… JSON {name, brand, size, barcode, count, label_price}». Язык названия не задан, многословность не ограничена. В режиме `invoice` — «название как в накладной», штрихкод не просится.
3. Сопоставление: `VisionService.match` (`vision.dart:1332–1357`):
   - штрихкод от ИИ с верной контрольной цифрой → `db.productByScan` → 0,9;
   - из `seen.title` (= бренд + название + объём) берутся **первые 4 слова длиной ≥ 3**, к каждому — его латиница→кириллица (`normWord`), от каждого — **первые 5 букв**, и `db.searchProducts(q, limit: 40)` (`database.dart:129–148`: `search_key LIKE '%q%'`, сортировка **по алфавиту**, первые 40);
   - каждому кандидату — `nameScore` (`vision.dart:1310–1318`): общие слова (совпадение целиком или по первым 4 буквам) `common/want·0,6 + common/have·0,4`; разный объём → не выше 0,4;
   - в ответ — 3 лучших.
4. Решение «узнан»:
   - продажа: `SeenMatch.best` — ≥ 0,5 (`vision.dart:36`), в списке показываются и слабые кандидаты;
   - **склад** (полка/накладная/ценники): `_CamItem` берёт товар только при ≥ **0,75** (`smart_camera.dart:589–590`), иначе карточка в разделе «Новые» с чипами «Это «…»?» (`smart_camera.dart:871–894`). Для владельца это и есть «не нашла».
5. Эталоны обучения (`exactMatches`, сверка снимка с эталонами через `vision.identify`) — **только при `mode == 'sale'`** (`smart_camera.dart:107`, `recognizeSaleShot`). В складском экране, в видеозвонке (`call_video_bridge.dart:251–252`: «Эталоны обучения здесь не используются») и в накладной — нет.

Каталог телефона — целиком (страницы по 300, до 100 страниц = 30 000 товаров, `catalog_repository.dart:17–50`); архивных/скрытых товаров в данных нет (поля нет), остаток в ранжировании не участвует. Значит, «ищем только в загруженной странице» — **не причина**; причина — способ поиска и оценки.

Где теряется совпадение (по строкам таблицы):
1. **Числа и единицы — «слова».** `_words` оставляет «1л», «500», «мл», «1000» (длина ≥ 2). «1л» у ИИ не равно «1» + «л» в карточке → лишнее «несовпавшее слово». «Адыгене 1л» (2 слова) против «Адыгене вода минеральная 1 л» → 1 общее из 3 → 0,40.
2. **Многословие ИИ штрафуется** с весом 0,6 (доля слов ИИ, найденных в карточке). Короткие карточки магазина («Фанта 0.5», «ASU Негаз 1 л клуб-киви») против описательного ответа ИИ теряют 0,2–0,4.
3. **Транслит только латиница → кириллица и грубый:** `y → й` («Adygene» → «адйгене»: первые 4 буквы «адйг» ≠ «адыг»), `c → к`, нет `ck`, `ee`, `ph`. Обратного направления нет вовсе: в `search_key` латиница хранится латиницей, поэтому кириллический ответ ИИ («Асу», «Фанта») не находит латинскую карточку («ASU», «Fanta») поиском — только случайно через другие слова.
4. **Поиск кандидатов уже оценки:** запрос — первые **5** букв (`vision.dart:1347`), а сравнение — по **4** («сникк» не найдёт «сникерс»). Лимит **40 по алфавиту**: на частых словах («вода», «water», «молоко», «сок») нужный товар может не попасть в 40. В примере «Adygene mineral water» «Адыгене» не нашлось вовсе, а «water» дал бытовую химию.
5. **Нет весов слов:** бренд («ASU», «Адыгене») весит столько же, сколько «вода».
6. **Порог склада 0,75** без выбора «лучший из похожих» — всё, что 0,5–0,75, уходит в «Новые».
7. **Штрихкод с упаковки** используется, только если его прочитал ИИ и он есть в базе телефона; сам снимок сканером штрихкодов не проверяется (а `analyzeImage` уже есть в `live_video.dart:262–266` и `payment_qr.dart:316`); справочник NurCRM по этому коду не спрашивается.

«Фанта 0.5» на NBS: в каталоге NBS Fanta нет вовсе (ни «фант», ни «fant») — там «не нашла» верно.

### 1.3. Предлагаемый алгоритм (без новых зависимостей, без изменения схемы drift)

Новый файл `lib/core/catalog/product_matcher.dart` — одна функция для умной камеры, накладной (`InvoiceMatcher`), поиска звонка и видеокарточки.

1. **Нормализация строки:** нижний регистр, `ё → е`; сокращения до разбиения: `н/г`, `н/газ`, `б/г`, `негаз.` → `негаз`; `газ.` → `газ`; `ж/б`, `ст/б`, `пэт` — оставить словом; склеенное «число+единица» разделить («1л» → «1 л», «500мл» → «500 мл»); «0,5»/«0.5» не резать по точке.
2. **Объём/вес — отдельно, не словами:** `мл/ml/л/l/литр*/кг/kg/г/гр/g/шт`; голая дробь ≤ 3 («0.5», «1,5») — литры. Совпал объём → +0,1; другой объём того же рода → не выше 0,4 (как сейчас); у одной стороны объёма нет → без изменения.
3. **Одна азбука для обеих сторон** (и каталог, и ответ ИИ, и речь): латиница → кириллица (как `normWord`, но `y` после согласной → `ы`, `ck → к`, `ph → ф`, `ee → и`), затем «скелет»: `й → и`, `ы → и`, `э → е`, `ь/ъ` убрать, двойные буквы → одна.
4. **Равенство слов:** точно; или короткое (≥ 3 букв) — начало длинного («негаз» ⊂ «негазированная», «клуб» ⊂ «клубника», «кока» ⊂ «кокакола»); или для слов ≥ 6 букв расстояние Левенштейна ≤ 1 (опечатка). Короткие слова нечётко **не** сравнивать — в наброске это давало «кымыз» к «киви» и «кант» к «фанта».
5. **Небольшой словарь синонимов** (5 языков ИИ/речи): water → вода, still → негаз, sparkling → газ, orange → апельсин, strawberry → клубника…; дополняется алиасами обучения (раздел 4).
6. **Веса слов — IDF по каталогу магазина** (`ln(N / df)`): бренд и вкус весят больше, «вода», «сок», «1» — меньше.
7. **Оценка:** `0,65 · (вес слов карточки, найденных в ответе) + 0,35 · (вес слов ответа, найденных в карточке)` + поправка объёма. Карточка короткая, ответ ИИ длинный — оценка высокая; лишние описательные слова ИИ почти не мешают.
8. **Кандидаты — весь каталог в памяти:** список `(id, токены, объём)` строится один раз после загрузки каталога (`catalog.syncedAt`) — 30 000 товаров × ~5 слов, десятки миллисекунд; без `LIKE` и лимита 40.
9. **Выдача:** топ-5 с оценками. Сам товар выбирается, только если лучший ≥ 0,85 **и** отрыв от второго ≥ 0,15; иначе — карточка «Похоже на:» с 3–5 вариантами крупно (а не раздел «Новые»). Порог 0,75 на складе убрать в пользу этого правила.
10. **Штрихкод первым:** (а) снимок прогнать `MobileScannerController.analyzeImage` (уже используется) **до** ИИ — код прочитан → `CodeLookup.find` (телефон → сервер) → готово без Gemini; (б) код от ИИ с верной цифрой → то же; (в) кода нет у магазина → `GlobalProducts.find(code)` → название справочника → сопоставление по названию (раздел 6: так ловятся опечатки и чужие коды).
11. **Подсказка ИИ:** «name — как на упаковке, коротко (бренд, вид, вкус), без описаний и рекламных слов; brand — как на упаковке (латиница/кириллица); size — объём/вес; name_ru — то же по-русски, как назвал бы продавец». Матчер пробует `title` и `name_ru`, берёт лучшее (решает «Sprite» ↔ «Спрайт»).
12. **Эталоны** (`exactMatches`) — во всех режимах умной камеры и в видеозвонке для 1–2 лучших кандидатов, а не только в продаже.
13. **Самообучение по выбору:** нажали чип «Это «…»?» / выбрали вариант → сохранить алиас «нормализованное название ИИ → id товара» (раздел 4). Следующий раз — оценка 1,0.

Набросок п. 1–9 уже есть в `match_repro.dart` (`tokens`, `skel`, `tokEq`, `score2`, `matchNew`) — по таблице выше все складские случаи становятся «узнан», «Adygene» находится, ложных совпадений на 343 товарах NBS выше 0,45 нет.

## 4. Обучение умной камеры в редактировании товара

### 4.1. Что есть

- «Обучить камеру» — `teachExistingProduct` (`smart_camera.dart:320–344`): до 5 снимков видоискателем (справа, слева, сверху, спереди, сзади — `teachCamera`, `:275–302`), затем шаг «Штрихкод» (`BarcodeBindPage`), если у товара его нет.
- Где кнопка: в карточке товара — **в «⋮»** (`product_edit.dart:712, 718`); в меню склада для пользователей без права «Склад» (`stock_screens.dart:141`); в «Новом товаре» — видимая кнопка (`new_item.dart:996–1016`). У владельца нажатие на товар открывает сразу карточку, поэтому видимой кнопки он не встречает.
- Хранение: `ProductRefs` (`lib/core/ai/product_refs.dart`) — до 3 снимков на телефоне (`refs/`), список — настройка `refs.index`; снимки уходят в NurCRM доп. фото товара (`shareTeachShots`) — другие телефоны берут их эталонами (`RefCache.remote`). Минус: эти фото видны на сайте (пункт Б-40 ТЗ — `purpose=ai_ref`, ещё не сделан сервером).
- Использование: `vision.identify` (кадр против эталонов) — **только в продаже**.
- «Как назвал ИИ» (алиасы) — нигде не хранится; по Grep `alias|embedding|samples` — ничего для камеры (в кассе есть `VoiceProductAliases` для голоса).

### 4.2. Что значит «обучение» и минимальный дизайн

Обучение = (а) эталонные снимки (упаковка с 3–4 сторон) + (б) алиасы — как товар называют ИИ и люди. Без новых зависимостей и без изменения схемы drift:

1. **Видимо:** в карточке товара — плитка «Умная камера»: «Обучена: 3 фото · 2 названия» / «Не обучена» и кнопка «Обучить камеру» (48 dp), рядом «Сбросить» (удалить эталоны).
2. **Снимки:** как сейчас (`teachCamera`); при обучении — сразу распознать первый снимок (`vision.recognize(mode: 'sale')`) и сохранить ответ ИИ как алиас (то, как ИИ «видит» этот товар).
3. **Алиасы — общие для компании:** ключ `CamAliases` в `api/main/app-settings/nurmarket-mobile/` (тот же механизм, что `AiAccess`/`DebtAccess`: `PATCH {key: value}` меняет только свой ключ, `ai_access.dart:203–210`), значение `{productId: ["asu негаз клубника киви", …]}`, ≤ 5 на товар, ≤ 3 000 товаров. Копия — `db.setSetting('cam.aliases', …)` для работы без связи. Запись: прочитать → слить → записать (две записи с разных телефонов не затирают друг друга целиком; последний пишет — риск принят, алиасы восстановимы).
4. **Пополнение без съёмки:** выбор чипа «Это «…»?» на складе, варианта «Похоже на» в продаже или в звонке → алиас «название ИИ → товар».
5. **Использование:** матчер (раздел 1.3) — совпадение алиаса = 1,0; `exactMatches` — во всех режимах умной камеры и в видеозвонке.
6. **Синхронизация эталонов между телефонами** — уже есть через фото NurCRM; после Б-40 — загружать с `purpose=ai_ref`, чтобы не светились на сайте.

Файлы: `lib/features/stock/product_edit.dart` (плитка), `lib/features/scan/smart_camera.dart` (алиас при обучении и выборе), новый `lib/core/ai/cam_aliases.dart` (загрузка/слияние/копия), `lib/core/catalog/product_matcher.dart` (учёт алиасов), `lib/features/assistant/call_video_bridge.dart` (эталоны), l10n ×5; тесты: слияние алиасов, «выбор чипа → следующий раз 1,0».

## 5. Видеозвонок (Gemini Live)

### 5а. «Не находит товар на складе»

Путь: модель вызывает `product_info` / `stock_list` (`lib/core/ai/assistant/read_tools.dart:706–928`) или действие с товаром → `_pickProduct` (`action_tools.dart:426–490`). Оба ищут через `db.searchProducts(query)` (`read_tools.dart:115`, `action_tools.dart:183`) — **каждое слово запроса должно быть подстрокой** `search_key` (название + артикул + штрихкод + категория + бренд в нижнем регистре). Речь распознаётся кириллицей, модель передаёт слова как услышала. Воспроизведение (`out3.txt`, каталог NBS):

| ASU клубника киви | **ничего** | ASU Негаз 1 л клуб-киви 0,85 |

**Исправление:**
1. `ReadSource.catalog(query)` и `ActionHost.findProducts(query)`: пустой `query` — как сейчас; иначе — `product_matcher` (топ-30 с оценкой ≥ 0,45; «одно точное» — если лучший ≥ 0,85 и отрыв ≥ 0,15). `productNameMatchesQuery` в `_pickProduct` оставить только как дополнительный фильтр, если он не опустошает список.
2. `stock_list` с `query` — тот же матчер, порог 0,45.
3. `VisionVideoRecognizer._product`: правило «≥ 0,85 и отрыв 0,15» вместо 0,99; эталоны (`exactMatches`) для 1–2 лучших; штрихкод со снимка уже есть (`still.barcode`).
4. Тест: подставной каталог (из `catalog.json`) — таблица выше зелёная.

Есть (`action_tools.dart`):

Почему владелец «не может редактировать в звонке»:
1. Подсказка модели при видео (`assistant_prompt.dart:121–127`): «Ты ничего не проводишь и не меняешь по картинке: не говори «провёл», «записал», «добавил»». Модель трактует это как запрет правок во время видео.
2. Каждое сообщение карточки камеры кончается «Ничего не меняй» (`call_video_bridge.dart:133–137`).
3. Товар с камеры нельзя назвать «этот»: инструменты принимают только `query`/`barcode`; модель пересказывает название → строгий поиск (5а) → «не нашла».
4. Нет инструментов: название, категория, единица, доп. штрихкод, фото, архив.

**Дизайн:**
1. Подсказка видео: «По картинке сам ничего не меняешь. По просьбе пользователя голосом меняй товар инструментами; товар с камеры передавай как `ref: "camera"`». Карточки: вместо «Ничего не меняй» — «Меняй только по просьбе пользователя: ref = camera».
2. `CallController` хранит `focusProductId`: последний товар видеокарточки, выбранный «Похоже на», последний `product_info`, строка таблицы. Аргумент `ref` (`camera` | `last` | `table:<id>:<row>`) в `set_price`, `product_edit`, `delete_product`, `receive_simple`, `write_off` — `_pickProduct` сначала смотрит `ref`.
3. Расширить `product_edit` (поля уже есть в `ProductDraft`, `product_edit_repository.dart:14–39`): `new_name`, `category`, `unit`, `add_alt_barcode` (+ `pack_qty`), `remove_alt_barcode`. Ворота: `new_name`/`category` — слова должны прозвучать (`objects`), цифры штрихкода — вслух (`numeric`). Отмена — `_undoDraft` с проверкой name/category/unit/alt (сейчас сравнивает цену, штрихкод и минимум).
4. «Архивировать» — после поля сервера (раздел 3.2 п. 6); до того — нет.
5. Подтверждение: правки цены уже `confirmInAskMode`; аномальная цена (×3, ниже закупки, наценка > 500 %) — тот же вопрос, что в карточке (В-2 аудита) — «Цена 85 → 8 588 (×101). Поставить?».
6. Журнал — `k.commit` как сейчас (`ai_actions.jsonl`, «Действия ИИ», отмена).

### 5в. Добавление товара в звонке: «спереди, сзади, сбоку, штрихкод»

Что уже позволяет:
- `LiveVideo.takeStill(preset)` (`live_video.dart:914–942`) — чёткий снимок с потока, `VideoStill.bytes` + `barcode` (сканер штрихкода по снимку, `analyzeImage`, `:262–266`);
- `CallController.askVideo` (`call_controller.dart:1331–1357`) — снимок → распознавание → карточка + `[Программа] …` модели;
- `videoIntent` (`call_video_bridge.dart:49–84`) — фраза → действие без кнопки;
- `create_product` → ручка `new_item` (`new_item.dart:100, 115–136`) — заполняет название, цену, закупку, штрихкод, категорию, единицу; фото и эталоны не принимает;
- `teachCamera`/`ProductRefs.save`/`shareTeachShots` — сохранение эталонов; `GlobalProducts.find` — название по штрихкоду; `CodeLookup.find` — дубль по штрихкоду.

Чего нет: сценария шагов, инструмента «шаг фото», передачи снимков в «Новый товар».

**Сценарий:**
1. Пользователь: «добавь товар» (слова `Intents.productCreate`) при включённой камере → инструмент `video_add_product` (группа `action`, право `canRoute('/admin/new-product')`) запускает мастер в `CallController` и сразу возвращает `say`: «Покажите товар спереди и скажите „готово“». Модель произносит это (правило «итог как есть»).
2. Шаги: **спереди → сзади → сбоку → штрихкод**. На экране звонка — полоса шагов «1 Спереди ✓ · 2 Сзади · 3 Сбоку · 4 Штрихкод» и большая кнопка «Снять» (48+ dp); «готово / есть / снимай / даяр / tayyor / done / tamam» — то же, что кнопка (как `videoIntent`). Каждый шаг — `takeStill(high)`, снимок держится в памяти звонка (не в журнале).
3. После каждого снимка — `still.barcode`: прочитан → `CodeLookup.find` (телефон → сервер). **Товар уже есть** → «[Программа] Такой товар есть: «…», 85 сом, остаток 12. Добавлять не нужно» → мастер предлагает «Обучить камеру этими снимками?» (то же, что `teachExistingProduct`, по «да»).
4. Шаг «Штрихкод»: «Покажите штрихкод крупно». 2 неудачи → «Скажите цифры штрихкода или „пропустить“» (цифры — через ворота `numeric`).
5. Название: `GlobalProducts.find(barcode)` (справочник NurCRM) → иначе `vision.recognize(front, mode: 'sale')` → «[Программа] Похоже: «ASU Негаз 1 л клуб-киви». Спроси цену продажи и закупку».
6. Цены — только вслух (ворота). Аномальная цена — вопрос.
7. Создание: `create_product` с новыми полями `ref_shots: "wizard"` → ручка `new_item` получает снимки: главное фото — «спереди», остальные — эталоны (`_camShots`) и доп. фото; экран «Новый товар» показывается заполненным, звонок сворачивается в плашку (как сейчас), сохранение — через ручку (`_aiSink.run(_save)`), запись в журнал, отмена — «удалить созданный, пока нет продаж» (`why.delete` уже есть).
8. Камера: звонок держит камеру; экран «Новый товар» свой сканер не включает (он включается только по кнопке), конфликтов нет; если пользователь сам нажмёт сканер — `CameraGate` (как сейчас).

Файлы: `lib/features/assistant/call_controller.dart` (мастер, шаги, снимки), `lib/features/assistant/call_overlay.dart` / `call_video_view.dart` (полоса шагов, «Снять»), `lib/features/assistant/call_video_bridge.dart` (интент «добавь товар», «готово»), `lib/core/ai/assistant/action_tools.dart` (`video_add_product`, поля `create_product`), `lib/core/ai/assistant/ai_handles.dart` + `lib/features/admin/new_item.dart` (снимки в ручке), `assistant_prompt.dart` (правило мастера), тексты 5 языков; тест на подставной камере (как `call_rig`).

## 6. Экран «Приёмка»: пять кодов «Неизвестный штрихкод»

### 6.1. Путь

«Склад → Приёмка» = `ReceiveScreen` (`stock_screens.dart:367–592`, маршрут `/stock/receive`, без поставщика и цен). Скан → `ScanScreen(returnCodes: true)` (в самом сканере подсказка «+1 · код» тоже только по базе телефона, `scan_screen.dart:185–196`) → `receiveScanHit` (`stock_screens.dart:365`) → `db.productByScan(code, allowWeightLabel: false)` → `barcodeVariants` (EAN-13 ↔ UPC-A, GTIN-14, UPC-E, русская раскладка) → основной штрихкод, артикул, доп. штрихкоды. **Только база телефона.** Нет:
- запроса на сервер (`CodeLookup.find` — есть, им пользуется обычный сканер, `scan_screen.dart:198`);
- справочника NurCRM (`GlobalProducts.find` — подключён в сканере продажи, новом товаре, накладной, массовом добавлении, но **не здесь**);
- кнопки «Завести товар».

Текст «… · администратор получит его и заведёт товар» (`app_localizations_ru.dart:1802–1803`) **неверен**: `postReceiving` (`stock_repository.dart:62–96`) отправляет только найденные строки, список `_unknown` живёт в черновике телефона и стирается после «Провести». Повторный скан неизвестного кода не считается (`if (!_unknown.contains(code))`) — количество теряется.

EAN-8 (48745000) поиск поддерживает: в `barcodeVariants` 8 цифр с первой «4» не считаются UPC-E и ищутся как есть; справочник 8-значные коды тоже принимает (`isJunkGlobalCode` отсекает < 6 и > 14).

### 6.3. Исправление

1. `ReceiveScreen._scan` (и ревизия, `stock_screens.dart:676`): код не найден в телефоне → `CodeLookup.find(db, api, code)` (2 с, как сканер). Найден — строка (+ товар в базу телефона уже кладётся в `CodeLookup`).
2. Не найден → `GlobalProducts.find(code)` (сначала локально, потом сервер, 2 с). Карточка вместо «Неизвестный»:
   - «Найдено в справочнике NurCRM: «ASU Негаз 1л»» + кнопка «Завести товар» (`/admin/new-product?barcode=…`, только при `canRoute('/admin/new-product')`; название подставит сам «Новый товар» — он уже смотрит справочник) → после создания строка сама попадает в приёмку с накопленным количеством;
   - если матчер (раздел 1.3) по названию справочника находит товар магазина ≥ 0,75 → «Похоже на ваш «…» — Привязать штрихкод» (доп. штрихкод через `ProductEditRepository`, право «Склад»);
   - если у товара магазина основной код совпадает в первых 12 цифрах, а контрольная цифра в карточке неверна (`VisionService.validEan` = false) → «Опечатка в штрихкоде карточки — Исправить».
3. Совсем неизвестный код — честный текст: «Нет в каталоге и в справочнике NurCRM. Заведите товар или отложите приёмку» (5 языков) + «×» убрать карточку. «Администратор получит» — убрать (или сделать по-настоящему: общий список в `app-settings` `UnknownBarcodes` с количеством и автором, показывать в «Уведомлениях» — по решению владельца).
4. Считать повторные сканы неизвестного кода (количество), чтобы после «Завести товар» в приход ушло верное число.
5. Подсказку в сканере (`scan_screen.dart:190–193`) — по той же цепочке (локально + справочник без сети): «+1 · Пепси 1.5л (справочник)».
6. Тест: подставные `CodeLookup`/`GlobalProducts`: 5 кодов из таблицы → найдено 1, «опечатка» 1, «привязать» 2, «завести» 1.

## 7. Риски

- **Ложное «узнал» на складе** опаснее, чем «не узнал»: остаток уйдёт чужому товару. Поэтому сам товар — только при ≥ 0,85 и отрыве 0,15, иначе выбор; тест на каталоге NBS — без ложных выше порога.
- **Скорость и память:** индекс 30 000 товаров в памяти — ~5–10 МБ, строится в изоляте после синхронизации; до готовности — старый путь.
- **Gemini:** длиннее подсказка и поле `name_ru` — +~10 % токенов; PDF — до 8 МБ и тайм-аут 40 с; лимиты общие с кассой и ботом. Чтение штрихкода со снимка до ИИ экономит запросы.
- **Удаление товара на сервере:** что NurCRM делает с продажами/приходами удалённого товара — не проверено (NBS — только чтение). Проверить на тестовом товаре без продаж и с одной продажей, по согласованию.
- **Общие настройки (`app-settings`)** — последний записавший выигрывает; для алиасов — чтение-слияние-запись, размер ≤ 200 КБ.
- **Звонок:** снятие запрета «не меняй» расширяет действия модели; держатся ворота намерения (слово + числа вслух), режимы `view_only`/`ask_money`, журнал и отмена. Мастер добавления — снимки только в памяти, не в журнал (приватность кадра).
- **Камера:** звонок и «Новый товар»/умная камера не должны держать камеру одновременно — через `CameraGate`, как сейчас.
- **Данные магазина:** 18 % штрихкодов NBS с ошибкой — подсказки «исправить/привязать» должны предлагать, а не менять сами.
- Сборку и `flutter test` не запускал (другой исполнитель собирает APK). `dotnet test` не применим и не запускался.
