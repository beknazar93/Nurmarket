# Накладные: умное сопоставление товаров и чтение рукописных (03.11.2026)

Задача владельца: при добавлении накладной на склад касса добавляла ПОХОЖИЕ товары как новые (разные компании пишут один товар по-разному).
Теперь касса сравнивает с товарами склада и спрашивает «новый или тот же (увеличить остаток)». Выбранный вариант: «1 + 2 сразу, 3 кнопкой, плюс рукописные».
Состояние: собрано (касса и Portable), проверено консольным стендом без сети; **не установлено, не закоммичено, вживую (с окном) не смотрено**. Мобилка не тронута.

## Что сделано по пунктам

### 1. Умнее оценка (InvoiceNameParser, InvoiceNameData, InvoiceMatcher)
- **Сокращения** — словарь в `InvoiceNameData.Abbreviations` (мол → молок, конд → кондитерск, шок → шоколад, печ → печень, нап → напит, газ → газирован, б/а, ж/б, ст/б, пл/б, т/п, ср-во и др.). Сокращаются до основы слова, поэтому «газ» совпадает и с «газированный», и с «газированная». Слово с точкой («Мол.», «Кол.») короче 4 букв считается сокращением и без словаря: достаточно, что чужое слово с него начинается. Словарь правится в одном месте.
- **Единицы**: «1л» = «1 литр» = «1000 мл», «0,5кг» = «500 г» = «500 гр». Объём хранится в мл, масса в граммах. «шт», «штук», «pcs», «GB» отбрасываются, число остаётся обычным числом. Обычное число совпадает с объёмом/массой, если это то же значение в литрах, мл, кг или г («Кока-кола 0,5» = «Coca-Cola 0.5л», «Шоколад 100» = «Шоколад 100г»). Объём против массы — не совпадение.
- **Латиница ↔ кириллица**: звуковой ключ слова (кириллица → латиница, «ck» → k, «c» перед e/i → s, иначе k, «y» → i, «x» → ks, «w» → v, повторы схлопываются). Coca-Cola ↔ Кока-кола, Fanta ↔ Фанта, Snickers ↔ Сникерс, Twix ↔ Твикс. Индекс кандидатов `_byToken` сохранён, ключи теперь звуковые (+ ключи «m:a15» для кодов моделей, чтобы «A15 128» вообще находил кандидатов: раньше слов длиннее 3 букв в нём не было).
- **Вложенность**: все слова и числа короткого названия есть в длинном (не меньше двух штук) — оценка не ниже `0,72 + 0,2 × доля длины`. «A15 128» ⊂ «Samsung Galaxy A15 128GB» даёт 0,84.
- **Пороги**: 0,75 как раньше; для коротких названий (слов и чисел не больше 3) — 0,70; в список «выбрать другой» попадает от 0,55. Подтверждение обязательно для всего нечёткого.
- **Запреты**: числа, объём, модель разные у обеих сторон — оценка 0 (одинаковое правило «15 против 16» теперь работает и для «1 л против 2 л»). Точные совпадения (штрихкод → артикул → точное название → слова в другом порядке) работают как раньше, до нового кода.

### 2. До 5 кандидатов (InvoiceMatch.Alternatives, окно «Загрузка накладной»)
- `InvoiceMatch.Alternatives` — до 5 товаров по убыванию похожести, лучший первым (при равенстве выигрывает тот, что в наличии).
- В ячейке статуса: «✓ Это он», «≠ Другой товар» (как было) и новая кнопка **«▾»**. Меню «▾»: другие кандидаты («≈ Название · 87 % · остаток 12 · закупка 54 (в накладной 60)» — различия по остатку и закупке, при расхождении закупки больше 15 % пометка), «Новый товар — это не он», «Забыть соответствие» (если найдено по памяти), «Пропустить строку».
- Выбор из списка = явное подтверждение; строка начисляет остаток выбранному товару. Если единица в накладной («упак») не совпала с единицей карточки («шт») — всё равно просит «✓ Это он» (`UnitWarning`). Количество и закупка, которые кассир успел поправить, при смене товара сохраняются.
- Под названием строки «Похожий» теперь написано «в карточке: остаток N, закупка X» и пометка, если закупка в накладной заметно другая.
- Для строк «Новый» с слабыми кандидатами (0,55–0,74) кнопка «▾» тоже есть: список по просьбе, автоматически ничего не предлагается.
- **Слияние одинаковых строк**: после «Это он» / выбора из списка строка склеивается с такой же строкой того же товара и той же закупки (`MergeSame`); неподтверждённые и со `UnitWarning` не склеиваются, как и раньше.

### 3. Память поставщика (InvoiceMatchMemory)
- Файл `%APPDATA%\<папка данных>\purchases\invoice-match-memory.json` (`NurMarketKassa` / `NurMarketOwner`). Папка `purchases` входит в список очистки при смене компании (`AccountDataIsolation.CompanyItems`), поэтому чужой компании записи не достаются; записанные id товаров при применении сверяются с текущим каталогом (товара нет — запись игнорируется).
- Запись: название у поставщика, нормализованное (`InvoiceNameParser.MemoryKey` — слова и числа отсортированы, регистр, «1л» = «1 литр» не важны) + ключ поставщика (`InvoiceImportRegistry.SupplierKey`: id / ИНН / название из шапки накладной, нет шапки — общий ключ «»), id товара, время, название как в накладной (для подсказки чтению фото). Секретов нет.
- Пишется при «Добавить в приёмку» для подтверждённых «похожих» и выбранных из списка/ИИ строк; «Новый товар» не запоминается. Строки, убранные кассиром, не запоминаются. Если запись опровергнута («≠» на строке, найденной по памяти) — она заодно забывается.
- Применяется после точных совпадений и **перед нечётким**: `Kind = Memory`, статус «Найден · память поставщика», подтверждение не нужно, но строку можно изменить («≠», «▾»). «Забыть соответствие» убирает запись сразу и подбирает строку заново.
- Не больше 5000 записей (старые вытесняются), запись атомарная через `AtomicFile`; если файл занят антивирусом — `DeferWrite`, прежнее не затирается.

### 4. Кнопка «Подобрать ИИ» (InvoiceAiPicker)
- В шапке окна накладной. Для строк «Новый» (не больше 30 за раз): в Gemini уходит название строки, единица и до 25 названий товаров склада (грубый отбор по общим словам, без чисел). Ответ `{"index": N или null, "reason": "одна фраза"}`.
- Результат — «ИИ предлагает — подтвердите» (нечёткое совпадение, нужен «✓»; пояснение ИИ в строке под названием). Автозаписи нет. После подтверждения соответствие запоминается в память поставщика.
- Те же ключи, платный доступ и вызов, что у Нур Советника: `TelegramAiChat.AskOnceAsync`, `GeminiKeyPool`, `TariffGate.CanUseAi`. Без доступа кнопка выключена с подсказкой (тариф «Старт» без пакета ИИ / Нур Советник выключен владельцем / нет ключа Gemini).
- Предел: 3 запроса одновременно, 15 секунд на строку, отмена (повторное нажатие «Остановить ИИ» или закрытие окна). В журнал — только числа («строк N, предложено K, отклонено M, без ответа L»); названий и ответов нет.
- Страховка от ошибки ИИ: номер вне списка — отказ; если у предложенного товара другой объём/вес/модель (числа не сходятся) — отказ, даже если ИИ «уверен». Название строки в запросе помечено как данные, а не команды.

### 5. Рукописные накладные (чтение по фото в Нур Советнике)
Чтение по фото живёт в Нур Советнике (`ProductActionPlan.PhotoPromptText`, `TelegramAiChat`, окно «Закупка по накладной» `InvoiceEditorWindow`), а не в `InvoiceImportService`.
- **(а) Словарь**: к подсказке для фото добавляется до 200 названий товаров склада (в наличии и свежие первыми, без цен и остатков) и до 40 недавних соответствий «как называли у поставщика → у нас» из памяти. Правило: чётко читаемое пиши как на фото, словарь — только когда почерк неразборчив; не выдумывать.
- **(б) Поля чтения** в каждой служебной строке `ТОВАР`: `n` (номер строки), `line_total` (сумма строки как в документе), `confidence` 0..1, `unclear`. Уверенность ниже 0,7 или `unclear` — строка получает новый признак `InvoiceRowFlag.LowConfidence`: значок ⚠ и подсказка «проверьте по фото», в сводке окна отдельная строка «Нечётко прочитано по фото: строки …». Такая строка в итог входит и проведению не мешает.
- **(в) Второй проход** (`InvoiceReadingAid.SecondPassAsync`, один дополнительный запрос, до 12 строк, до 50 с): перечитываются строки, где количество × цена ≠ сумма строки; если итог накладной по документу не сходится с суммой строк (учёт НДС и скидки через `InvoiceReconcile`), добавляются ещё и строки, отмеченные ИИ как нечёткие. В запросе — расхождение по каждой строке. Исправленные строки заменяют первые (и в служебных строках, и в видимой таблице); если сумма всё равно не сходится, в окне закупки строка подсвечена с пояснением «сумма строки в документе X, а количество × цена = Y».
- **(г) Шаблон поставщика (порядок колонок)** — пропущено сознательно: при чтении по фото модель сама возвращает нормализованную таблицу с фиксированными колонками, шаблону порядка колонок применять не к чему; для Excel/CSV порядок колонок уже запоминается (`InvoiceImportRegistry.SaveMapping`).
- «Сверка итога (НДС, скидка, число позиций)» из 1.17.70 не менялась: проверено, что `InvoiceTotalsHint` и подсказка «ИТОГ НАКЛАДНОЙ» на месте.
- **То же «новый или тот же?» в окне «Закупка по накладной»** (путь через Нур Советник): после открытия окна в фоне ищутся похожие товары склада для строк «Новый товар». Если нашлись — в ячейке кнопка «≈ Есть похожие (N) ▾». «Тот же» превращает строку в приход к выбранному товару (цену продажи ниже текущей не ставит; если такой товар уже есть в закупке — строки склеиваются); «Оставить новым» убирает подсказку.

## Что оставлено и почему
- **Мобилка не тронута** (по заданию). Правила переносятся один в один в `invoice_match.dart`: разбор названия (нижний регистр, ё → е, кавычки; «б/а», «ж/б» и т. п. в основу; число+единица → факт объём/масса, «шт»/«GB» → обычное число; слова с точкой — сокращения); словарь сокращений из `InvoiceNameData`; звуковой ключ из `InvoiceNameData.Phonetic`; слова близки при равном ключе, общем начале ≥ 4 букв, сокращении с точкой или расстоянии Левенштейна ≤ 1 при длине ≥ 5; числовые факты: тот же вид и значение, обычное число = значение в л/мл/кг/г; несовпавшие числа у обеих сторон → 0, лишнее число у одной стороны → −0,12; вложенность `0,72 + 0,2 × доля`; пороги 0,75 / 0,70 (≤ 3 фактов) / список от 0,55; память — тот же `MemoryKey`.
- Шаблон поставщика (п. 5г) — не делался, причина выше.
- «Новый товар» не запоминается (по заданию); «Подобрать ИИ» не запускается сам — только кнопкой.
- В истории разговора Нур Советника остаётся ответ первого чтения; исправленный вторым проходом показан в таблице и в карточке закупки.
- Автообучение синонимов по накладным не делалось; расширять словарь сокращений нужно правкой `InvoiceNameData`.
- Окно собрано и проверено сборкой и логикой стенда; **вживую (экран «Загрузка накладной», меню «▾», кнопка «Подобрать ИИ», кнопка «Есть похожие» в закупке по фото) не смотрено**: по правилам владельца кассу я не запускал. Перед выпуском стоит один раз пройти на тестовом аккаунте NBS: колонка статуса стала шире (236 вместо 184), в ней теперь до трёх кнопок.
