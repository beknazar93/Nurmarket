## 2. Что исправлено

1. **Продажа на планшете** (`lib/features/sale/sale_screen.dart`): при ширине ≥ 840 dp — плитки слева (5 долей), чек справа (4 доли), вкладки скрыты, кнопка «К товарам» не показывается, прокрутка плиток и подгрузка работают всегда. Телефон не изменился (вкладки как раньше). Тест: планшет 1280×800 и 1024×600 на 5 языках без переполнения, телефон 360×800 — вкладки на месте.
2. **Тексты ошибок** (`lib/core/api/api_client.dart`, `ApiText.friendly`): стандартные английские ответы сервера (нет прав, не найдено, слишком часто, обязательное поле, не число, такая запись уже есть) — на языке приложения; 403/404/429 без тела — человеческая фраза; русский текст сервера и незнакомые ответы — как раньше. 6 новых ключей × 5 языков.
3. **Пустые состояния** (`EmptyState` в `lib/core/util/ui.dart`): чеки, долги, отложенные чеки, заказы сайта, удалённые из чека, уведомления, очередь отправки.
4. **Цели касания**: кнопка закрытия плашки обновления, 3 кнопки в «Ключи Gemini», кнопка удаления строки «неизвестные коды» в приёмке — 48 dp; кнопка «Отменить» в звонке ИИ — 48 dp.
5. **Язык**: сообщение «Чек сохранён без связи» на экране чека — на 5 языках, цвет из палитры.
6. **Push, каркас** (`lib/core/push/push_service.dart`) — см. раздел 4.
7. **Тесты**: `test/mobile_ux_1113_test.dart` — 13 проверок (планшет и телефон, ошибки, пустое состояние, push).

**Чек-лист для проверки на устройстве (10 минут).** Планшет: открыть «Продажа», добавить товар касанием плитки — строка появляется справа, сумма в «Оплатить» растёт; повернуть экран — вид переключается без потери чека. Поставить язык ky, вызвать ошибку (например, удалить товар на сайте и открыть его) — текст по-кыргызски, без «Not found».

## 4. Push-уведомления — каркас без ключей

**Сделано** (`lib/core/push/push_service.dart`, зависимости не менялись, Firebase не подключён):
- виды: продажа, недостача, заказ с сайта, низкий остаток, закрытие смены; по каждому — экран, куда ведёт нажатие (`/checks`, `/admin/shifts`, `/admin/orders`, `/stock?filter=low`); внешние и «чужие» ссылки в сообщении отбрасываются;
- `PushPrefs` — какие виды человек выключил на этом телефоне (хранится в настройках телефона);
- `PushTransport` — единственное, что останется написать при подключении Firebase (токен, разрешение, нажатие, смена токена); сейчас `NoPushTransport` — ничего не запрашивает и не отправляет;
- `PushService` — работает только при трёх условиях: транспорт подключён, сервер объявил признак `push_notifications`, человек разрешил; токен уходит один раз, смена токена — отдельно, при выходе из аккаунта токен снимается.
К интерфейсу и к запуску приложения ничего не подключено (экрана настроек нет, пока уведомлений нет — чтобы не показывать переключатели, которые ничего не делают).

**Что нужно от сервера (Умар).**
1. Признак `push_notifications` в `GET api/main/capabilities/`.
2. `POST api/main/push/devices/` с телом `{token, platform: android|ios, app: mobile, lang: ru|ky|uz|en|tr}` — привязать токен к пользователю и компании; `DELETE` того же адреса — снять токен этого устройства. Имена полей и адрес — предложение, можно поменять (две константы в `PushService`).
3. Отправка через FCM (Android) и APNs через FCM (iPhone) по событиям ленты `main/changes`: новая продажа (по настройке — только крупнее N сом или все), закрытие смены с недостачей, заказ с сайта, товар опустился ниже минимума. В сообщение класть `data: {type, title, body}` (type — `sale`, `shortage`, `site_order`, `low_stock`, `shift_closed`); заголовок и текст — на языке пользователя (поле `lang`).
4. Кому слать: владельцу и сотрудникам с правом на соответствующий раздел (продажи — `can_view_checks`, заказы — `can_view_orders`).

**Что нужно от владельца.**
- Проект Firebase и файл `google-services.json` для `kg.nurcrm.nurmarket`; для iPhone — ключ APNs из аккаунта Apple Developer.
- Разрешение добавить в `pubspec.yaml` `firebase_core` и `firebase_messaging` (меняет сборку и размер APK — по правилу проекта нужен ответ «да»).
- Решение: показывать ли просьбу о разрешении при первом входе или после первой смены (рекомендация: после первой закрытой смены, а не при запуске).
