## 2. Новые находки — Android-касса

Формат: **ID. Важность (уверенность). Суть.** Где → сценарий → совет → трудоёмкость (S — до 2 ч, M — до дня, L — больше).

### 2.1. Ввод, окна, сенсор

**А4-01. ВЫСОКИЙ (ПЛАУЗИБЛЬНО). Enter и Esc с физической клавиатуры или HID-сканера нажимают кнопку не того окна.**
- **Где:** все «окна» кассы на Android — слои внутри одного настоящего `TopLevel` (`Shell/WindowLayerHost.cs:65-95`, `Shell/TopLevel.cs:24` — окно-слой это `ContentControl`). Кнопки `IsDefault`/`IsCancel` в Avalonia подписываются на клавиши корня визуального дерева, а корень у всех слоёв один. В кассе 140 таких кнопок в ~70 окнах (`PosConfirmDialog.axaml:20,26`, `CloseShiftDialog.axaml:24,31`, `PaymentConfirmationDialog.axaml:19,21`, `CheckoutDialog.axaml:1265`…).
- **Сценарий:** терминал Sunmi T2/D2 с USB-клавиатурой или сканером. Открыто «Закрыть смену», поверх — `PosConfirmDialog`. Кассир жмёт Enter (или Esc). Первым срабатывает обработчик кнопки, подписанной раньше, — нижнего окна: «Закрыть смену» или «Отмена» нижнего окна, а верхний вопрос остаётся висеть. Так же спрятанное (`Hide()`) окно продолжает ловить Enter. В Windows каждое окно — свой `TopLevel`, там этого нет.
- **Совет:** в `WindowLayerHost.UpdateInteractivity` для слоёв ниже верхнего снимать `IsDefault/IsCancel` (запомнить исходные в `ConditionalWeakTable<Button,…>`, вернуть, когда окно снова сверху). Проверить на устройстве: диалог поверх диалога, Enter и Esc.
- **Трудоёмкость:** M.

**А4-02. СРЕДНИЙ (по коду точно). Кнопка «Назад» Android закрывает оплату без вопроса «Закрыть оплату?».**
- **Где:** `Shell/WindowLayerHost.cs:591-597` → `Window.RequestCloseFromUser` (`Shell/Window.cs:455`) → закрытие без `Cancel_Click`. Вопрос К-17 живёт только в `Cancel_Click` (`CheckoutDialog.axaml.cs:525-553`), обработчика `Closing` у окна оплаты нет.
- **Сценарий:** выбран клиент, «в долг» или смешанная оплата → кассир смахнул «Назад» → всё сброшено молча. Так же у всех окон, где проверка «несохранённых данных» стоит на кнопке «Отмена», а не на `Closing`.
- **Совет:** «Назад» = Esc: в `OnBackRequested` сначала искать в верхнем окне видимую включённую кнопку `IsCancel` и нажимать её (`button.Command`/`RaiseEvent(Click)`), и только если её нет — `RequestCloseFromUser`. Это же закрывает «нет Esc на планшете» для всех окон.
- **Трудоёмкость:** S.

**А4-03. СРЕДНИЙ–ВЫСОКИЙ (по коду точно). HID-сканер (клавиатурный) на Android теряет начало кода — та же ошибка, что на Windows до 20.10.**
- **Где:** `Services/AvaloniaKeyboardWedgeBarcodeService.cs:97-100` — метка времени нажатия есть только в Windows (`GetMessageTime`), на Android `null` и пауза меряется по времени обработки. К тому же `MainActivity.cs:119-127` перекладывает каждую клавишу отдельным сообщением.
- **Сценарий:** приёмка или большой чек, кассир сканирует подряд; UI занят добавлением товара 300–800 мс → «пауза» внутри одного кода > 220 мс → буфер сброшен → в поиск уходит «7644469162» вместо «7807644469162» (на Windows 20.10: из 200 сканов принято 59).
- **Совет:** в `DispatchKeyEvent` и в отложенном вызове перед `base.DispatchKeyEvent(copy)` класть `copy.EventTime` (мс от загрузки системы) в статическое поле, например `AndroidKeyClock.Current`. В общем коде — крючок `KeyPressTimestampProvider` (`Func<ulong?>`), который Android ставит в `AndroidBootstrap`. Тогда `AppendChar` считает паузу по времени нажатия, как в Windows.
- **Трудоёмкость:** S.

**А4-04. СРЕДНИЙ (по коду точно). Экранная клавиатура закрывает поля ввода — содержимое под неё не сдвигается.**
- **Где:** `IInputPane` нигде не используется (Grep: только свойство в `Shell/TopLevel.cs:82`). По документации Avalonia 11 сама не сдвигает вид и прокрутку под клавиатуру. `AdjustResize` (`MainActivity.cs:24`) лишь уменьшает высоту `WindowLayerHost`, окна-диалоги стоят по центру.
- **Сценарий:** телефон стоя, окно оплаты: поле «Получено» или «Безнал» смешанной оплаты в нижней половине → клавиатура (40–50 % экрана) закрывает поле, кассир печатает вслепую. Так же цена в «Новом товаре», количество в «Укажите количество».
- **Совет:** в `WindowLayerHost` подписаться на `RealTopLevel.InputPane.StateChanged` и `GotFocus` полей; когда клавиатура открыта — модальное окно прижать к верху (`VerticalAlignment.Top`), а поле в фокусе — `BringIntoView(rect + 16 dp)` после раскладки. Заранее: при переходе на targetSdk 35/36 (edge-to-edge принудительно) `AdjustResize` перестанет сжимать вид — опираться на `InputPane.OccludedRect`, а не на сжатие.
- **Трудоёмкость:** M.

**А4-05. СРЕДНИЙ (по коду точно). Для сумм, количества, цен, телефона и PIN открывается полная буквенная клавиатура.**
- **Где:** `TextInputOptions` — 0 использований во всём приложении.
- **Сценарий:** «Получено», «Скидка», «Количество», «Цена», телефон клиента, PIN кассира — каждый раз QWERTY на пол-экрана, цифры — в верхнем ряду или на втором экране клавиатуры. Медленно и закрывает больше экрана (усиливает А4-04).
- **Совет:** `TextInputOptions.ContentType="Number"` (суммы, вес, количество), `Digits` (PIN, штрихкод вручную), `TelephoneNumber` (телефон), `ReturnKeyType="Done"`/`"Go"` (в оплате — «Оплатить»). Удобно одним общим стилем по классам (`Classes="money"`, `"qty"`). Своей клавиатуры не нужно — правило владельца соблюдается: это системная клавиатура в цифровом виде. Запятая/точка уже принимаются (`CheckoutValidation.NormalizeDecimal`).
- **Трудоёмкость:** S–M.

**А4-21. НИЗКИЙ (по коду точно). При уменьшении вида цели касания меньше 48 dp.**
- **Где:** `Shell/ScreenFitHost.cs:67-69`: горизонтально масштаб = min(w/1000, h/480), нижний предел 0,4. Телефон боком 809×355 → 0,74; кнопка 44 → ≈33 dp. Крестик заголовка окна — 52×44 (`Shell/Window.cs:177-178`).

### 2.3. Принтеры, сеть, права

**А4-11. СРЕДНИЙ (ПЛАУЗИБЛЬНО). Bluetooth-принтер: нет запасного способа подключения, неудачное подключение держит порт до 45 с, каждый чек — новое соединение.**
- **Где:** `Platform/AndroidPrinterTransport.cs:140` — только `CreateRfcommSocketToServiceRecord`. Ошибка подключения — `IOException` (`:145-148`), её `PrinterPortService.SendRawBytes` повторяет до N раз (`Infrastructure/Services/PrinterPortService.cs:186-191`), каждый раз до `limit` (15 с). Плюс пауза до 1,5 с после записи (`:174`).
- **Сценарий:** дешёвый китайский 58-мм принтер не принимает «защищённый» сокет («read failed, socket might closed») → 3 попытки по 5–15 с, следующий чек получает «Принтер занят». На рабочих принтерах каждый чек = подключение 1–3 с + 0,2–1,5 с.
- **Совет:** при отказе — `CreateInsecureRfcommSocketToServiceRecord`, затем отражением `createRfcommSocket(1)`; запоминать удачный способ по MAC. Тайм-аут подключения 6–8 с, повтор подключения — не больше 1. Держать соединение открытым 30–60 с между чеками (закрывать по таймеру и при уходе в фон).
- **Трудоёмкость:** M.

**А4-12. СРЕДНИЙ (по коду точно). Первый чек после установки на Android 12+ не печатается.**
- **Где:** `Platform/AndroidPrinterTransport.cs:98-107`: право Bluetooth запрашивается и сразу бросается ошибка «разрешите и повторите». `Platform/AndroidBuiltInPrinter.cs:48` сам ставит BT-порт на Sunmi/iMin, но права не спрашивает.
- **Сценарий:** новый терминал → первая продажа → окно Android «Устройства поблизости» поверх оплаты, чек не вышел, кассир не знает, прошла ли продажа.

## 8. Риски на будущее

- **targetSdk 35/36.** Android 15 при targetSdk 35 включает edge-to-edge принудительно (отказ ещё можно задать), Android 16 при targetSdk 36 — без возможности отказа. Тогда `AdjustResize` и текущие безопасные поля (`SafeAreaHost`) нужно перепроверить; держать клавиатуру через `InputPane` (А4-04). Сейчас .NET 8 → targetSdk 34, это не горит.
- **Доступ к локальной сети в новых Android** — ожидается отдельное разрешение для LAN-принтеров, весов и обмена кассами. Следить при переходе на новый targetSdk.
