## 0. Коротко

**8 главных проблем**
1. **Новый товар — это строка таблицы, а не карточка.** В «Закупках» новый товар занимает 5–7 действий (название → количество → закупка → продажа + единица мышью), категории нет вовсе, обязательность полей не видна. В «Склад → Приёмка» в узком виде поле названия почти невидимо (Б-5, видео 11.34.58).
2. **Нет обратной связи «что сейчас отсканировано».** Результат скана — подсветка строки 1,5 с и прыжок курсора; нет карточки «последний товар», нет звука; повторный скан в режиме упаковок «ничего не меняет» (Б-4); неизвестный код в «Складе» молчит.
3. **Путь клавиатуры длинный.** Известный товар с известными ценами: скан + 4 нажатия Enter (Кол-во → Закупка → Продажа → скан). Цель — 2 действия. «Сразу к скану» спрятан флажком с непонятным названием.
4. **«Оприходовать» — лестница модальных окон.** До 6–7 окон подряд (нет поставщика → поштучная → нет цены продажи → доп. расходы → изменение цен → оплата → итог). Ошибки — одной красной фразой «Нельзя оприходовать: …» без перехода к строке.
5. **Иерархия и плотность.** На 1024×600 шапка приёма (назад, шаги, поставщик, № накладной, скан, 3 кнопки, второй ряд инструментов, сообщение) съедает ~45 % высоты: таблице остаётся 2–3 строки. Итог — мелкая серая строка текста внизу; у веба — «Итого приход» крупно у кнопки.
6. **Таблица перегружена и неровная.** 9 колонок + 3–4 подписи под каждым полем («без изменений / было 20,00 / прибыль 10 сом с шт.» переносятся), цифры не моноширинные, суммы не выровнены по разряду, наценка — отдельное поле, которое Enter пропускает.
7. **Горячих клавиш нет и они не показаны.** Ни F-клавиш, ни Ctrl+F, ни Del для строки, ни Ctrl+Enter для проведения; кнопки собраны с `Focusable = false` — Tab до «Оприходовать»/«Очистить» не доходит; Esc при набранной работе молчит.
8. **Сенсорная тема в «Закупках» не работает.** Размеры заданы в коде (поля 40, кнопки 44–46, чипы единиц 32, «Найти в интернете»/«Сгенерировать штрихкод» 32, шрифты 12–14) — тема «Сенсорная» (поля 52, шрифт 16) их не меняет; часть зон касания < 44 px.

Плюс системная причина: **две разные реализации приёмки** («Склад → Приёмка» — DataGrid в XAML; «Закупки → Приём товара» — строки в коде), у каждой свои возможности (этикетки на приход — только в «Складе», чипы единиц — только в «Закупках», категория — нигде), каждую жалобу чиним дважды.

**Предлагаемый дизайн в 6 строк**
1. Шапка в одну строку: «← Закупки» · шаги «1 Поставщик · 2 Товары · 3 Итог» с подсказкой «что дальше» · поставщик (поиск + «+») · оплата «Сразу / В долг до …» · № накладной.
2. Под ней живая сводка (как в вебе): «Поставщик · Позиций · Количество · Сумма накладной», и огромное поле скана (56 px) с кнопками «Каталог», «＋ Новый товар».
3. Справа от поля — карточка «последний товар» (название крупно, значок источника, остаток «было → станет», количество с «−/+», звук и цветная вспышка: зелёный — склад, синий — база NurCRM, оранжевый — новый).
4. Таблица по умолчанию простая: № · значок · Наименование (широкое, 2 строки) · Сейчас · Кол-во · Закупка · Продажа · Сумма · ✕; остальное («изменилась», «как посчитана», наценка, прибыль, упаковка) — раскрытием строки «Подробнее ▸» или переключателем «Подробно».
5. Неизвестный код → компактная **карточка нового товара** над таблицей (не окно): Название* → единица чипами → количество → закупка* → продажа (по наценке) → категория (последняя + частые) → упаковка/штрихкод; Enter-цепочка, ≤ 3 действия.
6. Низ закреплён: «Итого приход 12 345,00 сом» крупно акцентом + флажки проблем («2 без цены», «1 ниже закупки» — нажатие ведёт к строке) + «Очистить» + **«Провести приход (Ctrl+Enter)»**, неактивная с причиной; перед проведением — одно окно «Проверка и оплата» вместо лестницы.

**Быстрые победы (≤ 1 дня каждая)** — раздел 6. **Порядок фаз:** Ф0 → Ф1 → Ф2 → Ф3 → Ф4 (раздел 7). **Вопросы владельцу** — раздел 9.

### 2.2. Таблица и цифры

- **Колонки:** № · Товар · На складе · Принимаем · Цена закупки · Наценка % · Цена продажи · Сумма закупки · ✕ — 9 колонок + до 4 подписей под полями. На 1366 название получает ~3,2* — уже лучше (10.11), но подписи «прибыль 10 сом с шт.», «без изменений / было 20,00» переносятся и делают строку 66–90 px.
- **Цифры:** стиль `TextBlock.num` (`TabularNumbers`) в «Закупках» не применён ни к одной ячейке; у полей класс `num` есть, но стиля `TextBox.num` в приложении нет — разряды «скачут» по высоте строк. Суммы — 13,5 SemiBold, но без выравнивания по разряду в шапке (подписи шапки переносятся «Цена\nзакупки»).
- **Наценка %** — отдельное поле, которое Enter пропускает (цепочка: Кол-во → Закупка → Продажа). Пользователи не понимают, зачем его видно, если в него не попадают.
- **Цвет строки:** «маржа мало» — `BrushWarningSoft`, «ниже закупки» — `BrushDangerSoft`; фон берётся `this.FindResource(...) as IBrush` **без варианта темы** (ловушка AI_HANDOFF §10) — в тёмной теме подсветка может не появиться.
- **Пустая строка количества** — строка становится полупрозрачной (0,72) — хорошо, но без текста «не будет оприходована».

| Проведение | кнопка «Оприходую…», затем окно итога или плашка «в фоне» | оптимистично: список очищается, плашка «Приход ПР-… отправляется» с прогрессом, по готовности — «Готово · Этикетки · Накладная» |

### 2.4. Ввод, подписи, ошибки

- Ошибки ввода уже частично инлайн (красные подписи «нет цены продажи», «маржа …»), но **итоговая проверка — одной фразой** в плашке («Нельзя оприходовать: …; …; …и ещё N»), без ссылки на строку. Нужны: красная рамка у поля, флажок в итогах «3 ошибки ▸» (нажатие — к первой).
- «Название не может быть пустым — вернули прежнее» появляется после ухода из поля — правильно, но у **нового** товара пустое название вскрывается только при проведении.
- Подсказки (ToolTip) длинные и важные («Пусто — общая наценка выключена…») — на сенсорном экране их не увидеть. Важное — текстом под полем, подсказка — для деталей.
- Поле «№ накладной поставщика» 190 px, подпись длиннее поля (в ky — «Жеткирүүчүнүн накладнойунун №»).

### 2.5. Горячие клавиши (сейчас)

| Клавиша | Где работает | Видна на экране |
|---|---|---|
| Enter в поле скана | добавить по коду/названию | в подсказке-абзаце |
| Enter/Tab в ячейках | Название → Кол-во → Закупка → Продажа → скан | в абзаце пустого списка |
| Esc в ячейке | откат правки | нет |
| Esc на странице | назад к списку, **только если строк нет** | нет |
| Ctrl+F | только реестр «Покупки» | нет |
| F-клавиши, Del, Ins, Ctrl+Enter | **нет** | — |

Кнопки `UiKit.Primary/Ghost` создаются с `Focusable = false` (у «Оприходовать» включено вручную) — с клавиатуры до них не дойти.

### 2.6. Цвет, контраст, фокус (WCAG AA)

- Подписи 12 px `BrushTextSoft` на белом и на `BrushWarningSoft` — на грани 4,5:1 (светлая), в тёмной `#8DA3C0`-подобные — ниже для 12 px. Подписи под полями — минимум 12,5 px и `BrushTextMuted`.
- Шаги: текущий «жёлтый на жёлтом» (`BrushWarningSoft` + `BrushText`) читается, будущие — `BrushTextSoft` на `BrushPanelSoft` слабо. Веб подсвечивает текущий шаг зелёным — у нас зелёный = «готово».
- Фокус поля — оранжевая рамка темы (хорошо); у строки нет признака «текущая строка» (у веба тоже), нужен `BrushAccentSoft` фон фокус-строки.
- Красный «новый товар» в мета-строке (`BrushDanger`) — смысл держится на цвете; у значка источника форма своя — хорошо.

### 2.7. Узкое окно и повторное открытие

- < 1000 px: колонка «На складе» прячется, остаток уходит в мета-строку «ост. 10» — хорошо; кнопки «Товары пост.», «Ко всем» сокращаются — хорошо. Но поле скана на 1024 — 540 px, а «Обнулить кол-во» и «Очистить» по 120 px.
- Черновик неоконченной приёмки — в рабочей копии (О-5, другой исполнитель): в шапке будет подпись «Черновик сохранён …». В дизайне — место под неё и «Неоконченная приёмка от 10:42 — Продолжить / Удалить» на странице реестра.
- Окно «Закупки» само разворачивается на маленьком экране (`FitKassaScreen`) — хорошо.

### 2.8. Сенсорный экран

Тема «Сенсорная» обещает «кнопки и поля высотой 52, шрифт 16», но в «Закупках» все размеры заданы числами в коде, поэтому снимки touch почти не отличаются от светлой. Мелкие зоны: чипы единиц 32×40, «Найти в интернете»/«Сгенерировать штрихкод» 32, ссылка «упаковками ▾» — текст 12 px без поля касания, «Как у всех» — текст. Нужны общие размеры-ресурсы (`TouchTarget` 44/52) и `MinHeight` из ресурса.

### 2.9. Скорость

- Строки — `StackPanel` без виртуализации; `ReceiveRender` пересобирает все строки при удалении/очистке; на 200+ строк (накладная) будет заметно. Итоги (`ReceiveRefresh`) пересобирают плитки на каждый символ — дёшево, но плитки мигают.
- Фоновое проведение (`BackgroundReceivingQueue`) — правильная основа для «оптимистичного» ощущения; его надо показать (прогресс в плашке, а не диалог).

### 4.6. Состояния, анимации, звук

- Вспышка строки/карточки «последний» — 150 мс появление, 1,2 с затухание фона (`BrushSuccessSoft` / `BrushAccentSoft` / `BrushWarningSoft`); без сдвигов раскладки. На слабых ПК (режим без анимаций) — без затухания.
- Звук — три коротких системных сигнала (успех / новый / ошибка), выключатель в «Настройки → Приёмка» (решение владельца, раздел 9).
- Итоги обновляются на каждый символ (Б-6), без пересборки плиток.

### 4.8. Пять языков

- Каждую новую надпись — `Tr.T(ru, ky, en, tr, uz)`; кыргызский длиннее русского на 20–40 % («Жеткирүүчүнүн накладнойунун №», «Сатып алуу суммасы») — подписи колонок с переносом в 2 строки, кнопки с `MinWidth`, не `Width`.

### 4.9. Доступность

- Все кнопки фокусируемые (`Focusable = true`), порядок Tab: шапка → скан → таблица → итог.

## 8. Что не делать

- Не искать в интернете без нажатия; не генерировать штрихкод сам; не создавать товар на сервере до проведения.
- Не открывать модальное окно на каждый неизвестный скан.
- Не копировать код и ресурсы веба — только идеи; не вводить то, что требует нового серверного контракта.
- Не своя экранная клавиатура — только `osk.exe`.
- Не менять зависимости, схему базы, сборку без спроса.
