## 2. Для `tools/qa/check-store-registry.ps1` (Л4-05)

Реестр хранилищ теперь — `NurMarketKassa.Infrastructure/Services/CompanyStoreRegistry.cs`:

| Список | Что |
|---|---|
| `CompanyItems`, `CompanyPatterns` | папка данных `%APPDATA%\NurMarketKassa\` (у владельца `NurMarketOwner`) — уносится в `_previous` при смене компании |
| `CompanyLocalItems` | `%LOCALAPPDATA%\NurMarketKassa\` — журналы компании |
| `SharedByCompanyItems` | общие кассы и владельца, у записей есть поле «компания» (`debt-payments`, `pending_shift_closes.json`) — не уносятся |
| `TerminalItems` | про компьютер (сессия, настройки, модель голоса, WebView2, справочник) — остаются |
| `Classify(имя)` | `Company` / `Terminal` / `SharedByCompanyField` / `Unknown`; учитывает хвосты `.bak`, `.pending`, `.pending.old`, `.tmp` |

Скрипт должен: найти в коде литералы имён файлов рядом с `AppPaths.Roaming|Local`, `DataFolderName`, `AtomicFile.WriteAllText` (`*.json`, `*.jsonl`, `*.txt`, `*.flag`, `*.dat`, `*.sqlite`) и сверить с объединением пяти списков (нужно разобрать `string[] … = [ … ]` в этом файле). Файл, которого нет в реестре, — ошибка. Тест `Wave3DataTests.Registry_lists_do_not_overlap` уже следит, чтобы файл не числился сразу в двух видах.

Известные пробелы, которые скрипт, скорее всего, найдёт (в реестр не вносил — нужно решение по каждому): `pending_shift_closes.json` внесён как общий; файлы стенда и Android (`*.sqlite` справочника, `device-key.txt`) — в `TerminalItems`; всё, что пишут В4/В5/В12 в Этапе 1, — по месту, нужно будет добавить строку в реестр.
