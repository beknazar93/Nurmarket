# Бекназару — итог по ТЗ 01.11 (витрина, Telegram, ИИ, вопросы кассы, накладные)

Дата: 01.11.2026. От: Умар.

Бекназар, по твоим ТЗ всё сделали на сервере. Ниже коротко, подробности в файлах (список в конце).

## ⚠️ Сначала предупреждения

1. **Правка накладных — правило поменялось.** Срока правки (24 ч / 48 ч / всегда) больше нет. У кого есть право `can_edit_purchase_documents`, тот правит любые приходы без ограничения по времени, пока право не снимут. Право всегда есть у владельца и администратора. Выдают и снимают его **владелец или администратор** (раньше только владелец).
   → В кассе: убрать выбор срока; не показывать «истёк срок правки»; админу не прятать кнопку «Изменить»; выдачу права разрешить и админу.
   В ответах: `edit_window: "always"`, `edit_window_until: null`, `receipt_edit_window_editable: false`. Ошибки `edit_window_expired` больше не будет.
2. **Округление.** Сервер складывает строки **без округления** и округляет только итог (`ROUND_HALF_UP` до 0,01). Весовая строка — **вниз** до шага весов компании. Если касса округляет каждую строку отдельно, будут копейки разницы. `line_total` строки теперь тоже `HALF_UP` (было банковское).
3. **Возврат долгового чека.** Выдачу наличных бери из `refund.cash`, а не из `debt_adjustment.reduced_by` (это на сколько уменьшился долг). Чек 001968: выдача 2 — верно. Поле `debt_adjustment.remaining_debt` раньше было неверным (2 вместо 0) — исправили.
4. **Ключ Gemini для помощника витрины — у каждого магазина свой** (ваш вариант «а»), общего ключа NurCRM нет. Без ключа или при выключенном помощнике ответ «помощник недоступен» + кнопки связи.
5. **Turnstile** (защита чата от ботов): пока ключа на сервере нет — проверка пропускается. Фронт может уже присылать токен, сервер начнёт проверять, когда добавим ключ.
6. **НДС в накладных не поддерживается** — такого поля нет.

## Что готово для кассы

**Витрина и Telegram (пункты 1–4, 10)**
- `showcase/design/` (публичный) — блок `telegram {enabled, url, product_url_template, placement, label}`. `enabled=true` только если бот серверный и вебхук работает, плюс включено в редакторе (`cart.telegram.*` через `design/draft/`). Токена нигде нет.
- `POST public/companies/{slug}/orders/` — `Idempotency-Key`, `source` (+ `web_chat`), `source_detail`, `cart_token`, позиции с `variant`. Повтор → 200 тот же заказ.
- `source` и `source_detail` в `showcase/orders/`, фильтры `?source=`, `?source_detail=` → можно делать чип «Откуда заказ» (ИИ-3).
- `POST public/companies/{slug}/cart-link/ {items}` → `{token}` (22 символа, 7 дней). Бот понимает `/start c_<token>` (корзина → заказ, один токен = один заказ), `/start p_<id>` (карточка товара), `/start w_<token>` (продолжение чата сайта).
- События `assistant_open`, `assistant_message`, `telegram_click`, `cart_link` (последнее сервер считает сам).
- «Правила магазина»: ключ дизайна `shop.info.knowledge` (ru, ky, en, uz, **kk** — как в дизайне витрины, не «kz»), до 2000 символов. Шлёте по «Сохранить» через `design/draft/` — помощник его цитирует.

**Чат и ИИ-помощник (пункты 5–9)**
- Чат: `public/companies/{slug}/chat/` — `sessions/`, `sessions/{id}/messages/`, согласие на номер `…/consent/`, «Удалить мой чат» `DELETE sessions/{id}/`. Старые адреса `/api/inbox/public/…` тоже работают.
- Помощник: функции `search_products`, `get_product`, `get_size_chart`, `get_shop_info`, `add_to_cart`, `handoff`; в ответе карточки товаров (цену и остаток рисует фронт). Неверные цифры в тексте заменяются на «Уточню у продавца».
- Лимиты как в ТЗ: 6/мин и 40/сутки на сессию, 120/сутки на IP, потолок магазина; при лимите `busy` + кнопки связи.
- Настройки (для редактора сайта, ИИ-1/ИИ-2): `GET/PUT api/main/inbox/assistant/settings/` (включён, потолок, правила), «Проверить помощника» — `POST api/main/inbox/assistant/test/`.
- Переписка хранится 90 дней.

**Ответы на вопросы раздела 7** — в отдельном файле. Коротко: возвраты по чеку (`returned_qty`, `returnable_qty`, `net_total`, `return_status`), `Idempotency-Key` на бонусах/возврате/товаре (`products/create-manual/`)/перемещениях (теперь и в теле), `status` и `comment` в перемещениях, архив товара — всё уже есть. Дробное количество в приходе — только у весовых/мерных товаров.

**Редактор накладных** — твой предложенный контракт уже работает с 31.10: `PATCH suppliers/receipts/{id}/` (Idempotency-Key, `version`/`If-Match`, только нужные поля, строки изменить/добавить/удалить, поставщик, дата, номер, комментарий, оплата). Добавили: скидка накладной (`discount`, `discount_percent`), цена продажи в строке (`sale_price`), `GET …/history/` (то же, что `versions/`). Кнопки «Требует серверной поддержки» можно включать по `capabilities`: `receipt_edit`, `receipt_edit_discount`, `receipt_edit_sale_price`.
