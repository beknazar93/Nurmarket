Касса, программа владельца и мобилка уже сохраняют новый `refresh` из ответа `auth/refresh/` (память, защищённое хранилище, файл автовхода). Чтобы это работало без ложных выходов, просим при включении ротации:
1. Всегда отдавать в ответе `auth/refresh/` и `access`, и новый `refresh`.
2. **Льготное окно для старого refresh 30–60 секунд** (повторное обновление по тому же старому токену отвечает 200 и возвращает тот же новый refresh). Нужно на случай, когда ответ потерялся по пути (обрыв на слабом интернете) или два запроса обновились одновременно. Без этого кассир может быть ложно выброшен.
3. Если включите чёрный список после ротации (`BLACKLIST_AFTER_ROTATION`) — тем более льготное окно обязательно.
4. На 401 у `auth/refresh/` отдавать причину кодом: `refresh_expired` (прошёл срок), `user_disabled` (пользователь выключен), `token_invalid` (токен испорчен). Тогда касса покажет точную фразу, а не общую.
5. Абсолютный максимум жизни входа (например, 90 дней без ввода пароля) — на ваше и директора усмотрение; касса ничего не ломает ни при каком значении.
