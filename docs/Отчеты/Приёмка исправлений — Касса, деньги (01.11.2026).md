## 1. Находки

### ВЫСОКАЯ-1. Ж-01: касса выдаёт 2, сервер записал 1 — остаток смены на сервере расходится, а поправка не пишется
- Где: `ReturnSaleDialog.axaml.cs:1584-1595` (новая ветка `ComputeRefundSplit`) вместе с `CheckDrawerAfterRefund` (`:1438-1463`). Вызовы: `:1282` и `:2214`.

Но сверка ящика вызывается с `cashOut = outcome.Cash` (2). Внутри `RecordIfKnownServerError(overstated = (after−before)+2 = −1+2 = 1, suspect = 2)` расхождение 1 ≠ 2, поэтому выходит «не похоже на известную ошибку, поправку не пишем».
- Сценарий (чек 001967). Из ящика ушло 2, сервер уменьшил «ожидаемо в кассе» на 1. Шапка «Касса:» и Z-отчёт показывают ложную недостачу 1 сом. - Как исправить. Если `ServerCashOut` известен и меньше `Cash`, передавать в сверку `suspect = Cash − ServerCashOut` (или сразу записывать поправку `ExchangeCashCorrections` с ключом `refund:…`). В заметку события смены добавить `server_under=…`, чтобы окно закрытия объясняло разницу.

## 2. Что проверено и признано верным
- **К-01**: исключение узкое (`RefundAmountMath.TryParseExceeds` — только `refund_exceeds_paid` и два русских текста). Другие 409 (`in_progress`, без кода) по-прежнему «неизвестен». Оплаты долга и прихода не задеты. Перечитывание чека после отказа есть в обоих путях. Обмен защищён лучше возврата: `VerifyUnknownExchangeAsync(beforeRetry: true)` не даёт повтора без проверки.
- **Ж-01 арифметика** (`decimal`, без потерь округления):
  - чек 001967 (3 сом; журнал: долг 2, наличными 1; долг сервера 1) → выдать 2, долг −1;
  - долг не погашен вовсе (долг 2) → выдать 1, долг −2;
  - погашен полностью (долг 0) → выдать 3 одной суммой (`splitKnown=false`);
  - частичный возврат 1 из 3 при долге 1 → выдать 0, долг −1, следующий → выдать 1;
  - скидка на чек входит в `amount` заранее;
  - ноль → 0/0/0.
  - Деление на ноль исключено (`cashShareLeft + nonCashShareLeft > 0`).
- **Ж-05**: `CanReturnWhole` обновляется через `IsBusy` (открытие чека обёрнуто) и `RaiseSelectionState`. Пустой список (`Lines`) кнопку не блокирует (как раньше). Тексты на 5 языках.
- **Ж-03**: тело запроса то же (`idempotency_key`, `cashbox_role`, `items[sale_item_id, quantity]`) + `reason`. `is_defect` уходит, только если `true`. Адрес тот же. Вызов через `RequestAsync` даже лучше: 4xx приходит как `ApiException`, и К-01 и деловые отказы распознаются. Обычные товары ведут себя так же, но живая проверка на NBS обязательна: владелец просил не трогать «Продукты». Причина при возврате без связи не передаётся (вне участка).
- **К-05**: проверка остатков строк до отправки (`StaleReturnLinesAsync`) идёт после проверки «прошлый обмен без ответа», поэтому свой прошедший обмен не примется за чужой. В `SaleReturnLedger` пишется `ServerDocId` документа возврата, так что следующий возврат не возьмёт документ обмена за свой. Двойного учёта в журнале смены нет (одна запись по `OperationKey(exchangeId)`).
- **К-04**: `UseLocalOperations` + настоящий GUID → `CloseLocallyAndQueue`. У автономных аккаунтов смены всегда `offline-…`, на сервер они не попадают. Повторы безопасны благодаря существующей логике очереди (`queuedRevival`, ожидание чеков, `AlreadyClosed` снимает запись).
- **К-03**: POST `shifts/offline-…/close/` и ветка 404 «закрыть другую смену» для офлайн-смены больше не достигаются. `shift_not_owned` ловится раньше общей обработки сбоя, чужая смена не закрывается.
- **К-06**: отказ «старше 7 суток» → `ReviewNeeded` + `MarkFailed(retryable:false)` + оповещение владельцу. Старым путём без даты чек не уходит ни из быстрого пути, ни после пакетного 400 (пакет → одиночный быстрый → перехват), ни при выключенном быстром пути (`IsTooOldForDatelessReplay`). Продажи на сервере нет, чек остаётся в кассе: ни потери, ни дубля.
- **К-08**: срок выбирается один раз на оплату. При сбое чек уходит в очередь с тем же ключом, двойной продажи нет. В аварии или без недавнего ответа — прежние 1,8 с. Поток UI не блокируется (таймер окна).
- **Н-02**: версия читается до загрузки, гонка «запись во время подсчёта» даёт пересчёт, а не устаревшее число. Все записи `OfflinePendingSalesStore` (Mark*, Requeue*, CloseWithoutSending) идут через `Update`/`SaveAll`/`Append`/`RemoveSynced` и сбрасывают кэш. Точный `PendingCount` (`maxAge 0`) после записи всегда свежий. `RefreshQueuedCount` вынесен в пул потоков, число возвращается через `Dispatcher.Post`.
- **Языки**: все новые строки `Tr.T`/`T` — в порядке ru, ky, en, tr, uz, переводы по смыслу совпадают.

## 4. Живая проверка на NBS (после правок ВЫСОКАЯ-1/2)
1. Чек 001967-подобный: «в долг» 3, предоплата 1, оплата долга 1 → полный возврат. Выдать 2, долг −1, «Касса:» и X-отчёт сходятся с ящиком.
2. Офлайн-смена → изъятие → связь вернулась → сразу «Закрыть смену». На сайте изъятие в закрытой смене, в новой смене его нет.
3. Возврат в «Продуктах» с причиной → причина видна у владельца; сервер не отвечает ошибкой.
4. Медленный сервер (2–3 с), оплата «в долг» → текст ожидания без обещания очереди.
