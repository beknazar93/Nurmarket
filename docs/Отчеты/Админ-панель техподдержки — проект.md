# Админ-панель техподдержки support.nurcrm.kg — проект (08.11.2026)

Просьба владельца 08.11: «Вид магазина меняется только с помощью тех поддержки… придумать эффективные способы, чтобы тех поддержке легко менять эти функции — целая админ-панель с тумблерами».
Документ — ТЗ/проект, сервер не реализован. Первый шаг уже сделан в кассе (см. §2.1).

---

## 1. Что уже есть (по коду)

| Где | Что есть | Чего нет |
|---|---|---|
| `NurRemoteSupport/Server` (ASP.NET 8, без БД) | вход операторов (`/api/login`, PBKDF2, токены, отзыв), удалённая помощь (`/ws/host`, `/ws/operator`), очередь «Ждут помощи» и журнал сеансов (`/api/sessions`, `journal*.jsonl`), заметки по кассам (`/api/notes`), лимиты попыток, веб-страница оператора `wwwroot/`, программа оператора `Operator/` | ролей (все операторы равны), 2FA, БД, доступа к данным NurCRM, журнала действий, кроме сеансов |
| Касса → NurCRM (что касса уже читает «сверху») | `GET api/users/company/` (тариф, `market_sphere`); `GET api/users/company/addons/` → `kassa-*` платные функции (`ServerAddons`, раз в 15 мин, сразу после заявки — раз в минуту 15 мин); `GET api/main/capabilities/` — признаки сервера (`ServerCapabilities`, кэш 10 мин, на диске); `GET api/main/app-settings/nurmarket-kassa/` — общие настройки компании, опрос ~30 с с ETag (`SettingsCloudSync`); `api/main/marketplace/themes/` — темы/виды (`marketplace_themes`); `public/tariffs/` + заявки «Своё» (`TariffApi`); `POST api/support/addon-requests/` — заявка «Подключить» | ничего из этого поддержка сама не меняет — только Умар/админка NurCRM |
| Касса, своё | канал обновлений — код тестера (`UpdateChannel`, хэш в коде, локально); отправка журнала в Telegram (`SupportLogService`); сеанс помощи с согласием кассира | удалённого переключения канала, принудительного обновления, объявлений |
| `NurSupportBot` | вход клиента через NurCRM (компания, тариф, сфера, роль), обращения в группу, база инструкций, админка в Telegram | связи с панелью |

Вывод: всё, что кассе нужно «сверху», уже читается из NurCRM. Не хватает **писателя**: места, где поддержка безопасно меняет эти значения с журналом и откатом.

## 2. Как касса получает изменения

### 2.1. Уже сделано в кассе (08.11.2026, часть 1)
- Вид магазина в «Настройки → Операции» **под замком**: кнопки серые, выбранная показывает текущий вид, надпись «Вид магазина меняется только через техподдержку» + «Написать в поддержку» (WhatsApp с готовым текстом) и телефон.
- Новая установка: вид выбирается **один раз** (окно первого запуска или настройки), потом замок. У работающих касс замок сразу, вид не меняется.
- Как поддержка меняет вид сейчас (без панели):
  1. `market_sphere` компании на сервере — как раньше: смену значения касса применяет;
  2. ключ **`SupportMarketSphere`** в общих настройках компании (`api/main/app-settings/nurmarket-kassa/`):
     `{"sphere":"hardware","stamp":"2026-11-08T10:00:00Z","allow_local_change":false,"by":"Айбек"}` — касса только читает его (не отправляет), применяет каждое новое `stamp` один раз в течение ~30 с, без перезапуска; `sphere` — любой id каталога (`grocery`, `clothing`, `services`, `hardware`); `allow_local_change: true` — разрешить владельцу выбрать самому;
  3. во время сеанса «Нур Поддержка» (оператор подключён) замок снят — оператор переключает вид сам.
- Слабое место: общие настройки может писать владелец/админ компании через API. Защита от случайного переключения есть, от злонамеренного — нет, пока сервер не охраняет поле (§4, Умар).

### 2.2. Единая схема на будущее
Касса ничего нового не опрашивает — используем существующие каналы:

| Что меняет поддержка | Куда пишет панель | Что читает касса |
|---|---|---|
| платные пакеты, срок | addons компании (NurCRM) | `users/company/addons/` (уже) |
| тариф | company.tariff (NurCRM) | `users/company/` (уже) |
| вид магазина | `market_sphere` + `SupportMarketSphere` | уже |
| флаги функций, объявления, канал обновлений, рабочее время | **новый документ** `api/main/app-settings/nurmarket-support/` (только чтение для компании, пишет только поддержка) | +1 запрос в тот же опрос ~30 с с ETag |
| признаки сервера | capabilities (NurCRM) | уже |

**Подпись.** Документ `nurmarket-support` подписывается ключом панели (Ed25519): `{"payload":{…},"sig":"…","kid":"2026-11"}`. Открытый ключ — в кассе. Неподписанное/чужое касса игнорирует (защита от того, что владелец сам впишет себе флаги, и от подмены). Кэш последнего подписанного документа — на диске, как у capabilities. Для `SupportMarketSphere` подпись — этап 2 (сейчас без подписи, см. риск).

## 3. Что должна уметь панель

**Поиск:** по названию компании, телефону/email владельца, ИНН, id компании, коду сеанса, имени ПК, версии. Результат — карточка компании.

**Карточка компании** (вкладки):
1. *Сводка* — тариф и срок, кассы (ПК, версия, канал, последний выход на связь, ОС), последние ошибки, открытые обращения бота, заметки операторов.
2. *Пакеты* — тумблеры `ai, clients, sales_analytics, restock, salary, debts, service, scales, telegram_bot, shift_analytics, analytics_export, timesheet` и касса-функции `kassa-loyalty, timesheet, analytics, pricetag, bulktag, labeleditor, scales, export, telegram, shiftstats, language`; срок `until`, причина, «пробный N дней». Заявки «Подключить» и «Своё» — входящие с кнопкой «Включить».
3. *Вид и оформление* — вид магазина (с точной сферой), разрешить смену владельцу (`allow_local_change`), темы/виды маркетплейса (выдать/забрать купленные), раскладка по умолчанию.
4. *Флаги функций* — список ключей с описанием, значение по умолчанию, значение компании, срок (feature flags для поэтапного включения: `receipt_delete`, офлайн-приёмка и т. п.).
5. *Устройства* — лимит касс/устройств, список входов, «выкинуть устройство» (нужен сервер Умара: сейчас лимита нет, вход живёт 7 суток).
6. *Рабочее время кассиров* — расписание (часы входа в кассу по дням), режим автоотметки табеля (`StaffAutoMarkMode`: off/shift/login), вне расписания — запрет или только предупреждение.
7. *Обновления* — канал (стабильный/тестовый — режим тестера без кода), «обновить до X сейчас», «откатить на X» (минимальная/максимальная разрешённая версия), статус установки.
8. *Связь и журнал* — последний пульс, ошибки (из «Отправить журнал» и отчётов о сбоях), состояние очередей (неотправленные продажи), кнопка «Запросить журнал».
9. *Удалённая помощь* — «Подключиться» (кассе приходит запрос, кассир разрешает — как сейчас), история сеансов (уже в `journal.jsonl`), заметки.
10. *Сообщения* — объявление в кассе (баннер/окно, срок, только владельцу/всем), личное сообщение компании; массовое — по фильтру.
11. *Журнал действий* — кто/что/когда/было→стало/причина, «Откатить» в один клик.

**Общие механики:**
- *Безопасный предпросмотр:* перед сохранением — «что изменится» (дифф было→стало, сколько касс затронет, предупреждения: «у компании 3 кассы на 1.17.70 — они ключ не понимают»).
- *Откат одним кликом:* каждое изменение — запись с прежним значением; откат = новое изменение с прежним значением (тоже в журнал).
- *Массовые операции* (флаг/объявление/канал на N компаний): фильтр → предпросмотр списка → ввод числа компаний для подтверждения → выполнение порциями с отчётом; только «старший» и выше.
- *Роли:* оператор — смотреть всё, удалённая помощь, заметки, сообщения одной компании; старший — пакеты/вид/флаги/канал одной компании, откат; админ — массовые операции, операторы и роли, ключи подписи, принудительное обновление/откат версий.
- *Вход:* логин + пароль (есть) + **TOTP** (Google Authenticator) обязательно для старшего и админа; сессия 12 ч (есть); действия «опасные» (массовые, откат версии) — повторный ввод кода TOTP.

## 4. API: что нужно от NurCRM (Умар) и что можно у себя

**Без Умара (в `NurRemoteSupport`):** роли и 2FA операторов, журнал действий, заметки, история сеансов, объявления и флаги **в своём хранилище** (SQLite) + публичный подписанный эндпоинт `GET https://support.nurcrm.kg/api/kassa/config?company=<id>` — касса может читать его напрямую (кассе уже известен адрес `support.nurcrm.kg`). Минус: панель не видит данных NurCRM (тариф, пакеты, компании) и не может их менять.

**Нужно от Умара** (сервис-аккаунт поддержки с отдельным токеном, только с IP панели):
1. `GET /api/support/companies/?q=` — поиск компаний (id, название, владелец, телефон, тариф, срок, `market_sphere`, число устройств).
2. `GET/PATCH /api/support/companies/{id}/` — тариф, срок, `market_sphere`, **`market_sphere_locked`** (меняет только поддержка; владельцу PATCH `market_sphere` → 403 при замке).
3. `GET/POST/DELETE /api/support/companies/{id}/addons/` — пакеты `kassa-*` и веб-пакеты, `until`, причина.
4. `GET/PUT /api/support/companies/{id}/app-settings/{app}/` — запись в общие настройки компании от имени поддержки (для `SupportMarketSphere` и будущих ключей) + **документ `nurmarket-support`**, который компания может только читать.
5. `GET /api/support/companies/{id}/devices/` и `DELETE …/devices/{id}/` — устройства/входы, лимит (`device_limit`).
6. `GET /api/support/requests/` — заявки «Подключить» (`addon-requests`) и «Своё» (`tariff/custom`) со статусами, `PATCH` статуса.
7. Журнал изменений на стороне NurCRM (кто из поддержки менял) — или хотя бы `updated_by` в ответах.

## 7. Этапы

**MVP (1–2 недели, без Умара — только то, что работает уже сейчас):**
1. Роли операторов (`role` в `operators.json`), TOTP для старших/админа, журнал действий (SQLite/JSONL) — 2–3 дня.
2. Веб-страница «Компания»: поиск по сеансам/заметкам/журналу (что уже знает сервер: компания, ПК, версия), история помощи, заметки — 2 дня.
3. Вид магазина: до API Умара писать в NurCRM панели нечем (токенов клиентов у неё нет и быть не должно). Поэтому в MVP оператор меняет вид в сеансе удалённой помощи (замок снят, §2.1 п. 3) — уже работает; в панели — кнопка «Подключиться» и запись «вид сменён» в журнал действий. Форма «Назначить вид» (пишет `market_sphere` + `SupportMarketSphere`) — этап 2.
4. Объявления и флаги в своём хранилище + подписанный `GET /api/kassa/config` (Ed25519) и чтение в кассе (опрос раз в 5 мин, кэш на диске, неподписанное игнорируется) — 3–4 дня.
5. Канал обновлений «тестовый» по флагу из конфига (вместо кода тестера) — 1 день.

**Этап 2 (после API Умара §4 п. 1–4, ~2 недели):** поиск компаний NurCRM, пакеты и сроки, тариф, `market_sphere` + `market_sphere_locked`, заявки «Подключить/Своё», предпросмотр и откат для всего этого, массовые операции.

**Этап 3:** устройства и лимиты (п. 5), рабочее время кассиров (касса проверяет расписание при входе), пульс касс и последние ошибки (касса шлёт раз в 10 мин версию/канал/ошибки), принудительное обновление и откат версии (`min/max_version` в конфиге; касса предлагает/ставит нужную версию через Velopack).

## 8. Риски и безопасность

- **Владелец сам меняет «замок».** Сейчас `SupportMarketSphere` пишется в общие настройки, которые владелец может менять через API → нужен серверный запрет (`market_sphere_locked`, документ `nurmarket-support` только для чтения) и подпись.
- **Утечка токена поддержки = доступ ко всем компаниям.** Сервис-токен только на сервере панели, ограничение по IP, короткий срок, ротация; в браузер не отдаётся. Все действия — через сервер панели с журналом.
- **Ошибка массовой операции.** Предпросмотр, подтверждение числом, порции, откат батча целиком.
- **Старые кассы не понимают новые ключи.** В справочнике флагов `min_kassa_version`, предпросмотр предупреждает; касса неизвестное игнорирует (как сейчас с `kassa-*`).
- **Касса без интернета.** Применяет последний подписанный кэш; срок `until` проверяется и по кэшу (как в `ServerAddons`).
- **Деньги не трогаем:** панель не меняет продажи, остатки, долги; только настройки и доступы.
- **Персональные данные:** в журнале — без паролей, PIN, токенов (как сейчас в `NurRemoteSupport`); экспорт журнала — только админ.
- **2FA обязательна** для изменяющих ролей; блокировка после неверных кодов (есть `AttemptLimiter`).

## 9. Вопросы

**Владельцу:**
1. Роли: кто будет старшим/админом (имена)? Нужен ли «только просмотр» для стажёров?
2. Рабочее время кассиров: вне расписания **запрещать вход** или только предупреждать и отмечать в табеле?
3. Разрешать ли владельцу самому менять вид (`allow_local_change`) по умолчанию для новых клиентов в первые N дней?
4. Объявления: только владельцу или всем кассирам? Нужны ли обязательные к прочтению (с кнопкой «Понятно»)?
5. Принудительное обновление: ставить молча ночью или только предлагать?

**Умару:**
1. Можно ли сервис-аккаунт поддержки с правом читать/менять компании (§4 п. 1–3)? Срок?
2. Добавить `market_sphere_locked` (PATCH владельцем → 403) и документ `nurmarket-support` (компания только читает)?
3. Отдаёт ли сервер `updated_by` у app-settings — чтобы в журнале было видно, кто менял?
4. Лимит устройств (`device_limit`) и список входов — когда (связано с ТЗ «слоты устройств»)?
5. Есть ли у админки NurCRM свой журнал изменений addons/тарифа, который можно читать?
