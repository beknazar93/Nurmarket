## 4. Скорость: WebSocket против опроса

| Что | Было (замер 29.10, опрос) | Сейчас |
|---|---|---|
| Цена изменена (`PATCH`) → событие | касса видела через **медиану 6,1 с** (2,0–10,0), из них ~4 с — ожидание такта ленты | событие `price_changed` по WebSocket через **399 мс после отправки PATCH** (72 мс после ответа сервера) |
| Продажа → событие | у владельца «чек» через **медиану 11,2 с**, остаток — 5,7 с | `stock_changed` и `sale_created` через **439–465 мс после отправки чека**, ещё до HTTP-ответа (604 мс) |
| Возврат, оплата долга → событие | только опросом | `sale_changed`, `debt_changed` за доли секунды |
| Опрос, если поток не подключён | ~4 с ожидания такта | изменение видно уже **в первом опросе**: `catalog-version` 0,57–0,61 с, `products/changes` 0,82–0,84 с, `main/changes` 1,04–1,06 с после PATCH. Неизменившиеся ответы — 304 без тела и без счёта в лимит |

Итого: «мгновенно» (≤ 1 с) теперь даёт сам сервер. Чтобы касса, программа владельца и мобилка видели изменения за ~0,5 с вместо 6–11 с, нужно подключить у них `wss://…/ws/main/events/` с `since` и оставить опрос с ETag как запасной.

Учесть при подключении:
- поле `at` округлено до секунды, а часы сервера спешат примерно на 2,5–3 с — задержку по `at` не считать;
- при истечении токена сервер закрывает поток с 4401. Новый `{"token"}` надо слать заранее, до истечения, и переподключаться с `since`.
