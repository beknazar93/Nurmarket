## Как сделать выпуски стабильными

`gh_release.py update` для этого не подходит: он принудительно ставит `prerelease=true`. Нужен запрос к API на каждый выпуск (токен из `token.txt`, в вывод не печатать):

`PATCH https://api.github.com/repos/beknazar93/<репозиторий>/releases/<id>` с телом `{"prerelease": false, "make_latest": "true"}`

Репозитории и теги: `Nurmarket` — `v1.17.71`; `Nurmarket-Android` — `android-1.17.71`; `Nurmarket-Linux` — `linux-1.17.71`; `Nurmarket-Mac` — `macos-1.17.71`; `Nurmarket-Mobile` — `mobile-1.18.14` (для мобилки решает руководитель). Идентификатор выпуска: `GET /repos/<репозиторий>/releases/tags/<тег>` → поле `id`. Сначала переводить Android, Linux, macOS, мобилку, Windows — последним (после него кассы стабильного канала увидят обновление). Тестовое описание выпусков содержит строку «Тестовая версия — только для тестировщиков» (кроме Windows и мобилки: у Windows заголовок `## v1.17.71` без пометки) — при переводе в стабильный её можно убрать через `PATCH` с новым `body`.

## Как откатить

Удалять выпуски и теги не нужно. Пока выпуск помечен prerelease, стабильные кассы его не видят — они остаются на 1.17.70. Если выпуск уже сделан стабильным и нужно спрятать: `PATCH` с `{"prerelease": true}` (или `{"draft": true}`, чтобы скрыть совсем). У тестировщиков, уже поставивших 1.17.71, откат на 1.17.70 — установкой `NurMarketKassa-win-Setup.exe` из выпуска v1.17.70.
