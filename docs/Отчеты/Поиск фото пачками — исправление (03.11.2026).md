# Поиск фото пачками — исправление (03.11.2026)

Жалоба владельца: «найди для них фото в интернете и описание… и дополни эти товары» — советник нашёл фото для 10 товаров из 15 252 без фото; на снимке неправильные фото (листовка Wildberries, кадр из YouTube). Просьба: «исправь это ограничение или по этапам добавляй по 50 или по 20 по очереди, чтобы не нагружать систему».

Статус: собрано (Windows и Portable), консольная имитация прошла. Не коммичено, не установлено, касса не запускалась. Живой проверки на NBS нет (касса занята аудитом) — нужна перед выпуском.

## Причина
`RunPhotoAssistantAsync` брал `withoutPhoto.Take(80)` и ставил `webLimit = 10` — интернет-поиск (Gemini) только для первых 10, остальные 70 искались лишь в открытых базах по штрихкоду/названию; результат нигде не запоминался, каждый запрос начинался с начала списка и снова упирался в те же 10/80.

## Что сделано по пунктам

1. **Пачки по очереди.** Размер пачки 20 (по умолчанию) или 50 — чипы «Пачка: 20 | 50» под результатами (запоминается в файле памяти). Интернет — для всех товаров пачки; параллелизм не больше 2; отмена в любой момент («Остановить» и общая «Стоп» окна). После пачки — карточки с «Поставить», «Поставить все (N)» только для этой пачки, кнопка «Искать дальше (ещё 20)». Режим «Искать автоматически по очереди» (по умолчанию выключен): следующая пачка сама через 7 с, пока не нажмут «Остановить», не кончатся товары или не кончится лимит ключа. Единый лимит запросов (`RequestPacer`, в минуту и с паузой между запросами): открытые базы 60/мин, Яндекс.Картинки 30/мин, Gemini (поиск и описание вместе) 10/мин, не чаще одного в 6 с. Лимит ключа Gemini: «Лимит ключа Gemini исчерпан, продолжу позже…» и остановка; найденное сохранено, непроверенный товар остаётся в очереди. Если поиск Google заблокирован (429), следующая пачка идёт только по открытым базам и Яндексу, «не найдено» в этом случае перепроверяется через сутки. Строка прогресса: «Без фото: 15 252 · просмотрено 40 · найдено 31 · осталось ~15 212».
2. **Память прогресса.** `photo-search-progress.json` в папке данных компании (`%APPDATA%\NurMarketKassa\`, AtomicFile с копией .bak): id товара → {состояние found / notfound / set, дата, признак «без интернета»}. Следующий запрос продолжает с того места. Правила: «не найдено» — перепроверка через 30 дней; «найдено, но не поставлено» — не показывается снова 2 суток; «поставлено» (и ручное «📷 Добавить фото») — никогда; кнопка «Искать заново» забывает всё, кроме поставленных. Файл внесён в список стираемого при смене компании (`AccountDataIsolation`) и сбрасывается из памяти. Порядок: по убыванию остатка, потом по названию (продаж в плитке нет, остаток есть дёшево).
3. **Качество.** Список закрытых источников — в одном месте (`ProductPhotoFinder.BlockedHosts`): YouTube (в т. ч. кадры ytimg), TikTok, Instagram, Facebook, VK/userapi, OK, X/Twitter, t.me, Rutube, Дзен, Vimeo и др. — ни страница, ни сама картинка не принимаются (и для одиночного поиска «на выбор» тоже). Совпадение названия: доля значимых слов названия (основа 5 букв, объём вроде «450гр») в подписи страницы/картинки; меньше 0,5 или подписи нет — кандидат «сомнительный». Размер по заголовку файла (PNG/JPEG/GIF/WebP): меньше 150 px — отброс; меньше 300 px или вытянутая (отношение сторон вне 0,6–1,7, баннер/листовка) — «сомнительный». Сомнительные показываются отдельно с пометкой «⚠ проверьте», в «Поставить все» не входят (ставятся только вручную). Фото по штрихкоду из открытой базы — уверенное, если нормальный размер.
4. **Описание.** Инфраструктура была (Gemini с поиском `TelegramAiChat.AskWebAsync`, `PatchProductFieldsAsync`, поле `description`). Для найденного фото, у которого в карточке нет описания, делается отдельный запрос: 1–3 предложения по-русски, без рекламы, цен и ссылок, с названием источника; показывается в карточке рядом с фото (подсказка — полный текст). Кнопка становится «Поставить фото и описание»; при нажатии программа читает карточку с сервера и пишет `description` только если оно там пустое (существующее не затирается; не смогла прочитать — не пишет). Описание ищется, только если включён тумблер `bc.web`, ключ ИИ есть и поиск Google не заблокирован. Цена: каждый найденный товар = +1 запрос Gemini, поэтому пачка с описаниями идёт заметно дольше (лимит 10 в минуту — пачка из 20 около 2–4 минут).
5. **Реплика.** «Без фото: N товаров. Ищу пачками по 20; в любой момент можно остановить» (5 языков), плюс строки «Уже проверено раньше: K — продолжаю с того места» и «Поиск Google сейчас недоступен…», если применимо.

## Что оставлено
- Название «Проверка товара для совершенно…» слишком общее: даже при сверке подписи такой товар чаще попадёт в «проверьте», а не в «Поставить все» — это ожидаемо. Распознавать саму листовку по картинке (текст на изображении) нельзя без ИИ-распознавания; защита — совпадение названия, форма и размер.
- Продажи в плитке нет, поэтому порядок по остатку, а не по продажам.
- Описание ищется только вместе с найденным фото (не отдельной командой «дополни описание»).
- Одиночный поиск «на выбор» (1–3 товара) работает как раньше, но тоже не принимает видео/соцсети и мелкие картинки; описания в нём нет.
- `graphify update` не запускался.
