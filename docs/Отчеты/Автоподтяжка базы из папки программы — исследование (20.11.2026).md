# Автоподтяжка базы из папки программы — исследование (20.11.2026)

Просьба владельца: «обдумай и реализуй автоматическое подтягивание базы, если указать установленную папку программы, и с подсказкой, где по стандарту база». Мастер «Массовая загрузка» → шаг «Файл» → панель «Или подтяните базу из папки программы».

Пометки: **[П]** — проверено (источник указан, или проверено на файле/в тесте), **[Г]** — гипотеза (по соглашениям Windows и описанию программы; реальной установки/образца у нас не было), **[О]** — общеизвестный факт, на образце не проверялся.

Сообщение: «Эту базу прочитать напрямую нельзя: … Выгрузите товары в Excel или CSV» + «Как выгрузить» для программы.

## 2. Образец CT MAX (docs/Образцы/Ситимакс/CTMAX-выгрузка-товаров.xlsx, в .gitignore)

[П] проверено на файле: книга Excel, 3 листа (данные на первом, два пустых), диапазон `A3:D15641` (≈ 15 600 строк), **шапка в 3-й строке**: «Штрих Код», «Наименование», «Цена», «Закупочная». Остатков нет. Среди товаров стоят **строки-группы** (в справочнике строк видны «АЛЬЯНС», «Дисконтная карта», «Grifon», «ФитоКосметик» …) — у них нет штрихкода/цены; мастер пометит их ошибкой «нет штрихкода», как у выгрузок 1С/Paloma365, их можно не загружать. Заголовки узнаются автоподбором (Штрихкод, Наименование, Цена продажи, Закупка); отдельный профиль CT MAX в `ImportSourceProfiles` не нужен (если появится плитка — id `ctmax` уже есть в справочнике подсказок). Тест читает этот образец через «папку» (если файл есть в копии).

Где CT MAX хранит локальную базу и в каком формате — **выяснить не удалось**: сайт и страница загрузок формат не называют, App Store: приложение синхронизируется с сервером. Нужно спросить разработчика (тел. на ctmax.kg) или посмотреть папку установки у клиента с `ctmaxsetup.exe`.

## 3. Что реализовано (без новых зависимостей)

Код — в `NurMarketKassa.Infrastructure/Services/BulkImport/ProgramFolder/` (новые файлы) и `Views.axaml/Main/BulkImportWizardWindow.ProgramFolder.cs` (панель); в чужие файлы внесены только хуки (2 строки в `BulkImportWizardWindow.Steps.cs`, перегрузка `ClientsImportWindow.ShowAsync(owner, table)`, значение `ProductFileKind.Database`).

- Справочник «программа → стандартные пути → облако/читаем/нужна выгрузка» (`ProgramFolderHints`), подсказка «Обычно здесь: …» и кнопка «Открыть папку» (только если папка существует).
- «Найти на этом компьютере» — только проверка существования заранее известных путей и чтение списка баз 1С `ibases.v8i`; обхода диска нет.
- Просмотр выбранной папки (`ProgramFolderImporter.Scan`): глубина до 4, не больше 4000 файлов, системные папки и ссылки пропускаются, открываются только первые байты (признак SQLite/DBF/XML 1С).
- Распознавание программы: по словам в пути/именах (уверенность «высокая»), по файлам 1С, по заголовкам выгрузки (профили столбцов), иначе по выбранной плитке («низкая»); для баз SQLite/DBF после чтения «высокая» понижается до «средней» (схема таблиц — наша догадка).
- Чтение: **SQLite** (универсально: таблица товаров находится по названиям столбцов теми же синонимами, что у Excel; штрихкоды, цены, остатки — из соседних таблиц по столбцу-ссылке на товар; доп. штрихкоды; категория и единица — по `category_id`/`unit_id`; пометки «удалён» и «папка» пропускаются; клиенты и долги — отдельной таблицей), **DBF** (свой читатель без пакетов, кодировка 866/1251), **CommerceML** (import.xml + offers.xml сливаются), **Excel/CSV**.
- Безопасность: только чтение; база копируется вместе с `-wal/-shm/-journal` во временную папку (чтение с FileShare.ReadWrite — программа может держать файл) и копия удаляется (в том числе при отмене и ошибке); в исходной папке ничего не меняется (тест сверяет хэш); на сервер ничего не уходит до «Загрузить» на шаге «Проверьте»; в журнал — только вид файла и числа.
- Ошибки: папка не найдена / пуста / нет подходящих файлов / файл занят / нет прав / база зашифрована / больше 1 ГБ / больше 50 000 товаров / формат не поддерживается — понятный текст на 5 языках и «Как выгрузить».
- Android: панель заменена пояснением «только на компьютере»; код собирается на всех платформах (SQLite и файлы — обычные API).

## 4. Что нужно для закрытых форматов (НЕ добавлено — решение владельца)

| Формат | Что нужно | Оценка |
|---|---|---|
| Firebird `.fdb` | пакет `FirebirdSql.Data.FirebirdClient` (IPL, ~1 МБ) + встроенный движок (embedded, ~7–10 МБ на платформу) или работающий сервер; база часто в кодировке WIN1251 | 2–3 дня; рост установщика ≈ 10 МБ; Android/Linux — отдельные библиотеки |
| Access `.mdb/.accdb` | на Windows — драйвер ACE OLEDB (ставится с Office, не у всех); без драйвера — пакет-читалка (напр. `MDBTools`-порты, `AccessDatabaseEngine`) — зрелых бесплатных нет | 2–4 дня, риск |
| SQL Server `.mdf` / LocalDB | `Microsoft.Data.SqlClient` + установленный SQL Server/LocalDB, база должна быть подключена (прикрепить `.mdf` без сервера нельзя) | 1–2 дня, плюс установка LocalDB у клиента |
| 1С `1Cv8.1CD` | закрытый формат; чтение возможно только через платформу 1С (COM-соединение) или ibcmd — сторонние читатели ненадёжны | не рекомендуется; путь — выгрузка CommerceML/Excel из самой 1С |
| 1С `.dt` | закрытый, только платформой 1С | выгрузка |

## 5. Что нужно от владельца

1. Образцы реальных папок с данными (без персональных данных): **Paloma365, Umag, Rosta, CT MAX** — после установки программы: папка установки + `%APPDATA%\<программа>` + `%LOCALAPPDATA%\<программа>` + `%PROGRAMDATA%\<программа>` (список файлов и размеры хватит, если сами файлы нельзя). Тогда стандартные пути [Г] станут [П], а универсальный разбор SQLite/DBF — точным профилем.
2. Решение по Firebird/Access/SQL Server (раздел 4) — только если у клиентов эти базы встречаются.
3. Для CT MAX — спросить у разработчика формат серверной базы и есть ли выгрузка «остатки» (в образце только цены).

## 6. Проверки (21.11.2026)

- Unit (`ProgramFolderImportTests`, 27 тестов; вместе с профилями и «только новые» — 48 зелёных): поиск и распознавание программы по набору файлов и имени папки; глубина обхода и пропуск системных папок; копия базы во временную папку, **хэш исходной базы не меняется**, после чтения и при отмене временных копий не остаётся; база, которую «держит» другая программа (чтение с общим доступом), читается, при монопольной блокировке — «файл занят»; SQLite с отдельными таблицами штрихкодов/цен/остатков/групп/единиц, доп. штрихкоды, помеченные удалёнными пропускаются, клиенты находятся отдельно; зашифрованный `.sqlite3`; DBF в кодировке 866 с удалённой записью; 1С (CommerceML import+offers сливаются, закрытая `1Cv8.1CD` рядом); Firebird/Access/SQL Server — понятное сообщение; Excel/CSV в папке (программа узнана по заголовкам); пустая/несуществующая папка; **реальный образец CT MAX** (≈ 15 600 строк, программа узнана, остатков нет); справочник подсказок и разбор `ibases.v8i`.
- UI (`BulkImportProgramFolderUiTests`, 6 случаев: 1024×600 и 1366×768 × ru/ky/uz; вместе с UI-тестами мастера и `FormFieldsOverlapUiTests` — 214 зелёных): панель на шаге «Файл» не налезает на соседние поля, текст не обрезан; у облачной программы — пояснение «в облаке» без «Обычно здесь», у Paloma365 — подсказка и обе кнопки; чтение синтетической базы оставляет на шаге «Файл», показывает карточку файла, «Далее» доступна; пустая папка — понятная ошибка. Снимки (смотрены глазами): `%TEMP%\nurmarket-tests\ui-actual\bulk-folder-*.png`.
- Не проверено вживую: системный диалог выбора папки, кнопка «Открыть папку», чтение настоящих баз Paloma365/Umag/Rosta/CT MAX (нет образцов), Linux и Android (на Android панель — только пояснение).
