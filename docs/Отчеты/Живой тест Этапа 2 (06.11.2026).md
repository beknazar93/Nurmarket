### Найдено в A/B
- **Б2-1 (высокая, деньги):** касса запущена без связи → связь вернулась (очередь ушла, «Онлайн») → «Оплата долга» → «Погасить» → красное «**Не удалось определить компанию — оплата не проведена. Проверьте вход и связь, затем повторите.**» (S2-B33). «Обновить данные (F5)» не помогает; помогает только перезапуск кассы. В журнале после старта без связи нет ни «Company loaded», ни «Компания дозагружена фоном» (при медленном старте — есть). Причина по коду: `DebtPaymentRunner.CurrentCompany` = `CompanyInfoService.LastCompany`, а после старта без связи компания не загружается и при восстановлении связи не дозагружается. Шаги: выйти без закрытия смены → оборвать связь → запустить кассу → вернуть связь → Меню → Оплата долга → клиент → Погасить. Регресс или старое — не проверял.
- **Б2-2 (средняя, деньги):** «Оплата долга» показывает только чеки со статусом `debt` (`pos/sales/?status=debt`). Долговой чек после частичного возврата на сервере становится `partially_returned` и **пропадает из «Непогашенных»**: у «Клиент-2» в списке клиентов «по чекам: 40,00 сом», а в окне — пусто и «Итого к оплате: 0,00» (S2-B31). Остаток долга по такому чеку кассир принять не может. У «Клиент» подтверждение «Останется долг: 0,00 сом», а после оплаты «Оплачено 7,00 сом. Остаток долга: 23,00 сом» (23 — чеки `partially_returned`), «Итого к оплате: 7,00» не обновилось после оплаты (S2-B34).
- **Б2-3 (средняя, вид денег, владелец):** «Продажи и финансы» → вкладка «Продажи»: колонка «Сумма» = **0,00 сом у всех чеков** (сегодня и вчера; плитки и «Средний чек» верные) — S2-F03. Строки, по-видимому, приходят через `FinanceWindow.Merged.cs` (`ShowFirstRowsFromFinance`/`ToSalesRows`); регресс или старое — не проверял.
- **Б2-4 (низкая):** при медленном сервере (запрос остатка после продажи > 8 с) «Касса:» не прибавляет наличные продажи сразу — остаётся прежней до следующего тихого запроса (без ввода — раз в 4 мин): 11 728 вместо 11 738 с 20:10:50 до ~20:14:20. Онлайн-продажа в кассу локально не прибавляется, только с сервера.
- Мелочи журнала: при старте без связи и при медленном старте сразу после «Сбой сервера… подряд 1» пишется «[OFFLINE] **Связь с сервером восстановлена** — касса вышла из офлайн-режима» (неправда); при старте без связи 3 первых отказа сразу переводят кассу на HTTP/1.1 «до перезапуска»; «После восстановления связи отправлено продаж: 2» при 1 чеке + 1 возврате.
- Не баг (артефакт UIA): при скрипте «2 раза добавить Крышку» второй раз открылось «Товара нет в наличии» (остаток 1), а мой UIA-вызов «Оплатить» прошёл сквозь модальное окно — оплата открылась поверх него. Мышью так не сделать.

## Баги по серьёзности

### Высокая (деньги)
- **Б2-1.** После старта кассы без связи «Оплата долга» до перезапуска невозможна: «Не удалось определить компанию — оплата не проведена…», хотя связь вернулась и F5 нажат. Компания не дозагружается при восстановлении связи (`CompanyInfoService.LastCompany` = null → `DebtPaymentRunner.CurrentCompany`). Шаги и снимок — в разделе B (S2-B33).

### Средняя
- **Б2-2 (деньги).** «Оплата долга» видит только `status=debt`; долговой чек после частичного возврата (`partially_returned`, остаток долга > 0) исчезает из «Непогашенных» — остаток долга по нему в кассе не принять; подтверждение «Останется долг: 0,00», а после оплаты «Остаток долга: 23,00»; «Итого к оплате» не обновляется после оплаты (S2-B31, S2-B34).
- **Б2-3 (вид денег).** Программа владельца → «Продажи и финансы» → «Продажи»: колонка «Сумма» = 0,00 сом у всех чеков, за любой период (S2-F03, S2-F30).
- **Сервер (Умару):** частичный возврат долгового чека — `debt_remaining` не уменьшается (№2075: 12 → 12); возврат поставщику 0,13 уменьшает сделку долга на 0,12 (1,00 → 0,88).

### Низкая (вид / удобство)
- **Б2-4.** При медленном сервере «Касса:» после продажи не обновляется до следующего тихого запроса (до ~4 мин без ввода).
- **Б2-5.** «Приём товара» → «Доп. расходы» → «Применить»: строка не показывает «с расходами …» и прибыль считает без расходов, пока строку не править.
- Удаление весов «Штрих РС-200» оставляет в настройках правило префикса 27 (`ScaleWeightPrefixes`), папку обмена (`ShtrikhPcConfig`) и блок «Весы «Штрих РС-200»: раскладка этикетки».
- Окна ошибок скана («Штрихкод прочитан неверно…», «PLU … не найден») — лишняя кнопка «Отложить ошибку».
- Вопрос «Отменить прокат?» всегда пишет «залог принят», даже при залоге 0.
- Возврат поставщику: «можно вернуть: 8 шт · 0,12 сом» при «Сумма возврата: 0,13».
- Esc во всплывашке «?» закрывает весь раздел «Продажи и финансы».
- «Заканчивается — меньше 10» на плитке Склада, хотя правило теперь учитывает «Минимальный остаток».
- «Новый товар»: без штрихкода «Добавить» молчит, подсказка «Введите штрихкод…» внизу прокрутки.
- Журнал: «Связь с сервером восстановлена» сразу после сбоя на старте; «смена остаётся открытой» при уже закрытой смене; «отправлено продаж: 2» при 1 чеке + 1 возврате; при старте без связи — переход на HTTP/1.1 до перезапуска.
- Поля с точкой: количество «1.250» в чеке, «11753.00» в закрытии смены (известно с прошлых прогонов).
