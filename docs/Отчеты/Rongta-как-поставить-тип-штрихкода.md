# Rongta: как поставить тип штрихкода «по весу» (07) — 12–13.11.2026

> **13.11, позже:** разобран протокол самой программы RLS1000 (UDP 5001). Тип штрихкода — байт 42 карточки. Касса теперь пишет его сама: «Настройки весов Rongta» → «Штрих-код» → «Исправить: тип 07». Подробности и порядок проверки — `Rongta-RLS1000-разбор.md`. Шаги на весах ниже остаются запасным путём.

> **Проверено вживую 13.11.2026** на весах Rongta RLS1000 владельца (192.168.1.87): тип 07 записан кассой по UDP 5001 после «Отправить на весы» (PLU 11 «Айфон»); этикетка 5,165 кг на 1074,32 сом напечатала штрихкод `2000011051655`, касса отсканировала: «Айфон» 5,165 кг × 208 = 1074,32. Затем тип записан во все 17 весовых товаров (весы ответили `02` на все пакеты), дата на этикетке верная. Старая проблема «нет штрихкода при сумме > 1000 сом» решена.
>
> **Что сделано в программе (13.11.2026):** в «Настройки весов Rongta» → «Штрих-код» кнопка «Исправить: тип 07 (рекомендуется)» показывается для ЛЮБОГО типа, который касса не прочтёт или у которого есть предел суммы (раньше — только для типов по сумме); крупная строка «★ Для Rongta рекомендуем тип 07 — проверено»; в списке типов 07 стоит первым с пометкой «★ рекомендуется»; у новых настроек тип по умолчанию 07, отдел 20 (у сохранённых настроек ничего не меняется); после «Отправить на весы» в окнах «Весы» и «Отправка товаров на весы» появляется плашка «Проверьте на весах…» (или запасной путь с весов и путь к `rongta-udp-exchange.log`, если весы не ответили по 5001); статья «Весы Rongta: подключение и штрихкод» в базе знаний (5 языков) и обновлённая «Инструкция подключения» у весов Rongta. **После обновления кассы** товары надо отправить на весы заново (названия в карточках теперь пишутся обычной cp1251 — раньше в «Мясо Барана (мякоть)» печатались лишние знаки); это сказано и в статье, и в инструкции.

**Проблема.** У товаров, которые касса записала на весы напрямую по сети (порт 4001), штрихкод печатается по типу **02**: отдел + код 5 цифр + **сумма 5 цифр** (в сотых). Больше **999,99 сом** в него не помещается, и весы печатают этикетку **без штрихкода**. Примеры: «Бука лакым» 1265,00, «Мясо Барана» 1328,00, 1665,00 и 1900,00, «Ларан Шоколад» 1415,25. При меньшей сумме штрихкод есть: «Айфон» 721,76 → `20 00011 72176 3` [фото].
**Решение — тип 07:** отдел + код 5 цифр + **вес** WW.WWW (до 99,999 кг). Суммы в нём нет, касса сама считает её по своей цене. В руководстве программы RLS1000 (прил. II) так и сказано: «для весового штрихкода обычно 7 или 27».

Обозначения: **[док]** — официальные руководства Rongta (RLS Series User Manual V1.2/V1.3, RLS1000 Software User Manual, Label Scale Simple Manual). **[фото]** — фото владельца. **[проверено]** — проверено на весах владельца. **[не проверено]** — догадка.

## Вывод
- **В прямом режиме (порт 4001) касса тип штрихкода карточки НЕ задаёт.** В записи «!0V» поля типа нет. Поле madv4 = 07 проверено на весах владельца 12.11: тип не изменился [проверено]. Экспериментальная настройка в кассе убрана, касса снова пишет 0.
- **Тип по умолчанию** (*set default barcode type*) действует только на **новые** карточки. На уже записанные товары он не влияет [фото, проверено].
- **Надёжные пути:**
  **(а)** на весах — системный пункт «тип для всех товаров» (ниже, шаг 2);
  **(б)** режим «свой сервер» через программу RLS1000. Там тип штрихкода есть в записи товара (команда 0110, поле «Barcode type, 2 цифры» после «Art. No.») [док]. С 13.11 касса пишет туда тип, выбранный в «Настройках весов Rongta» → «Штрих-код». Пока структура не выбиралась — 05, как раньше.

## Шаги на весах [док, разд. 7.2 и 7.1]
1. Зажмите **[SETTING]** на 2–3 с — откроются системные настройки. Если спросят пароль, это пароль из программы RLS1000. Пункты листают стрелками **[◄]/[►]**, открывают и подтверждают кнопкой **[PRN/ENTER]**. Значения: 0 — нет, 1 — да.
2. **Тип для всех товаров:** пункт **«barcode type: set all barcodes' type»** (в V1.3 — *Set print barcode type*) → **07** → **[PRN/ENTER]**. Этот пункт меняет тип у ВСЕХ записанных товаров.
3. **Тип для новых товаров:** пункт **«set default barcode type»** (0–99) → **07** → **[PRN/ENTER]**.
4. **Одна карточка** (если пункта из шага 2 нет):
   - зажмите **[PLU]** до надписи «single item edit»;
   - наберите **6-значный СВЕЖИЙ КОД товара** (LFCode), а не номер ячейки, → **[PRN/ENTER]**;
   - нажмите **B** («Bar Code Type 0–99») → **07**;
   - нажмите **S** («Save»).
   **Какой код вводить:** касса пишет в запись товара «код товара для штрихкода». Он берётся из колонки «Код в ШК» окна «Весы», а если она пуста — это номер PLU товара. Этот же код стоит в штрихкоде этикетки после «20». Значит, «Мясо Барана» (на этикетке `20 00005 …`) — **000005**, «Айфон» — **000011**, «картошка» — **000017**, тестовый товар в ячейке 4000 — **009999**. Что весы ищут карточку именно по этому коду, вывод сделан по штрихкодам этикеток, на весах не проверено. Если «000005» не найдётся, попробуйте номер ячейки.
5. **Дата и время:** пункт **«T date adjusting»** → текущие дата и время → **[PRN/ENTER]**. Дата на этикетках (08-13-94, 27-09-26) — это **часы весов**. Касса дату не пишет: в записи «!0V» есть только срок годности в днях. Если дата снова сбивается после выключения — батарейка часов [не проверено].
6. **Знаки цены:**
   - «J decimal digits in unit price» = 2;
   - «X total price precision» = **2 (N.NN)** (варианты: 1 — N.N0, 2 — N.NN, 3 — N.N);
   - в кассе «Знаков после запятой в цене на весах» тоже = 2. Должно совпадать, иначе цены будут в 10 раз неверны.

**Не трогайте:** «ВЫБОР ФОРМАТА ЭТИКЕТКИ» (D0/D1 — при неверном значении этикетка выходит пустой [док, 8.2]) и «Recover factory system para» (сброс к заводским).

## Шаги в кассе
1. «Настройки весов Rongta» → «Штрих-код» → **«Выбрать структуру без ограничения суммы»**. Касса начнёт читать префикс 20 как **вес**; в режиме «свой сервер» тип 07 и отдел 20 уйдут в каждую запись товара.
2. Окно «Весы» → **«Отправить на весы»**.
3. На весах проверьте тип (шаг 2 или 4 выше). Положите товар дороже 1000 сом, напечатайте этикетку: штрихкод `20 0000N 0WWWW C` есть? Отсканируйте его кассой: сумма должна совпасть с этикеткой.

## ⚠ Важно
- После смены типа **перезапишите товары и распечатайте этикетки заново**.
- **Этикетки, напечатанные ДО смены (тип 02, сумма), после смены не сканируйте.** У обоих типов префикс 20, и касса прочтёт старую сумму как вес: «00290» превратится в 0,290 кг × цену. Продайте или перепечатайте их до переключения.
- Тип должен совпадать **и на весах, и в кассе**.
- Если нужны суммы на этикетке от 10 000,00 сом (8 знаков): расширьте поле TOTAL PRICE в шаблоне RLS1000 и загрузите шаблон на весы с видом D0. При 2 знаках «1265,00» и «1900,00» в рамку помещаются [фото].

## Что проверено на весах владельца (12.11)
- Чтение карточек по сети («!0U», ячейки 1–300) у Rongta не работает: весы всегда отвечают «пусто».
- Тестовый товар записан в ячейку 4000: код 9999, «ТЕСТ ШК 07», 1000,00/кг, madv4 = 07. Весы приняли запись (`0v4000a`). Тип штрихкода в карточке от madv4 **не изменился**.
- Автоотправки на весы в кассе нет: только кнопка «Отправить на весы». Каждая отправка пишется в журнал кассы.

## Для сайта (бэкенд)
Файл `.txp` для способа «файл + F9» собирает сайт, и тип штрихкода в нём сейчас 5. По формату TXP/TXU [док] поле «Barcode Type» (2 цифры) стоит после Code (10):
PLU No 4, Name 36, LFCode 6, Code 10, Barcode Type 2, Unit Price 8, Weight Unit 1, Dept 2, Tare 6, Shelf 3, Pack Type 1, Pack Weight 6, Pack Tol 2, Msg1 3, Msg2 3, Account 10, Multi Label 3, Rebate 3, PCS Type 2 — числа выравниваются вправо, после каждого поля пробел, строки через CRLF.
Чтобы тип выбирался из настроек весов компании, нужна правка на сайте (ТЗ Умару).
