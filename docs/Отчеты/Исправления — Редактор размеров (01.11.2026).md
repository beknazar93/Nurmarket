## Что сделано

**С2-04. Проверка остатка и цены размера** (`TryReadQty` :308, `TryReadPrice` :312, проверка строк в `SaveAsync` :386+)
- Остаток разбирается через `CheckoutValidation.TryParseAmount` (до 3 знаков): пусто, «abc», «−5», «1.000» — ошибка; «1 000» и «12,5» читаются верно.
- Цена: пусто или 0 = цена товара; «abc» — ошибка (раньше молча становилась ценой товара).
- Неверная строка не уходит на сервер вообще, поле получает красную рамку (`MarkBad` :303, снимается при правке поля), в строке состояния — «{размер, цвет}: остаток — число 0 или больше…». Остальные строки сохраняются.

**С2-05. Второе сохранение не стирает продажу**
- В строке новое поле `BaseQty` (:64) — остаток, который знает окно (при открытии / после сохранения / после перечитывания). `SendQuantity` = новая строка или число в поле ≠ `BaseQty` (раньше сравнивалось с `Source.Quantity`, который после первого сохранения брал ответ сервера, а в поле оставалось старое число).
- После успешного сохранения строки поле остатка и `BaseQty` переписываются из ответа сервера; затем варианты перечитываются целиком (уже было для кеша) и остатки всех не упавших строк обновляются по серверу (кроме строк, где кассир уже правит остаток).
- Сверка перед записью (:460+): если остаток меняли, окно запрашивает варианты с сервера. Если серверный остаток ≠ `BaseQty` (была продажа/приход) — вопрос «Остаток изменился: было X, стало Y, вы ввели Z (изменение ±d). Применить изменение к текущему остатку (получится Y+d)?» Кнопки «Применить изменение» / «Оставить как на сервере». «Применить» шлёт Y+d (дельта поверх текущего), «Оставить» — поле принимает серверное число, остаток не пишется. Если результат дельты < 0 — считается как «Оставить».
- Сервер не ответил на сверку — остаток вслепую не пишется (ошибка в строке, число в поле остаётся, остальные поля строки сохраняются). Размер, которого уже нет на сервере — ошибка, строка не пишется.
- API шлёт абсолютное число (дельты на сервере нет), поэтому дельта считается в окне.

**С2-06. Этикетки только с сохранённых кодов** (`PrintLabelsCoreAsync`, :707)
- `SaveAsync` теперь возвращает `true`, только если всё сохранено без ошибок.
- Если в окне есть несохранённое (`HasUnsavedChanges` :322: новые строки, правки полей, удалённые строки, изменённый остаток) — окно «Сначала сохраните» с кнопками «Сохранить и печатать» / «Отмена». Сохранение не удалось — печати нет.
- Печатаются только строки, у которых штрихкод в поле совпадает с сохранённым на сервере (`Source.Barcode`) и есть `Id`.

**Дубли штрихкодов до сохранения** (`FindBarcodeDuplicates` :345)
- Проверяются только штрихкоды, которые правили в этом окне: совпадение с другой строкой окна, с основным/дополнительным штрихкодом другого товара каталога (`CatalogCacheService`), с размером другого товара (`VariantBarcodeIndex`). Свой товар и неизменённые коды не проверяются.
- Найдено — окно «Штрихкод повторяется» со списком (до 8), кнопки «Сохранить всё равно» / «Исправить»; поля красные; «Исправить» — ничего не уходит на сервер.

Все надписи на 5 языках (`Tr.T`), комментарии с датой 2026-11-01.

## Что проверить вживую на NBS (товар с размерами)
1. Остаток размера: стереть поле, «abc», «−5», «1.000» → «Сохранить»: красное поле, на сервере остаток прежний. «1 000» и «12,5» сохраняются как 1000 и 12,5.
2. Открыть размер с остатком 5, на кассе (другой экран) продать 1 (на сервере 4), в редакторе поменять только цену → «Сохранить» → остаток на сервере остаётся 4, в поле становится 4. Нажать «Этикетки» / сохранить ещё раз — остаток остаётся 4.
3. То же, но в поле поставить 7 (было 5, на сервере 4): вопрос «было 5, стало 4, изменение +2, получится 6» → «Применить» → на сервере 6; «Оставить» → 4.
4. Копеечные правки с компенсацией: размер M +1 и размер L −1 одним сохранением при продаже между ними — суммы сходятся с учётом продажи; сумма по размерам сверяется с остатком товара (подсказка вверху).
5. Новый размер с кодом → «Этикетки» без сохранения: предупреждение «Сначала сохраните» → «Сохранить и печатать» печатает; при обрыве связи (отключить сеть) печати нет.
6. Одинаковый код у двух размеров / код как у другого товара → окно дублей.

## Ограничения
- Запись остатка остаётся абсолютным числом (сервер не принимает дельту): между сверкой и PATCH теоретически возможна гонка в доли секунды.
- Дубли с товарами проверяются по кешу каталога кассы (не по серверу); неизменённые коды не проверяются.
- «Продаётся», размер и цвет в сверке конфликтов не участвуют (последний записавший выигрывает), как и раньше.
- С2-38 (сырой `ex.Message`), С2-39 (коды на «29»), С2-43 (цена «85.00 сом» на этикетке), подтверждение удаления строки — не трогались (вне задачи).
