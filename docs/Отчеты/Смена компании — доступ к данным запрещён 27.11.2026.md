# Смена компании — «доступ к данным запрещён» (27.11.2026)

## Жалоба
Фото с кассы клиента (пользователь Windows «admin», экран «Вход в кассу», «Загрузка компании…»):
«Не удалось сменить компанию. Данные прежней компании заняты другой программой (не удалось убрать: data (Access to the path 'C:\Users\admin\AppData\Roaming\NurMarketKassa\data' is denied.)). Закройте программу владельца и антивирус и войдите снова».

## Причина (найдена и подтверждена на этом ПК)
- При смене компании касса переносит папку `%APPDATA%\NurMarketKassa\data` (там `pos_local.db`, `-wal`, `-shm`, `backups`) целиком в `_previous\{время}` с помощью `Directory.Move` (`Services/AccountDataIsolation.cs`).
- В Windows папку нельзя переименовать, пока внутри открыт хоть один файл. Тогда ОС отвечает «Access … is denied».
- Программа владельца (`--owner`) в «Сводке → Требует внимания» читает очередь кассы этого ПК (`SiblingTillQueue.CountSales`). Она открывала `pos_local.db` кассы соединением SQLite **с пулом**. После `Dispose` соединение оставалось в пуле, и файлы `pos_local.db`, `-wal`, `-shm` были открыты до выхода из программы владельца.
- Проверено через Windows Restart Manager на старой версии: держатели базы кассы — касса (PID 20056) и **программа владельца** (PID 11868, `--owner`). Поэтому смена компании падала всякий раз, когда открыта программа владельца.
- Права NTFS, атрибут «только чтение», OneDrive и «Контролируемый доступ к папкам» здесь ни при чём. Папка `%APPDATA%` не синхронизируется и не защищается по умолчанию, а файл «только чтение» не мешает переносу (это проверено тестом). Антивирус мог бы дать такую же ошибку, но на короткое время.

## Что исправлено
1. **Сама причина:** в `SiblingTillQueue` соединение открывается с `Pooling=False`. После чтения программа владельца больше не держит базу кассы. Проверено вживую после установки: держатель только касса (PID 13964), программа владельца (PID 16300) — нет.
2. **Надёжный перенос** (`AccountDataIsolation`):
   - 5 попыток с растущей паузой, всего около 2,5 с (было 3 попытки по 300 мс). Между попытками закрывается пул соединений.
   - Если папку целиком перенести не удалось, она переносится **по частям**: подпапки и свободные файлы — переносом. Базу SQLite, которую кто-то держит на чтение, касса сначала копирует целиком в карантин средствами SQLite (вместе с WAL) и проверяет копию (`quick_check`). Только после этого таблицы убираются на месте, и новая компания получает пустую базу, как после обычного переноса. Данные прежней компании не удаляются без проверенной копии.
   - Если что-то всё равно не вышло, всё возвращается на место: файлы переносятся обратно, база восстанавливается из копии, пустой набор `_previous\{время}` убирается (иначе «Повторить» в ту же секунду упёрся бы в него).
   - Касса через Restart Manager определяет, кто держит файлы (новый `Infrastructure/Services/FileLockHolders.cs`, только чтение), и пишет это в журнал (процесс, имя, «сама касса» или «программа владельца»).
3. **Понятное окно вместо тупика** (`UnsentDataDialog.ShowSwitchFailed`): без путей и текста ОС (они только в журнале). Одна главная кнопка:
   - держит программа владельца — «Закрыть программу владельца и повторить». Касса закрывает её штатно, как кнопкой «×» (несохранённые разделы программа спросит сама), ждёт до 20 с и повторяет. Принудительно не убивает;
   - иначе — «Повторить». Текст называет держателя (антивирус и т. п.) и советует перезапустить компьютер, если не помогает;
   - «Отмена» — выход из входа, касса остаётся в прежней компании. Ничего не потеряно.
   - Все надписи на 5 языках, `check-tr.ps1` — 0 нарушений.

## Тесты
`NurMarketKassa.UiTests/Scenarios/AccountSwitchLockedDataTests.cs`, 5 тестов, все прошли через `test-safe.ps1 -Phase ui`:
- база открыта «другой программой» на чтение → смена проходит; в карантине целая копия (товары и неотправленный чек), `backups` унесены, база на месте пустая;
- файл открыт без общего доступа → ошибка с «Повторить», держатель назван, всё на месте, пустого набора нет; после освобождения повтор проходит;
- файлы «только чтение» не мешают;
- после `SiblingTillQueue.CountUnsent` папку `data` можно переименовать (до исправления пул держал файл);
- текст окна на 5 языках без `C:\`, «Access to the path», «denied».

Связанные группы `Wave3`, `OutboxStage1`, `Sibling` — 88 из 88. Сборка Debug и publish dev-out — без ошибок. Настоящие `pos_local.db` и `user-settings.json` тестами не тронуты (хэши). Резервная копия перед установкой — `C:\Users\User\NurMarket-test\backup-switch-20261127`.

## Что не проверено вживую
- Полная смена компании через окно входа (market@nur.kg → mini-hozmag@nur.kg и обратно) не выполнялась. Пароля market@nur.kg у меня нет: после смены сохранённый вход прежней компании уходит в карантин вместе с базой, и тестовая касса владельца могла остаться на чужом аккаунте. Кроме того, параллельно работает другой исполнитель. Вживую проверено главное: новая программа владельца не держит базу кассы.
- Ветка «закрыть программу владельца» проверена только кодом и тестом текста: после исправления №1 до неё практически не дойдёт.

## Доработка: 4 хранилища 1.17.96 в реестре
- В `CompanyStoreRegistry` как данные компании внесены: `cashier_badge_sessions.dat` (+`.bak`), `client-mailing.json`, `onec-export.json` (CompanyItems) и `badge_attempts.json` (CompanyLocalItems, он лежит в `%LOCALAPPDATA%`). При смене компании они уходят в `_previous`, при сорванной смене возвращаются на место.
- Добавлены `CashierBadgeThrottle.ResetMemory()` и `ClientMailing.ResetMemory()`, их вызывает `AccountDataIsolation.SwitchTo`. Без этого старые счётчик попыток и рассылка из памяти записались бы в файлы новой компании. `CashierBadgeVault` и `OneCExport` читают файл при каждом обращении, сброс им не нужен.
- При возврате в прежнюю компанию файлы из карантина **не** восстанавливаются: по решению владельца от 29.10 данные приходят с сервера заново. Входы по QR-бейджам хранятся только на ПК, поэтому после возврата бейджи придётся выпустить заново. Если нужно восстановление — это отдельное решение владельца.
- Тест `Badge_sessions_mailing_and_onec_files_leave_with_the_company_and_come_back_on_rollback`. `check-store-registry.ps1`: все имена есть в реестре.
