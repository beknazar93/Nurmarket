## 3. Новые находки — мобилка

**М4-01. СРЕДНИЙ (деньги, ПЛАУЗИБЛЬНО). Команды ИИ очищают, откладывают и подменяют чек во время оплаты.**
- **Где:**
  - `lib/core/providers.dart:660-667`: в `clear()` и `restore(Cart)` нет проверки `frozen`;
  - вызовы из ИИ: `lib/core/ai/assistant/action_tools.dart:810` (отмена правки чека), `:913` (очистка), `:948, :959` (отложить и отменить это), `:987, :1000` (вернуть отложенный).
- **Сценарий:**
  1. Кассир нажал «Провести оплату», сервер отвечает 3–10 с. Звонок ИИ открыт плашкой поверх.
  2. Кассир (или ИИ, неправильно поняв) говорит «отложи чек». Оплачиваемые строки уходят в «Отложенные», чек очищается.
  3. Продажа проходит. `payment_screen.dart:656`: чек «не тот же» (`identical` ложно), поэтому ключ не стирается.
  4. Кассир пробивает следующего покупателя. Очистка после его оплаты увеличивает `cart.clearedSeq`, и старый ключ становится «зомби» (`sales_repository.dart:248-251`).
  5. Позже из «Отложенных» возвращают уже оплаченный чек и оплачивают — получается **вторая продажа** тех же товаров (новый ключ).
- Так же «отмени» после «добавь» подменяет оплачиваемый чек снимком.
- **Как исправить:**
  - `restore()`: `if (frozen) return;`;
  - `clear()`: обходить заморозку только при очистке после оплаты (параметр `force` из `payment_screen`);
  - в начале `_cartRun`, `_holdCart` и отката корзины: при `frozen` ответить «идёт оплата».

**М4-02. СРЕДНИЙ (ложные записи, по коду точно). Во время оплаты ИИ отвечает «сделано», а в журнал пишется удаление, которого не было.**

- **Как исправить:** та же проверка `frozen` в начале `_cartRun`; журнал писать только если строка действительно исчезла.

## 4. Новые находки — Android-касса

**А3-01. ВЫСОКИЙ (ПЛАУЗИБЛЬНО; цепочка проверена мной по коду). Уход в фон и открытие камеры запускают сценарий выхода из программы.**
- **Где:**
  - `MainActivity.cs:164-171` (`OnStop`) → `AndroidBootstrap.OnEnteredBackground` → `Shell/AndroidDesktopLifetime.cs:85-95` вызывает `ShutdownRequested`;
  - подписчики в `NurMarketKassa.Avalonia/App.axaml.cs:377-385`: `BackgroundReceiptsHost.OnShutdownRequested` (`Views.axaml/Main/BackgroundReceiptsHost.cs:139-216`) и `CartRemovalLogStore.FlushAsync().Wait(2 с)` + `CheckpointWal()` на UI-потоке.
- **Сценарий:**
  - `ScannerActivity` непрозрачна: сканирование камерой, кнопка «Домой» и гашение экрана — это `OnStop`.
  - Если идут «Приходы в фоне»: каждый такой уход показывает «Есть приходы в фоне: N… [Выйти] [Подождать]». «Выйти» → `desktop.Shutdown()`, и касса закрывается. Типичный путь — приёмка с камерой: окно после каждого скана.
  - Если приходов нет: вызывается `queue.Shutdown()`.
  - Каждое открытие камеры держит UI-поток до 2 с плюс чекпоинт.
  - Данные не теряются (очередь на диске), но работа срывается.
- **Как исправить:** отдельное событие «ушли в фон» — только сброс журнала и чекпоинт в `Task.Run`, без подписчиков `ShutdownRequested`.

**А3-02. СРЕДНИЙ. Bluetooth-печать: повтор после обрыва печатает дубль.**
- **Где:** `Platform/AndroidPrinterTransport.cs:132-146`. Ошибка `stream.Write` («Broken pipe») приходит не как `PrinterStalledException`, и `PrinterPortService.SendRawBytes` (`:181-186`) повторяет отправку до 3 раз. Для TCP это исправлено в 1.17.73 через `NetworkPrinterAddress.Write`, для BT — нет.
- **Что ещё:** `socket.Connect()` без тайм-аута, параметр `timeout` не используется. После тайм-аута записи брошенный поток допечатывает чек и держит RFCOMM.
- **Как исправить:** ошибки после начала записи — `PrinterStalledException`; закрывать сокет по тайм-ауту.

**А3-03. СРЕДНИЙ (ПЛАУЗИБЛЬНО). Фоновая проверка связи с принтером на Android: окна разрешений сами по себе и подключение раз в 90 с.**
- **Где:** `PrinterKeepAliveService` (регистрация — `AvaloniaHostServiceRegistration.cs:230`) → `WriteBluetooth/WriteUsb`.
- **Bluetooth:**
  - `EnsureBluetoothPermission` (`AndroidPrinterTransport.cs:98-107`) из фонового таймера вызывает `RequestPermissions`;
