## 0. Вердикт: **НЕЛЬЗЯ ВЫПУСКАТЬ** (1 блокер, правка на одну строку)

**Блокер Б-1 (новый, внесён правкой ПР-9).** Окно оплаты пишет в журнал кассы `[Error] Unobserved task exception … Call from invalid thread`:
- случилось в 4 окнах оплаты из 6, в 12:59:56, 13:00:38, 13:03:04 и 13:03:50;
- до этой сборки такой ошибки в журнале не было. Две похожие записи от 22.10 — от стенда, с другим стеком.

Стек:
```
CheckoutDialog.<.ctor>b__4_2 (CheckoutDialog.axaml.cs:58)  ← UpdateErrorVisibility()
CheckoutViewModel.EnsureClientsLoadedAsync() (CheckoutViewModel.cs:1611)  ← finally { IsLoadingClients = false; }
```

Почему так:
- ПР-9 добавил `UpdateErrorVisibility()` в обработчик `_viewModel.PropertyChanged`. Обработчик срабатывает на **любое** свойство, а `UpdateErrorVisibility` меняет `ErrorText.IsVisible`;
- список клиентов грузится не в потоке интерфейса: модель создаётся вне его, и `ConfigureAwait(true)` там не помогает;
- поэтому `IsLoadingClients = false` вызывает обработчик из чужого потока, и Avalonia бросает исключение.

Что видно в работе:
- продажа проходит, список клиентов в карточке есть, на экране ошибки нет;
- но в журнале появляется `[Error]`, а оповещение о `IsLoadingClients` дальше по цепочке обрывается.

Правка (минимальная): в обработчике `PropertyChanged` диалога, если `!Dispatcher.UIThread.CheckAccess()`, передавать вызов через `Dispatcher.UIThread.Post(...)`. Либо так же оборачивать только `UpdateErrorVisibility()`. После правки — заново открыть окно оплаты 5–6 раз и проверить, что `[Error]` в журнале нет.
