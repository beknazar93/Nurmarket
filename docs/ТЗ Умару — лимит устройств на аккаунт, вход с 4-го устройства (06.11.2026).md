# ТЗ Умару — один вход на каждый ТИП устройства (06.11.2026, уточнено владельцем)

**Правило владельца.** Один аккаунт может быть одновременно на устройствах РАЗНЫХ типов, и это нормально: телефон (мобилка), Android-планшет (касса), ПК (программа кассы), ПК (программа владельца). Но если входят **вторым устройством того же типа** (второй телефон, второй ПК с кассой, второй планшет), нужно сообщение: «Вы уже входили на другом устройстве такого типа (Телефон «Айфон Айбека», был в сети 14:32). Выйти там и войти здесь?». Да — старое устройство отключается, новое входит. Нет — вход отменяется.

**Типы (слоты) на один аккаунт — по одному:**
| slot | кто |
|---|---|
| `mobile` | мобилка Flutter (телефон) |
| `android_pos` | Android-касса (планшет/телефон-касса) |
| `desktop_pos` | касса Windows/Linux |
| `desktop_owner` | программа владельца (`--owner`) |
| `web` | сайт/CRM в браузере — **вопрос**: считать ли слотом? предлагаем не ограничивать |

**Зачем.** 04.11 у клиента сервер молча отозвал вход (refresh-токен отклонён), касса показала «Сессия недействительна (часто из-за входа с другого ПК или телефона)». Кассир не понял, что случилось.

**Что нужно от сервера (касса, владелец, мобилка одинаково):**
1. В теле входа (`auth/login/`, вход по PIN, refresh) — `client_type` (из слотов выше; сервер может определить и по `X-NurMarket-Client`: `kassa/<версия>`, `owner/<версия>`, `mobile/<версия>`, `android-pos/<версия>`), `device_key` (8–64 символа) и `device_name` («Касса Магазин-1», «Телефон Айбека»).
2. Если в слоте уже есть другой `device_key` с живой сессией — **409** `{code:"device_slot_taken", slot:"mobile", device:{id, name, platform, last_seen_at}}`. Чужую сессию молча НЕ отзывать.
3. Повтор входа с `replace_device: true` (или `replace_device_id`) — сервер отзывает старую сессию в этом слоте и пускает новую.
4. Тот же `device_key` в том же слоте (перестановка приложения, второй вход с того же устройства) — вход без вопроса.
5. Отключённому устройству — **401** `{code:"session_revoked", reason:"device_replaced", by_device_name, at}`: касса/мобилка покажет «Ваш вход закрыт: вы вошли на другом устройстве (Телефон «Айбек», 14:32)», а не общий текст.
6. `GET auth/devices/` (мои устройства по слотам, `last_seen_at`, `current`) и `DELETE auth/devices/{id}/` (выйти с устройства) — для экрана «Мои устройства».
7. Признак в `main/capabilities/`: `device_slots`. Старые клиенты без `client_type` — слот не ограничивается (обратная совместимость).

**Со стороны кассы (сделаем после ответа):** диалог на 5 языках при 409 `device_slot_taken`; понятное сообщение при `session_revoked`; передача `client_type`/`device_key`/`device_name` при входе; экран «Мои устройства». Автономную кассу (офлайн-вход) лимит не касается, пока нет связи.

**Вопросы Умару:** сейчас сервер сам отзывает старый вход? по какому правилу (один на аккаунт? один на тип?); считается ли браузер слотом; как определять «тот же тип» — по `client_type` из клиента или по заголовку; что с кассирами с общим логином (два кассира на одном аккаунте на разных ПК одного типа — это допустимо? владельцу нужен переключатель «разрешить несколько касс» на компанию — `allow_multi_desktop_pos`).
