## 2. Какие боты есть в проекте

### 2.1. Бот магазина (в кассе и в программе владельца)
Работает внутри кассы: касса сама спрашивает Telegram (`getUpdates`, длинный опрос 25 с). Касса выключена — бот молчит. Если бот перенесён на сервер NurCRM (вебхук), касса не опрашивает Telegram, а только проверяет режим.

| Файл | Что делает |
|---|---|
| `NurMarketKassa.Infrastructure/Services/TelegramBotPollingService.cs` (+ `.Server.cs`) | Цикл опроса, разбор сообщений, права «владелец / покупатель», команды, должники, рассылка напоминаний |
| `TelegramBotService.cs` | Отправка (HTML, нарезка по 4000 знаков, 429/5xx/миграция группы), кнопки, голос, определение получателя, сводка смены |
| `TelegramAssistant.cs` | Понимание обычных фраз по ключевым словам (ru/ky), поиск товара, прокат, запасной ответ покупателю |
| `TelegramAiChat.cs` | ИИ (Google Gemini, 5 моделей по очереди, запасные OpenRouter/Groq): помощник владельца, консультант покупателя, заказы |
| `TelegramReportBuilder.cs` | Отчёты: выручка, топ, ABC, сезонность, советы, что заказать, остатки |
| `TelegramInquiryStore.cs`, `TelegramSubscriberStore.cs` | Журнал обращений покупателей (`telegram-inquiries.json`, до 2000 записей), профили для заказов, подписки «чат ↔ клиент» (SQLite) |
| `TelegramVoice.cs` | Голос: распознавание и озвучка через Gemini |
| `ProductActionPlan.cs` | Действия ИИ с товарами (списать, цена, описание…) и подтверждение кнопками «✅ Выполнить / ✖ Отмена» |
| `Api/ServerTelegramBotApi.cs`, `Avalonia/Services/ServerBotOffer.cs` | Перенос бота на сервер NurCRM и его статус |
| `Views.axaml/Main/TelegramBotSetupWindow*`, `TelegramBotAnalyticsWindow.cs`, `TelegramBotStatusChips.cs`, `Views/Settings/OperationsSettingsView` | Мастер подключения, аналитика бота, настройки |

**Кто есть кто.** «Владелец» — это **чат**, чей `chat_id` совпадает с `TelegramChatId` из настроек (`TelegramBotPollingService.cs:356`). Все остальные — покупатели. Отдельной роли кассира в боте нет. Если чат владельца — группа, владельцами считаются **все** её участники.

**Сценарии и команды.**

| Кто | Что пишет | Что получает |
|---|---|---|
| Владелец | `/segodnya` `/nedelya` `/top` `/abc` `/sezon` `/soveti` `/zakaz` `/ostatki` `/dolgi` `/help`, те же слова по-русски («сегодня», «долги»…) | Готовые отчёты (HTML). Должники — до 25 человек, с готовой ссылкой WhatsApp или пометкой «подписан на бота» |
| Владелец | Обычный текст: «кто должен», «цена кола», «бүгүн канча түшүм», «сколько обращений», «прокат джинсов» | Отчёт по ключевым словам (без интернета) |
| Владелец | Вопрос-рассуждение («почему упала выручка?») или просьба изменить товар («спиши 5 молока») | Ответ ИИ по сводке магазина. Действия — карточкой с кнопками «Выполнить / Отмена» или ответом «да / нет». Шаги накладной бот не проводит, отправляет в программу владельца |
| Владелец | Голосовое | Расшифровка курсивом, ответ текстом и голосом |
| Покупатель | `/start <id клиента>` (ссылка из карточки клиента) | Подписка на напоминания о долге и акциях |
| Покупатель | `/dolg`, «долг», «карыз» | Сумма своего долга |
| Покупатель | Любой вопрос о товарах | ИИ-продавец только по каталогу (цена, «есть / нет», размеры и цвета, замена). Без ИИ — поиск по каталогу или телефон магазина |
| Покупатель | «хочу купить…» → «Оформить заказ» / «да» | Черновик заказа, после подтверждения — настоящий заказ витрины и уведомление владельцу |
| Покупатель | Неизвестная `/команда`, стикер, пробелы, `/dolgi`, `/segodnya` | **Тишина** |

**Что бот шлёт сам** (подробнее — раздел 5): сводку при закрытии смены, сроки проката (раз в час 8:00–21:00), уведомления о заказах из бота, напоминания должникам (вручную, кнопкой в настройках).

**Как отвечает.** Отчёты собираются из готовых шаблонов. Фразы понимаются по основам слов (`TelegramAssistant`). Разговор и действия идут через ИИ Gemini: системная подсказка + до 8 пар реплик истории, ответ переводится из Markdown в HTML Telegram (`ToTelegramHtml`, обрезка до 3800 знаков). Покупателю — не больше 20 вопросов ИИ в час.

**Журнал.** `PosLogger`, категория `TELEGRAM`/`WARNING`: запуск/остановка опроса, ошибки отправки (причина из `description` Telegram), «ответ не отправлен — повторяю простым текстом», долгие отчёты (>3 с), подписки, черновики и заказы, действия ИИ. Тексты сообщений в журнал не пишутся. Тексты покупателей хранятся отдельно, в `telegram-inquiries.json` (первые 300 знаков).

**Токен.** На Windows хранится в `user-settings.json` под DPAPI (`TelegramBotTokenProtected`, `UserPreferences.cs:1589`). Ключ ИИ — так же, в облачную синхронизацию не попадает. При переносе на сервер токен уходит в NurCRM по HTTPS (PATCH `telegram-bot/settings/`), обратно сервер его не отдаёт. Токен стоит в адресе запросов Telegram (`/bot<токен>/…`), но в журнал адреса не пишутся.

**Языки.** Ответы бота — **только русский**: около 480 русских строк без `Tr.T`, часть из них — журнал. Исключения — 2 строки сводки смены и напоминания о прокате (на языке интерфейса). ИИ отвечает на языке собеседника (ru/ky).

### 2.2. Бот на сервере NurCRM (по ТЗ, части 7–11)
В репозитории это только требования: части 7, 8, 9, 10, 11 лежат в `docs/` (HEAD). Части 5 нет ни в папке, ни в истории git.

**Что заказано серверу:**
- **Архитектура.** Вебхук `POST /api/telegram/webhook/{bot_uuid}/` с секретом, ответ ≤100 мс. Очередь воркеров, дубли отсекаются по `(bot_id, update_id)`. 15 000 компаний, ответ владельцу ≤5 с (с ИИ ≤10 с). Лимиты 30/с и 1/с на чат, рассылки растягиваются. Проверка вебхука раз в час, поля `webhook_ok`, `last_update_at`, `last_reply_at`.
- **ИИ.** Общий ключ NurCRM для всех. 300 ответов в сутки на компанию. Повторы 1 и 3 с, затем другая модель, за 15 с — ответ без ИИ. Не больше 3 одновременных запросов на бота, кэш одинаковых вопросов 5 минут.
- **Покупатель.** Меню «Каталог / Найти / Корзина / Мои заказы / Связаться», карточки с фото, корзина −/+, размеры и цвета кнопками, заказ только после подтверждения, фото товаров.
- **Владелец.** Меню «Сегодня / Касса / Долги / Остатки / Заказы / Прокат», под новым заказом кнопки «Принять / Отклонить / Позвонить». Сценарии владельца (ч. 11): команды и ключевые слова без ИИ, до 100 штук.

**Что касса ждёт от сервера:** `settings/` (GET/PATCH), `detect-owner-chat/`, `test-message/`, `test-ai/`, `stats/`, `inquiries/`, `customers/`, `scenarios/`. На 404 касса работает как раньше, сама.

**Риски по ТЗ:**
- **КРИТИЧНО.** Если сервер упал, бот молчит, а касса его подхватить не может: вебхук не снят, `deleteWebhook` касса не вызывает.
- **КРИТИЧНО.** Перенос шлёт `ai_enabled=false` тем, у кого нет своего ключа (`ServerTelegramBotApi.cs:127`), хотя ч. 8 обещает общий ключ.
- **КРИТИЧНО.** Владелец определяется по чату, который написал боту, — та же дыра, что в кассе (п. К1).
- **КРИТИЧНО.** Кэши ИИ и каталога не привязаны в ТЗ явно к компании и чату.
- **ВАЖНО.** Дубли сводки и проката «касса + сервер», пока режим неизвестен. Галочки «Сводка / Команды» не доходят до сервера, пока не нажать «Перенести / Обновить». Перенос принудительно включает консультанта и голос. Двойное нажатие «Подтвердить заказ» в ТЗ не закрыто ключом идемпотентности.
- **ВАЖНО.** Подпись к фото — максимум 1024 знака, а ответ сценария может быть до 3500.

### 2.3. Бот поддержки `NurSupportBot/`
Отдельная программа для сервера (Linux, systemd). Долгий опрос `getUpdates` (50 с), база SQLite. Файл `appsettings.json` с секретами не открывался.

- **Роли.** Клиент NurCRM (вход по желанию). Администраторы — по `user_id`, это правильно. Операторы — участники группы поддержки.
- **Команды.** Для клиента: `/start /menu /cancel /search /report /operator /account /login /help /id`. Для админа: `/admin /stats /export /import`. В группе: `/setsupport /close`.
- **Кнопки.** Только inline: разделы базы знаний, «🔎 Поиск», «📊 Финансовый отчёт», «🆘 Оператор», «✅ Помогло / ❌ Не помогло», черновик обращения «📨 Отправить оператору», админка с редактором разделов.
- **Как отвечает.** ИИ нет: дерево инструкций (около 107 узлов) и поиск по основам слов. Отчёт берётся из NurCRM после входа. Язык — только русский.
- **Секреты.** Пароль NurCRM сообщение удаляется и не хранится. refresh-токен хранится зашифрованным (AES-256-GCM), но ключ `data/token.key` лежит рядом с базой с правами по умолчанию.
- **Оценка.** Дизайн 7/10, Удобство 7/10, логика в целом ок.
- **Ошибки:**
  - **ВАЖНО.** Ловушка черновика: после «Описать проблему» все следующие вопросы молча дописываются в черновик.
  - **ВАЖНО.** `tr:<чужой id>` не проверяет владельца обращения: можно влезть в чужую ветку (`Bot/SupportBot.Tickets.cs:174`).
  - **ВАЖНО.** Обработка по одному на всех: вход в NurCRM (до 3×60 с) замораживает бота.
  - **ВАЖНО.** Нет лимита попыток входа: через бота можно перебирать пароли NurCRM.
  - **ВАЖНО.** Таймауты и ошибки разбора при входе и в отчёте не перехватываются.
  - **ВАЖНО.** Без группы поддержки ответить клиенту невозможно.
  - **ВАЖНО.** `token.key` не защищён (chmod 600).
  - **МЕЛОЧЬ.** Пароль после «Отмена» уходит в поиск и в статистику админа.
  - **МЕЛОЧЬ.** Возвраты в отчёте присваиваются, а не суммируются (`Services/NurCrmClient.cs:102`).
  - **МЕЛОЧЬ.** Анонимные админы группы отфильтровываются.
  - **МЕЛОЧЬ.** `/import` ломает старые кнопки.

  Живой стресс-тест этого бота не делался: проверены только чтение кода и точки подмены. Адрес Telegram задаётся в `NURBOT_TELEGRAM_URL`, так что фейк-сервер подключается без правки кода.

## 6. Ошибки по важности

### КРИТИЧНО

**К1. Чужой человек может стать «владельцем» бота.** ✅ *21.10: подтверждение одноразовым кодом, роли по `from.id` (`TelegramBotOwner.cs`).*
- Где: `TelegramBotService.cs:427-470` (`TryDetectChatIdAsync`), вызов в `TelegramBotSetupWindow.axaml.cs:429` и `OperationsSettingsView.axaml.cs:394`.
- Причина: «Определить получателя» берёт чат последнего сообщения из `getUpdates` от **кого угодно**.
- Шаги: у работающего бота пишет покупатель → владелец заново жмёт «Определить получателя» → `TelegramChatId` = чат покупателя.
- Последствие: этот человек получает выручку, должников с телефонами, остатки, сводки смен и может менять товары через ИИ (`TelegramBotPollingService.cs:356, 369, 387`).
- Ещё: `getUpdates?limit=20` без offset отдаёт **первые** 20 неподтверждённых, а не последние. Пока опрос работает, функция отвечает «сообщений нет» или 409.

**К2. Выручка в боте считается по местной истории кассы, а не по серверу.** ✅ *21.10: /segodnya, /nedelya, /mesyac и сводка ИИ — с сервера через `OwnerPeriodStats` (как «Сводка»), местная история — запасной путь с пометкой.*
- Где: `TelegramReportBuilder.BuildRevenue` → `SoldLineItemsStore` (только продажи этой кассы, без возвратов); сводка для ИИ бота — `TelegramAiChat.BuildShopContext(localRevenue: true)`.
- В коде записан живой случай 05.10: 1 353 572 сом за 7 дней по местной истории против 886 049 сом на сервере (`TelegramAiChat.cs:66-68`).
- Для программы владельца это исправлено (цифры с сервера), для бота — нет.
- Шаги: две кассы или повторы в истории → `/nedelya` → сумма не совпадает с сайтом.

**К3. «Недостача / Излишек» в сводке смены не совпадает с отчётом смены.** ✅ *21.10: та же формула, что бумажный отчёт (`ExpectedCash` сервера).*
- В Телеграме: `expected = opening + CashSales + deposits − withdrawals` (`TelegramBotService.cs:642`). Серверные `ExpectedCash` и `CashDiff` игнорируются.
- В окне смены и на бумаге — сначала `shift.ExpectedCash` с сервера, иначе своя формула без внесений (`ShiftDetailsDialog.axaml.cs:758-761`).
- Комментарий «тот же расчёт» неверен.
- Шаги: внесение 1000 сом или наличная оплата долга → закрыть смену → в Телеграме «Недостача/Излишек» на 1000 отличается от бумаги. Владелец может зря обвинить кассира.

**К4. Бот замирает под нагрузкой: одна очередь на всех.** ✅ *21.10: очередь на каждый чат, до 100 чатов параллельно, полоса владельца, ИИ покупателей ≤8 одновременно, ограничитель 25/с и ~1/с в чат.*
- Где: `TelegramBotPollingService.cs:267-276` — каждое сообщение ждёт ответа ИИ или NurCRM по предыдущему.
- Цифры: при реальной скорости ИИ пропускная способность ≈ 0,5 сообщ./с, p95 = 205 с (S1b).
- Один «висящий» ответ ИИ (до 45 с) или NurCRM (до 55 с, `/dolgi` — до ~110 с) останавливает бот для всех, включая владельца.
- Один шумный чат с 429 держит всех (S2b: 205 с).
- Для магазина с акцией в Instagram или для сервера на 15 000 компаний это фактически «бот не отвечает».
