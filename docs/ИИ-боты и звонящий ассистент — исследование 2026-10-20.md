## 0. Коротко: главное

**Боты (Telegram):**
1. **Главная слабость нашего бота сейчас — он работает, только пока включена касса.** Касса сама спрашивает Telegram о новых сообщениях (`getUpdates`, см. `TelegramBotPollingService.cs`). У хороших ботов магазинов бот живёт на сервере (webhook) и отвечает ночью, в выходные и когда касса выключена. Это первое, что нужно сделать, причём ещё до голосового агента.
2. **В Telegram за 2026 год появилось три вещи, полезные именно нам** ([список изменений Bot API](https://core.telegram.org/bots/api-changelog)):
   - **«Управляемые боты» (Bot API 9.6, апрель).** Наш общий бот NurMarket может сам создать бота для магазина и получить его токен. Владельцу больше не нужно ходить в BotFather и копировать токен.
   - **Бизнес-боты без Premium (10.0, май).** Бот отвечает покупателям прямо из личного Telegram владельца, как секретарь.
   - **«Богатые» сообщения с таблицами и ответ ИИ, который печатается на глазах (9.3–10.3).** В нашем боте сейчас таблиц нет, теперь их можно сделать.
3. **Telegram не знает кыргызского.** В официальных приложениях Telegram нет кыргызского языка интерфейса, поэтому `language_code` у покупателей в КР почти всегда `ru` **[не проверено, по нашему знанию]**. Язык нужно спрашивать при первом `/start` тремя кнопками: «Кыргызча / Русский / O‘zbekcha».
4. **Оплата внутри Telegram для КР неудобна.** Telegram Payments принимает сом (KGS), но кыргызского платёжного провайдера в списке нет ([Bot Payments](https://core.telegram.org/bots/payments)). Stars — только для цифровых товаров. Разумнее, чтобы бот давал ссылку или QR на оплату через местный банк (MBank / ELQR — касса это уже умеет).
5. **Без спама — значит так:**
   - сами по себе боту разрешены только «служебные» сообщения: чек, долг, заказ, прокат;
   - реклама — только тем, кто согласился;
   - тихие часы 21:00–09:00, не чаще одного напоминания о долге в 3–7 дней, кнопка «Отписаться»;
   - лимиты Telegram: около 30 сообщений в секунду на рассылку, иначе ошибка 429 ([FAQ](https://core.telegram.org/bots/faq)).
6. **Защита от обмана:**
   - долг и личные данные показывать только тому, кто подтвердил свой номер кнопкой «Поделиться контактом» (и только если это его собственный контакт);
   - одноразовая ссылка-приглашение из чека;
   - опасные команды владельца — только из его чата и с PIN-кодом.

**ИИ-помощник владельца:**

7. **Лидеры рынка сделали одно и то же: ИИ предлагает, человек подтверждает, всё пишется в журнал.**
   - Lightspeed (15.10.2026): «ИИ предлагает — продавец решает»; предпросмотр, явное «Одобрить», журнал действий ([обзор](https://stellagent.ai/insights/lightspeed-ai-agentic-retail-workflows)).
   - Toast IQ и Shopify Sidekick так же меняют цены, «нет в наличии» и смены прямо из чата ([Toast](https://pos.toasttab.com/blog/on-the-line/toast-iq), [Shopify](https://www.shopify.com/news/winter-26-edition-renaissance)).
   - Нур Советник уже показывает карточку «Выполнить / Отмена» — это правильно. Не хватает журнала на сервере и проверки прав по роли.
8. **Цифры — только из инструментов, никогда «из головы» ИИ.**
   - ИИ вызывает функцию (выручка, остаток, долг), а сумму считает код.
   - Shopify советует держать не больше ~20 инструментов: при 20–50 их границы размываются, при 50+ агент путается. Правила к каждому инструменту лучше подавать вместе с его ответом, а не в огромном общем промпте ([Shopify Engineering](https://shopify.engineering/building-production-ready-agentic-systems)).
   - Нужен проверочный набор из 50–100 реальных вопросов владельцев с правильными ответами.
9. **Что делают все лидеры и чего пока нет у нас:**
   - сводка сама приходит утром или вечером («Pulse», «For you»);
   - поиск странностей (возвраты, удаления из чека, скидки кассиров, недостача, падение продаж);
   - черновик заказа поставщику по скорости продаж — его одобряет человек.

**Звонящий ИИ:**

10. **Главная новость с 18.10:**
    - **Gemini Live API (Google) официально включил кыргызский (`ky`) в список из 99 языков** ([возможности Live API](https://ai.google.dev/gemini-api/docs/live-api/capabilities));
    - вышла модель **Gemini 3.8 Live** (сентябрь 2026);
    - цена: $0,005 за минуту входящего звука и $0,018 за минуту ответа ([цены](https://ai.google.dev/gemini-api/docs/pricing)) — в 3–4 раза дешевле ElevenLabs;
    - Нур Советник уже работает на Gemini Live (`GeminiLiveVoice.cs`, модель `gemini-3.1-flash-live-preview` — Google теперь называет её устаревшей);
    - своей телефонии у Gemini нет, нужен мост: Voximplant (официальный партнёр), LiveKit или Pipecat;
    - **качество кыргызского по телефону не проверено никем**, «есть в списке» ≠ «хорошо понимает».
11. **ElevenLabs по-прежнему единственная платформа «под ключ» с подтверждённым кыргызским голосом:**
    - голос: модели v4 и v4 Turbo (её и советуют для агентов);
    - **ловушка:** в быстрой модели Flash v2.5 кыргызского нет;
    - распознавание: у Scribe v1 ошибка 13,3 % слов на кыргызском; для потоковой Scribe v2 Realtime кыргызский **не подтверждён**.

**Рекомендация (подробно — раздел 4):**
- **Сейчас:**
  - перенести бота на сервер;
  - сделать ботов для магазина и для владельца по сценариям из раздела 1;
  - в голосе — **пилот на одном магазине**: только входящие звонки, русский + кыргызский, только чтение и «заявка», без денег.
- **Платформа пилота:**
  - **ElevenLabs Agents** — быстрее всего запустить: SIP, инструменты, перевод на человека без своего сервера;
  - параллельно — бесплатное сравнение кыргызского у **Gemini 3.8 Live** (через тот же «звонок» в Нур Советнике).
- **Позже:** свой агент на сервере (LiveKit + Gemini Live), примерно в 2 раза дешевле, данные под нашим контролем.

## 1. Telegram-боты для магазина: как делают хорошо

### 1.1. Что у нас есть сейчас (по коду кассы)

- **Бот владельца** (`TelegramBotPollingService.cs`, `TelegramReportBuilder.cs`, `TelegramAiChat.cs`):
  - выручка, топ товаров, «что заказать», должники, малый остаток;
  - ИИ-ответы (Gemini, поиск через Groq);
  - действия с товарами с кнопками «да/нет» (`pa:<token>:y|n`).
- **Подписка покупателей.** Покупатель нажимает «Старт» по ссылке из чека, и касса может слать ему напоминание о долге.
- **Тем, кто не подписан,** уходит готовая ссылка WhatsApp с текстом.
- **Ограничения, честно описанные в коде:**
  - бот отвечает, только пока касса включена;
  - Telegram не даёт написать человеку по номеру телефона, только тому, кто сам начал разговор.

### 1.2. Сценарии бота покупателя — что стоит иметь

| Сценарий | Как сделано у хороших ботов | Что нужно нам |
|---|---|---|
| **Знакомство** | `/start` по ссылке с меткой (`t.me/<бот>?start=<метка>`, до 64 символов [Telegram](https://core.telegram.org/bots/features)); сразу выбор языка; одна фраза «что я умею»; кнопка «Поделиться номером» с объяснением зачем | Одноразовая метка в QR на чеке (магазин + чек), подтверждение номера |
| **Электронный чек** | Чек приходит в чат сразу после оплаты, с кнопками «Вернуть / Вопрос по чеку» | Часть 27 сводного ТЗ (электронный чек) |
| **Каталог** | До ~50 товаров — кнопки в чате (листать, не присылая новые сообщения: «редактируйте клавиатуру» — совет Telegram); больше — Mini App (витрина внутри Telegram). Типовая схема: Mini App — каталог/корзина/оплата, бот — уведомления ([кейс](https://workspace.ru/cases/cvetochnyy-magazin-v-telegram-mini-app-katalog-korzina-i-oplata-za-minutu/)) | Ссылка «Витрина» на market.nurcrm.kg как Mini App (своя Mini App — позже) |
| **Заказ / резерв** | Корзина не теряется, оформление не уводит из Telegram; подтверждение, статус «собран / готов к выдаче» | Заказ с сайта уже есть в NurCRM; боту нужны статусы через события (часть 20) |
| **Бонусы** | Баланс по кнопке, «у вас N бонусов, сгорят через 7 дней» — раз в месяц | Бонусы на сервере (сейчас лояльность локальная) |
| **Долг** | Баланс по кнопке; напоминание с суммой, датой и кнопкой «Оплатить» (QR банка); после оплаты — «спасибо, долг 0» | Части 17–18 (оплата долга, точный остаток), события части 20 |
| **Прокат** | За день до срока, в день срока, на следующий день после просрочки; кнопка «Продлить» | Часть 23 (срок, продление, телефон) |
| **Отзыв** | Один вопрос через 2–24 ч после покупки: ⭐1–5; 1–3 ⭐ → сразу уведомление владельцу; не чаще раза в месяц на человека | Журнал опросов, согласие |
| **Поддержка** | «Позвать человека» видно всегда; бизнес-режим: бот отвечает из аккаунта владельца, а владелец в любой момент перехватывает чат | Бизнес-подключение (Bot API 9.0/10.0) |
| **Обязательные команды** | `/start`, `/help`, `/settings` — глобальные команды Telegram; при приёме оплат — `/terms` и `/support` ([Bot Payments](https://core.telegram.org/bots/payments)) | Сделать на 3 языках |

### 1.3. Бот владельца — что стоит добавить

- **Сводка в 21:00 (или после закрытия смены):**
  - выручка в сравнении с тем же днём недели прошлых недель;
  - наличные и безнал, возвраты, долги за день;
  - топ-3 товара, что заканчивается.
- **Сигналы о странностях** (сразу, но не чаще раза в час):
  - много удалений из чека или возвратов у одного кассира;
  - скидка больше порога;
  - открытие ящика без продажи;
  - разница в кассе при закрытии смены;
  - продажи ниже обычного на 30 %+ к 15:00.
- **Черновик заказа поставщику** по скорости продаж и сроку поставки с кнопкой «Отправить поставщику» (раздел 2.3).
- **Опасные действия** (смена цены, списание, выплата) — только из чата владельца по белому списку `chat_id`, с карточкой подтверждения, а для денег — ещё и PIN-код.

### 1.5. Лимиты и правила Telegram

- **Рассылка:** около 30 сообщений в секунду, больше — ошибка 429 с `retry_after` ([FAQ](https://core.telegram.org/bots/faq)).
  - Платная рассылка (до 1000 в секунду, 0,1 Star за сообщение) требует большого баланса Stars и аудитории — нам не нужна.
  - В одном чате — не чаще ~1 сообщения в секунду, в группе — ~20 в минуту ([grammY](https://grammy.dev/advanced/flood)).
- **Касса уже делает паузу ~25 сообщений в секунду** (комментарий 2026-09-29 в коде) — это правильно.
  - На сервере нужна очередь с повтором после `retry_after`.
  - Ошибка 403 «бот заблокирован» — отметить «отписан» и больше не слать.
- **Тестовый бот отдельно от боевого.** Идентификаторы файлов (`file_id`) у каждого бота свои.
- **Telegram следит, отвечает ли бот:** BotFather присылает предупреждение, если бот отвечает редко ([features](https://core.telegram.org/bots/features)). Ещё один довод за сервер.
- **Оплата:**
  - физические товары — через подключённого провайдера; Telegram комиссии не берёт, KGS в списке валют есть;
  - цифровые товары — только Stars, и на iOS оплата цифрового пока ограничена ([Bot Payments](https://core.telegram.org/bots/payments), [Stars](https://telegram.org/blog/telegram-stars/kk?setln=en));
  - провайдера из КР в документации нет, поэтому для КР — ссылка или QR местного банка.

### 1.6. Тон текстов и языки

- **Тон:**
  - коротко, на «вы», тепло, без капслока и восклицательных знаков подряд, эмодзи — 0–1 на сообщение;
  - сначала главное («Долг: 1 250 сом»), потом детали, потом одна кнопка действия;
  - напоминание о долге — без угроз и стыда: «Напоминаем: за вами 1 250 сом с 05.10. Оплатить можно по кнопке или в магазине. Спасибо!».
- **Языки:**
  - кыргызский и узбекский шаблоны пишет носитель языка (не машинный перевод), русский — по умолчанию;
  - выбранный язык хранить у клиента в NurCRM, чтобы бот, касса и звонок говорили на одном языке;
  - команды и описание бота — на 3 языках (`setMyCommands` с `language_code`, локальное описание);
  - Telegram советует, если язык неизвестен, брать последний выбранный, а не язык телефона ([features](https://core.telegram.org/bots/features)).
- **WhatsApp** (у нас — ссылки `wa.me`). Если когда-нибудь слать через официальный WhatsApp Business API:
  - с 01.07.2025 оплата за каждое шаблонное сообщение;
  - тариф по стране получателя, таблица цен — с 01.04.2026;
  - «служебные» шаблоны в течение 24 часов после сообщения клиента — бесплатно ([Meta](https://developers.facebook.com/docs/whatsapp/pricing)).

### 1.7. Защита от обмана и приватность

| Угроза | Защита |
|---|---|
| Чужой человек пишет «я Асан, какой у меня долг?» | Долг и чеки — только после «Поделиться контактом», причём контакт должен быть **своим** (`contact.user_id == from.id`) и номер совпадает с карточкой клиента |
| Пересланная ссылка из чека | Метка `/start` одноразовая и со сроком (например, 7 дней); повторная — «попросите новую ссылку в магазине» |
| Подделка нажатия кнопки | В кнопках — короткий случайный токен со сроком (как наш `pa:<token>`), а не id и сумма открытым текстом |
| «Скрин оплаты» вместо оплаты | Бот никогда не закрывает долг по картинке; оплата — только по подтверждению банка или кассой |
| Кто-то пишет боту владельца | Команды владельца — только из белого списка `chat_id`; деньги — плюс PIN |
| Утечка | Минимум данных в сообщениях (без полного телефона, без адреса); хранить переписку 90 дней; токен бота — только на сервере (часть 21.4 ТЗ: секреты компании) |

### 2.2. Как лидеры не дают ИИ «врать цифрами»

1. **Инструменты вместо свободного текста.**
   - ИИ не считает выручку сам, а вызывает функцию `sales_summary(period)`; сумму считает сервер или код.
   - В ответе — период и источник («по чекам 01–19.10, без возвратов»).
2. **Мало инструментов, но чётких.** У Shopify при 0–20 инструментах границы ясные, при 20–50 размываются, при 50+ агент находит «несколько способов сделать одно и то же» ([Shopify Engineering](https://shopify.engineering/building-production-ready-agentic-systems)).
3. **Правила «вовремя».** Правило к инструменту возвращается вместе с его ответом (например, «суммы — с 2 знаками, не округлять»), а не лежит в огромном общем промпте. Промпт короче, кэш работает.
4. **Проверка на реальных разговорах.**
   - Shopify проверяет агента на выборке настоящих диалогов, размеченной 3 экспертами, а не на «идеальных примерах»;
   - «проверка на глаз» недостаточна;
   - ИИ-судья согласился с людьми на 0,61 при 0,69 между самими людьми.
   - **Для нас:** 50–100 реальных вопросов владельцев с правильными ответами, посчитанными на NBS; прогонять при каждой смене модели.
5. **Модель «подыгрывает» проверке.** Выдумывает id и значения списков. Поэтому любой id и любое число из ответа ИИ сверять с данными до показа или выполнения.
6. **Права и подтверждение** (OWASP LLM06 «Excessive Agency», [обзор](https://aembit.io/blog/owasp-top-10-llm-risks-explained/)):
   - у инструмента — права пользователя, а не «всемогущий» токен;
   - для важного действия — подтверждение человеком;
   - права проверяет сервер, а не промпт.

### 2.3. Что добавить в Нур Советник (идеи, код не меняли)

| Что | Как правильно | Откуда данные |
|---|---|---|

**Сверху для любого варианта:**
- номер $4–8 в месяц у Zadarma или ВАТС местного оператора от ~2500–2900 сом в месяц (18.10);
- входящие на номер — по тарифу провайдера **[не проверено]**;
- **исходящие на мобильные** — $0,16–0,28 за минуту у Zadarma: 1000 минут обзвона ≈ $160–280.

**Как сэкономить:**
- ИИ берёт только пропущенные звонки (переадресация «не ответил»): обычно это 20–40 % звонков **[оценка]** → 1200–2400 минут вместо 6000;
- ограничение звонка 4–5 минутами, выход при тишине.

## 4. Рекомендация для NurMarket

### 4.1. Что делать по шагам

**Шаг 1 — сейчас (без голоса).** Сначала бот, потому что без сервера голосовой агент тоже не сможет ни на что опереться.
1. **Бот на сервере (webhook) вместо `getUpdates` из кассы:**
   - лучше на стороне NurCRM;
   - временно — рядом с `NurRemoteSupport` или `NurSupportBot`, но тогда токен и доступ к данным — по согласованию с бэкендом.
2. **Мастер «Создать бота магазина»** через управляемых ботов (Bot API 9.6).
3. **Бот покупателя:** язык (3 кнопки), подтверждение номера, чек, долг с кнопкой оплаты (QR банка), прокат, статус заказа, отзыв, «позвать человека».
4. **Бот владельца:** сводка в 21:00, сигналы о странностях, черновик закупки; таблицы — через Rich Messages.
5. **Правила «без спама»** и согласие (раздел 1.5–1.7).

**Шаг 2 — пилот голосового агента (1 магазин, 1 месяц):**
- только входящие и только пропущенные (переадресация «не ответил»);
- русский по умолчанию, кыргызский — если клиент заговорил по-кыргызски;
- сценарии: часы и адрес, наличие и цена, черновик заказа, статус, долг звонящего; всё прочее — перевод на продавца или задача «перезвонить»;
- **платформа: ElevenLabs Agents.** Без своего сервера звонка, SIP и webhook-инструменты готовы, кыргызский голос v4 Turbo подтверждён. LLM внутри — недорогая (Gemini Flash).
- **Перед пилотом — бесплатное сравнение кыргызского:**
  - 50–100 записанных фраз покупателей (шум, 8 кГц, смесь языков);
  - прогнать через ElevenLabs Scribe и через Gemini 3.8 Live; Gemini можно попробовать прямо в «звонке» Нур Советника;
  - считать: доля понятых названий товаров и чисел, естественность голоса (оценка 5 носителей языка).
- **Приветствие на двух языках:** «Сизге виртуалдык жардамчы жооп берет, сүйлөшүү жазылат. Вам отвечает виртуальный помощник, разговор записывается. Чтобы поговорить с продавцом, скажите „продавец“». Текст на кыргызском — проверить носителем.

**Шаг 3 — когда звонков станет много (3+ магазина или 3000+ минут в месяц):**
- свой агент: **LiveKit Agents (или Voximplant) + Gemini Live** на своём сервере;
- ≈ в 2 раза дешевле, данные и журналы у нас, можно подключить местный кыргызский голос (NineNineSix / KaniTTS), если он окажется лучше;
- исходящие напоминания — только тем, кто согласился, и через местный SIP-транк (дешевле Zadarma на мобильные).

### 4.2. Архитектура: где живёт агент

```
Покупатель ──► свой номер магазина ──(не ответил / занято)──► SIP-номер (Zadarma / ВАТС Beeline / SunPBX)
                                                   │
                                                   ▼
                         ИИ-агент в облаке провайдера (ElevenLabs Agents)
                         [позже: свой сервер — LiveKit + Gemini Live]
                                │ инструменты (HTTPS, ключ точки)
                                ▼
                 NurCRM API (app.nurcrm.kg): товары, остатки, клиенты, долги, заказы
                 права ключа + журнал + ключи повтора
                                │ события (часть 20)
              ┌─────────────────┼──────────────────────────┐
              ▼                 ▼                          ▼
   Telegram владельцу     касса и программа         покупателю в Telegram:
   (сводка звонка)        владельца (заказ,         «заказ №123 принят»
                          задача «перезвонить»)
```

- **Агент не ходит в кассу** (она может быть выключена) — только в NurCRM.
- **Агент никогда не двигает деньги.** Оплата — QR банка или касса.
- **Ключ API у агента — отдельный на точку**, только чтение плюс «черновик заказа». Не токен владельца.

### 4.3. Что нужно от бэкенда NurCRM

- общие правила: формат ошибки, ключи повтора, время +06:00, деньги строкой, права на сервере;

### 4.4. Риски

| Риск | Насколько серьёзно | Чем закрыть |
|---|---|---|
| **Кыргызский понимается плохо** (шум, 8 кГц, смесь с русским, диалекты) | Высоко | Сравнение до пилота; переспрашивать и повторять ключевое; номер из звонка, а не диктовка; после 2 непониманий — перевод на продавца; кыргызский — пилот, не обещание |
| **Качество связи** (мобильная связь, задержка до ЕС/США) | Средне | Цель ответа ≤ 1,2 с; «секунду, смотрю…» во время запроса; лимит 4–5 мин; запасной путь — переадресация на живой номер |
| **ИИ ошибся с товаром или деньгами** | Высоко | Никаких денежных инструментов; «заказ принят» — только при номере от сервера; сумма долга — только из инструмента; подтверждение в Telegram или SMS; продавец проверяет черновик |
| **Приватность и закон** (штрафы до 65–120 тыс. сом) | Средне–высоко | Предупреждение о роботе и записи; согласие на передачу за рубеж; срок хранения записей 30–90 дней; договор обработки данных с провайдером; долг — только своему номеру |
| **Счёт за минуты** | Средне | Только пропущенные звонки, лимиты минут в месяц, уведомление владельцу при 80 % лимита |
| **Провайдер недоступен из КР / оплата картой** | Средне | Проверить регистрацию и оплату до пилота (санкции касаются отдельных банков КР — см. 18.10); держать второй вариант (Gemini) |
| **Бот спамит → блокируют** | Средне | Только служебные сообщения, частота, тихие часы, «Отписаться», ошибка 403 → отписать |
