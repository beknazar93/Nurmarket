# Большие объёмы — шаблон списков и модалок (30.10.2026)

Повод: модалка «Позиции прихода» (`Views.axaml/Main/PurchaseDialogs.cs`, ~стр. 371) рисует строки `foreach` в `StackPanel` без прокрутки и
виртуализации — при 500 позициях окно вырастет на ~22 000 px, кнопки «Закрыть/PDF» уедут за экран, открытие займёт секунды и ~100 МБ.
Та же беда у всех списков, собранных `StackPanel`/`ItemsControl` в `ScrollViewer` (ревизия: `WarehouseWindow.Revision.cs:200`).
Реальные объёмы в Кыргызстане: накладные 50–500+, ревизии 4 000+, чеки 100+ строк, CSV 20 000 строк; экраны 1024×600…1920×1080, Android 360–1280 dp; ПК с 7,8 ГБ.

Макеты (HTML без зависимостей, 500/5 000 фейковых строк, тема светлая/тёмная, 1296×879 / 1024×600 / 360×800): `design/Large-lists/`
`index.html` · `01-receipt-items-modal.html` (шаблон целиком) · `02-print-pdf.html` · `03-mobile-list.html` · общие `shared.css`, `shared.js` (данные, поиск, виртуальный список).
Цвета — кисти кассы (`Brush*`, обе темы), шрифт Montserrat, скругления: кнопки 10, карточки 12, модалка 14.

## 2. Для 50+ позиций — поиск, фильтры, навигация

- **Поиск** внутри модалки (`Ctrl+F` → фокус, `Esc` — очистить, второй `Esc` — закрыть окно): по названию, штрихкоду, категории, поставщику;
  ё=е, не та раскладка (`cjrf` → Coca), транслит (`moloko`), слова в любом порядке — тот же `SearchNormalizer`, что в единый поиск кассы 1.17.64.
  < 200 строк — мгновенно, ≥ 200 — дебаунс 200 мс. Пусто → состояние «Нет совпадений» с кнопкой «Сбросить поиск и фильтры».
- **Чипы** с количеством: «Только расхождения 37», «Новые 29», «С ошибкой 14», «Дорогие ≥ 1 000 21» (набор — по экрану, см. § 9). Чип = AND.
- **Сортировка** кликом по заголовку (▲ → ▼ → сброс), числа по значению, строки — `ru` collation.
- **Группировка** (select): нет / категория / поставщик; заголовок группы 36 px PanelSoft «▾ Напитки · 42 поз. · 12 340,00 сом», сворачивается кликом; группы по убыванию суммы.
- **Счётчик** «Показано 37 из 500» рядом с переключателем режимов; при полном списке — «Показано 500».
- **Клавиши** во вьюпорте: Home/End, PgUp/PgDn, стрелки; ⤢/F11 — полный экран; Enter в поле поиска — к первой найденной строке.
- **Выделение**: чекбокс в строке + «все видимые» в шапке; появляется тёмная панель над футером «Выбрано 3 · 120 шт · 8 450,00 сом · [Вернуть поставщику] [Печать ценников] [Снять выделение]».

## 3. Итоги

Сводка вверху считается по **всему** документу; футер — по **текущему фильтру** (надпись меняется: «Итого:» / «По фильтру:»).
«Требуют внимания: N ›» — единственная цветная плитка (WarningSoft/Warning), клик включает фильтр «расхождение ИЛИ ошибка» (не чипы — те работают через И), повторный — снимает.
Режим **«Обзор»**: Топ-5 по сумме (горизонтальные полосы Accent, подпись + число tabular), список проблем (расхождение / без штрихкода или цена ниже закупки /
новые / дорогие — клик открывает таблицу с этим чипом), таблица по категориям (позиций, сумма). Без диаграмм других цветов — один жёлтый на сером, читается в обеих темах.

## 4. Режимы отображения и экраны

| Режим | Когда | Что внутри |
|---|---|---|
| Таблица (по умолчанию) | ≥ 1024 px | колонки: ☐ 36 · № 46 · Наименование (≥ 140, flex) · Штрихкод 118 (p3) · Категория 104 (p4) · Кол-во 96 · Закупка 92 (p2) · Продажа 92 (p3) · Сумма 104 · Статус 130 (p2); отступ ячейки 8 |
| Карточки | 360–1023 dp, по выбору — везде | 76–80 px: название + бейджи / штрихкод · категория · статус / справа сумма жирно и «10 шт из 12 × 90,00» |
| Обзор | кнопка; на 5 000+ строк — предлагать первым | итоги и проблемы без полного списка (§ 3) |

Приоритет скрытия колонок: p4 (Категория) → p3 (Штрихкод, Продажа) → p2 (Закупка, Статус; статус остаётся цветной полоской слева у строки). 1024×600 прячет p3+p4,
Android 600–1023 — p2–p4, 360 — только карточки. Строки с ошибкой — полоска 3 px Danger слева, с расхождением — Warning; бейджи: «новый» AccentSoft, «расхождение −2» WarningSoft, «нет штрихкода» DangerSoft, «изменено» SuccessSoft.
Полноэкранный режим ⤢: модалка на всё окно без скруглений, список получает всю высоту; на 360 это режим по умолчанию (лист).

## 5. Печать, PDF, экспорт (макет 02)

- A4 книжная 38 строк/стр., альбомная 26 (с ценой продажи и наценкой), лента 80 мм ≤ 100 строк (дальше предлагаем A4 или «Только итоги»).
- На каждой странице: шапка документа + «стр. 3 из 14», шапка таблицы, внизу «по странице / нарастающим итогом» и «Продолжение на стр. 4». Реквизиты и ИНН — только на 1-й.
- Итог (позиций, штук, сумма, расхождений/ошибок), подписи «Сдал / Принял» — только на последней.
- Опции: «Все позиции» / **«Только итоги»** (всегда 1 страница: суммы, по категориям, первые 20 проблемных) / «Только расхождения и ошибки» (для сверки с поставщиком); «Без пустых колонок»; «С ценой продажи».
- Excel/CSV — без ограничения строк, UTF-8 BOM, `;`; > 10 страниц PDF и > 2 000 строк Excel — в фоне с прогрессом и отменой, готовый файл — уведомление.

## 7. Производительность (цели и порог)

- Порог **200 строк**: ниже — обычный список и поиск без задержки; от 200 — виртуализация, дебаунс поиска 200 мс, сворачивание реквизитов, предложение «Обзора» при ≥ 5 000.
- Цели: открытие модалки ≤ 300 мс при 500 строках (макет: 10–40 мс на построение, отрисовка окна ≤ 3 мс), прокрутка 60 к/с, память не растёт при прокрутке (переиспользование контейнеров, никаких `foreach → new Grid`).
- Фильтр и сортировка — над массивом моделей, не над визуальными элементами; строку-«сено» для поиска (`_hay`) считать один раз лениво.
- Данные грузить страницами с сервера, если API отдаёт > 1 000 строк (`page_size` 500), показывать «Загрузка N из M»; сортировку/поиск по не догруженным данным — после догрузки.
- На 7,8 ГБ: никаких теней/размытий на каждой строке; бейджи — `Border` без эффектов; одна общая `Style` на строку.

## 8. Мобилка и планшеты (макет 03)

Карточка 72 dp, одна колонка (≥ 720 dp — две, ≥ 1024 dp — таблица как в кассе). Поиск + чипы закреплены сверху и прячутся при прокрутке вниз;
итоги + главная кнопка закреплены снизу (`resizeToAvoidBottomInset`, клавиатура не перекрывает); `ListView.builder` + подгрузка по 40 при приближении к концу (сентинел за 10 карточек,
скелетон 2 карточки + «показано 1 240 из 4 000»); sticky-заголовки групп; «К началу» после двух экранов; «Обзор» — нижний лист 88 % (плитки, топ-5, по категориям).
Ввод факта в ревизии — поле 92×40 прямо в карточке, курсор идёт вниз по Enter/скану.

## 10. Порядок внедрения

1. Общий контрол `LargeListPanel` (шапка колонок + виртуальный список + футер + состояния) в `Ui.Shared`, строки — `IDataTemplate` на экран.
2. Первым — «Позиции прихода» (самое больное, читаемое), затем ревизия (снять внешний `ScrollViewer`), затем массовая загрузка (чипы «С ошибкой»).
3. Проверка на стенде 1024×600 и NBS: 500 строк — открытие ≤ 300 мс, журнал без предупреждений о раскладке, память до/после прокрутки ±5 МБ.
4. Надписи — `Tr.T(ru, ky, en, tr, uz)`: «Реквизиты», «Требуют внимания», «Показано {0} из {1}», «Только расхождения», «К началу», «Только итоги», «Без пустых колонок», «Загрузка {0} из {1}».
