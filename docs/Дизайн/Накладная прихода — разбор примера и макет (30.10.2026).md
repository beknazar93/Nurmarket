## 1. Что показано на снимках

**Вкладка «Покупки» (реестр позиций по всем документам за период).**
Фильтры: «Период с … по …», «поставщик: Все», ✕, «Обновить», «Экспорт». Колонки: № · Код · Штрих код · Наименование товара · Единица изм. · Количество · Цена покупки · Сумма · Документ № · Дата (с временем) · Поставщик · Склад · Пользователь. Внизу жёлтая строка ИТОГО: количество 1 799,32 и сумма 299 984,60 — итог по всему фильтру. Строки — позиции всех документов дня подряд (док. 11380, 11381, 11383, 11384, 11375…), документ виден только колонкой «Документ №». Статусная строка: «Менеджер: Менеджер 1».

**Окно «Приходная накладная № 11381 от 30 октября 2026 г.»** (модалка поверх реестра).
Шапка: Склад [Магазин …], Поставщик [ОсОО Кока Кола …]. Справа флажки «Добавить ценник для всех покупаемых товаров», «Предварительное сканирование всех товаров». Кнопки: «Вставить товар [Insert]», «Вставить по штрих коду»; справа «Печать», «Просмотр», «Экспорт», «Закрыть».
Таблица: № · Код · Штрих код · Наименование товара · Количество · Цена покупки · Сумма · Цена реализации · Наценка (%) · Код тов(ара)… 13 строк Coca-Cola. Жёлтая строка ИТОГО: 268 шт · 22 550 · средняя наценка 15,44.
Цвет строк: белые — № 1 «Фанта 0,5 л» (48 × 50, наценка 18 %) и № 6 «Кока Кола Zero 0,5 л» (16 × 50, 20 %); розовые — остальные 11. У розовых цена покупки дробная (141,6667 = 1 700 / 12; 108,3333 = 1 300 / 12; 79,1666 = 950 / 12 — пересчёт из цены за коробку), у белых — целая 50, как раньше. Строка № 3 с количеством 0 тоже розовая. Наиболее вероятное правило: **розовый = цена покупки отличается от прошлой закупки в карточке** (Coca-Cola подняла цены на коробку, а 0,5 л не менялись); альтернатива — «наценка ниже 18 %», но № 3 (24 %) её опровергает. Один цвет на всё — причину приходится угадывать.
Поведение, которое читается по интерфейсу: ввод строк с клавиатуры (Insert), ввод сканером, «предварительное сканирование» — сначала накопить товар сканером, цены потом; «ценник для всех» — после проведения печатаются ценники на все позиции; «Просмотр» — печатная форма; «Экспорт» — Excel.

## 2. Что берём · что делаем лучше

**Берём как есть:** одна форма на создание и просмотр; реестр позиций по всем документам с итогом; Insert / по штрихкоду; флажки «ценники для всех» и «предварительное сканирование»; колонки «Цена продажи» и «Наценка %» прямо в накладной; средняя наценка в итоге; Печать / Просмотр / Экспорт; цветная строка-итог.

**Делаем лучше (список):**
1. Номер документа наш — `ПР-2026-000123` (`DocumentNumbering`), плюс отдельное поле «№ накладной поставщика» и дата накладной (К-11 `document_number`, `document_date`).
2. Цвет строки объясняет причину: не один розовый, а 4 понятных состояния + маркер ↑ (§ 4) и бейдж с текстом; клик по плитке «Требуют внимания» = фильтр.
3. Итог — не 3 числа, а 6: позиций · штук · сумма закупки · средняя наценка · ожидаемая выручка · ожидаемая прибыль (`ReceiptMarkupLog.Totals`).
4. Статусы и версии: черновик → проведён → исправлен v2 → возврат частичный; история версий, «ИСПРАВЛЕНО · версия N» на печати (ТЗ редактора 2.5–2.6).
5. Правка после проведения — только владелец, только в окне 24/48 ч/всегда, через предпросмотр «до → после» с причиной и паролем (ТЗ редактора 2.2–2.4). В примере правки нет вообще.
6. Редактирование ячеек на месте с клавиатурной навигацией (Enter/Tab/стрелки), а не отдельное окно на строку; наценка ↔ цена продажи пересчитываются друг из друга.
7. Поиск товара подсказками (ё=е, раскладка, транслит, слова в любом порядке — `SearchNormalizer`), сканирование в любую строку (повторный скан = +1 к количеству).
8. Прошлая закупка и рост в % видны в строке до проведения (С-ЗАК-06), «новый» — для товара без закупок.
9. 500 строк без тормозов: виртуализация, закреплённые шапка и итог, чипы с количеством, «Показано N из M» (шаблон больших списков).
10. Реестр «Покупки» с переключателем **Документы | Позиции**, фильтрами период / поставщик / склад / товар / статус; документ открывается из обеих вкладок.
11. Черновик автосохраняется на ПК; без связи — проведение в очередь (`BackgroundReceivingQueue`), номер «ч1» до подтверждения.
12. Компактный режим 1024×600 (колонки скрываются по приоритету), тёмная тема, 5 языков.

## 4. Правила цвета строк (приоритет сверху вниз, одна полоса слева 3 px + бейдж)

| Условие | Вид | Бейдж | Чип |
|---|---|---|---|
| Цена продажи < закупки (`sale < purchase`) | полоса Danger, ячейки «Наценка/Продажа» DangerSoft | «ниже закупки» | Ниже закупки N |
| Наценка < 10 % (`LowMarginPercent`) | полоса Warning, ячейка «Наценка» WarningSoft | «маржа 7 %» | Маржа < 10 % N |
| Закупка выросла против прошлой (> 0,1 %; красным, если > 10 %) | маркер «↑ +12 %» в ячейке «Закупка» (не красит строку целиком) | — | Закупка выросла N |
| Товар без закупок / создан в этой накладной | — | «новый» AccentSoft | Новые N |
| Количество 0 | текст строки 55 % (серый), в итог не входит | «0 шт» | Без количества N |
| Изменено при правке (режим редактирования) | ячейка с рамкой Warning, под ней «было 10» серым | «изменено» SuccessSoft | Изменённые N |
| Удалено при правке | строка зачёркнута, кнопка «Вернуть» | — | Удалённые N |
| Возвращено поставщику (частично) | подстрока «возвращено 2 из 18» | «возврат 2» | С возвратом N |

Состояния совмещаются: полоса — одна (по приоритету), бейджей может быть несколько. Плитка «Требуют внимания: N ›» = ниже закупки ИЛИ маржа < 10 % ИЛИ без цены закупки. Строка без цены закупки при проведении — ошибка (С-ЗАК-06), кнопка «Провести» выключена с подсказкой.

## 7. Права и окно времени (кратко, подробно — ТЗ редактора)

- Создать и провести — кассир с правом «Приёмка»; цену продажи менять — право «Цены» (иначе колонка только показ).
- «Изменить» проведённый — только роль `owner` (`can_edit_purchase_documents`), в окне 24 ч (по умолчанию) / 48 ч / всегда от времени проведения по часам сервера; настройка — «Настройки → Операции → Закупки: правка накладных», меняет только владелец.
- Сохранение правки — через предпросмотр «до → после» (сумма, долг, остатки, закупка в карточке, затронутые продажи), причина (список + текст) и пароль владельца. Только изменённые строки уходят в PATCH.
- Количество не ниже проданного; строка с возвратом — цена заблокирована; приход в очереди — правка недоступна.

## 8. Реестр «Покупки»

- Путь: Склад → Закупки → вкладка «Покупки» (рядом с «Заказы», «Возвраты»). Переключатель **Документы | Позиции** (сегмент, запоминается).
- Фильтры (чипы и списки): период (Сегодня / 7 дней / Месяц / Всё / Даты…), поставщик, склад, товар (поиск — только в «Позициях»), статус (Черновики / Проведены / Исправлены / С возвратом), оплата (наличные / в долг / частично). Поиск по номеру ПР-2026-123 / 123 / № накладной поставщика (`DocumentNumbering.MatchesQuery`).
- «Документы»: № · Дата · Поставщик · № накл. поставщика · Склад · Позиций · Штук · Сумма · Ср. наценка · Оплата · Статус · Принял. Клик — открыть накладную (та же форма).
- «Позиции»: № · Код · Штрихкод · Наименование · Ед. · Кол-во · Закупка · Сумма · Продажа · Наценка · Документ · Дата · Поставщик · Склад · Принял. Клик — открыть накладную на этой строке.
- Итог закреплён внизу по текущему фильтру: «Документов 42 · Позиций 1 240 · Штук 18 330 · Сумма закупки 1 284 350,00 · ср. наценка 17,2 %». Кнопки: Обновить · Excel · «+ Новая накладная».
- Большие объёмы: виртуализация, догрузка по страницам сервера (`page_size` 500), сортировка по заголовку, «Показано N из M».
- 1024×600: в «Документах» скрыты «№ накл. поставщика», «Штук», «Принял»; в «Позициях» — «Код», «Штрихкод», «Ед.», «Склад», «Принял».
