## П0-1. Фискализация (касса сама пробивает чек в eKassa, сервер хранит реквизиты)

  - `mode=kassa` — чеки пробивает касса; `off` — как сегодня; `server` — пробивает сервер, касса НЕ пробивает (запись реквизитов → 409 `fiscal_mode_server`).
- Запись реквизитов: `POST api/main/pos/sales/{id}/fiscal/` и `POST api/main/pos/returns/{id}/fiscal/`, тело `{fiscal_status: pending|accepted|failed, fiscal_doc_number, fiscal_memory_number, kkm_reg_number, fiscal_sign, fiscal_qr_url, fiscal_at, kkm_shift_id, fiscal_error}`. Для `accepted` обязателен `fiscal_doc_number`. Повтор тех же реквизитов → 200 `replayed:true`; другие реквизиты у accepted → 409 `fiscal_already_set` (`current`). `pending`/`failed` перезаписываются, `accepted` — нет. Ошибки: 400 validation_error(fields), 409 sale_not_completed, return_voided, fiscal_mode_server, 404.
- Поля `fiscal_*` приходят в `GET pos/sales/`, `pos/sales/{id}/`, `pos/returns/`, `pos/returns/{id}/`; у старых чеков `fiscal_status="none"`. Части оплаты: `payments:[{method, amount}]`, номер чека `number`.
- Пробитый чек (`accepted`): PATCH/DELETE продажи → 409 `fiscal_locked`; массовое удаление → 409 со `locked_ids`; правка и аннулирование пробитого возврата → 409 `fiscal_locked`.
- `GET/PUT/PATCH settings/fiscal/` (PUT/PATCH — владелец/админ): `fiscal_enabled, tax_regime(≤32), vat_payer, vat_rates, nsp_rate`. У товара `vat_rate` (null = ставка компании). Маркировка — ждём документацию.

## Строймаркет
- `sale_unit` — это **id** единицы (число/строка из `sale_units[].id`), НЕ код `pack`. В `add-item` поле `sale_unit_id`; в `pos/checkout/` — `sale_unit` или `sale_unit_id`. Единица без id — ещё не сохранена на сервере. Конфликт единиц одного товара в чеке: 409 `sale_unit_conflict` (index); нет единицы: 404 `sale_unit_not_found`; вместе с `sale_package` нельзя (400).
- Цена упаковки: без `price` сервер берёт `wholesale_price` единицы (если опт), иначе `price` единицы, иначе `factor × цена товара`. ВЫКАЧЕНО 13.11 21:58: для строки с `sale_unit` сервер сравнивает с оптом ЕДИНИЦЫ, `is_wholesale` не обязателен (но слать можно). Ниже закупки: `purchase_price × factor`.
- Дробные упаковки/штучные — до 3 знаков; списание `quantity × factor`; шаг (`quantity_step`) и минимум (`min_sale_quantity`) в БАЗОВЫХ единицах, только при флаге `hardware_2026_11`, новой кассе и онлайн: 400 `quantity_step_mismatch`(`data.step`), `quantity_below_min`(`data.min`); офлайн-досылка не проверяет. Поля товара: `unit_code` (pcs, m, m2, m3, kg, l, t, pack, box, bag, roll, sheet, set, pair), `quantity_step`, `min_sale_quantity`, `quantity_decimals` (0–3).
- Строка продажи: `sale_unit` = объект `{id, name, factor}` или null, `base_quantity` (строка), `quantity` — в единицах продажи; остаток списывается/возвращается `quantity × factor`.
- `GET main/price-levels/` → `[{id, code, name, sort_order, is_system}]` (своих уровней ≤ 5); `GET main/products/<id>/prices/` → `{prices:[{level:<код>, price}], volume_prices:[{min_qty, price, level:null|код}]}`; `POST main/price-levels/quote/ {client?, items:[{product, qty, price?}]}` → `{applied, items:[{product, qty, price, price_source: retail|wholesale|level:<код>|volume|manual, base_price}]}`; `applied=true` только при флаге hardware и новой кассе. `price_level` у клиента — число (id уровня) или null. Цена в quote зависит от количества (ступени); `sale_unit` в quote нет — пересчёт только для строк без единицы/упаковки/варианта.
- Checkout по уровню: ручная цена кассира главнее; розничную цену или равную расчётной сервер заменяет ценой уровня клиента и ступенью; строки с sale_unit/sale_package/вариантом не пересчитываются.
- Объект прораба: поле `object` (id) в `pos/checkout/`; чужой объект → 404 `object_not_found`; `GET clients/<id>/objects/` → `{id, name, address, is_active}`. Лимит долга `credit_limit` клиента: превышен → 409 `credit_limit_exceeded` (`data:{limit,debt,requested}`, только при флаге хозмага); владелец может `override_credit_limit:true`.
