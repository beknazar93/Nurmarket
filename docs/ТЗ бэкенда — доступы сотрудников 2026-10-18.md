# ТЗ для бэкенда NurCRM — доступы сотрудников (18.10.2026)

Найдено живой проверкой: компания NBS, сотрудник «Тест Кассир 1810», роль «Кассир», доступы: Касса, Продажа,
Интерфейс кассира, Смены (сервер сам добавил `can_view_showcase`). Вход на app.nurcrm.kg под сотрудником.

## 1. Закрытые разделы открываются по прямой ссылке (серьёзно)
В меню сотрудника пунктов нет, но страницы и API отдают данные:
- `/crm/sklad` — весь склад, кнопки «Создать товар», «Редактировать», «Удалить» (доступа «Склад» нет);
- `/crm/employ` и `GET api/users/employees/` (200) — все сотрудники с email, кнопки «Доступы» и «Удалить»;
- `/crm/clients` — клиенты с телефонами (доступа «Клиенты» нет);
- `/crm/market/history`, рекомендации закупки — открываются (спорно).
Нужно: проверять `can_view_*` на сервере в КАЖДОМ API (403), а не только скрывать пункты меню на сайте.
Для сравнения: «Аналитика» сделана правильно — страница открывается, API отвечает 403.

## 2. Общие настройки компании читает любой сотрудник
`GET api/main/app-settings/nurmarket-kassa/` отдаёт настройки кассы всей компании любому сотруднику. Касса хранила там
пароли и личные коды сотрудников (в кассе исправляется 18.10: пароли не отправляются, коды — только хэш).
Нужно: запись настроек — только владелец/админ; чтение секретных полей — только владелец/админ; лучше — отдельный
серверный механизм кодов доступа (проверка кода на сервере, без выдачи кодов клиенту).

## 3. Подпись доступа `can_view_cashbox`
На сайте это «Финансы → Кассы» (все кассы компании с приходом/расходом), а в списке доступов называется «Касса» —
владелец выдаёт его кассиру, думая, что это доступ к кассе. Нужно: переименовать в «Финансы: кассы компании» и
отдельный доступ «Работа на кассе», если его нет.

## 4. Создание сотрудника
`POST api/users/employees/create/` возвращает пароль один раз — хорошо. Нужно: в ответе всегда `id` сотрудника
(касса 18.10 разбирает его; проверить, что поле есть), и возможность сбросить пароль владельцем.
