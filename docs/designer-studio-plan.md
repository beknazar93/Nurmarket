# «NurMarket Студия» — программа для дизайнеров (план, 18.10.2026)

Решения владельца 18.10.2026:
- Форма: тот же exe с ключом `--designer` (как `--owner`), без нового проекта и новых зависимостей.
  Вход в NurCRM не нужен — экраны кассы и владельца на тестовых данных (как headless-предпросмотр этапов О3–О4).
- Что создаёт дизайнер: полные темы; виды кассы (настройка поверх 6 готовых раскладок); экран покупателя и шаблоны
  чека/ценника/этикетки; «функции» — только макет + описание → заявка команде (чужой КОД в кассу не грузится).
- Публикация: через владельца. Дизайнер сохраняет файл → владелец проверяет → публикует в общий каталог
  (публичный JSON в GitHub, только чтение для касс) → кассы видят новые темы в «Маркетплейсе» без новой версии exe.

## Что уже есть (переиспользовать)
- `Services/CustomThemeStore.cs` — формат `*.nmtheme.json` («nurmarket-theme» v1, 9 цветов + радиус + шрифт), проверка импорта.
- `Views.axaml/Dialogs/ThemeEditorWindow.axaml(.cs)` — редактор, предпросмотр, контраст, импорт/экспорт.
- `Services/AccentThemeService.cs` — Palette (28 цветов) + Skin (радиусы, шрифт, плитка, высоты); BuildCustomPalette, GetPreview.
- `Services/KassaLayouts.cs` (6 раскладок, BuildPreview), `CustomerDisplaySettings.cs` (экран покупателя — данные),
  `Assets/SiteThemes/*.json` (темы сайта — данные с картинками), `MarketplaceView.axaml.cs` (галерея тем, вкладки).

## Этапы
- С1 — Формат темы v2: полные Palette (светлая/тёмная) + Skin + картинки-узоры (PNG/JPG, лимит размера), обратная
  совместимость с v1; синхронизация своих тем магазина через общие app-settings (сейчас на другой кассе своя тема → classic).
- С2 — Убрать зашитые цвета: ~258 hex в Views (121 axaml, 137 cs) → ресурсы темы, иначе часть экрана тема не красит.
- С3 — Режим `--designer`: окно «Студия» — слева настройки токенов, справа НАСТОЯЩИЕ экраны (касса: продажа, оплата,
  чек; владелец: сводка, склад, продажи) на тестовых данных; светлая/тёмная, 1366/1024, 5 языков; проверка контраста
  и обрезки надписей; экспорт пакета `*.nmpack` (тема + превью + описание + автор).
- С4 — Виды кассы как данные: параметры поверх 6 раскладок (колонки, показ блоков/кнопок, порядок, размеры).
- С5 — Экран покупателя, шаблоны чека/ценника/этикетки в Студии (поверх существующих редакторов).
- С6 — Каталог: публичный `catalog.json` в GitHub (id, автор, версия, превью, ссылка на файл, sha256); в «Маркетплейсе»
  кассы вкладка «От дизайнеров», установка = копия в общие app-settings магазина; проверка sha256 и формата.
- С7 — Заявка на функцию: в Студии форма «Новая функция» (экраны-картинки + описание) → файл/сообщение владельцу.
- С8 — Платные темы (по решению владельца, нужен сервер — ТЗ бэкенда п.7).

## Безопасность
- Только данные: цвета, числа, PNG/JPG. Никакого XAML/скриптов/сборок извне (RuntimeXamlLoader не использовать).
- Дизайнеры НЕ получают токен записи в GitHub (токен записи = подмена автообновления на всех кассах).
- Найдено 18.10: мастер-ключ функций лежит открытым текстом в `NurMarketKassa.Infrastructure/Services/LicenseKeys.cs:19` —
  его видно в exe. Решение — у владельца (перевыпуск ключа, проверка только на сервере).
