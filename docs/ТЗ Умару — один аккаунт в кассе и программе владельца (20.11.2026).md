# ТЗ Умару — один аккаунт владельца в кассе и в программе владельца (20.11.2026)

**Требование владельца:** один и тот же аккаунт (например market@nur.kg) входит и в кассу (обычный exe), и в программу владельца (`--owner`) одновременно — на одном ПК и на разных ПК. Вход в одну программу не должен выкидывать другую (никаких 401 `session_revoked`, «вход выполнен на другом устройстве», повторного ввода пароля), и один ПК не должен занимать два слота.

## Что клиент уже делает (проверено по коду 20.11)
- У каждой программы СВОЯ сессия: свой `auth.dat` и свой refresh-токен (папки `NurMarketKassa` / `NurMarketOwner`), токены не общие.
- Заголовок `X-NurMarket-Client`: касса `kassa/<версия>`, Android `android-pos/<версия>`, владелец `owner/<версия>`; в теле входа `client_type` = `desktop_pos` / `android_pos` / `desktop_owner`, `device_key`, `device_name`.
- `device_key` на одном ПК ОДИН для кассы и программы владельца (общий файл в `%LOCALAPPDATA%\NurMarketKassa\device-key.txt`); при одновременном первом запуске обе программы берут один ключ.
- Проверка пароля (для подтверждения правки) шлёт тот же `auth/login/`, но БЕЗ `device_key` и `client_type` (ответ клиент отбрасывает).

## Что нужно от сервера (клиентом не решается)
1. **Вход в один слот не должен отзывать сессию другого слота и другого клиента того же пользователя.** Касса (`desktop_pos`) и владелец (`desktop_owner`) — разные слоты: вход одного не вызывает 401 `session_revoked` у другого, не ротирует и не инвалидирует чужой refresh-токен. Просьба подтвердить и проверить на market@nur.kg.
2. **Вход без `device_key` (проверка пароля, `auth/login/` без `client_type`)** не должен занимать слот, отзывать чьи-либо сессии и выпускать токен, который гасит текущий.
3. **Разные ПК.** Сейчас два ПК одного типа (кассы на двух ПК или владелец на двух ПК) = 409 `device_slot_taken`. Для аккаунтов с ролью `owner` (и `admin`) нужно НЕ ограничивать слоты `desktop_pos` и `desktop_owner` (или флаги компании `allow_multi_desktop_pos` + новый `allow_multi_desktop_owner` включать по умолчанию для владельца). Иначе владелец, зашедший в кассу в магазине и дома, получит вопрос о замене и выкинет себя же.
4. **Один ПК — один слот каждого типа:** тот же `device_key` в том же слоте — всегда без вопроса и без отзыва (уже так по ответу 13.11; просьба подтвердить для `desktop_owner`).
5. `GET auth/devices/` — отдавать `client_type` каждой сессии, чтобы касса и владелец с одним `device_key` показывались как одно устройство (два приложения).
6. Лимит сессий/устройств на аккаунт НЕ по общему числу активных refresh-токенов: два живых токена (касса и владелец) на одном аккаунте допустимы.

## Как владелец проверит за 2 минуты (на тестовом аккаунте, не на боевых кассах)
1. Войти в кассу под market@nur.kg (или тестовой компанией NBS). 2. Не выходя, открыть программу владельца (ярлык «NurCRM Владелец»), войти тем же логином: вопроса о замене и сообщений об ошибке быть не должно. 3. Вернуться в кассу, продать/обновить каталог 1–2 минуты: «Вход выполнен на другом устройстве» не появляется. 4. В журналах (`%LOCALAPPDATA%\NurMarketKassa\Logs\nurmarket-kassa.log` и `...\NurMarketOwner\Logs\...`) нет 401/409 `session_revoked`/`device_slot_taken`. 5. Для проверки «разные ПК»: войти на втором ПК той же кассой — сейчас будет вопрос о замене (п. 3 выше), после правки сервера — нет.
