# NurMarket — мобильное приложение (Flutter)

ТЗ: `docs/ТЗ для мобильного приложения (Flutter).md`. Макеты: холст «Мобильное приложение», доски Т1–Т19 (кассир).
Начато 13.10.2026. Отдельный проект, с кодом кассы на C# не делится.

## Сборка

Flutter 3.47.5 (стабильный, лежит в `D:\flutter`), Android SDK 36, JDK 17.

```
cd NurMarketMobile
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # база drift (lib/core/db/database.g.dart)
python tool/gen_arb.py && flutter gen-l10n                  # переводы на 5 языков
flutter analyze
flutter test                                                # только правила чека, без сети и без боевой базы
flutter build apk --debug
```

Надписи меняются в `tool/gen_arb.py` (одна таблица: ru, ky, en, tr, uz), затем — две команды выше.

## Что сделано — этап 1, роль кассира

| Экран | Доска | Сервер NurCRM |
|---|---|---|
| Вход, выбор кассы | Т15 | `auth/login`, `auth/refresh`, `users/profile`, `users/company`, `construction/cashboxes` |
| Главная кассира: смена, продажи за смену, «Заканчиваются N товаров» | Т1 | `construction/shifts/?status=open`, `shifts/open/` |
| Продажа: поиск, избранное, категории, плитки, чек, скидка на чек и на строку, доп. услуга | Т2 | каталог — `products/list/` по 300 в локальную базу |
| Сканер камерой: «В чек / Узнать цену / Приёмка», фонарик, подряд без подтверждения | Т3 | — |
| Оплата: наличные, карта, в долг (поиск и создание клиента), сдача, чек в WhatsApp | Т4 | `pos/checkout/` одним запросом с `Idempotency-Key`, `clients/` |
| Чеки смены и неотправленные, карточка чека, отправка покупателю | Т5, Т6 | `pos/sales/`, `pos/sales/{id}/` |
| Склад: остатки, фильтры | Т7 | — |
| Приёмка сканером (без цен), «Отложить» | Т16 | `products/{id}/` GET + PATCH `quantity` |
| Ревизия по категории, расхождения, «Отправить администратору» | Т17 | `inventory/sessions/` (без применения) |
| Закрытие смены: итоги, «должно быть в кассе», пересчёт | Т18 | `shifts/{id}/close/` |
| Профиль: касса, язык, тёмная тема, выход | Т19 | — |
| Синхронизация: что ждёт, что не принято, «Отправить сейчас» | О10 | — |

**Без интернета:** каталог и остатки — в локальной базе (drift). Продажа, приёмка и ревизия встают в очередь.
Чек досылается тем же ключом, поэтому сервер не проведёт его дважды. Продажа в долг — только при связи (нужна сделка клиента).
Остатки на телефоне уменьшаются сразу после продажи.

## Отличия от рекомендованного стека (ТЗ, раздел 1)

- `freezed` и `json_serializable` не используются: ответы NurCRM разбираются вручную и «мягко», как в кассе.
  Имена полей у сервера бывают разными, и строгие модели падали бы на них.
- Ключ выпуска создан 21.10.2026 и хранится у владельца (ТЗ, раздел 12): `C:\Users\User\Documents\NurMarket-keys\nurmarket-mobile.keystore`
  (alias `nurmarket-mobile`, копия в `backup\`, пароль — в `README.txt` рядом). Подпись release — из `android/key.properties`
  (путь, alias, пароли); файл в `.gitignore` и не коммитится. Нет файла — release подписывается отладочным ключом.
  Выпуски APK — `github.com/beknazar93/Nurmarket-Mobile` (тег `mobile-X.Y.Z`, тестовые — prerelease).
